# Механизм внимания (attention)

<!-- время: 14 мин -->

> **О чём лекция.** Откуда взялось внимание: почему перевод через один вектор-«бутылочное горлышко» терял смысл длинных фраз, как модель научилась на каждом шаге «смотреть» на нужные слова источника и почему эта идея выросла в трансформеры.

## Зачем это нужно

Классическая модель машинного перевода seq2seq (2014) устроена так: **энкодер** — рекуррентная сеть — читает исходную фразу и сжимает её в один вектор фиксированного размера. **Декодер** — другая RNN — по этому вектору генерирует перевод слово за словом.

Проблема видна сразу: весь смысл предложения любой длины должен уместиться в один вектор из, скажем, 512 чисел. Для фразы из 5 слов это нормально, для абзаца из 50 — нет. Качество перевода резко падало на длинных предложениях. Это называют **бутылочным горлышком** (bottleneck).

Кроме того, переводчику-человеку не нужен «пересказ всей фразы»: когда он пишет слово «cats», он смотрит на слово «кошек» в оригинале. **Механизм внимания** (Bahdanau, Cho, Bengio, 2014) дал модели именно такую возможность.

## Интуиция: подсветка нужных слов

Вместо одного итогового вектора энкодер оставляет состояния для **каждого** слова источника: `h_1, h_2, …, h_n`. Когда декодер генерирует очередное слово, он:

1. смотрит на своё текущее состояние — «что я сейчас собираюсь сказать»;
2. оценивает, насколько каждое слово источника полезно прямо сейчас;
3. превращает оценки в веса, которые в сумме дают 1;
4. берёт взвешенную сумму состояний источника — **вектор контекста**;
5. использует этот контекст, чтобы выбрать следующее слово.

Это как маркер, которым на каждом шаге подсвечиваются нужные слова оригинала. Подсветка своя для каждого слова перевода. Если нарисовать веса внимания для всех пар «слово перевода — слово источника», получится карта выравнивания: почти диагональ, с отступлениями там, где порядок слов в языках разный.

## Как это работает: запросы, ключи, значения

Современная запись внимания использует три роли:

- **Query** (запрос, Q) — то, что ищем: состояние декодера;
- **Key** (ключ, K) — «метки» элементов, с которыми сравнивается запрос: состояния энкодера;
- **Value** (значение, V) — то, что достаём: обычно те же состояния энкодера.

Аналогия — поиск в библиотеке: запрос — ваша тема, ключи — названия на корешках книг, значения — содержание книг. Вы берёте понемногу из каждой книги пропорционально тому, насколько название подходит к теме.

Вычисление:

```
scores  = score(q, k_i)         для каждого элемента i
weights = softmax(scores)       неотрицательные, сумма = 1
context = Σ_i weights_i · v_i
```

Для многих запросов сразу это записывается матрично; в трансформерах используют масштабированное скалярное произведение:

```
Attention(Q, K, V) = softmax(Q·Kᵀ / √d_k) · V
```

Деление на `√d_k` (d_k — размерность ключа) не даёт оценкам становиться слишком большими: иначе softmax «залипает» на одном элементе, и градиенты исчезают.

## Аддитивное и мультипликативное внимание

Функцию `score` можно выбрать по-разному:

| вариант | score(q, k) | особенности |
|---|---|---|
| аддитивное (Bahdanau) | `vᵀ · tanh(W_1·q + W_2·k)` | маленькая сеть сравнивает запрос и ключ; работает и при разных размерностях |
| мультипликативное (Luong) | `qᵀ · W · k` или просто `q · k` | быстрее: сводится к умножению матриц |
| масштабированное скалярное | `q · k / √d_k` | стандарт в трансформерах |

На практике победило скалярное произведение: оно отлично ложится на матричные операции GPU.

## Можно ли верить весам внимания?

Карты внимания красивы и часто выглядят осмысленно — поэтому их используют как «объяснение» модели. Но с осторожностью: исследования показали, что можно получить совсем другие веса внимания почти без изменения предсказаний. Веса показывают, *откуда* модель смешивает информацию на этом слое, но не обязательно, *почему* она приняла решение. Для объяснений лучше подходят специальные методы (градиентные, SHAP и др.).

## Почему внимание стало основой трансформеров

У внимания оказались свойства, которых не было у RNN:

- **короткий путь между любыми позициями**: слово 1 и слово 100 связаны одной операцией, а не цепочкой из 99 шагов — длинные зависимости учатся легче;
- **параллельность**: веса для всех пар считаются одним умножением матриц, а не шаг за шагом;
- **гибкость**: связи между словами не заданы заранее, модель сама выбирает, на что смотреть.

В 2017 году статья «Attention Is All You Need» показала, что рекуррентность можно убрать совсем и оставить только внимание — так появился Transformer. Когда запросы, ключи и значения берутся из одной и той же последовательности, это **self-attention** — ему посвящена отдельная лекция.

## Пример на Python

Декодер собирается выдать слово «cats» и смотрит на состояния энкодера фразы «я люблю кошек .»:

```python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max(axis=-1, keepdims=True))   # вычитаем максимум для устойчивости
    return e / e.sum(axis=-1, keepdims=True)

# Скрытые состояния энкодера для 4 слов исходной фразы (размерность 3)
encoder_states = np.array([[1.0, 0.0, 0.0],    # «я»
                           [0.0, 1.0, 0.0],    # «люблю»
                           [0.0, 0.0, 1.0],    # «кошек»
                           [0.3, 0.3, 0.3]])   # «.»
# Состояние декодера, когда он собирается выдать слово «cats»
decoder_state = np.array([0.1, 0.2, 2.0])

scores = encoder_states @ decoder_state          # насколько каждое слово «подходит» запросу
weights = softmax(scores)
context = weights @ encoder_states               # взвешенная сумма — вектор контекста
print(weights.round(3))                          # [0.094 0.104 0.631 0.17 ] — больше всего на «кошек»
print(context.round(3))                          # [0.145 0.155 0.682]
```

Вектор контекста получился похож на состояние слова «кошек» — именно эта информация нужна декодеру сейчас.

В PyTorch масштабированное внимание есть готовой функцией (она же использует быстрые ядра на GPU):

```python
import torch
import torch.nn.functional as F

q = torch.randn(2, 1, 64)       # (batch, число запросов, d_k)
k = torch.randn(2, 10, 64)      # 10 элементов источника
v = torch.randn(2, 10, 64)
context = F.scaled_dot_product_attention(q, k, v)   # (2, 1, 64)
```

## Подводные камни

- **Маски.** Позиции паддинга должны получить вес 0: перед softmax к их оценкам прибавляют −∞ (или очень большое отрицательное число). Иначе модель «смотрит» на пустые токены.
- **Без масштабирования** большие размерности дают огромные оценки, softmax становится почти one-hot, и обучение застревает.
- **Квадратичная стоимость.** Для n запросов и n ключей считается n² оценок: на длинных последовательностях память растёт быстро.
- **Внимание ≠ объяснение.** Не делайте выводов о причинах решения только по картам внимания.
- **Числовая устойчивость softmax.** Вычитайте максимум перед экспонентой, как в примере, — иначе переполнение.

## Итоги

- Внимание решает проблему бутылочного горлышка seq2seq: декодер на каждом шаге смотрит на все состояния источника.
- Схема: оценки сходства запроса с ключами → softmax → взвешенная сумма значений (вектор контекста).
- Основная формула: `softmax(Q·Kᵀ / √d_k) · V`; деление на `√d_k` стабилизирует softmax.
- Bahdanau — аддитивное внимание, Luong — мультипликативное; в трансформерах — масштабированное скалярное произведение.
- Короткий путь между любыми позициями и параллельность сделали внимание основой трансформеров.
