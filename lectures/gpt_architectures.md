# GPT-архитектуры

<!-- время: 17 мин -->

> **О чём лекция.** Как устроены GPT и другие генеративные языковые модели: декодер трансформера с каузальной маской, обучение предсказанию следующего токена, генерация с temperature, top-k и top-p, KV-кэш и путь от «продолжателя текста» к ассистенту.

## Зачем это нужно

BERT отлично понимает текст, но не умеет писать. А многим задачам нужна именно генерация: ответить на вопрос своими словами, написать письмо, пересказать документ, перевести, сгенерировать код. **GPT** (Generative Pre-trained Transformer, OpenAI) — архитектура, которая учится ровно одному: **предсказывать следующий токен**. Оказалось, что если делать это очень хорошо на огромном объёме текстов, модель попутно выучивает грамматику, факты, стиль и даже умение решать задачи по нескольким примерам в запросе.

Почти все современные большие языковые модели (LLM) — ChatGPT, Claude, LLaMA, Mistral и другие — построены по этой же decoder-only схеме с разными улучшениями.

## Интуиция: очень начитанный автодополнитель

Клавиатура телефона предлагает следующее слово по двум предыдущим. GPT делает то же самое, но учитывает тысячи предыдущих токенов и обучена на значительной части интернета, книг и кода.

Чтобы хорошо продолжить фразу «Столица Франции — », нужно знать факт. Чтобы продолжить «2 + 3 · 4 = », нужно уметь считать. Чтобы продолжить письмо в деловом стиле, нужно чувствовать стиль. Задача «предскажи следующий токен» простая по формулировке, но для хорошего решения требует почти всего, что мы называем пониманием языка.

## Как это работает

**Архитектура** — стопка блоков **декодера** Transformer без cross-attention: masked multi-head self-attention, затем FFN, с остаточными связями и LayerNorm (с GPT-2 — Pre-LN). **Каузальная маска** запрещает каждому токену смотреть вправо: позиция t видит только токены 1…t.

**Обучение** — минимизация кросс-энтропии следующего токена по всем позициям текста:

```
L = −Σ_t log P(x_t | x_1, …, x_{t−1})
```

Благодаря маске предсказания для всех позиций считаются за один проход: из предложения длиной 1000 токенов получается 1000 обучающих примеров сразу. Разметка не нужна — правильный ответ всегда следующий токен текста.

**Масштаб.** Эволюция линейки показывает, как важен размер:

| модель | год | параметров | что показала |
|---|---|---|---|
| GPT-1 | 2018 | 117 млн | предобучение + дообучение работает для генерации |
| GPT-2 | 2019 | 1.5 млрд | связные длинные тексты, zero-shot на некоторых задачах |
| GPT-3 | 2020 | 175 млрд | few-shot обучение по примерам прямо в запросе |

## Генерация: как выбрать следующий токен

На выходе модель даёт **логиты** — по одному числу на каждый токен словаря. Softmax превращает их в вероятности. Дальше нужно выбрать токен, добавить его к тексту и повторить — это **авторегрессионная** генерация.

Стратегии выбора:

- **Greedy** — всегда самый вероятный токен. Детерминированно, но текст часто скучный и зацикливается («я думаю, что я думаю, что…»).
- **Beam search** — держит несколько лучших вариантов продолжения одновременно. Хорош для перевода, где ответ почти однозначен; для свободного текста даёт шаблонные фразы.
- **Сэмплирование** — случайный выбор пропорционально вероятностям.

У сэмплирования три основные настройки:

- **temperature** T делит логиты: `P = softmax(logits / T)`. T < 1 делает распределение острее (уверенно и предсказуемо), T > 1 — ровнее (разнообразно, но рискованнее);
- **top-k** — выбирать только из k самых вероятных токенов;
- **top-p** (nucleus) — из минимального набора самых вероятных токенов с суммарной вероятностью ≥ p. Набор сам подстраивается: если модель уверена, он маленький; если нет — большой.

Типичные значения: T = 0.7–1.0, top-p = 0.9–0.95. Для фактов и кода — низкая температура, для творческих текстов — повыше.

## KV-кэш

При генерации на каждом шаге добавляется один токен. Пересчитывать внимание для всех предыдущих токенов заново — расточительно: их ключи и значения не изменились (каузальная маска гарантирует, что прошлые токены не видят новых). Поэтому K и V каждого слоя сохраняют в **KV-кэш**, и на новом шаге считают запрос, ключ и значение только для нового токена. Это ускоряет генерацию в разы, но кэш занимает много памяти на длинных контекстах — отсюда приёмы вроде grouped-query attention.

## Zero-shot, few-shot и in-context learning

Большие GPT-модели умеют решать задачу, описанную прямо в тексте запроса, **без обновления весов**:

- **zero-shot**: «Переведи на английский: кошка →»;
- **few-shot**: дать несколько примеров «вход → выход», а затем новый вход — модель продолжит по шаблону.

Это называется **in-context learning**: модель «учится» по примерам в контексте. Как именно это работает внутри — активная область исследований.

## От продолжателя текста к ассистенту

Предобученная GPT продолжает текст, а не отвечает на вопросы: на «Как испечь хлеб?» она может выдать ещё десять похожих вопросов, как в форуме. Чтобы получить полезного ассистента, модель дообучают:

1. **Instruction tuning (SFT)** — дообучение на парах «инструкция → хороший ответ», написанных людьми.
2. **Обучение на предпочтениях** — люди сравнивают несколько ответов модели. В **RLHF** по этим сравнениям обучают модель-оценщик (reward model) и затем дообучают LLM с подкреплением (часто алгоритмом PPO). Более простые альтернативы, например DPO, оптимизируют модель на парах «лучше/хуже» напрямую.

Так модель учится следовать инструкциям, отвечать по делу и отказываться от вредных запросов.

## Пример на Python

Как temperature и top-p меняют выбор следующего токена — на NumPy:

```python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()

vocab = ["кот", "пёс", "дом", "мяч", "сон"]
logits = np.array([2.0, 1.5, 0.5, 0.2, -1.0])   # «сырые» оценки модели для следующего токена

for T in (0.5, 1.0, 2.0):
    print(T, softmax(logits / T).round(2))
# 0.5 [0.69 0.25 0.03 0.02 0.  ]  — почти всегда «кот»
# 1.0 [0.49 0.3  0.11 0.08 0.02]
# 2.0 [0.35 0.27 0.16 0.14 0.08]  — распределение ровнее, текст разнообразнее

def sample_next(logits, rng, T=1.0, top_k=None, top_p=None):
    probs = softmax(logits / T)
    order = np.argsort(probs)[::-1]
    keep = np.ones(len(probs), bool)
    if top_k is not None:
        keep[order[top_k:]] = False                       # оставляем k самых вероятных
    if top_p is not None:
        cum = np.cumsum(probs[order])
        cut = np.searchsorted(cum, top_p) + 1             # минимальный набор с суммой ≥ p
        keep[order[cut:]] = False
    probs = np.where(keep, probs, 0)
    return rng.choice(len(probs), p=probs / probs.sum())

rng = np.random.default_rng(0)
picks = [vocab[sample_next(logits, rng, T=1.0, top_p=0.8)] for _ in range(1000)]
print({w: picks.count(w) for w in vocab})
# {'кот': 513, 'пёс': 367, 'дом': 120, 'мяч': 0, 'сон': 0} — «мяч» и «сон» вне top-p
```

Генерация с настоящей моделью GPT-2 в библиотеке `transformers`:

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")

inputs = tokenizer("Machine learning is", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=40, do_sample=True,
                     temperature=0.8, top_p=0.95,
                     pad_token_id=tokenizer.eos_token_id)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

## Подводные камни

- **Галлюцинации.** Модель оптимизирует правдоподобие текста, а не истинность: уверенно звучащий ответ может быть выдумкой. Для фактов нужны проверка и источники (например, RAG — подстановка найденных документов в запрос).
- **Контекстное окно.** Всё, что не поместилось в контекст, модель не видит. Длинные документы режут или суммируют частями.
- **Сэмплирование ≠ воспроизводимость.** При `do_sample=True` ответы разные от запуска к запуску; фиксируйте seed или используйте greedy для тестов.
- **Повторы.** Greedy и низкая температура приводят к зацикливанию; помогают сэмплирование и `repetition_penalty`.
- **Токены, а не слова.** Ограничения длины и стоимость API считаются в токенах; русский текст обычно занимает больше токенов, чем английский того же смысла.
- **Утечка данных в оценке.** Тестовые задачи могли попасть в обучающий корпус модели — проверяйте на своих свежих данных.

## Итоги

- GPT — стопка декодеров Transformer с каузальной маской, обученная предсказывать следующий токен.
- Обучение не требует разметки: каждый токен текста — правильный ответ для предыдущих.
- Генерация авторегрессионная; стиль задают temperature, top-k и top-p.
- KV-кэш хранит ключи и значения прошлых токенов и ускоряет генерацию.
- Большие модели умеют few-shot по примерам в запросе; ассистентом модель становится после instruction tuning и обучения на предпочтениях (RLHF, DPO).
