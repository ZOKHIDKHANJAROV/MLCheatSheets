# Векторный поиск

<!-- время: 18 мин -->

> **О чём лекция.** Как искать «похожее» среди миллионов векторов: чем отличаются косинус, скалярное произведение и L2, зачем нормализовать, как приближённые индексы (IVF, HNSW, PQ) обменивают немного точности на большую скорость и как это измерять.

## Зачем это нужно

Эмбеддинги превращают тексты, картинки, товары и пользователей в векторы так, что похожие объекты оказываются рядом. Дальше почти любая задача — найти k объектов, ближайших к запросу: RAG ищет подходящие фрагменты, рекомендательные системы — похожие товары, дедупликация — почти одинаковые записи, память агента — релевантные воспоминания.

Пока векторов тысячи, достаточно сравнить запрос с каждым. Когда их миллионы, а ответ нужен за миллисекунды, перебор становится слишком дорогим. Тогда используют **приближённый поиск ближайших соседей** (ANN, approximate nearest neighbors).

## Интуиция: библиотека без каталога

Вам нужна книга, «похожая на эту». Можно пройти по всем полкам и сравнить каждую книгу — надёжно, но долго. Если книги разложены по залам по тематике, достаточно заглянуть в два-три ближайших зала: быстро, но редкая похожая книга, оказавшаяся в другом зале, будет пропущена.

- **Перебор всех полок** — точный поиск.
- **Залы по тематике** — ячейки индекса IVF.
- **Сколько залов вы обойдёте** — параметр nprobe: больше залов — точнее и дольше.

Весь вопрос в обмене: какую долю потерянных соседей (recall) мы готовы терпеть ради скорости.

## Как это работает

### Меры близости

Для векторов a и b размерности d:

```
a · b = Σᵢ aᵢ · bᵢ                      скалярное произведение
cos(a, b) = a · b / (‖a‖ · ‖b‖)         косинусное сходство
‖a − b‖² = ‖a‖² + ‖b‖² − 2 · a · b      квадрат L2-расстояния
```

Косинус зависит только от угла между векторами, скалярное произведение — ещё и от их длин, L2 — от расстояния между концами. Если векторы **нормализованы** (‖a‖ = ‖b‖ = 1), то cos(a, b) = a · b и ‖a − b‖² = 2 − 2 · cos(a, b): все три меры дают один и тот же порядок соседей. Поэтому эмбеддинги часто нормализуют заранее и ищут по скалярному произведению — это одно матричное умножение. Метрику выбирают ту, на которой обучалась модель эмбеддингов.

### Точный перебор

Считаем сходство запроса со всеми N векторами и берём k лучших: порядка N · d операций на запрос. Для сотен тысяч векторов это обычно быстро, особенно на GPU. Память — N · d · 4 байта для float32 (миллион векторов размерности 768 занимает около 3 ГБ). Точный перебор — эталон, с которым сравнивают любой приближённый индекс.

### Приближённые индексы

**IVF** (inverted file). Все векторы разбиваются алгоритмом k-means на `nlist` ячеек. Для каждой ячейки хранится центроид и список её векторов. На запросе выбираются `nprobe` ближайших центроидов и перебираются только векторы их ячеек. Сравнений получается порядка nlist + nprobe · N / nlist вместо N. При nprobe = nlist индекс превращается в точный перебор.

**HNSW** — многоуровневый граф «малого мира». Верхние уровни разрежены и позволяют быстро «прыгнуть» к нужной области, нижний содержит все точки. Поиск жадно идёт по рёбрам к вершинам, всё более близким к запросу. Параметры: `M` — число связей вершины, `efSearch` — ширина просмотра при запросе (больше — точнее, медленнее). Время поиска растёт примерно как log N, но граф требует много памяти.

**PQ** (product quantization) сжимает векторы. Вектор делится на m подвекторов; для каждой части обучается словарь из k центроидов (часто 256), и подвектор заменяется номером ближайшего центроида. Вектор из d чисел float32 (4 · d байт) превращается в m байт. Расстояния считаются приблизительно, зато памяти нужно в десятки раз меньше. Часто комбинируют: IVF сужает поиск, PQ сжимает содержимое ячеек.

### Recall против скорости

Качество приближённого поиска меряют так:

```
recall@k = |ANN-top-k ∩ точный top-k| / k
```

У каждого индекса есть «ручка» компромисса: nprobe у IVF, efSearch у HNSW. Строят кривую «recall — доля просмотренных векторов (или время)» и выбирают точку под требования, например recall@10 не ниже 0.95.

### Метаданные-фильтры

Часто нужно искать «среди документов языка ru за 2025 год». **Пре-фильтр** сначала отбирает подходящие записи, потом ищет среди них: результат точный, но структуры ANN плохо дружат с жёсткими фильтрами. **Пост-фильтр** ищет top-k и отбрасывает неподходящее: просто, но можно остаться без результатов, поэтому берут запас (например, k · 10). Если под фильтр попадает очень малая доля базы, надёжнее всего точный перебор по отобранным записям.

## Пример на Python

Игрушечный IVF на NumPy: k-means строит ячейки, поиск просматривает только `nprobe` ближайших, а recall@10 считается относительно точного перебора.

```python
import numpy as np

rng = np.random.default_rng(0)
n, d, n_centers, nlist = 5000, 32, 25, 25

# данные из облаков и нормализация: теперь скалярное произведение = косинус
centers = rng.normal(size=(n_centers, d)) * 0.7
X = centers[rng.integers(0, n_centers, n)] + rng.normal(size=(n, d))
X /= np.linalg.norm(X, axis=1, keepdims=True)
Q = centers[rng.integers(0, n_centers, 50)] + rng.normal(size=(50, d))
Q /= np.linalg.norm(Q, axis=1, keepdims=True)


def nearest_center(M, C):
    # argmin ‖x − c‖² = argmax (x · c − ‖c‖² / 2)
    return np.argmax(M @ C.T - 0.5 * (C ** 2).sum(1), axis=1)


C = X[rng.choice(n, nlist, replace=False)].copy()
for _ in range(10):                        # несколько итераций k-means
    cell = nearest_center(X, C)
    for j in range(nlist):
        if (cell == j).any():
            C[j] = X[cell == j].mean(axis=0)
cell = nearest_center(X, C)


def exact_top_k(q, k=10):
    return np.argsort(-(X @ q))[:k]


def ivf_top_k(q, nprobe, k=10):
    probes = np.argsort(-(C @ q - 0.5 * (C ** 2).sum(1)))[:nprobe]
    cand = np.flatnonzero(np.isin(cell, probes))     # векторы выбранных ячеек
    return cand[np.argsort(-(X[cand] @ q))[:k]], len(cand)


for nprobe in (1, 3, 8, nlist):
    recalls, scanned = [], []
    for q in Q:
        found, n_cand = ivf_top_k(q, nprobe)
        recalls.append(len(set(found) & set(exact_top_k(q))) / 10)
        scanned.append(n_cand / n)
    print(f"nprobe={nprobe:2d}  recall@10 = {np.mean(recalls):.2f}  "
          f"просмотрено {100 * np.mean(scanned):.0f}% базы")
```

С ростом `nprobe` recall растёт, но растёт и доля просмотренных векторов; при `nprobe = nlist` поиск совпадает с точным (recall равен 1). Именно эту кривую и строят, подбирая параметры индекса. Попробуйте убрать нормализацию и сравнить результаты скалярного произведения и L2.

## Подводные камни

- **Нет нормализации при скалярном произведении.** Длинные векторы получают завышенный счёт, порядок соседей отличается от косинусного. Нормализуйте векторы, если модель обучена на косинусе.
- **Разные модели для запроса и документов.** Векторы из разных моделей живут в разных пространствах, сравнивать их бессмысленно. Смена модели эмбеддингов означает переиндексацию всей базы.
- **Recall не измеряют.** ANN приблизителен по определению. Берите набор реальных запросов, считайте точный top-k и сравнивайте с индексом.
- **Слишком много ячеек на маленькой базе.** При большом nlist ячейки получаются пустыми и перекошенными, а точный перебор по такой базе дешевле.
- **Пост-фильтр с малым k.** После отбрасывания неподходящих записей остаётся пусто. Увеличьте k или используйте пре-фильтр.
- **Обновления.** Добавление и удаление векторов в ANN-индексе сложнее, чем в обычной базе, а при сильном дрейфе данных центроиды IVF устаревают — индекс приходится пересобирать.
- **«Проклятие размерности».** Чем выше размерность, тем меньше различаются расстояния до ближних и дальних точек, и тем труднее ANN сохранять высокий recall без роста просмотра.

## Итоги

- Векторный поиск — это поиск k ближайших векторов; для нормализованных векторов косинус, скалярное произведение и L2 дают одинаковый порядок.
- Точный перебор (N · d операций) прост и служит эталоном; на миллионах векторов нужен ANN.
- IVF смотрит только nprobe ближайших ячеек, HNSW идёт по графу, PQ сжимает векторы в m байт.
- Качество ANN — recall@k относительно точного поиска; параметры (nprobe, efSearch) меняют recall на скорость.
- Фильтры по метаданным бывают пре- и пост-; узкие фильтры лучше выполнять точным перебором.
