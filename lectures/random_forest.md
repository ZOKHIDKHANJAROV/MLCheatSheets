# Случайный лес для классификации

<!-- время: 15 мин -->

> **О чём лекция.** Как из множества неустойчивых деревьев получить одну устойчивую и точную модель: бэггинг, случайный выбор признаков, out-of-bag оценка и важность признаков. И почему случайный лес — одна из самых надёжных моделей «из коробки».

## Зачем это нужно

Одно дерево решений понятно, но капризно: оно переобучается, а небольшое изменение данных может полностью поменять его структуру и прогнозы. Хочется сохранить сильные стороны деревьев — нелинейность, работу без масштабирования, устойчивость к выбросам в признаках — и убрать главную слабость.

Случайный лес (Random Forest) делает именно это. Он почти не требует настройки, редко катастрофически переобучается, сам даёт оценку качества без отдельной валидации и показывает важность признаков. Поэтому его часто берут как первую серьёзную модель для табличных данных и как сильный baseline для сравнения с бустингом.

## Интуиция: мудрость толпы

Попросите одного человека угадать вес быка — он может сильно ошибиться. Попросите тысячу человек и возьмите среднее — результат окажется удивительно точным. Это работает при одном условии: люди должны ошибаться **по-разному**. Если все смотрят на одну и ту же неверную подсказку, их ошибки не компенсируют друг друга.

Случайный лес — это толпа деревьев. Каждое дерево по отдельности переобучено и ошибается, но если их ошибки слабо связаны между собой, при усреднении они взаимно гасятся. Вся хитрость алгоритма — в том, чтобы сделать деревья **непохожими** друг на друга.

## Как это работает

Деревья делаются разными двумя источниками случайности.

**1. Бэггинг (bootstrap aggregating).** Каждое дерево обучается на своей бутстрэп-выборке: из n обучающих объектов случайно выбираются n объектов **с возвращением**. Какие-то объекты попадают в выборку по несколько раз, а примерно треть не попадает вовсе. Доля объектов, попавших в бутстрэп-выборку, стремится к `1 − 1/e ≈ 0.632`.

**2. Случайные подмножества признаков.** При каждом разбиении узла дерево выбирает лучший порог не среди всех признаков, а среди случайного подмножества размера `max_features`. Для классификации по умолчанию это `√(число признаков)`. Без этого шага все деревья выбирали бы в корне один и тот же самый сильный признак и оказывались бы похожими.

**Прогноз** — голосование: в sklearn усредняются вероятности классов от всех деревьев, и выбирается класс с наибольшей средней вероятностью. Для регрессии усредняются прогнозы.

Деревья в лесу обычно растут глубокими, без сильных ограничений: у каждого низкое смещение и высокая дисперсия, а усреднение снижает дисперсию. Это ключевая идея: **лес уменьшает дисперсию, почти не увеличивая смещение**. Чем меньше корреляция между деревьями, тем сильнее выигрыш от усреднения.

## Out-of-bag оценка

Каждое дерево не видело примерно 37% объектов — они остались «вне мешка» (out-of-bag, OOB). Для каждого объекта можно собрать прогнозы только тех деревьев, которые его не видели, и сравнить с правильным ответом. Получается оценка качества на новых данных — почти бесплатно, без отдельной валидационной выборки. В sklearn: `oob_score=True`, результат в `oob_score_`.

## Сколько деревьев нужно

С ростом `n_estimators` качество сначала быстро растёт, затем выходит на плато. **Переобучения от увеличения числа деревьев не происходит**: больше деревьев — просто более точное усреднение, только медленнее. Обычно хватает 200–500 деревьев. Переобучиться лес может из-за слишком глубоких деревьев на шумных данных, и тогда помогают `min_samples_leaf` и `max_depth`.

Главные гиперпараметры:

| параметр | что делает | совет |
|---|---|---|
| `n_estimators` | число деревьев | 200–500, больше — не хуже, но медленнее |
| `max_features` | признаков на разбиение | `"sqrt"` для классификации; меньше — деревья разнообразнее |
| `min_samples_leaf` | минимум объектов в листе | 1–10; увеличить при шумных данных |
| `max_depth` | глубина деревьев | обычно `None`; ограничить, если модель тяжёлая или переобучается |
| `n_jobs` | параллельность | `-1` — все ядра: деревья строятся независимо |

## Важность признаков

Лес показывает, какие признаки он использует сильнее всего. Есть два способа:

- `feature_importances_` (по уменьшению impurity) — быстро, но **смещено**: признаки с большим числом уникальных значений (ID, непрерывные шумные признаки) получают завышенную важность, а считается она на обучающих данных;
- **permutation importance** — перемешиваем значения одного признака на валидации и смотрим, насколько упало качество. Медленнее, но честнее (`sklearn.inspection.permutation_importance`).

Оба способа делят важность между коррелирующими признаками: два почти одинаковых признака могут оба выглядеть «средне важными».

## Пример на Python

```python
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = make_classification(n_samples=1000, n_features=10, n_informative=4, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)

tree = DecisionTreeClassifier(random_state=0).fit(X_tr, y_tr)
print("одно дерево, test:", round(tree.score(X_te, y_te), 3))        # 0.784

for n in [10, 100, 300]:
    rf = RandomForestClassifier(n_estimators=n, oob_score=True, random_state=0, n_jobs=-1)
    rf.fit(X_tr, y_tr)
    print(f"лес из {n}: test {rf.score(X_te, y_te):.3f}, OOB {rf.oob_score_:.3f}")

# лес из 10: test 0.844, OOB 0.819
# лес из 100: test 0.868, OOB 0.873
# лес из 300: test 0.876, OOB 0.876
```

Лес обыгрывает одиночное дерево почти на 10 процентных пунктов. При росте числа деревьев качество растёт и выходит на плато, а OOB-оценка всё точнее совпадает с качеством на тесте. При 10 деревьях OOB занижена: каждый объект оценивают всего 3–4 дерева, которые его не видели.

## Подводные камни

- **Важность по impurity** обманывает на признаках с высокой кардинальностью — проверяйте permutation importance.
- **Экстраполяция.** Как и дерево, лес не предсказывает за пределами диапазона обучающих ответов. Для прогноза растущего тренда (продажи растут год от года) он систематически занижает прогноз.
- **Размер модели.** Сотни глубоких деревьев занимают много памяти и медленно предсказывают. Помогают `max_depth`, `min_samples_leaf` и меньшее число деревьев.
- **Вероятности** леса обычно «сжаты» к середине (редко бывают близки к 0 и 1). Если нужны точные вероятности — калибруйте.
- **Дисбаланс классов**: `class_weight="balanced"` или `"balanced_subsample"`, плюс подбор порога.
- **Лес против бустинга.** На табличных данных хорошо настроенный градиентный бустинг обычно немного точнее, но лес проще настроить и труднее «сломать» неудачными гиперпараметрами.

## Итоги

- Случайный лес — ансамбль глубоких деревьев, обученных на бутстрэп-выборках со случайным подмножеством признаков в каждом разбиении.
- Усреднение некоррелированных деревьев уменьшает дисперсию — главную слабость одиночного дерева.
- OOB-оценка даёт почти бесплатную проверку качества: каждый объект оценивают деревья, которые его не видели.
- Увеличение числа деревьев не вызывает переобучения, только замедляет модель.
- Для важности признаков надёжнее permutation importance, чем встроенная `feature_importances_`.
