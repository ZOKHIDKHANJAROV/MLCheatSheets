# Основы ИИ-агентов

<!-- время: 14 мин -->

> **О чём лекция.** Что такое ИИ-агент, из каких частей он состоит, как работает его цикл «восприятие → рассуждение → действие → наблюдение» и как понять, нужен ли агент или хватит простой цепочки.

## Зачем это нужно

Обычная языковая модель отвечает на запрос один раз, опираясь только на то, что запомнила при обучении. Но многие задачи так не решить: узнать актуальные данные, посчитать точно, поискать в базе, изменить файл, выполнить десять шагов подряд и по пути поправить план. Для таких задач вокруг модели строят **агента** — систему, где модель управляет циклом действий.

Понимать устройство агента нужно, чтобы осознанно решать, где он оправдан, и чтобы он не превратился в дорогой, медленный и непредсказуемый механизм там, где хватило бы одного запроса.

## Интуиция: стажёр с заданием и инструментами

Представьте стажёра, которому дали цель: «Выясни, сколько стоят билеты в два города, и посчитай сумму». У него есть телефон, калькулятор и блокнот. Он не знает заранее, сколько звонков понадобится. Он действует так: подумал, что узнать → позвонил → записал ответ → понял, что делать дальше → и так до результата. Если звонок не помог, пробует другой способ. Если через два часа ничего нет — докладывает, что не вышло.

Это и есть агент:

- **стажёр** — языковая модель (LLM), принимающая решения;
- **телефон и калькулятор** — инструменты;
- **блокнот** — память;
- **цель и ограничение по времени** — задача и лимит шагов.

## Как это работает

**Цикл агента** состоит из четырёх фаз:

1. **Восприятие.** Агент получает цель, историю действий и состояние среды.
2. **Рассуждение.** LLM решает, что делать дальше: вызвать инструмент или выдать ответ.
3. **Действие.** Программа выполняет выбранный вызов (поиск, код, запрос к API).
4. **Наблюдение.** Результат добавляется в контекст, и цикл начинается заново.

Цикл заканчивается, когда модель выдала финальный ответ или сработал ограничитель — лимит шагов, бюджета, времени.

**Компоненты агента:**

| компонент | роль |
|---|---|
| LLM | выбирает действие, формирует ответ |
| инструменты | дают доступ к данным и действиям во внешнем мире |
| память | краткосрочная — контекст текущей задачи; долгосрочная — внешнее хранилище, которое подгружают по необходимости |
| планировщик | разбивает цель на подзадачи, иногда пересматривает план |
| ограничители | лимиты шагов и стоимости, права доступа, подтверждение опасных действий |

**Автономность** — это шкала, а не переключатель: от «агент только предлагает, решает человек» до «действует сам». Чем необратимее действия (отправка писем, платежи, удаление данных), тем больше причин оставить человека в контуре.

### Агент, чат-бот и workflow

| | чат-бот | workflow (цепочка) | агент |
|---|---|---|---|
| шаги | один ответ | порядок задан в коде | порядок выбирает модель |
| инструменты | обычно нет | по сценарию | выбираются по ситуации |
| предсказуемость | высокая | высокая | ниже |
| цена и задержка | низкие | средние | высокие и переменные |

### Когда агент нужен, а когда достаточно цепочки

Если шаги известны заранее (например, «извлечь поля из письма → классифицировать → составить ответ»), используйте **цепочку**: она дешевле, быстрее и проще в тестировании. **Агент** оправдан, когда:

- путь к цели зависит от промежуточных результатов;
- число шагов заранее неизвестно;
- нужно выбирать из многих инструментов;
- допустимы более высокая цена и задержка.

Общее правило: начинайте с простейшего решения и усложняйте его, только когда оно не справляется.

## Пример на Python

Настоящая LLM здесь не нужна: «модель» заменим функцией, которая принимает решения по правилам. Цикл агента при этом остаётся настоящим — его можно запускать и тестировать без обращения к сети.

```python
# Мини-агент без реальной LLM: «модель» — функция с правилами
PRICES = {"Москва": 100, "Казань": 80}          # условная база цен

def search_price(city):
    return PRICES.get(city, "нет данных")

TOOLS = {"search_price": search_price}

def fake_llm(goal, history):
    """Решает по правилам, что делать, глядя на цель и историю."""
    done = {h["arg"] for h in history}
    for city in ("Москва", "Казань"):
        if city in goal and city not in done:
            return {"action": "search_price", "arg": city}
    prices = [h["observation"] for h in history
              if isinstance(h["observation"], int)]
    return {"action": "finish", "arg": f"Сумма: {sum(prices)}"}

def run_agent(goal, max_steps=5):
    history = []
    for _ in range(max_steps):
        decision = fake_llm(goal, history)                   # рассуждение
        if decision["action"] == "finish":                   # остановка
            return decision["arg"], history
        tool = TOOLS[decision["action"]]
        observation = tool(decision["arg"])                  # действие
        history.append({**decision, "observation": observation})  # наблюдение
    return "лимит шагов", history

answer, trace = run_agent("Сколько стоят билеты: Москва и Казань?")
print(answer)       # Сумма: 180
print(len(trace))   # 2
```

В `fake_llm` каждая итерация анализирует историю и выбирает следующее действие; `run_agent` выполняет его, записывает наблюдение и проверяет остановку. Попробуйте передать `max_steps=1` — агент не успеет ответить и вернёт «лимит шагов».

## Подводные камни

- **Нет лимита шагов.** Агент может зациклиться и тратить токены без конца. Лимит и бюджет задавайте всегда.
- **Агент вместо цепочки.** Лишняя автономность — это лишняя цена, задержка и источник ошибок. Если шаги ясны, пишите цепочку.
- **Накопление ошибок.** Если каждый шаг верен с вероятностью 0.9, то после 10 шагов вся траектория верна лишь с вероятностью около 0.9¹⁰ ≈ 0.35. Чем длиннее траектория, тем важнее проверки и короткие цепочки действий.
- **Слишком много инструментов.** Похожие описания путают модель при выборе.
- **Нет логов.** Без записи шагов (мысль, действие, наблюдение) сбой нельзя разобрать и воспроизвести.
- **Опасные действия без подтверждения.** Необратимые операции стоит пропускать через человека.

## Итоги

- Агент — это LLM, управляющая циклом «восприятие → рассуждение → действие → наблюдение» с инструментами и памятью.
- Компоненты: LLM, инструменты, память, планировщик и ограничители.
- Чат-бот отвечает за один шаг, workflow идёт по заданному порядку, агент сам выбирает путь.
- Агент нужен, когда путь заранее неизвестен; иначе хватит цепочки.
- Лимит шагов, логи и контроль опасных действий — обязательная часть любого агента.
