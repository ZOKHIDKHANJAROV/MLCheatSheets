# Детекция объектов (YOLO, SSD, Faster R-CNN)

<!-- время: 16 мин -->

> **О чём лекция.** Чем детекция отличается от классификации, как YOLO находит все объекты на кадре за один проход сети и какие три идеи — IoU, NMS и mAP — нужно понимать, чтобы обучать и оценивать любой детектор.

## Зачем это нужно

Классификатор отвечает на вопрос «что на картинке?» одним словом: «кошка». Но во многих задачах этого мало. Беспилотному автомобилю нужно знать, где именно пешеходы и машины; камере в магазине — сколько людей у кассы; системе контроля на производстве — где на ленте дефектная деталь.

**Детекция объектов** отвечает на два вопроса сразу: *что* и *где*. Результат — список рамок (bounding boxes), у каждой есть координаты, класс и уверенность модели:

```
[x_min, y_min, x_max, y_max, класс, уверенность]
[  34,    50,   210,   300, "человек", 0.93]
```

Объектов на кадре может быть сколько угодно, и они бывают разного размера — от машины на весь кадр до светофора в углу. Поэтому детекция сложнее классификации.

## Интуиция: два подхода

Исторически сложились два семейства детекторов.

**Двухстадийные** (R-CNN, Fast R-CNN, Faster R-CNN). Сначала находим места, где *может быть* объект (region proposals), затем для каждого кандидата отдельно решаем, что это и как точнее поставить рамку. Аналогия: сначала обвести карандашом всё подозрительное, потом рассмотреть каждое пятно через лупу. Точно, но медленнее.

**Одностадийные** (YOLO, SSD, RetinaNet). Сеть за **один проход** сразу выдаёт и рамки, и классы для всей картинки. Название YOLO — *You Only Look Once*, «смотришь только один раз». Это быстрее и подходит для видео в реальном времени.

Со временем разница в точности почти исчезла: современные одностадийные детекторы (линейка YOLO от Ultralytics и др.) точны и при этом работают на видео десятки кадров в секунду.

## Как это работает (YOLO)

Идея оригинального YOLO: разбить изображение сеткой S×S клеток. Каждая клетка отвечает за объекты, центр которых в неё попал, и предсказывает:

- несколько рамок: смещение центра внутри клетки, ширину и высоту;
- **objectness** — уверенность, что в рамке вообще есть объект;
- вероятности классов.

Вся картинка обрабатывается свёрточной сетью один раз, а выход — это тензор «сетка × предсказания для клетки». Поэтому скорость не зависит от числа объектов.

Дальнейшие версии развили идею:

- **якорные рамки (anchors)** — заранее заданные шаблоны формы (высокая узкая для человека, широкая для машины); сеть предсказывает не рамку с нуля, а поправку к шаблону;
- **несколько масштабов** — предсказания делаются на картах признаков разного разрешения: мелкие объекты ищутся на детальной карте, крупные — на грубой (идея Feature Pyramid Network);
- **anchor-free** — многие новые версии (например, YOLOv8) отказались от якорей и предсказывают рамку напрямую относительно точки; это убирает подбор шаблонов под датасет.

SSD работает похоже: предсказания с нескольких слоёв сети разного разрешения, для каждой позиции — набор рамок-шаблонов. Faster R-CNN использует сеть-генератор кандидатов (RPN), а затем отдельную «голову», которая уточняет каждого кандидата.

## IoU: насколько рамки совпадают

Чтобы сказать, правильно ли найдена рамка, её сравнивают с эталонной через **IoU** (Intersection over Union):

```
IoU = площадь пересечения / площадь объединения
```

IoU = 1 — рамки совпадают идеально, IoU = 0 — не пересекаются. Обычно предсказание считается правильным (true positive), если IoU с эталоном ≥ 0.5 и класс совпадает.

## NMS: убираем дубли

Детектор обычно выдаёт для одного объекта много похожих рамок — от соседних клеток и якорей. **Non-Maximum Suppression** оставляет по одной:

1. Отсортировать рамки по уверенности.
2. Взять самую уверенную, добавить в ответ.
3. Удалить все рамки, у которых IoU с ней выше порога (например, 0.5).
4. Повторять, пока рамки не кончатся.

NMS делают отдельно для каждого класса, чтобы рамка «человек» не удаляла пересекающуюся рамку «велосипед».

## mAP: как оценивают детектор

Accuracy здесь не подходит. Используют **mAP** (mean Average Precision):

1. Для каждого класса строят кривую precision–recall, меняя порог уверенности.
2. Площадь под ней — **AP** этого класса.
3. Среднее AP по классам — **mAP**.

Пишут `mAP@0.5` — при пороге IoU 0.5 — или `mAP@0.5:0.95` (метрика COCO): среднее по порогам IoU от 0.5 до 0.95 с шагом 0.05. Вторая строже и награждает точное положение рамок.

## Пример на Python

IoU и NMS — сердце постобработки любого детектора. Вот они на NumPy:

```python
import numpy as np

def iou(a, b):
    """a, b — рамки [x_min, y_min, x_max, y_max]."""
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    area = lambda r: (r[2] - r[0]) * (r[3] - r[1])
    return inter / (area(a) + area(b) - inter)

def nms(boxes, scores, iou_threshold=0.5):
    order = np.argsort(scores)[::-1]          # от самой уверенной рамки к наименее уверенной
    keep = []
    while len(order):
        best, rest = order[0], order[1:]
        keep.append(int(best))
        order = np.array([i for i in rest if iou(boxes[best], boxes[i]) < iou_threshold], dtype=int)
    return keep

boxes = np.array([[10, 10, 50, 50],     # кошка, вариант 1
                  [12, 12, 52, 52],     # кошка, почти та же рамка
                  [60, 60, 90, 95],     # собака
                  [11, 8, 48, 49]])     # кошка, ещё один дубль
scores = np.array([0.90, 0.75, 0.80, 0.60])

print(round(iou(boxes[0], boxes[1]), 3))   # 0.822
print(nms(boxes, scores))                  # [0, 2] — по одной рамке на объект
```

На практике берут готовую модель. С библиотекой `ultralytics` детекция и дообучение занимают несколько строк:

```python
from ultralytics import YOLO

model = YOLO("yolov8n.pt")                 # n — самая маленькая и быстрая версия
results = model("street.jpg", conf=0.25)   # порог уверенности
for box in results[0].boxes:
    print(box.cls, box.conf, box.xyxy)     # класс, уверенность, координаты

model.train(data="my_data.yaml", epochs=50, imgsz=640)   # дообучение на своих данных
```

## Подводные камни

- **Формат разметки.** YOLO хранит рамки как `класс x_center y_center width height`, нормированные на размер картинки (от 0 до 1); COCO — как `x_min y_min width height` в пикселях; Pascal VOC — `x_min y_min x_max y_max`. Перепутанный формат — самая частая причина «модель ничего не находит».
- **Порог уверенности.** Низкий — много ложных срабатываний, высокий — пропуски. Подбирайте на валидации под задачу: для охраны пропуск дороже ложной тревоги.
- **Порог NMS.** Слишком низкий удалит соседние объекты в толпе, слишком высокий оставит дубли.
- **Мелкие объекты.** При уменьшении картинки до 640 пикселей мелкие объекты почти исчезают. Помогают большее разрешение входа и нарезка изображения на тайлы.
- **Аугментация.** При отражении и обрезке рамки должны меняться вместе с картинкой.
- **Сравнение mAP.** Сравнивать можно только одинаковые метрики: `mAP@0.5` всегда заметно выше `mAP@0.5:0.95`.

## Итоги

- Детекция = классификация + локализация: на выходе список рамок с классом и уверенностью.
- Двухстадийные детекторы (Faster R-CNN) сначала ищут кандидатов, одностадийные (YOLO, SSD) всё делают за один проход и быстрее.
- IoU измеряет совпадение рамок, NMS убирает дубли, mAP оценивает качество детектора.
- Ключевые настройки на практике — формат разметки, порог уверенности и порог NMS.
