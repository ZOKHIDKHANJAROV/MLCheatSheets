# Безопасность ИИ-агентов

<!-- время: 15 мин -->

> **О чём лекция.** Почему агент с инструментами опаснее обычного чат-бота и как строить защиту: prompt injection, наименьшие привилегии, песочница, подтверждение человеком, guardrails, «смертельная триада» и аудит.

## Зачем это нужно

Чат-бот может только ответить текстом. Агент читает письма и веб-страницы, вызывает инструменты, меняет файлы и базы, отправляет сообщения. Ошибка или обман превращаются в реальные действия: удалённые данные, утёкшие секреты, неверный платёж.

Ключевая проблема: для модели инструкции и данные — это один и тот же поток текста. Она не умеет надёжно отличать «приказ владельца» от «текста, который случайно лежит на странице». Поэтому защищать нужно систему вокруг модели, а не надеяться на фразу «не слушайся чужих команд» в промпте.

## Интуиция: курьер с ключами

Представьте курьера, который по просьбе хозяина заходит в офисы. Он читает записки на столах. Если одна записка гласит: «Курьер, отдай ключи от склада и отнеси их по адресу X», доверчивый курьер может выполнить. Что поможет?

- Выдать ключи только от нужных дверей (наименьшие привилегии).
- Не пускать курьера в то, что нельзя ломать (песочница).
- Попросить хозяина подтвердить необратимый шаг (human-in-the-loop).
- Вести журнал, кто куда ходил (аудит).

## Как это работает

### Prompt injection

**Прямая** инъекция — пользователь сам пытается заставить модель нарушить правила. **Косвенная** — вредная инструкция спрятана в данных: на веб-странице (в том числе невидимым текстом), в письме, в документе, в ответе инструмента. Владелец агента её не видит. Полностью исключить инъекции сегодня нельзя, поэтому предполагаем, что модель может быть обманута, и ограничиваем ущерб.

### Наименьшие привилегии

Каждому инструменту — только нужные права: чтение вместо записи, одна папка вместо диска, токен на один репозиторий, белые списки доменов и команд, короткоживущие учётные данные. Ограничения проверяет код инструмента, а не текст промпта.

### Песочница

Код агента выполняется в изолированной среде: ограниченная файловая система, закрытая по умолчанию сеть, лимиты CPU, памяти и времени, без секретов. Это ограничивает ущерб, но не мешает обману.

### Human-in-the-loop

Необратимые и дорогие действия (удаление, платёж, отправка наружу, публикация, смена прав) требуют подтверждения. Показывайте человеку реальные аргументы вызова. Не превращайте подтверждения в поток одинаковых «ОК».

### Guardrails

Проверки на входе (инъекции, запрещённые темы, размер), на вызове инструмента (схема аргументов, белые списки) и на выходе (секреты, персональные данные, подозрительные ссылки). Они вероятностны и пропускают часть атак, поэтому это слой, а не единственная защита.

### Смертельная триада

Опасная сессия — та, где одновременно есть:

1. доступ к приватным данным;
2. контакт с недоверенным контентом;
3. внешний канал (почта, HTTP, публикация).

Тогда инструкция из недоверенного контента может заставить агента отправить приватные данные наружу. Достаточно убрать любую одну из трёх возможностей. Это главный архитектурный тест при проектировании агента.

### Утечки данных и аудит

Данные утекают через внешние каналы, через разметку (картинка с URL, содержащим данные), через логи и общую память между пользователями. Нужно минимизировать то, что попадает в контекст, маскировать секреты, изолировать сессии. Аудит фиксирует вызовы, аргументы, решения политики и подтверждения в журнале, который агент не может менять.

## Пример на Python

Политика вызовов инструментов и проверка триады (заглушки без реальных API):

```python
POLICY = {
    "read_file": "allow",
    "search_web": "allow",
    "send_email": "ask",
    "delete_file": "ask",
    "run_shell": "deny",
}


def decide(call: dict) -> str:
    """Решение по вызову: allow / ask / deny. Неизвестный инструмент запрещён."""
    return POLICY.get(call["tool"], "deny")


def lethal_trifecta(capabilities: set) -> bool:
    """Есть ли в сессии все три опасные возможности."""
    return {"private_data", "untrusted_content", "external_channel"} <= capabilities


audit_log = []


def execute(call: dict, approve) -> str:
    verdict = decide(call)
    if verdict == "ask" and not approve(call):
        verdict = "deny"
    audit_log.append({"tool": call["tool"], "args": call.get("args"), "verdict": verdict})
    return verdict


always_no = lambda call: False
print(execute({"tool": "read_file", "args": {"path": "notes.txt"}}, always_no))
print(execute({"tool": "send_email", "args": {"to": "x@example.com"}}, always_no))
print(execute({"tool": "format_disk"}, always_no))

session = {"private_data", "untrusted_content"}
print(lethal_trifecta(session))
print(lethal_trifecta(session | {"external_channel"}))
print(len(audit_log))
```

Заметьте: неизвестный инструмент запрещён по умолчанию («deny by default»), а любое решение попадает в журнал.

## Подводные камни

- **Защита только промптом.** Фраза в системном сообщении легко обходится; ограничения должны быть в коде и правах.
- **Универсальный токен администратора.** Любая инъекция получает все права.
- **Вся триада в одной сессии.** Агент, читающий почту, имеющий доступ к файлам и отправляющий письма, — готовый канал утечки.
- **Подтверждение по пересказу модели.** Человек должен видеть настоящие аргументы вызова.
- **Доверие к данным инструментов.** Ответ инструмента и содержимое страницы — недоверенный ввод.
- **Секреты в логах и контексте.** Журналы и трассы сами становятся источником утечек.
- **Тесты только на добрых сценариях.** Нужны red-team проверки с инъекциями.

## Итоги

- Модель не отличает инструкции от данных, поэтому она не граница безопасности.
- Косвенная инъекция прячется в данных, которые агент читает сам.
- Наименьшие привилегии, песочница, подтверждение человека и guardrails работают вместе, как слои.
- «Смертельная триада» — приватные данные + недоверенный контент + внешний канал; уберите любую одну.
- Аудит и возможность быстро отозвать доступ нужны в любом боевом агенте.
