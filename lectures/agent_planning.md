# Планирование и рефлексия агентов

<!-- время: 15 мин -->

> **О чём лекция.** Как агент превращает большую цель в последовательность выполнимых шагов, что делает, когда шаг сорвался, и как не потратить на всё это бесконечное число токенов.

## Зачем это нужно

Простой агент действует по принципу «подумал — сделал шаг — посмотрел результат — подумал снова» (так работает ReAct). Для коротких задач этого хватает. Но когда задача состоит из десятков шагов («подготовь отчёт по трём источникам, сверь цифры, оформи, проверь»), такой агент теряет цель из виду, повторяется и тратит токены на то, чтобы каждый раз заново осмыслять всё сделанное.

Планирование решает три проблемы сразу: даёт агенту **карту** (что осталось сделать), позволяет **проверять** промежуточные результаты и даёт возможность **исправлять курс**, когда что-то пошло не так. А рефлексия — способ учиться на собственных ошибках прямо внутри задачи, без дообучения модели.

## Интуиция: маршрут в навигаторе

Планирование агента похоже на навигатор в машине. Сначала он строит маршрут целиком (план). Вы едете, и навигатор следит за положением (исполнение). Если дорога перекрыта, он не начинает поездку с нуля, а перестраивает оставшийся отрезок от текущей точки (перепланирование). Если вы три раза подряд свернули не туда, он сообщает об этом, а не молча ведёт вас по кругу (контроль бюджета и циклов).

- **Цель** — пункт назначения.
- **Шаги плана** — участки маршрута.
- **Зависимости** — порядок, который нельзя нарушить: мост нельзя проехать до того, как доехали до моста.
- **Бюджет** — запас бензина: сколько шагов и токенов агент может позволить себе потратить.

## Как это работает

**1. Plan-and-execute.** Планировщик (обычно один вызов LLM) раскладывает цель на шаги. Исполнитель выполняет их по порядку, возможно, с помощью инструментов. К планировщику возвращаются только если шаг не удался или результат изменил картину. По сравнению с ReAct это экономит вызовы: не нужно каждый раз «переосмысливать» всю задачу.

**2. Декомпозиция в DAG.** Подзадачи зависят друг от друга, и эти зависимости образуют ориентированный граф без циклов (DAG). Для плана важны три понятия:

- *топологический порядок* — порядок выполнения, при котором каждая подзадача стоит после всех своих предпосылок;
- *параллелизм* — подзадачи без взаимных зависимостей можно выполнять одновременно;
- *критический путь* — самая длинная по сумме длительностей цепочка зависимых подзадач. Если длительность подзадачи dᵢ, то минимальное время плана T равно длине критического пути, а запас подзадачи (slack) — это на сколько её можно задержать, не увеличив T. У подзадач на критическом пути запас равен нулю.

**3. Рефлексия и самокритика.** После неудачной попытки агент формулирует текстовое описание ошибки: «Тест упал, потому что я не учёл пустой список. В следующий раз проверю граничные случаи». Эта запись хранится в памяти и попадает в промпт следующей попытки. Идею описали в работе Reflexion (2023): модель не дообучается, опыт накапливается в виде текста. Ключевое условие — **внешний сигнал**: результаты тестов, сообщение об ошибке, проверка по правилам. Если критик — та же модель, которая только что написала ответ, он часто соглашается с собой.

**4. Tree of Thoughts (идея).** Вместо одной цепочки рассуждений модель на каждом шаге порождает несколько вариантов «мыслей», оценивает их и продолжает лучшие, а из тупиков возвращается назад — получается поиск по дереву, например в ширину с ограниченной шириной (beam). Стоимость растёт как «ширина луча × число вариантов × глубина», поэтому метод применяют к задачам, где перебор вариантов оправдан.

**5. Перепланирование.** Реакция на ошибку зависит от её типа:

| ситуация | реакция |
|---|---|
| временный сбой (сеть, лимит запросов) | повтор с паузой |
| шаг дал неверный результат | рефлексия и повтор шага |
| оказалась ложной предпосылка | пересборка оставшейся части плана |
| нет прогресса несколько шагов | остановка и запрос к человеку |

Выполненные шаги не выбрасывают без причины: пересобирают только остаток.

**6. Бюджет.** Агент без лимита способен зациклиться. Поэтому задают максимум шагов, токенов и времени, а ещё следят за повторами одинаковых вызовов. Когда бюджет исчерпан, агент возвращает частичный результат и отчёт о том, что не успел.

## Пример на Python

Здесь нет реальных вызовов модели: план задан таблицей зависимостей, а «стоимость» шагов — числами. Скрипт упорядочивает подзадачи, находит критический путь и выполняет план в рамках бюджета токенов.

```python
from graphlib import TopologicalSorter

# подзадача: (длительность в шагах, токены, зависимости)
plan = {
    "источники": (1, 300, []),
    "чтение A": (2, 600, ["источники"]),
    "чтение B": (4, 900, ["источники"]),
    "сверка": (2, 400, ["чтение A", "чтение B"]),
    "отчёт": (3, 800, ["сверка"]),
}

graph = {name: set(deps) for name, (_, _, deps) in plan.items()}
order = list(TopologicalSorter(graph).static_order())

# самое раннее окончание каждой подзадачи
finish = {}
for name in order:
    duration, _, deps = plan[name]
    start = max((finish[d] for d in deps), default=0)
    finish[name] = start + duration
total_time = max(finish.values())
print("порядок:", order)
print("минимальное время плана:", total_time)

# выполнение в рамках бюджета токенов
budget, spent, done = 2500, 0, []
for name in order:
    tokens = plan[name][1]
    if spent + tokens > budget:
        print("бюджет исчерпан на шаге:", name)
        break
    spent += tokens
    done.append(name)
print("выполнено:", done, "| потрачено токенов:", spent)
```

Попробуйте поднять `budget` до 3000 — план выполнится полностью. Добавьте зависимость «источники» от «отчёт» — `TopologicalSorter` сообщит о цикле исключением `CycleError`.

## Подводные камни

- **Нет лимита шагов и токенов.** Самая частая причина «сожжённого» бюджета — агент, который бесконечно повторяет неудачный шаг или переделывает план.
- **Самокритика без внешнего сигнала.** Модель легко подтверждает собственный неверный ответ. Подключайте тесты, проверки по правилам или результаты инструментов.
- **Перепланирование с нуля.** Если после каждой ошибки план строится заново, теряются результаты уже сделанного. Правьте только оставшуюся часть.
- **Слишком мелкие шаги.** Каждая подзадача — это вызов модели; чрезмерная декомпозиция увеличивает расходы и число мест для ошибок.
- **Правдоподобный, но невыполнимый план.** Модель может предложить шаги, для которых нет инструментов. Проверяйте план на соответствие доступным действиям до запуска.
- **Устаревший план.** Результат шага может изменить картину; не следуйте плану слепо, если исходные предположения не подтвердились.

## Итоги

- Планирование даёт агенту карту задачи, возможность проверки и исправления курса; plan-and-execute экономит вызовы по сравнению с ReAct на длинных задачах.
- Подзадачи образуют DAG: топологический порядок задаёт допустимую последовательность, критический путь — минимальное время.
- Reflexion накапливает опыт в тексте, а не в весах; он работает, когда есть внешний сигнал об ошибке.
- Tree of Thoughts — поиск по дереву вариантов, дорогой, но полезный для задач с тупиками.
- При ошибке сначала определите тип сбоя, затем повторите шаг, пересоберите остаток плана или остановитесь.
- Всегда задавайте бюджет шагов и токенов.
