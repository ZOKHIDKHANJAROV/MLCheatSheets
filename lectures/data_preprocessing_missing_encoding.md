# Data Preprocessing (missing values, encoding)

> **О чём лекция.** Почему пропуски бывают разной природы и от неё зависит способ их обработки, чем заполнять числовые и категориальные признаки и как превратить категории в числа, не сломав модель.

## Зачем это нужно

Две самые частые проблемы табличных данных — **пропуски** и **категориальные признаки**. Почти в любом реальном датасете часть значений не заполнена, а часть столбцов — строки: город, тариф, марка автомобиля. Большинство моделей scikit-learn не принимает ни `NaN`, ни строки, поэтому без обработки обучение просто не начнётся.

Но важнее другое: способ обработки влияет на качество и на честность модели. Неправильно заполненные пропуски искажают распределения, а неправильно закодированные категории придумывают несуществующие зависимости.

## Интуиция: почему значение пропало

Пропуск — это не просто «дырка», а информация о том, *как собирались данные*. Сначала стоит спросить: почему значения нет?

- Датчик случайно не записал измерение — пропуск ничего не говорит о самом значении.
- Молодые клиенты реже указывают доход — пропуск связан с другим наблюдаемым признаком (возрастом).
- Люди с очень высоким доходом не хотят его указывать — пропуск связан с самим пропущенным значением.

От ответа зависит, можно ли просто заполнить пропуск средним или сам факт пропуска надо сделать признаком.

## Как это работает

### Три типа пропусков

| тип | что значит | пример | что делать |
|---|---|---|---|
| MCAR — полностью случайные | не зависят ни от чего | сбой оборудования | удаление или простое заполнение почти безопасны |
| MAR — случайные при условии | зависят от других наблюдаемых признаков | молодые реже указывают доход | заполнять с учётом других признаков (KNN, Iterative) |
| MNAR — неслучайные | зависят от самого пропущенного значения | богатые скрывают доход | добавить флаг пропуска; простое заполнение смещает данные |

Отличить MAR от MNAR по самим данным обычно нельзя — помогает знание предметной области.

### Стратегии для числовых признаков

- **Удаление строк** — только если пропусков мало (единицы процентов) и они похожи на MCAR. Иначе теряются данные и появляется смещение.
- **Удаление столбца** — если пропущено большинство значений и признак неважен.
- **Медиана** — разумный выбор по умолчанию: устойчива к выбросам. Среднее подходит для симметричных распределений без выбросов.
- **`KNNImputer`, `IterativeImputer`** — заполняют по похожим объектам или моделируют признак через остальные; полезны при MAR.
- **Флаг пропуска** (`add_indicator=True`) — бинарный признак «значение было пропущено». Если пропуски неслучайны, флаг часто сам по себе предсказательный.

Бустинги (LightGBM, XGBoost, CatBoost) умеют работать с `NaN` сами: для пропусков выбирается своё направление в каждом разбиении.

### Стратегии для категориальных признаков

- Самая частая категория (`most_frequent`) — если пропусков мало.
- **Отдельная категория `"missing"`** — часто лучший вариант: модель сама решит, чем пропуск похож на другие значения.

### Кодирование категорий

- **One-hot** — по бинарному столбцу на каждую категорию. Для номинальных признаков (город, цвет) и линейных моделей. При тысячах категорий матрица становится огромной и разреженной.
- **Ordinal** — категории заменяются числами `0, 1, 2…`. Корректно для порядковых признаков (`low < medium < high`) с явно заданным порядком; для деревьев допустимо и для номинальных.
- **Target encoding** — категория заменяется средним значением цели в ней. Компактно для высококардинальных признаков, но требует защиты от утечки (подсчёт по фолдам и сглаживание).
- **Frequency encoding** — частота категории в данных.

Отдельный вопрос — **новые категории** в тесте и в продакшене: кодировщик должен их обрабатывать (`handle_unknown="ignore"` в `OneHotEncoder`), а не падать.

## Пример на Python

Пропуски в числовом и категориальном признаках; числовой заполняем медианой с флагом, категориальный — отдельной категорией с последующим one-hot.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder

df = pd.DataFrame({
    "income": [52.0, np.nan, 61.0, 1500.0, np.nan, 48.0],
    "plan":   ["basic", "pro", np.nan, "basic", "pro", np.nan],
})
print(df.isna().mean().round(2).to_dict())   # {'income': 0.33, 'plan': 0.33}

prep = ColumnTransformer([
    ("num", SimpleImputer(strategy="median", add_indicator=True), ["income"]),
    ("cat", make_pipeline(SimpleImputer(strategy="constant", fill_value="missing"),
                          OneHotEncoder(handle_unknown="ignore")), ["plan"]),
])
X = prep.fit_transform(df)
print(prep.get_feature_names_out().tolist())
# ['num__income', 'num__missingindicator_income',
#  'cat__plan_basic', 'cat__plan_missing', 'cat__plan_pro']
```

Пропуски в `income` заполнились медианой 56.5 — среднее из-за значения 1500 было бы 415, что совсем не похоже на типичный доход. В реальном проекте этот `ColumnTransformer` ставят первым шагом `Pipeline` перед моделью.

## Подводные камни

- **Заполнение до разбиения на train/test** — утечка: медиана и категории должны вычисляться только на train.
- **Среднее при выбросах** даёт нетипичное значение; используйте медиану.
- **Массовое заполнение одной константой** сужает распределение признака и ослабляет его связи с другими. Если пропусков много — добавьте флаг.
- **Скрытые пропуски**: `-999`, `0`, `"unknown"`, пустая строка. Их нужно найти и явно превратить в `NaN`.
- **Label encoding номинальных признаков для линейных моделей** создаёт ложный порядок: модель решит, что «Самара» = 2 «больше» «Казани» = 1.
- **Target encoding без фолдов** переобучается: для редких категорий среднее цели почти равно цели самого объекта.

## Итоги

- Сначала поймите, почему значения пропущены: MCAR, MAR или MNAR.
- Числовые признаки — медиана (по умолчанию), продвинутые импьютеры при MAR, флаг пропуска при подозрении на MNAR.
- Категориальные — отдельная категория `"missing"` или самая частая.
- One-hot для номинальных признаков, ordinal для порядковых, target encoding — для высококардинальных и только с защитой от утечки.
- Все преобразования — внутри `Pipeline`, обучение только на train, новые категории обрабатываются явно.
