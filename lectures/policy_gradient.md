# Policy Gradient методы

<!-- время: 16 мин -->

> **О чём лекция.** Как учить политику напрямую, не проходя через Q-функцию: параметризовать вероятности действий нейросетью и двигать параметры по градиенту ожидаемой награды. Разберём теорему о градиенте политики, алгоритм REINFORCE, зачем вычитать baseline и как из этого вырастает actor-critic.

## Зачем это нужно

Value-based методы (Q-learning, DQN) учат ценность действий, а политику получают как argmax. У этого подхода есть ограничения:

- **непрерывные действия**: угол поворота руля или сила в суставе робота — бесконечно много вариантов, max по ним на каждом шаге посчитать трудно;
- **стохастические политики**: в некоторых задачах (игра «камень–ножницы–бумага», частично наблюдаемые среды) оптимальна случайная стратегия, а argmax всегда детерминирован;
- **резкие скачки**: маленькое изменение Q может перевернуть argmax и резко поменять поведение.

**Методы градиента политики** (policy gradient) параметризуют саму политику π(a | s; θ) — например, нейросетью, выдающей вероятности действий или параметры нормального распределения — и улучшают её градиентным подъёмом по ожидаемой награде. На этой идее построены A2C, PPO, SAC и RLHF для языковых моделей.

## Интуиция: чаще делать то, что сработало

Представьте, что агент сыграл эпизод и получил высокую награду. Естественная мысль: сделать действия этого эпизода **более вероятными**. Если награда низкая — менее вероятными. Сила изменения пропорциональна тому, насколько эпизод был хорош.

Это и есть REINFORCE — по сути, обучение с учителем, где «правильными ответами» служат собственные действия агента, взвешенные полученной наградой. Хорошие действия усиливаются, плохие ослабляются.

## Как это работает: теорема о градиенте политики

Цель — максимизировать ожидаемый возврат J(θ) = E[G]. Проблема: награда зависит от θ через вероятности действий и через среду, а среду дифференцировать нельзя. **Теорема о градиенте политики** обходит это:

```
∇J(θ) = E[ ∇ log π(a | s; θ) · Q(s, a) ]
```

- `∇ log π(a | s; θ)` — направление в пространстве параметров, увеличивающее вероятность действия a в состоянии s;
- `Q(s, a)` — насколько это действие хорошо: вес, с которым мы двигаемся в этом направлении.

Важно: градиент выражен через то, что можно посчитать по траекториям — производные среды не нужны. Берём сэмплы, считаем log-вероятности, умножаем на возвраты, усредняем.

## REINFORCE

Простейший алгоритм — **REINFORCE** (Monte Carlo policy gradient). Вместо неизвестного Q(s, a) подставляем фактический возврат G(t) из эпизода:

1. Сыграть эпизод по текущей политике: (s₀, a₀, r₁), (s₁, a₁, r₂), …
2. Для каждого шага посчитать возврат G(t) = r(t+1) + γ·r(t+2) + …
3. Обновить: θ ← θ + α · Σ ∇ log π(aₜ | sₜ; θ) · G(t).

В коде с автоматическим дифференцированием достаточно минимизировать `loss = −Σ log π(aₜ | sₜ) · G(t)`.

Главный недостаток REINFORCE — **высокая дисперсия**. Возврат одного эпизода — очень шумная оценка: из-за случайности среды и самой политики два эпизода с одинаковыми действиями могут дать совсем разные награды. Обучение идёт медленно и рывками.

## Baseline: снижаем дисперсию без смещения

Если все награды положительные, REINFORCE увеличивает вероятность *всех* сыгранных действий — просто хорошим чуть больше. Гораздо полезнее сравнивать действие со «средним уровнем». Для этого из возврата вычитают **baseline** b(s):

```
∇J(θ) = E[ ∇ log π(a | s; θ) · (G − b(s)) ]
```

Вычитание baseline **не меняет ожидаемый градиент**: E[∇ log π(a | s)] = 0, ведь сумма вероятностей всегда равна 1 и её градиент нулевой. Но дисперсия заметно падает — сигнал становится «лучше или хуже, чем обычно».

Лучший естественный baseline — ценность состояния V(s). Тогда множитель превращается в **преимущество** (advantage):

```
A(s, a) = Q(s, a) − V(s)
```

Положительное преимущество — действие лучше среднего для этого состояния, отрицательное — хуже.

## Actor-critic

Если V(s) нужно оценивать, почему бы не обучить для этого вторую сеть? Так получается **actor-critic**:

- **актёр** (actor) — политика π(a | s; θ), обновляется по градиенту политики с преимуществом;
- **критик** (critic) — функция ценности V(s; w), обучается регрессией к возвратам или TD-целям.

Преимущество можно оценивать через TD-ошибку критика: A ≈ r + γ·V(s') − V(s). Это позволяет обновляться на каждом шаге, а не ждать конца эпизода, и ещё сильнее снижает дисперсию ценой небольшого смещения. **A2C** (Advantage Actor-Critic) — стандартная синхронная версия, а **PPO** — её усовершенствование с ограничением шага.

## Сравнение с value-based методами

| | value-based (DQN) | policy gradient |
|---|---|---|
| что учим | Q(s, a) | саму политику π напрямую |
| действия | дискретные | дискретные и непрерывные |
| политика | детерминированная (argmax) | стохастическая |
| данные | off-policy, replay buffer | on-policy, свежие траектории |
| эффективность по данным | выше | ниже |
| устойчивость | может расходиться | плавные изменения, но шумный градиент |

Policy gradient методы обычно требуют **больше данных**: они on-policy, и после каждого обновления политики старые траектории формально устаревают.

## Пример на Python

REINFORCE с baseline на простейшей задаче — бандите с тремя действиями. Политика — softmax по параметрам θ:

```python
import numpy as np

rng = np.random.default_rng(0)
true_reward = np.array([1.0, 2.0, 1.5])     # средняя награда трёх действий
theta = np.zeros(3)                          # параметры softmax-политики
lr, baseline = 0.05, 0.0

for step in range(3000):
    pi = np.exp(theta - theta.max()); pi /= pi.sum()
    a = rng.choice(3, p=pi)
    G = true_reward[a] + rng.normal()        # шумный возврат
    grad_log = -pi; grad_log[a] += 1         # ∇ log π(a) для softmax: one_hot(a) − π
    theta += lr * grad_log * (G - baseline)  # REINFORCE с baseline
    baseline += 0.01 * (G - baseline)        # скользящее среднее возврата

print("π =", np.round(pi, 3))                # [0.002 0.992 0.006] — выбрано лучшее действие
```

Политика сама сместилась к действию 1 с наибольшей средней наградой, хотя каждая отдельная награда была сильно зашумлена.

## Подводные камни

- **Знак функции потерь.** Градиент политики — это *подъём*. В PyTorch минимизируют `−log π · A`; потерянный минус учит худшую политику.
- **Нет нормализации преимуществ.** Нормализация advantage в батче (вычесть среднее, разделить на стандартное отклонение) сильно стабилизирует обучение.
- **Коллапс энтропии.** Политика слишком рано становится почти детерминированной и перестаёт исследовать. Добавляют бонус за энтропию политики в функцию потерь.
- **Слишком большой шаг.** Одно неудачное обновление может «сломать» политику, после чего она соберёт плохие данные и не восстановится. Это мотивация TRPO и PPO.
- **Использование старых данных.** Обычный policy gradient — on-policy; обучение на траекториях старой политики без поправки (importance sampling) смещает градиент.

## Итоги

- Policy gradient методы параметризуют политику и улучшают её градиентным подъёмом по ожидаемому возврату.
- Теорема: ∇J = E[∇ log π(a | s) · Q(s, a)] — модель среды не нужна.
- REINFORCE подставляет фактический возврат; его беда — высокая дисперсия.
- Baseline (обычно V(s)) снижает дисперсию без смещения; множитель становится преимуществом A = Q − V.
- Actor-critic обучает политику и критика вместе; A2C и PPO — его практические версии.
