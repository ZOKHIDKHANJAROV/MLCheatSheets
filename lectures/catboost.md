> **О чём лекция.** Как CatBoost работает с категориальными признаками без ручного кодирования и без утечки целевой переменной, что такое ordered boosting и симметричные деревья и почему CatBoost так часто хорошо работает с параметрами по умолчанию.

## Зачем это нужно

В реальных таблицах много **категориальных** признаков: город, марка телефона, категория товара, канал привлечения, ID магазина. Линейные модели и большинство реализаций бустинга требуют превратить их в числа. One-hot раздувает таблицу, когда у признака тысячи значений, а простое target-кодирование (заменить категорию средним значением целевой переменной) незаметно приводит к переобучению.

CatBoost — библиотека градиентного бустинга от Яндекса (2017), которая решает эту проблему «из коробки». Достаточно указать, какие столбцы категориальные, — можно прямо со строками. Кроме того, CatBoost известен хорошими параметрами по умолчанию: часто он даёт сильный результат вообще без настройки. Это делает его отличным выбором для бизнес-данных с большим числом категорий и для быстрых прототипов.

## Интуиция: не подглядывать в собственный ответ

Самый естественный способ закодировать категорию — посчитать среднее целевой переменной для неё. Если в Казани покупают 30% клиентов, заменим «Казань» на 0.3. Проблема в том, что при подсчёте этого среднего для конкретного клиента учитывается **его собственный ответ**. Для редких категорий это особенно опасно: если клиент из Томска единственный в выборке и он купил, то «Томск» = 1.0 — признак просто содержит правильный ответ. На обучении модель выглядит гениальной, на новых данных — проваливается. Это **утечка целевой переменной**.

Идея CatBoost: при кодировании объекта использовать только «прошлые» объекты. Данные случайно перемешиваются, и каждый объект получает статистику, посчитанную только по объектам, стоящим перед ним в этой перестановке. Собственный ответ никогда не участвует в собственном признаке — как в реальной жизни, где о новом клиенте мы знаем только по прошлым.

## Как это работает

**Ordered target statistics.** Для объекта на позиции i в случайной перестановке и категории c:

```
TS(i) = (сумма y у предыдущих объектов с категорией c + a · prior) / (число таких объектов + a)
```

`prior` — априорное значение (например, доля положительного класса), `a` — сила сглаживания. Для первого объекта категории статистика равна просто prior, для частых категорий — почти среднему по категории. CatBoost использует несколько перестановок, чтобы уменьшить шум первых объектов, и умеет строить **комбинации** категорий (например, «город × устройство») прямо во время обучения.

Категории с малым числом значений (не больше `one_hot_max_size`) кодируются обычным one-hot.

**Ordered boosting.** Та же проблема «подглядывания» есть и в самом бустинге. Остатки, на которых учится новое дерево, считаются моделью, которая уже обучалась на этих же объектах. Из-за этого остатки на обучении систематически меньше, чем на новых данных, — это называют **сдвигом прогноза** (prediction shift). Ordered boosting считает остаток для объекта моделью, обученной только на предыдущих в перестановке объектах. На небольших данных это заметно уменьшает переобучение. В параметрах это `boosting_type="Ordered"` (на больших данных по умолчанию используется более быстрый режим `"Plain"`).

**Симметричные (oblivious) деревья.** CatBoost по умолчанию строит деревья, в которых **на каждом уровне используется одно и то же разбиение** для всех узлов. Дерево глубины 6 — это 6 вопросов вида «xⱼ ≤ t?», и ответы на них образуют двоичный код номера листа из 64. Такие деревья:

- проще и сами по себе меньше склонны к переобучению — работают как регуляризация;
- очень быстро применяются: прогноз — это несколько сравнений и обращение к таблице;
- хуже ловят очень локальные закономерности, но в ансамбле из сотен деревьев это редко мешает.

## Почему CatBoost хорош «из коробки»

- категории обрабатываются корректно без ручной работы;
- симметричные деревья и ordered-схемы снижают переобучение;
- learning rate по умолчанию подбирается автоматически исходя из размера данных и числа итераций;
- разумные значения регуляризации (`l2_leaf_reg=3`) и глубины (`depth=6`);
- пропуски в числовых признаках обрабатываются сами (по умолчанию они считаются меньше всех значений).

## Параметры, которые настраивают в первую очередь

| параметр | что делает | с чего начать |
|---|---|---|
| `iterations` | максимум деревьев | 1000–5000 с ранней остановкой |
| `learning_rate` | вклад дерева | авто, либо 0.03–0.1 |
| `depth` | глубина симметричного дерева | 4–10 (по умолчанию 6) |
| `l2_leaf_reg` | L2-регуляризация листьев | 1–10 |
| `cat_features` | список категориальных столбцов | обязательно указать |
| `auto_class_weights` | веса классов при дисбалансе | `"Balanced"` |
| `one_hot_max_size` | порог для one-hot | 2–10 |

Также полезны `eval_metric` (например, `"AUC"`), `early_stopping_rounds` и `task_type="GPU"` для больших данных.

## Пример на Python

```python
import numpy as np
import pandas as pd
from catboost import CatBoostClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)
n = 3000
df = pd.DataFrame({
    "city": rng.choice(["Москва", "Казань", "Самара", "Томск"], size=n),   # строки — можно!
    "age": rng.integers(18, 70, size=n),
    "visits": rng.poisson(5, size=n),
})
logit = (df["city"] == "Казань") * 1.5 - (df["age"] - 40) * 0.05 + df["visits"] * 0.2 - 1
df["bought"] = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)

X, y = df[["city", "age", "visits"]], df["bought"]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)
X_fit, X_val, y_fit, y_val = train_test_split(X_tr, y_tr, test_size=0.2, random_state=0)

model = CatBoostClassifier(
    iterations=2000,
    depth=6,
    eval_metric="AUC",
    random_seed=0,
    verbose=0,
)
model.fit(X_fit, y_fit, cat_features=["city"],
          eval_set=(X_val, y_val), early_stopping_rounds=100)

print("лучшая итерация:", model.get_best_iteration())
print("ROC-AUC на тесте:", roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]))
print(model.get_feature_importance(prettified=True))
```

Город передаётся строками — никакого предварительного кодирования. При переданном `eval_set` CatBoost по умолчанию оставляет модель с лучшей итерации (`use_best_model=True`).

## Подводные камни

- **Не указали `cat_features`** — CatBoost либо упадёт на строковом столбце, либо воспримет закодированные числами категории как числовой признак с бессмысленным порядком.
- **Категории — только строки или целые числа.** Числа с плавающей точкой в категориальном столбце вызывают ошибку; пропуски в категориях лучше заменить на отдельное значение, например `"missing"`.
- **Медленное обучение на CPU** при большой глубине и многих комбинациях категорий. Уменьшите `depth`, ограничьте `max_ctr_complexity` или используйте GPU.
- **Ранняя остановка по тесту** завышает оценку — нужна отдельная валидация.
- **Не повторяйте target-кодирование вручную** перед CatBoost: получите утечку, от которой он как раз защищает.
- **Сравнение с LightGBM/XGBoost** честно делать при одинаковых условиях: та же валидация, ранняя остановка, сопоставимая настройка. Иногда выигрывает один, иногда другой.

## Итоги

- CatBoost — градиентный бустинг, сильный на данных с категориальными признаками; категории можно передавать строками.
- Ordered target statistics кодируют категории только по «прошлым» объектам и тем самым избегают утечки целевой переменной.
- Ordered boosting устраняет сдвиг прогноза, связанный с тем, что остатки считаются на тех же данных, на которых обучалась модель.
- Симметричные деревья регуляризуют модель и очень быстро применяются.
- Хорошие значения по умолчанию: часто достаточно указать `cat_features` и включить раннюю остановку.
