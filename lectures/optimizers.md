# Оптимизаторы (SGD, Momentum, Adam, RMSProp)

<!-- время: 15 мин -->

> **О чём лекция.** Как улучшенные варианты градиентного спуска ускоряют обучение: инерция в Momentum, свой шаг для каждого параметра в RMSProp, их сочетание в Adam, отличие AdamW и зачем менять learning rate по ходу обучения.

## Зачем это нужно

Обычный градиентный спуск делает шаг `θ ← θ − η·∇L(θ)`. На реальных функциях потерь нейросетей этого мало: поверхность потерь похожа на систему узких оврагов, плато и седловых точек. Простой SGD мечется поперёк оврага, медленно ползёт вдоль него и долго стоит на плато.

Оптимизатор — правило, *как* превратить градиент в шаг. Хороший оптимизатор сокращает обучение в разы и делает его менее чувствительным к выбору learning rate. На практике выбор обычно сводится к двум вариантам: SGD с momentum или Adam/AdamW.

## Интуиция

- **SGD** — пешеход, который на каждом шаге смотрит под ноги и идёт туда, где круче вниз.
- **Momentum** — тяжёлый шар, катящийся с горы: он набирает скорость в постоянном направлении и не дёргается от каждой кочки.
- **RMSProp / AdaGrad** — пешеход, который на крутых склонах осторожничает (маленький шаг), а на пологих делает шаги шире — отдельно по каждому направлению.
- **Adam** — шар с инерцией, который вдобавок сам подстраивает шаг под крутизну по каждому направлению.

## Как это работает

**SGD с momentum** копит «скорость» — экспоненциальное среднее прошлых градиентов:

```
v ← β·v + ∇L(θ)
θ ← θ − η·v              # β обычно 0.9
```

Колебания поперёк оврага (градиенты с чередующимся знаком) взаимно гасятся, а движение вдоль оврага (градиенты одного знака) накапливается. Вариант Нестерова считает градиент в точке «с упреждением» и обычно немного стабильнее.

**AdaGrad и RMSProp** делят шаг на корень из накопленного квадрата градиентов — для каждого параметра отдельно:

```
s ← β·s + (1 − β)·g²     # RMSProp: скользящее среднее квадратов
θ ← θ − η·g / (√s + ε)
```

Параметры с большими градиентами получают меньший шаг, с маленькими — больший. AdaGrad суммирует квадраты за всё время, поэтому его шаг со временем затухает до нуля; RMSProp заменил сумму скользящим средним и этим исправил проблему.

**Adam** объединяет обе идеи — первый момент (среднее градиентов, как momentum) и второй (среднее квадратов, как RMSProp):

```
m ← β₁·m + (1 − β₁)·g          # β₁ = 0.9
v ← β₂·v + (1 − β₂)·g²         # β₂ = 0.999
m̂ = m / (1 − β₁ᵗ),  v̂ = v / (1 − β₂ᵗ)    # поправка смещения
θ ← θ − η·m̂ / (√v̂ + ε)
```

Поправка смещения нужна, потому что m и v стартуют с нуля и на первых шагах сильно занижены. Стандартный learning rate для Adam — `0.001` (`1e-3`), для fine-tuning трансформеров — порядка `1e-5`…`5e-5`.

## AdamW: правильный weight decay

L2-регуляризация в обычном SGD эквивалентна weight decay — уменьшению весов на каждом шаге. В Adam это не так: L2-штраф добавляется к градиенту и затем делится на `√v̂`, поэтому параметры с большими градиентами регуляризуются слабее, чем задумано. **AdamW** применяет weight decay напрямую к весам, отдельно от адаптивного шага: `θ ← θ − η·(m̂/(√v̂+ε) + λ·θ)`. Это работает лучше, и AdamW — стандарт для трансформеров.

## Расписания learning rate

Постоянный шаг редко оптимален: в начале хочется двигаться быстро, в конце — аккуратно «осесть» в минимуме.

- **Step decay** — уменьшать шаг в 10 раз каждые N эпох (классика для ResNet с SGD).
- **Cosine annealing** — плавно снижать шаг по косинусу до почти нуля.
- **ReduceLROnPlateau** — уменьшать, когда валидационные потери перестали падать.
- **Warmup** — первые сотни или тысячи шагов линейно поднимать шаг от нуля. Статистики Adam в начале ещё неточны, а веса случайны; большие первые шаги могут «сломать» модель. Для трансформеров warmup почти обязателен.
- **One-cycle** — сначала поднять, потом опустить; часто даёт быстрое обучение.

## Пример на Python

Сравним оптимизаторы на вытянутой «долине» `L = ½(x² + 50·y²)`: по y склон в 50 раз круче, чем по x.

```python
import numpy as np

# Вытянутая «долина»: L(x, y) = 0.5·(x² + 50·y²), минимум в (0, 0)
grad = lambda t: np.array([t[0], 50 * t[1]])
start = np.array([10.0, 1.0])

def run(update, steps=100):
    theta, state = start.copy(), {}
    for t in range(1, steps + 1):
        theta = update(theta, grad(theta), state, t)
    return np.linalg.norm(theta)        # расстояние до минимума

def sgd(theta, g, s, t, lr=0.035):
    return theta - lr * g

def momentum(theta, g, s, t, lr=0.035, beta=0.9):
    s["v"] = beta * s.get("v", 0) + g
    return theta - lr * s["v"]

def adam(theta, g, s, t, lr=0.5, b1=0.9, b2=0.999, eps=1e-8):
    s["m"] = b1 * s.get("m", 0) + (1 - b1) * g
    s["v"] = b2 * s.get("v", 0) + (1 - b2) * g ** 2
    m_hat, v_hat = s["m"] / (1 - b1 ** t), s["v"] / (1 - b2 ** t)
    return theta - lr * m_hat / (np.sqrt(v_hat) + eps)

for name, f in [("SGD", sgd), ("Momentum", momentum), ("Adam", adam)]:
    print(f"{name:9s} расстояние до минимума через 100 шагов: {run(f):.4f}")
# SGD       … 0.2836
# Momentum  … 0.0453
# Adam      … 0.0423
```

SGD не может взять шаг больше `0.04`: по крутому направлению y он начнёт расходиться, а по пологому x при таком шаге ползёт медленно. Momentum разгоняется вдоль долины, Adam выравнивает масштаб направлений. В PyTorch это `optim.SGD(params, lr=0.01, momentum=0.9)`, `optim.Adam(params, lr=1e-3)`, `optim.AdamW(params, lr=1e-3, weight_decay=0.01)`.

## Подводные камни

- **Learning rate важнее выбора оптимизатора.** Плохо подобранный шаг испортит любой метод. Начинайте с типичных значений и смотрите на кривую обучения.
- **Adam быстрее, SGD иногда обобщает лучше.** В компьютерном зрении хорошо настроенный SGD с momentum и расписанием нередко даёт чуть лучшую точность на тесте.
- **Adam + L2 через `weight_decay`** в классическом `optim.Adam` — это не тот weight decay. Нужна регуляризация — берите `AdamW`.
- **Смена оптимизатора при дообучении.** Состояние оптимизатора (m, v) сохраняйте вместе с моделью в чекпоинте, иначе продолжение обучения начнётся «с холодного старта».
- **Шаг scheduler'а.** В PyTorch `scheduler.step()` вызывают после `optimizer.step()`, а для одних расписаний — раз за эпоху, для других (warmup, one-cycle) — на каждом батче.

## Итоги

- Оптимизатор определяет, как превратить градиент в шаг по параметрам.
- Momentum копит инерцию и гасит колебания; RMSProp/AdaGrad масштабируют шаг для каждого параметра.
- Adam объединяет обе идеи и почти всегда работает «из коробки» с `lr = 1e-3`.
- AdamW применяет weight decay правильно — стандарт для трансформеров.
- Расписания learning rate и warmup часто дают не меньше, чем выбор самого оптимизатора.
