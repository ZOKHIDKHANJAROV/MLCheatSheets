# RNN/LSTM для временных рядов

<!-- время: 16 мин -->

> **О чём лекция.** Как подать временной ряд рекуррентной сети: окна, нормализация, разбиение по времени. Чем отличаются стратегии многошагового прогноза, как поступать с трендом и почему первое, что нужно сделать перед LSTM, — посчитать наивный прогноз.

## Зачем это нужно

Классические модели (ARIMA, экспоненциальное сглаживание) хорошо работают на одном ряде с линейной структурой. Но бывают задачи, где этого мало:

- зависимость **нелинейная** (потребление электричества по-разному зависит от температуры зимой и летом);
- рядов **много и они связаны** (датчики на одной установке, продажи в разных магазинах);
- есть **дополнительные признаки** на каждом шаге (погода, цена, день недели).

Рекуррентные сети — RNN, LSTM, GRU — естественно подходят для последовательностей: они читают ряд шаг за шагом и копят информацию в скрытом состоянии. LSTM благодаря механизму вентилей помнит зависимости на десятки и сотни шагов назад.

## Интуиция: сеть читает окно истории

Сеть не видит ряд целиком. Ей показывают **окно** — последние, скажем, 30 значений — и просят предсказать следующее. Затем окно сдвигают на шаг, и так по всему ряду. Из одного ряда длиной 1000 получается почти 1000 обучающих примеров.

Внутри LSTM проходит по окну слева направо. На каждом шаге она обновляет **скрытое состояние** — сжатое описание прочитанного: «последние дни был рост, сейчас выходные, утром был пик». После последнего шага состояние подаётся в линейный слой, который выдаёт прогноз.

## Как это работает: подготовка данных

Подготовка данных для LSTM важнее архитектуры. Порядок действий:

1. **Разбить по времени**: train — прошлое, validation и test — более поздние отрезки. Никакого перемешивания до формирования окон.
2. **Нормализовать**: обучить скейлер (MinMaxScaler или StandardScaler) **только на train** и применить к остальным частям. Нейросети плохо учатся на значениях порядка тысяч.
3. **Нарезать окна**: из ряда получить пары «окно длины L → следующее значение».
4. **Придать форму**: LSTM в PyTorch с `batch_first=True` ждёт тензор `(batch, seq_len, features)`. Для одного ряда без признаков features = 1.

После обучения прогноз нужно перевести обратно в исходный масштаб (`inverse_transform`).

## Тренд и нестационарность

Сеть с нормализацией по train плохо экстраполирует: если ряд растёт, значения в test окажутся выше всего, что сеть видела, и прогноз «упрётся в потолок». Что помогает:

- **предсказывать приращения** `y(t) − y(t−1)` вместо уровня, а затем складывать их обратно;
- **нормализовать каждое окно** отдельно: вычесть из окна его последнее значение (или среднее) и добавить обратно к прогнозу;
- **убрать тренд** заранее простой моделью и обучать сеть на остатках.

## Многошаговый прогноз

Часто нужен прогноз не на шаг, а на горизонт H (например, на 7 дней). Есть три стратегии:

| стратегия | как | плюсы | минусы |
|---|---|---|---|
| рекурсивная | прогноз на шаг, подставить его в окно, снова прогноз | одна модель | ошибки накапливаются |
| прямая | отдельная модель на каждый шаг горизонта | нет накопления ошибок | H моделей, шаги не согласованы |
| многовыходная (MIMO) | выходной слой сразу выдаёт H значений | одна модель, согласованный прогноз | нужно больше данных |

Для нейросетей естественнее всего многовыходная стратегия: последний линейный слой просто имеет H выходов. Более сложный вариант — архитектура encoder–decoder (seq2seq), где декодер генерирует горизонт по шагам.

## Обязательный бейзлайн

Нейросеть на временном ряде легко «выглядит хорошо»: график прогноза почти совпадает с фактом. Часто это иллюзия — сеть просто научилась повторять последнее значение окна, и прогноз — тот же ряд, сдвинутый на шаг.

Поэтому всегда считайте:

- **наивный прогноз** — последнее значение окна;
- **сезонный наивный** — значение сезон назад;
- **линейную модель** по тому же окну.

Если LSTM не обыгрывает их на тесте, она не нужна. Удобная метрика для сравнения — **MASE**: ошибка модели, делённая на ошибку наивного прогноза; MASE < 1 — модель лучше наивной.

## Пример на Python

Нарезка окон, разбиение по времени и два бейзлайна, которые LSTM обязана обыграть:

```python
import numpy as np
from sklearn.linear_model import Ridge

def create_sequences(series, window, horizon=1):
    X, y = [], []
    for i in range(len(series) - window - horizon + 1):
        X.append(series[i:i + window])
        y.append(series[i + window + horizon - 1])
    return np.array(X), np.array(y)

rng = np.random.default_rng(0)
series = np.sin(np.arange(200) / 5) + np.arange(200) / 50 + rng.normal(scale=0.1, size=200)
X, y = create_sequences(series, window=10)
print(X.shape, y.shape)                                   # (190, 10) (190,)

split = int(0.8 * len(X))                                 # по времени: первые 80% — train
X_train, y_train, X_test, y_test = X[:split], y[:split], X[split:], y[split:]

naive = X_test[:, -1]                                     # последнее значение окна
print(f"MAE наивного прогноза: {np.mean(np.abs(naive - y_test)):.3f}")          # 0.166
lin = Ridge(alpha=1e-3).fit(X_train, y_train)
print(f"MAE линейной модели по окну: {np.mean(np.abs(lin.predict(X_test) - y_test)):.3f}")   # 0.114
```

Сама LSTM в PyTorch — несколько строк (`X` нужно превратить в тензор формы `(batch, 10, 1)`):

```python
import torch
import torch.nn as nn

class LSTMForecaster(nn.Module):
    def __init__(self, hidden=64, horizon=1):
        super().__init__()
        self.lstm = nn.LSTM(input_size=1, hidden_size=hidden, num_layers=2,
                            batch_first=True, dropout=0.2)
        self.head = nn.Linear(hidden, horizon)     # horizon > 1 — многовыходная стратегия

    def forward(self, x):                          # x: (batch, seq_len, 1)
        out, _ = self.lstm(x)
        return self.head(out[:, -1])               # состояние после последнего шага окна

model = LSTMForecaster()
X_t = torch.tensor(X_train, dtype=torch.float32).unsqueeze(-1)
y_t = torch.tensor(y_train, dtype=torch.float32).unsqueeze(-1)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
for epoch in range(200):
    loss = nn.functional.mse_loss(model(X_t), y_t)
    opt.zero_grad(); loss.backward(); opt.step()
```

## Подводные камни

- **Скейлер, обученный на всём ряде.** Минимум и максимум теста «просачиваются» в обучение. Обучайте скейлер только на train.
- **Перемешанные окна до разбиения.** Соседние окна почти одинаковы; если они попадут в train и test, оценка будет завышена. Сначала разбивайте по времени, потом нарезайте окна (или оставляйте зазор длиной в окно).
- **Прогноз-«тень».** Прогноз, повторяющий ряд со сдвигом на шаг, — признак того, что сеть выучила наивный прогноз. Смотрите на MASE.
- **Слишком большая сеть на маленьком ряде.** Несколько сотен точек — мало для LSTM; бустинг или ETS тут обычно надёжнее.
- **Состояние между батчами.** В режиме stateful скрытое состояние переносится между батчами — легко ошибиться с порядком. Для начала используйте обычный режим, где каждое окно обрабатывается с нуля.

## Итоги

- LSTM получает окна истории формы `(batch, seq_len, features)` и предсказывает следующее значение или весь горизонт.
- Разбиение — только по времени, скейлер — только по train, тренд — через приращения или нормализацию окна.
- Многошаговый прогноз: рекурсивная, прямая или многовыходная стратегия; для сетей удобна многовыходная.
- LSTM имеет смысл, только если обыгрывает наивный прогноз и линейную модель на том же окне.
