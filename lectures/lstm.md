# LSTM (Long Short-Term Memory)

<!-- время: 16 мин -->

> **О чём лекция.** Как LSTM научилась помнить на сотни шагов: отдельная «лента памяти», три вентиля, которые решают, что забыть, что записать и что показать, и почему сложение вместо умножения спасает градиент.

## Зачем это нужно

Простая RNN на каждом шаге полностью переписывает своё скрытое состояние: `h_t = tanh(W·h_{t−1} + …)`. Информация из начала последовательности проходит через десятки умножений на матрицу и функцию tanh и к концу почти исчезает. То же происходит с градиентом при обучении: он затухает, и сеть не может выучить связь между далёкими шагами.

А такие связи встречаются постоянно. В предложении «Девушка, которую я встретил вчера в библиотеке у старого вокзала, **была** очень вежлива» род глагола зависит от слова в самом начале. В прогнозе продаж важен прошлогодний сезонный пик, а не только вчерашний день.

**LSTM** (Long Short-Term Memory, Hochreiter и Schmidhuber, 1997) — архитектура рекуррентной сети, которая специально построена, чтобы хранить информацию долго. До появления трансформеров LSTM была стандартом для перевода, распознавания речи и работы с текстом, и до сих пор широко используется для временных рядов.

## Интуиция: лента памяти и вентили

Представьте конвейерную ленту, которая проходит через все шаги последовательности. Это **состояние ячейки** (cell state) `C_t` — долгосрочная память. Лента едет почти без изменений; на каждом шаге у неё стоят три «контролёра»:

- **forget gate** (вентиль забывания) решает, что *стереть* с ленты: «подлежащее сменилось — старый род больше не нужен»;
- **input gate** (входной вентиль) решает, что *записать* нового: «появилось новое подлежащее — запомнить его род»;
- **output gate** (выходной вентиль) решает, что из памяти *показать* наружу на этом шаге — это скрытое состояние `h_t`, краткосрочная «рабочая» память.

Каждый вентиль — это вектор чисел от 0 до 1 (выход сигмоиды), который поэлементно умножается на сигнал: 0 — «закрыто, не пропускать», 1 — «открыто полностью».

## Как это работает

На шаге t LSTM получает вход `x_t` и прошлые состояния `h_{t−1}`, `C_{t−1}`:

```
f_t = σ(W_f · [h_{t−1}, x_t] + b_f)      вентиль забывания
i_t = σ(W_i · [h_{t−1}, x_t] + b_i)      входной вентиль
C̃_t = tanh(W_C · [h_{t−1}, x_t] + b_C)   кандидат в память
o_t = σ(W_o · [h_{t−1}, x_t] + b_o)      выходной вентиль

C_t = f_t ⊙ C_{t−1} + i_t ⊙ C̃_t          обновление памяти
h_t = o_t ⊙ tanh(C_t)                    выход шага
```

Здесь `σ` — сигмоида, `⊙` — поэлементное умножение, `[h, x]` — склейка векторов.

Ключевая строка — обновление памяти. Старая память не пропускается через матрицу и tanh, а лишь **умножается на f_t и складывается** с новой порцией. Если вентиль забывания близок к 1, память переходит на следующий шаг почти без изменений. Градиент по `C` при движении назад тоже умножается только на `f_t` — нет многократного умножения на матрицу весов, поэтому он затухает гораздо медленнее. Сеть сама учится, когда держать вентиль открытым.

## Сколько параметров

У LSTM четыре блока (три вентиля и кандидат), у каждого своя матрица размера `hidden × (hidden + input)` и смещение. Поэтому у слоя LSTM примерно **в 4 раза больше параметров**, чем у простой RNN того же размера:

```
RNN:  hidden · (hidden + input) + hidden
LSTM: 4 · [hidden · (hidden + input) + hidden]
```

Для `hidden = 128` и `input = 64` — около 99 тысяч параметров против 25 тысяч у RNN. (В PyTorch у каждого блока два вектора смещения, поэтому реальное число чуть больше.)

## Как используют LSTM на практике

- **Стек слоёв.** 1–3 слоя LSTM друг на друге: выходы нижнего слоя на всех шагах становятся входами верхнего. В Keras для этого у нижних слоёв ставят `return_sequences=True`.
- **Dropout между слоями** (0.2–0.5) — против переобучения.
- **Двунаправленная LSTM** для задач, где виден весь вход: классификация текста, NER.
- **Временные ряды.** Ряд нарезают окнами: из 10 прошлых значений предсказываем следующее. Вход имеет форму `(samples, timesteps, features)`.

## Пример на Python

Один шаг LSTM на NumPy — видно, как вентили смешивают старую память и новую:

```python
import numpy as np

sigmoid = lambda z: 1 / (1 + np.exp(-z))
rng = np.random.default_rng(0)
n_in, n_h = 3, 4
W = rng.normal(scale=0.3, size=(4 * n_h, n_h + n_in))   # веса всех четырёх блоков одной матрицей
b = np.zeros(4 * n_h)
b[:n_h] = 1.0                                           # смещение forget gate = 1: по умолчанию «помнить»

def lstm_step(x_t, h_prev, c_prev):
    z = W @ np.concatenate([h_prev, x_t]) + b
    f = sigmoid(z[:n_h])                    # forget gate: что оставить из старой памяти
    i = sigmoid(z[n_h:2 * n_h])             # input gate: что записать
    c_tilde = np.tanh(z[2 * n_h:3 * n_h])   # кандидат в память
    o = sigmoid(z[3 * n_h:])                # output gate: что показать наружу
    c = f * c_prev + i * c_tilde            # обновление памяти — сложение, а не перемножение матриц
    h = o * np.tanh(c)
    return h, c

h, c = np.zeros(n_h), np.zeros(n_h)
for x_t in rng.normal(size=(6, n_in)):
    h, c = lstm_step(x_t, h, c)
print(h.round(3), c.round(3))

params = lambda gates: gates * (n_h * (n_h + n_in) + n_h)
print(params(1), params(4))             # простая RNN: 32, LSTM: 128 — вчетверо больше
```

Модель для прогноза временного ряда в PyTorch:

```python
import torch
import torch.nn as nn

class LSTMModel(nn.Module):
    def __init__(self, input_size=1, hidden_size=64, num_layers=2):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden_size, num_layers,
                            batch_first=True, dropout=0.2)
        self.fc = nn.Linear(hidden_size, 1)

    def forward(self, x):                   # x: (batch, timesteps, features)
        out, (h_n, c_n) = self.lstm(x)      # LSTM возвращает два состояния
        return self.fc(out[:, -1, :])

model = LSTMModel()
y = model(torch.randn(32, 10, 1))           # 32 окна по 10 шагов → (32, 1)
```

## Подводные камни

- **Масштаб данных.** LSTM чувствительна к масштабу: нормализуйте ряд (MinMaxScaler или StandardScaler), причём обучайте скейлер только на обучающей части — иначе утечка данных.
- **Перемешивание временных рядов.** Окна можно перемешивать внутри обучающей части, но разбиение на train/test — строго по времени: тест позже обучения.
- **Возвращаются два состояния.** `nn.LSTM` возвращает `(h_n, c_n)`, а не одно состояние, как `nn.RNN` и `nn.GRU`, — частая ошибка при замене одной архитектуры другой.
- **Инициализация forget gate.** Смещение вентиля забывания около 1 помогает в начале обучения: сеть по умолчанию «помнит», и градиент проходит дальше. Keras делает это по умолчанию (`unit_forget_bias=True`).
- **Не панацея.** На очень длинных последовательностях (тысячи шагов) LSTM тоже забывает и учится медленно — там лучше трансформеры или свёрточные модели (TCN). Для табличных признаков по времени часто сильнее градиентный бустинг на лаговых признаках.
- **Проверяйте простой бейзлайн.** Прогноз «завтра = сегодня» на временных рядах бывает удивительно сильным; LSTM должна его обыгрывать.

## Итоги

- LSTM добавляет к RNN отдельное состояние ячейки `C_t` — долгосрочную память.
- Три вентиля (забывания, входной, выходной) решают, что стереть, что записать и что показать.
- Память обновляется сложением `C_t = f ⊙ C_{t−1} + i ⊙ C̃_t`, поэтому градиент не затухает так быстро, как в RNN.
- Параметров примерно в 4 раза больше, чем у RNN того же размера.
- Хорошо подходит для временных рядов и последовательностей средней длины; в NLP её во многом заменили трансформеры.
