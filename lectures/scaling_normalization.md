# Масштабирование и нормализация

<!-- время: 12 мин -->

> **О чём лекция.** Почему признаки в разных единицах измерения мешают многим моделям, чем отличаются StandardScaler, MinMaxScaler и RobustScaler и каким моделям масштабирование нужно, а каким нет.

## Зачем это нужно

Возраст клиента меняется от 18 до 80, а доход — от 20 000 до 500 000. Для человека это просто разные единицы. Для многих алгоритмов — катастрофа: всё, что основано на расстояниях или градиентах, будет почти целиком определяться доходом просто потому, что его числа больше.

- **k-NN, k-means, SVM** считают расстояния: разница в доходе на 1000 перевесит разницу в возрасте на 50 лет.
- **Градиентный спуск** (линейные модели, нейросети) на неотмасштабированных признаках идёт по узкому вытянутому оврагу и сходится медленно.
- **Регуляризация** (Ridge, Lasso) штрафует веса одинаково, а размер веса зависит от единиц признака — штраф становится несправедливым.
- **PCA** ищет направления наибольшей дисперсии и без масштабирования просто выберет признак с самыми большими числами.

Масштабирование приводит признаки к сопоставимым шкалам, чтобы их вклад определялся информацией, а не единицами измерения.

## Интуиция: общая линейка

Представьте карту, где расстояние по горизонтали измерено в километрах, а по вертикали — в миллиметрах. Две точки, разнесённые на 1 км по горизонтали, окажутся «ближе», чем точки, разнесённые на 2 м по вертикали. Масштабирование — это перевод всех осей на одну линейку.

## Как это работает

### StandardScaler — стандартизация

```
x' = (x − среднее) / std
```

После преобразования у признака среднее 0 и стандартное отклонение 1. Значение показывает, на сколько стандартных отклонений объект отличается от среднего. Это выбор по умолчанию для линейных моделей, SVM, нейросетей, PCA.

### MinMaxScaler — нормализация в диапазон

```
x' = (x − min) / (max − min)
```

Значения попадают в `[0, 1]`. Удобно, когда нужен ограниченный диапазон: пиксели изображений, некоторые нейросети, алгоритмы, ожидающие неотрицательных входов. Очень чувствителен к выбросам: один большой выброс сжимает все остальные значения к нулю.

### RobustScaler — устойчивое масштабирование

```
x' = (x − медиана) / IQR
```

Медиана и межквартильный размах почти не реагируют на выбросы, поэтому основная масса данных масштабируется правильно, а выбросы просто остаются большими числами.

### Другие преобразования

- **MaxAbsScaler** — деление на максимальное по модулю значение; не сдвигает данные и сохраняет разреженность (нули остаются нулями) — для разреженных матриц, например TF-IDF.
- **Normalizer** — нормирует не столбцы, а **строки**: каждый объект приводится к вектору единичной длины. Нужен для косинусной близости текстов; это совсем другая операция.
- **`PowerTransformer`** (Yeo-Johnson, Box-Cox), **`QuantileTransformer`**, логарифм — меняют *форму* распределения, делая его ближе к нормальному.

Важно: StandardScaler, MinMaxScaler и RobustScaler — линейные преобразования. Они сдвигают и растягивают шкалу, но **не меняют форму распределения**: скошенный признак останется скошенным. Для формы нужны нелинейные преобразования.

### Кому нужно масштабирование

| нужно | не нужно |
|---|---|
| k-NN, k-means, SVM | деревья решений |
| линейная и логистическая регрессия с регуляризацией | случайный лес |
| нейросети | градиентный бустинг (XGBoost, LightGBM, CatBoost) |
| PCA, LDA | наивный Байес |

Деревьям важен только порядок значений: разбиение «доход > 50 000» и «стандартизированный доход > 0.3» делят выборку одинаково.

## Пример на Python

Как три скейлера обрабатывают данные с одним выбросом:

```python
import numpy as np
from sklearn.preprocessing import MinMaxScaler, RobustScaler, StandardScaler

X = np.array([[1.0], [2.0], [3.0], [4.0], [100.0]])   # один выброс

for scaler in [StandardScaler(), MinMaxScaler(), RobustScaler()]:
    print(f"{type(scaler).__name__:15s}", scaler.fit_transform(X).ravel().round(2))

# StandardScaler  [-0.54 -0.51 -0.49 -0.46  2.  ]
# MinMaxScaler    [0.   0.01 0.02 0.03 1.  ]
# RobustScaler    [-1.  -0.5  0.   0.5 48.5]
```

У MinMaxScaler четыре обычных значения сжались в диапазон 0–0.03 и стали почти неразличимы. RobustScaler сохранил нормальные различия между ними, а выброс честно остался выбросом.

А вот эффект на реальной модели — k-NN на датасете вин, где признаки имеют очень разные шкалы:

```python
from sklearn.datasets import load_wine
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
raw = cross_val_score(KNeighborsClassifier(), X, y, cv=5).mean()
scaled = cross_val_score(make_pipeline(StandardScaler(), KNeighborsClassifier()), X, y, cv=5).mean()
print(f"k-NN без масштабирования: {raw:.3f}, со StandardScaler: {scaled:.3f}")
# k-NN без масштабирования: 0.691, со StandardScaler: 0.949
```

## Подводные камни

- **`fit` на всём датасете.** Скейлер обучают на train (`fit_transform`), а к тесту применяют только `transform`. Иначе среднее и std теста просачиваются в обучение — утечка данных.
- **Отдельный `fit` на тесте** — другая ошибка: тест окажется в другой шкале, чем та, на которой училась модель.
- **MinMaxScaler и выбросы** — выбирайте RobustScaler или сначала обработайте выбросы.
- **Масштабирование one-hot столбцов** обычно не нужно и ухудшает интерпретируемость.
- **Normalizer вместо StandardScaler** — частая путаница: первый работает по строкам, второй по столбцам.
- **Забыли скейлер в продакшене.** Сохраняйте его вместе с моделью — проще всего внутри `Pipeline`.

## Итоги

- Масштабирование выравнивает вклад признаков в моделях на расстояниях и градиентах.
- StandardScaler — по умолчанию; MinMaxScaler — когда нужен диапазон `[0, 1]`; RobustScaler — при выбросах.
- Линейные скейлеры не меняют форму распределения; для формы — логарифм, PowerTransformer, QuantileTransformer.
- Деревьям и бустингам масштабирование не нужно.
- `fit` только на train, `transform` для всего остального; скейлер — часть пайплайна.
