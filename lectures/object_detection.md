# Детекция объектов — Faster R-CNN, SSD, RetinaNet, EfficientDet

> **О чём лекция.** Как нейросеть находит на изображении все объекты и обводит их рамками: формат ответа, IoU и NMS, двухстадийные (Faster R-CNN) и одностадийные (SSD, RetinaNet) детекторы, FPN, focal loss, DETR и метрика mAP.

## Зачем это нужно

Классификатор говорит, что на фото есть кошка. Но камере видеонаблюдения нужно знать, сколько людей в кадре и где каждый, беспилотнику — где пешеходы и машины, складу — сколько коробок на полке. Это задача **детекции объектов**: найти все объекты нужных классов и для каждого указать:

- **bounding box** — прямоугольник, обычно в формате (x1, y1, x2, y2) или (x, y, w, h);
- **класс** объекта;
- **уверенность** (confidence score).

Сложность в том, что объектов заранее неизвестное количество, они бывают разного размера и могут перекрываться.

## Интуиция: много кандидатов и отбор лучших

Почти любой детектор работает по одной схеме: сначала предлагает очень много рамок-кандидатов по всему изображению, для каждой предсказывает класс и уточняет координаты, а потом выбрасывает лишнее — фон и дубликаты одного и того же объекта.

Кандидаты обычно задаются **якорями (anchor boxes)** — заранее определёнными рамками нескольких размеров и пропорций в каждой точке карты признаков. Сеть не рисует рамку с нуля, а предсказывает смещение относительно ближайшего якоря: так задача становится проще.

## Как это работает: IoU и NMS

**IoU** (Intersection over Union) — главная мера совпадения двух рамок:

```
IoU = площадь пересечения / площадь объединения
```

IoU = 1 — рамки совпадают, 0 — не пересекаются. Она используется трижды: чтобы решить, какой якорь отвечает за объект при обучении, чтобы удалить дубликаты и чтобы считать метрики.

**NMS (Non-Maximum Suppression)** убирает дубликаты: сеть обычно выдаёт несколько похожих рамок вокруг одного объекта. Алгоритм:

1. Отсортировать рамки по уверенности.
2. Взять самую уверенную рамку и оставить её.
3. Удалить все оставшиеся рамки, у которых IoU с ней больше порога (обычно 0.5).
4. Повторять с оставшимися.

## Двухстадийные детекторы: Faster R-CNN

Семейство R-CNN развивалось так: R-CNN запускал CNN на ~2000 вырезанных регионов (очень медленно), Fast R-CNN считал признаки один раз для всего изображения, а **Faster R-CNN** (2015) научился и сами регионы предлагать нейросетью.

Устройство Faster R-CNN:

1. **Backbone** (ResNet, VGG) считает карту признаков всего изображения.
2. **RPN (Region Proposal Network)** скользит по карте признаков и в каждой точке для 9 якорей (3 размера × 3 пропорции) предсказывает: «объект или фон» и уточнение координат. Остаются несколько сотен лучших предложений.
3. **RoI Pooling** (или RoIAlign) вырезает из карты признаков участок под каждое предложение и приводит его к фиксированному размеру, например 7×7.
4. **Голова** классифицирует каждый регион и ещё раз уточняет рамку.

Двухстадийные детекторы точны, особенно на маленьких объектах, но медленнее одностадийных.

## Одностадийные детекторы: SSD и RetinaNet

**SSD** и **YOLO** убирают отдельную стадию предложений: в каждой точке нескольких карт признаков сеть сразу предсказывает класс и рамку для каждого якоря. Это быстро — подходит для видео в реальном времени.

Долгое время одностадийные детекторы уступали в точности. Причину нашли авторы **RetinaNet** (2017): **дисбаланс классов**. На изображении десятки тысяч якорей, и почти все — лёгкий фон. Их суммарная потеря в обычной кросс-энтропии подавляет вклад немногих настоящих объектов.

**Focal loss** решает это множителем, который уменьшает вклад хорошо классифицированных примеров:

```
FL(p_t) = −α · (1 − p_t)^γ · log(p_t)
```

Здесь p_t — вероятность правильного класса. Если пример лёгкий (p_t = 0.99), множитель (1 − p_t)^γ при γ = 2 равен 0.0001, и пример почти не влияет на обучение. Трудные примеры сохраняют полный вес.

## Многомасштабность: FPN

Объекты бывают крупными и крошечными. Глубокие слои CNN понимают смысл, но имеют низкое разрешение — маленький объект там занимает долю пикселя. Ранние слои имеют высокое разрешение, но слабые признаки.

**FPN (Feature Pyramid Network)** строит пирамиду: от глубокого слоя идёт путь «сверху вниз» с увеличением разрешения, и на каждом уровне к нему прибавляется карта признаков энкодера того же размера. В итоге на каждом уровне — и хорошее разрешение, и сильные признаки. Маленькие объекты ищут на детальных уровнях, крупные — на грубых. FPN используется почти во всех современных детекторах. **EfficientDet** развивает идею: BiFPN с взвешенным объединением уровней и согласованное масштабирование сети.

## Детекторы без якорей и трансформеры

- **Anchor-free** (FCOS, CenterNet): вместо якорей каждая точка карты признаков предсказывает расстояния до краёв объекта или центр объекта и его размер. Меньше гиперпараметров.
- **DETR** (2020): трансформер получает признаки изображения и фиксированный набор «запросов объектов» и сразу выдаёт множество рамок. При обучении предсказания сопоставляются с разметкой **венгерским алгоритмом** один к одному, поэтому NMS не нужен. Первые версии обучались долго и плохо находили маленькие объекты; Deformable DETR и последующие варианты это исправили.

## Метрика mAP

Предсказание считается верным (**true positive**), если IoU с объектом разметки не меньше порога (например, 0.5) и этот объект ещё не «занят» другим предсказанием. Для каждого класса по предсказаниям, отсортированным по уверенности, строится кривая precision–recall, и площадь под ней — **AP**. Среднее по классам — **mAP**.

- **mAP@0.5** (метрика PASCAL VOC) — порог IoU 0.5.
- **mAP@[.5:.95]** (метрика COCO) — среднее по порогам от 0.5 до 0.95 с шагом 0.05; требует точной локализации.

## Пример на Python

IoU и NMS на NumPy:

```python
import numpy as np

def iou_box(a, b):
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0, x2 - x1) * max(0, y2 - y1)
    area = lambda r: (r[2] - r[0]) * (r[3] - r[1])
    return inter / (area(a) + area(b) - inter)

def nms(boxes, scores, thr=0.5):
    order = np.argsort(scores)[::-1]
    keep = []
    while len(order):
        i = order[0]
        keep.append(int(i))
        order = np.array([j for j in order[1:] if iou_box(boxes[i], boxes[j]) < thr])
    return keep

boxes = np.array([[10, 10, 50, 50],      # объект 1
                  [12, 12, 52, 52],      # дубликат объекта 1
                  [100, 100, 140, 150],  # объект 2
                  [11, 9, 49, 51]], float)  # ещё один дубликат
scores = np.array([0.9, 0.75, 0.8, 0.6])

print(round(iou_box(boxes[0], boxes[1]), 3))   # 0.822
print(nms(boxes, scores))                      # [0, 2] — по одной рамке на объект
```

В torchvision то же самое делает `torchvision.ops.nms(boxes, scores, 0.5)`, а готовый Faster R-CNN загружается одной строкой: `fasterrcnn_resnet50_fpn(weights="DEFAULT")`.

## Подводные камни

- **Порог NMS.** Слишком низкий удаляет соседние реальные объекты в толпе, слишком высокий оставляет дубликаты.
- **Маленькие объекты.** Они теряются на картах низкого разрешения; помогают FPN, большее разрешение входа и якоря подходящего размера.
- **Неподходящие якоря.** Если размеры и пропорции якорей не похожи на объекты вашего датасета (например, длинные узкие трубы), качество падает; их подбирают по статистике разметки.
- **Сравнение mAP разных определений.** mAP@0.5 и COCO mAP — разные числа, сравнивать их напрямую нельзя.
- **Формат координат.** Путаница между (x, y, w, h) и (x1, y1, x2, y2) или между пикселями и долями изображения — частая и тихая ошибка.

## Итоги

- Детекция = рамка + класс + уверенность для каждого объекта.
- IoU измеряет перекрытие рамок; NMS удаляет дубликаты.
- Двухстадийные детекторы (Faster R-CNN: backbone → RPN → RoI → голова) точнее, одностадийные (SSD, YOLO, RetinaNet) быстрее.
- Focal loss решает проблему дисбаланса «фон против объектов», FPN — проблему разных масштабов.
- DETR предсказывает множество рамок трансформером без якорей и NMS.
- Основная метрика — mAP; на COCO её усредняют по порогам IoU от 0.5 до 0.95.
