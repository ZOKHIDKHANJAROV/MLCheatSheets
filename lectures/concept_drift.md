# Дрейф данных и концептуальный дрейф

<!-- время: 15 мин -->

> **О чём лекция.** Почему модель, отлично работавшая на запуске, через полгода начинает ошибаться, хотя код никто не трогал. Разберём виды дрейфа, статистические способы его обнаружить (PSI, тест Колмогорова–Смирнова, ADWIN) и что делать, когда дрейф найден.

## Зачем это нужно

Обучение модели опирается на неявное допущение: будущие данные похожи на обучающие. В реальности мир меняется:

- в 2020 году пандемия за несколько недель изменила покупательское поведение, и модели прогноза спроса стали ошибаться;
- мошенники меняют схемы, как только старые начинают ловить;
- банк запустил новый продукт — и пришли клиенты другого профиля;
- поставщик данных поменял единицы измерения или формат поля.

Модель при этом ничего «не знает» — она продолжает уверенно выдавать прогнозы. Без мониторинга деградацию замечают, когда она уже стоила денег. Поэтому обнаружение дрейфа — обязательная часть эксплуатации ML-систем.

## Интуиция: старая карта

Модель — это карта местности, нарисованная по прошлогодним съёмкам. Если в городе построили новые районы (изменилось, *где* люди бывают), карта не покрывает часть мест. Если перекрыли улицы (изменилось, *куда* ведут дороги), карта покрывает места, но ведёт не туда. В первом случае это видно по самим запросам, во втором — только когда люди начинают приезжать не туда.

## Виды дрейфа

Модель учит связь P(Y | X), а данные приходят из P(X). Меняться может разное:

| вид | что меняется | пример | как заметить |
|---|---|---|---|
| Data drift (covariate shift) | распределение признаков P(X) | пришли более молодые клиенты | по входным данным, без меток |
| Concept drift | связь P(Y∣X) | при том же доходе люди стали чаще не возвращать кредиты | нужны метки (или их заменители) |
| Label drift (prior shift) | распределение целевой P(Y) | доля мошенничества выросла с 1% до 3% | по меткам или по распределению прогнозов |

По форме во времени дрейф бывает **внезапным** (смена законодательства), **постепенным** (медленное старение аудитории), **инкрементальным** и **сезонным/повторяющимся** (праздники каждый год).

Важно: data drift не всегда вредит. Если сдвинулся признак, который модель почти не использует, качество не изменится. И наоборот, concept drift может сильно ухудшить модель при неизменном P(X) — его по входным данным не увидеть.

## Как это обнаружить

**1. Мониторинг качества.** Самый прямой путь: считать метрику на свежих размеченных данных. Проблема — метки приходят с задержкой (возврат кредита виден через месяцы). Поэтому дополнительно следят за входами и прогнозами.

**2. Сравнение распределений признаков** — эталон (обучение или стабильный период) против текущего окна.

**PSI (Population Stability Index)** — популярен в банковском скоринге. Разбиваем признак на корзины (обычно 10, по квантилям эталона), считаем доли объектов в корзинах e и a:

```
PSI = Σ (aᵢ − eᵢ) · ln(aᵢ / eᵢ)
```

Принятые на практике пороги: PSI < 0.1 — стабильно, 0.1–0.25 — умеренный сдвиг, стоит посмотреть, > 0.25 — значительный сдвиг.

**Тест Колмогорова–Смирнова** — для непрерывного признака сравнивает эмпирические функции распределения двух выборок; статистика — максимальная разница между ними. Для категориальных признаков — тест хи-квадрат. Есть также расстояние Вассерштейна и дивергенция Йенсена–Шеннона.

**3. Мониторинг прогнозов.** Распределение выхода модели (средняя вероятность, доля положительных решений) — дешёвый сигнал, который реагирует на дрейф в важных для модели признаках.

**4. Потоковые детекторы.** ADWIN, DDM, Page–Hinkley следят за потоком ошибок (или значений) и сигналят, когда среднее статистически значимо изменилось. ADWIN держит адаптивное окно и отбрасывает старую часть, если она отличается от новой. Реализованы в библиотеке `river`.

**5. Классификатор-детектор.** Обучить модель отличать «старые» данные от «новых». Если ROC-AUC такого классификатора заметно выше 0.5 — распределения различаются, а его важности признаков показывают, *что* сдвинулось.

## Пример на Python

Сравним эталонное распределение признака с двумя «продовыми» окнами: без изменений и со сдвигом.

```python
import numpy as np
from scipy.stats import ks_2samp

def psi(expected, actual, bins=10):
    edges = np.quantile(expected, np.linspace(0, 1, bins + 1))
    edges[0], edges[-1] = -np.inf, np.inf            # выход за края — в крайние корзины
    e = np.histogram(expected, edges)[0] / len(expected)
    a = np.histogram(actual, edges)[0] / len(actual)
    e, a = np.clip(e, 1e-6, None), np.clip(a, 1e-6, None)   # защита от log(0)
    return np.sum((a - e) * np.log(a / e))

rng = np.random.default_rng(0)
train = rng.normal(50, 10, size=10_000)
same = rng.normal(50, 10, size=2_000)
shifted = rng.normal(55, 12, size=2_000)

for name, prod in [("без сдвига", same), ("со сдвигом", shifted)]:
    stat, p = ks_2samp(train, prod)
    print(f"{name}: PSI = {psi(train, prod):.3f}, KS = {stat:.3f}, p = {p:.2g}")
# без сдвига: PSI = 0.003, KS = 0.010, p = 1
# со сдвигом: PSI = 0.233, KS = 0.195, p = 5.7e-56
```

Сдвиг среднего на полстандартного отклонения дал PSI 0.23 — на границе «значительного». Обратите внимание на две детали в `psi`: края корзин расширены до бесконечности (иначе новые значения за пределами эталонного диапазона потерялись бы) и доли защищены от нуля.

## Что делать, если дрейф найден

1. **Проверить, не баг ли это.** Значительная часть «дрейфа» — сломанный пайплайн: поменялись единицы, поле стало пустым, изменилась кодировка категорий.
2. **Оценить влияние на качество.** Если метки доступны — посчитать метрику; если нет — посмотреть, затронуты ли важные для модели признаки.
3. **Переобучить** на свежих данных: по расписанию, по сигналу детектора или на скользящем окне. Можно давать новым данным больший вес.
4. **Адаптировать модель**: онлайн-обучение для потоков, пересчёт порогов при label drift, отдельные модели для новых сегментов.
5. **Зафиксировать выводы**: какой сдвиг, почему, как отреагировали — чтобы в следующий раз быстрее.

## Подводные камни

- **Ложные тревоги на больших данных.** На сотнях тысяч объектов KS-тест находит «значимые» различия, которые ничего не значат для модели. Смотрите на величину эффекта (PSI, статистику KS), а не только на p-value.
- **Множественные сравнения.** Сотня признаков, каждый тестируется ежедневно — что-нибудь «сработает» случайно. Используйте поправки и пороги на величину сдвига.
- **Сезонность.** Сравнение декабря с июлем покажет дрейф, который на самом деле ожидаем. Сравнивайте с тем же периодом прошлого года или учитывайте сезонность в эталоне.
- **Concept drift невидим во входах.** Мониторинг только P(X) его не поймает — нужны метки, хотя бы на подвыборке, или прокси-метрики бизнеса.
- **Переобучение на дрейфе.** Слишком частое переобучение на маленьких свежих окнах делает модель нестабильной и подгоняет её под шум.

## Итоги

- Мир меняется, и модели деградируют: это нормальный процесс, который нужно мониторить.
- Data drift — сдвиг P(X), concept drift — изменение P(Y | X), label drift — изменение P(Y).
- Инструменты: мониторинг качества, PSI и KS-тест для признаков, распределение прогнозов, потоковые детекторы (ADWIN), классификатор «старое/новое».
- PSI > 0.25 — общепринятый сигнал значительного сдвига; смотрите на величину эффекта, а не только на p-value.
- Реакция: сначала исключить баг в данных, затем оценить влияние и переобучить или адаптировать модель.
