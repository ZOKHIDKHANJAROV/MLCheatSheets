# Deep Q-Networks (DQN)

<!-- время: 16 мин -->

> **О чём лекция.** Как Q-learning научился играть в Atari по пикселям: таблицу заменили нейросетью, а чтобы обучение не развалилось, добавили два приёма — буфер воспроизведения и целевую сеть. Разберём, зачем каждый из них нужен, откуда берётся переоценка ценностей и как её лечат Double DQN, а также что дают Dueling DQN и другие улучшения.

## Зачем это нужно

Табличный Q-learning хранит отдельное число для каждой пары «состояние–действие». Это работает в сетке 4×12, но не в реальных задачах: кадр Atari 84×84 пикселя в оттенках серого — это астрономическое число возможных состояний, и агент почти никогда не увидит один и тот же кадр дважды. Таблица не просто огромна — она не **обобщает**: опыт в одном состоянии ничего не говорит о похожем.

В 2013–2015 годах DeepMind показала **DQN** (Deep Q-Network): нейросеть, которая по сырым пикселям оценивает Q-значения и с одним набором гиперпараметров достигла уровня человека на десятках игр Atari (статья в Nature, 2015). Это стало началом глубокого обучения с подкреплением.

## Интуиция: нейросеть вместо таблицы

Идея проста: вместо таблицы Q(s, a) обучить нейросеть Q(s, ·; θ), которая получает состояние и **за один проход** выдаёт Q-значения всех действий. Похожие состояния дают похожие выходы — сеть обобщает опыт.

Учим её так же, как в Q-learning: подгоняем Q(s, a) к TD-цели r + γ · max Q(s', ·). Только теперь это не обновление ячейки, а шаг градиентного спуска по функции потерь.

Наивная версия этой идеи обучается очень плохо. Причины две, и DQN решает каждую отдельным приёмом.

## Проблема 1: коррелированные данные → experience replay

Подряд идущие кадры почти одинаковы. Если обучать сеть на опыте в том порядке, в каком он приходит, градиенты сильно коррелированы, сеть переобучается на текущем участке игры и забывает предыдущие.

**Буфер воспроизведения (experience replay)** хранит последние переходы (s, a, r, s', done) — в оригинале миллион. Для обучения из буфера берут **случайный мини-батч**. Это:

- разрушает корреляции между соседними примерами — данные становятся ближе к независимым, как в обычном обучении с учителем;
- позволяет использовать каждый переход много раз — выше эффективность по данным;
- возможно только потому, что Q-learning — off-policy: можно учиться на опыте старой политики.

## Проблема 2: движущаяся цель → target network

В Q-learning цель r + γ · max Q(s', ·) сама вычисляется той же сетью, которую мы обучаем. Каждый шаг градиента меняет и предсказание, и цель — как пытаться догнать собственную тень. Обучение колеблется и расходится.

**Целевая сеть (target network)** — копия основной сети с весами θ⁻, которые **заморожены** и обновляются копированием раз в C шагов (например, раз в 10 000) или плавно: θ⁻ ← τ·θ + (1 − τ)·θ⁻ с маленьким τ. Цель считается по ней:

```
y = r + γ · (1 − done) · max_a' Q(s', a'; θ⁻)
L(θ) = E[ ℓ( y − Q(s, a; θ) ) ]
```

Теперь на время между обновлениями цель неподвижна, и задача становится похожей на обычную регрессию. В качестве ℓ часто берут **функцию потерь Хьюбера**: она квадратичная для маленьких ошибок и линейная для больших, поэтому редкие огромные TD-ошибки не дают взрывных градиентов.

## Как это работает: алгоритм целиком

1. Инициализировать сеть Q(θ), копию θ⁻ ← θ и пустой буфер.
2. В каждом шаге выбрать действие ε-жадно по Q(s, ·; θ), сделать его, сохранить переход в буфер.
3. Взять случайный мини-батч из буфера, посчитать цели по целевой сети, сделать шаг градиента по θ.
4. Раз в C шагов скопировать θ в θ⁻. Постепенно уменьшать ε.

Для Atari состоянием служат **четыре последних кадра**: по одному кадру не понять, куда и как быстро летит мяч, а стек кадров делает состояние почти марковским.

## Переоценка и Double DQN

Максимум по шумным оценкам систематически **завышен**. Даже если все действия на самом деле одинаково хороши, из-за случайных ошибок одно из них будет выглядеть лучше, и max выберет именно его. В Q-learning это завышение затем распространяется по всем ценностям через бутстрап.

**Double DQN** разделяет две роли: **выбор** лучшего действия делает основная сеть, а **оценку** этого действия — целевая:

```
a* = argmax_a' Q(s', a'; θ)
y  = r + γ · (1 − done) · Q(s', a*; θ⁻)
```

Ошибки двух сетей частично независимы, поэтому завышение почти пропадает. Это изменение одной строки кода, которое почти всегда улучшает результат.

## Другие улучшения

- **Dueling DQN** раскладывает Q на ценность состояния и преимущество действия: Q(s, a) = V(s) + A(s, a) − среднее по a от A(s, a). Сеть быстрее узнаёт, что состояние в целом плохое, даже не перебирая все действия.
- **Приоритизированный replay** чаще воспроизводит переходы с большой TD-ошибкой — на них сеть учится больше.
- **n-step returns** — цель по нескольким реальным наградам вперёд, а не по одной: быстрее распространяет награду.
- **Rainbow** (2017) объединил шесть улучшений и заметно превзошёл каждое по отдельности.

Ограничение DQN: он работает только с **дискретными действиями**, ведь нужен max по действиям. Для непрерывного управления (углы суставов робота) используют DDPG, TD3, SAC или PPO.

## Пример на Python

Покажем источник переоценки численно. У всех 10 действий истинная ценность 0, а оценки зашумлены:

```python
import numpy as np

rng = np.random.default_rng(0)
est_a = rng.normal(size=(100_000, 10))     # оценки сети A
est_b = rng.normal(size=(100_000, 10))     # независимые оценки сети B

print(f"max по шумным оценкам: {est_a.max(axis=1).mean():.2f}")   # 1.54 вместо 0
best = est_a.argmax(axis=1)                                       # Double: выбираем по A…
print(f"double-оценка: {est_b[np.arange(100_000), best].mean():.2f}")   # …оцениваем по B: ≈ 0
```

А вот шаг обучения DQN в PyTorch (сети `q_net` и `target_net` — обычные MLP, батч взят из буфера):

```python
import torch
import torch.nn.functional as F

def dqn_update(q_net, target_net, optimizer, batch, gamma=0.99):
    s, a, r, s2, done = batch                              # тензоры батча из replay buffer
    q = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)      # Q(s, a; θ)
    with torch.no_grad():                                  # цель без градиента
        a_star = q_net(s2).argmax(dim=1, keepdim=True)     # Double DQN: выбор по основной сети
        q_next = target_net(s2).gather(1, a_star).squeeze(1)   # оценка по целевой
        y = r + gamma * (1 - done) * q_next
    loss = F.smooth_l1_loss(q, y)                          # функция потерь Хьюбера
    optimizer.zero_grad(); loss.backward(); optimizer.step()
    return loss.item()
```

## Подводные камни

- **Граница эпизода по лимиту времени.** Если эпизод оборвали по лимиту шагов (truncated), а не потому, что игра закончилась (terminated), будущее существует, и цель нужно бутстрапить. Ставить done = 1 для обрезанных эпизодов — частая ошибка.
- **Градиент через цель.** Цель должна считаться без градиента (`torch.no_grad()`), иначе сеть «двигает» и цель.
- **Слишком маленький буфер** возвращает корреляции; слишком большой хранит сильно устаревший опыт.
- **Слишком частое обновление целевой сети** возвращает проблему движущейся цели.
- **Нестабильность.** Результаты DQN сильно зависят от сида и гиперпараметров. Смотрите на среднее по нескольким запускам.

## Итоги

- DQN — Q-learning с нейросетью: вход — состояние, выход — Q-значения всех действий.
- Буфер воспроизведения разрушает корреляции и повторно использует опыт; целевая сеть делает цель неподвижной.
- Максимум по шумным оценкам завышен; Double DQN разделяет выбор действия и его оценку.
- Dueling, приоритизированный replay, n-step и Rainbow улучшают DQN; для непрерывных действий нужны другие алгоритмы.
