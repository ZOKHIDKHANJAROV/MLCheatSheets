# Основы RNN

<!-- время: 15 мин -->

> **О чём лекция.** Как нейросеть читает последовательность слово за словом и держит в голове прочитанное: скрытое состояние, общие веса для всех шагов, обучение через время — и почему простая RNN быстро всё забывает.

## Зачем это нужно

Многие данные — это последовательности: текст (слова по порядку), речь (звук во времени), курсы валют, показания датчиков, клики пользователя. В них важен **порядок**: «собака укусила человека» и «человек укусил собаку» состоят из одних слов, но значат разное.

Обычная полносвязная сеть (MLP) принимает вход фиксированного размера и не знает о порядке. Можно склеить все слова в один длинный вектор, но тогда:

- длина входа должна быть одинаковой, а предложения бывают разные;
- закономерность, выученная для позиции 3, не переносится на позицию 7 — веса у каждой позиции свои;
- параметров становится очень много.

**Рекуррентная нейросеть** (RNN, Recurrent Neural Network) решает это иначе: она читает последовательность по одному элементу и после каждого шага обновляет свою «память» — **скрытое состояние**.

## Интуиция: чтение с конспектом

Представьте, что вы читаете книгу и после каждого предложения дописываете короткий конспект, который помещается на одну карточку. Новое предложение вы понимаете с учётом карточки, а затем переписываете её: что-то добавляете, что-то вытесняете.

- **Карточка** — скрытое состояние `h_t`, вектор фиксированного размера.
- **Новое предложение** — вход `x_t` на шаге t.
- **Правила, как переписывать карточку**, — веса сети. Они одинаковые на всех шагах: вы читаете первую и сотую страницу одним и тем же способом.

Карточка маленькая, поэтому старое постепенно вытесняется. Это главная слабость простой RNN, к ней мы вернёмся.

## Как это работает

На каждом шаге t RNN считает:

```
h_t = tanh(W_hh · h_{t−1} + W_xh · x_t + b_h)
y_t = W_hy · h_t + b_y
```

- `x_t` — вход на шаге t (например, эмбеддинг слова);
- `h_{t−1}` — скрытое состояние с прошлого шага, `h_0` обычно нули;
- `W_xh`, `W_hh`, `W_hy` — матрицы весов, **общие для всех шагов**;
- `tanh` удерживает значения состояния в диапазоне (−1, 1);
- `y_t` — выход на шаге t, если он нужен.

Если «развернуть» RNN во времени, получится очень глубокая сеть: один и тот же слой, повторённый столько раз, сколько шагов в последовательности. Общие веса дают два преимущества: число параметров не зависит от длины последовательности, а закономерность, выученная в одном месте текста, работает в любом другом.

## Какие задачи решает RNN

От того, какие выходы мы берём, зависит тип задачи:

| схема | вход → выход | пример |
|---|---|---|
| many-to-one | последовательность → одно значение | тональность отзыва, класс временного ряда |
| one-to-many | одно значение → последовательность | генерация подписи к картинке |
| many-to-many (синхронно) | метка для каждого шага | разметка частей речи, NER |
| seq2seq (encoder–decoder) | последовательность → другая последовательность | машинный перевод |

Для many-to-one обычно берут последнее скрытое состояние `h_T`: оно «прочитало» всю последовательность. **Двунаправленная RNN** (bidirectional) читает последовательность в обе стороны и склеивает состояния — полезно, когда доступен весь текст сразу (классификация, NER), но неприменимо для прогноза будущего: там «справа» ещё ничего нет.

## Обучение: backpropagation through time

RNN обучают обычным обратным распространением ошибки, применённым к развёрнутой во времени сети, — **BPTT** (backpropagation through time). Градиент течёт от выхода назад через все шаги. Поскольку веса общие, вклады от всех шагов суммируются.

И здесь проблема. На каждом шаге назад градиент умножается на матрицу `W_hh` и на производную tanh (она не больше 1, обычно меньше). После десятков шагов произведение множителей:

- **затухает** (vanishing gradient), если множители меньше 1 — сеть перестаёт учиться связи между далёкими шагами;
- **взрывается** (exploding gradient), если больше 1 — веса прыгают, потери становятся `nan`.

Затухание объясняет, почему простая RNN плохо помнит начало длинного предложения: сигнал ошибки до него просто не доходит. Взрыв лечат **обрезкой градиента** (gradient clipping): если норма градиента больше порога, его масштабируют вниз. Затухание лечат архитектурно — LSTM и GRU, у которых есть «прямой канал» для памяти.

На очень длинных последовательностях используют **truncated BPTT**: градиент пропускают только на фиксированное число шагов назад, чтобы экономить память.

## Пример на Python

Шаг RNN на NumPy и демонстрация того, как градиент тает при движении назад по времени:

```python
import numpy as np

rng = np.random.default_rng(0)
input_size, hidden_size, seq_len = 3, 4, 5
W_xh = rng.normal(scale=0.5, size=(hidden_size, input_size))
W_hh = rng.normal(scale=0.5, size=(hidden_size, hidden_size))
b_h = np.zeros(hidden_size)

xs = rng.normal(size=(seq_len, input_size))   # последовательность из 5 шагов
h = np.zeros(hidden_size)                     # начальная память — нули
for t, x_t in enumerate(xs):
    h = np.tanh(W_hh @ h + W_xh @ x_t + b_h)  # одни и те же веса на каждом шаге
    print(t, h.round(3))

# Почему градиент затухает: на каждом шаге назад он умножается на W_hhᵀ и производную tanh
grad = np.ones(hidden_size)
for steps in range(1, 31):
    grad = W_hh.T @ (grad * 0.6)              # 0.6 — типичная производная tanh в рабочей зоне
    if steps in (1, 10, 30):
        print(steps, f"{np.linalg.norm(grad):.2e}")
# 1 9.65e-01
# 10 2.24e-02
# 30 7.61e-06  — через 30 шагов сигнала почти нет
```

В PyTorch слой RNN принимает тензор формы `(batch, seq_len, input_size)` при `batch_first=True`:

```python
import torch
import torch.nn as nn

class SimpleRNN(nn.Module):
    def __init__(self, input_size, hidden_size, output_size):
        super().__init__()
        self.rnn = nn.RNN(input_size, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, output_size)

    def forward(self, x):
        out, h_n = self.rnn(x)          # out: (batch, seq_len, hidden_size)
        return self.fc(out[:, -1, :])   # many-to-one: берём последний шаг

model = SimpleRNN(input_size=10, hidden_size=128, output_size=1)
```

## Подводные камни

- **Порядок размерностей.** В PyTorch по умолчанию `(seq_len, batch, features)`; если данные в формате `(batch, seq_len, features)`, нужен `batch_first=True`. Ошибка не всегда падает с исключением — модель просто учится на перепутанных данных.
- **Паддинг.** Последовательности в батче выравнивают по длине нулями. Если брать `out[:, -1, :]`, у коротких последовательностей это будет состояние после паддинга. Используйте `pack_padded_sequence` или берите состояние на реальной последней позиции.
- **Взрыв градиента.** Потери внезапно становятся `nan` — добавьте `clip_grad_norm_` (порог около 1–5).
- **Длинные зависимости.** Простая RNN почти не помнит дальше 10–20 шагов. Для текста и длинных рядов берите LSTM, GRU или трансформер.
- **Медленное обучение.** Шаги вычисляются строго последовательно, параллелить по времени нельзя — одна из причин, почему трансформеры вытеснили RNN в NLP.

## Итоги

- RNN обрабатывает последовательность по шагам и хранит прочитанное в скрытом состоянии `h_t`.
- Веса общие для всех шагов: параметров немного, длина входа может быть любой.
- Схема выходов определяет задачу: many-to-one, one-to-many, many-to-many, seq2seq.
- Обучение — BPTT; градиент на длинных цепочках затухает или взрывается.
- Взрыв лечат gradient clipping, затухание — архитектурами LSTM и GRU.
