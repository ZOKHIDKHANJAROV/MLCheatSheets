> **О чём лекция.** Чем гиперпараметры отличаются от параметров, как честно сравнивать их значения через кросс-валидацию и почему случайный поиск часто находит хорошие настройки быстрее полного перебора по сетке.

## Зачем это нужно

У каждой модели есть два вида «настроек». **Параметры** модель находит сама при обучении: веса линейной регрессии, пороги в узлах дерева. **Гиперпараметры** задаёт человек до обучения: глубина дерева, число деревьев в лесу, сила регуляризации `C`, learning rate. От них зависит, переобучится модель или недообучится, и разница между настройками «по умолчанию» и подобранными бывает заметной.

Подбирать гиперпараметры «на глаз», глядя на тест, — прямой путь к самообману: если перепробовать много вариантов и выбрать лучший по тестовой выборке, оценка на этом тесте будет завышена. Нужна дисциплина: перебор по понятной схеме и оценка через кросс-валидацию на обучающих данных.

## Интуиция: настройка радиоприёмника

Представьте приёмник с двумя ручками — частота и громкость, — и вам нужно найти лучший звук. Можно крутить каждую ручку по делениям и пробовать все сочетания (сетка). Можно ставить ручки в случайные положения (случайный поиск). Можно запоминать, где было лучше, и пробовать рядом (байесовская оптимизация — о ней отдельная лекция).

Каждая «проба» стоит дорого: это обучение модели, а с кросс-валидацией — несколько обучений. Поэтому вопрос не «как найти идеальную точку», а «как найти хорошую точку за разумное число проб».

## Как это работает

Общая схема для любого метода:

1. Задать **пространство поиска**: какие гиперпараметры перебираем и в каких пределах.
2. Выбрать **метрику** (`scoring`) — ту, что важна для задачи: ROC-AUC, F1, RMSE.
3. Для каждой пробной комбинации оценить метрику **кросс-валидацией** на обучающей выборке.
4. Выбрать лучшую комбинацию и переобучить модель на всей обучающей выборке (в scikit-learn это делает `refit=True` по умолчанию).
5. Один раз оценить итоговую модель на отложенном тесте.

**Grid Search** перебирает все сочетания из заданных списков. Сетка `max_depth ∈ {3, 6, None}` × `min_samples_leaf ∈ {1, 5, 20}` — это 9 комбинаций, а с 5 фолдами — 45 обучений. Число комбинаций растёт как произведение размеров списков: четыре гиперпараметра по 5 значений — уже 625 комбинаций и 3125 обучений.

**Random Search** вместо сетки задаёт *распределения* и делает фиксированное число случайных проб `n_iter`. Бюджет вы контролируете напрямую, и он не зависит от числа гиперпараметров.

## Почему случайный поиск часто лучше

Наблюдение Бергстры и Бенжио (2012): обычно лишь один-два гиперпараметра действительно сильно влияют на качество, а остальные — слабо. Сетка 3×3 проверяет всего 3 разных значения каждого параметра — в том числе важного. Девять случайных проб проверяют 9 разных значений важного параметра. При том же бюджете случайный поиск исследует важные измерения гораздо плотнее.

| | Grid Search | Random Search |
|---|---|---|
| что перебирает | все сочетания из списков | n_iter случайных точек из распределений |
| бюджет | растёт экспоненциально с числом параметров | задаётся явно |
| непрерывные параметры | только выбранные вручную точки | любые значения из распределения |
| когда хорош | 1–2 параметра, мало значений | 3 и более параметров, первый грубый поиск |

Практический рецепт: широкий Random Search, чтобы найти перспективную область, затем, при желании, узкий Grid Search вокруг лучшей точки. Для параметров вроде learning rate или `C`, которые меняются на порядки, берите **логарифмическую шкалу**: `loguniform(1e-4, 1e-1)`, а не равномерное распределение — иначе 90% проб попадёт в интервал от 0.01 до 0.1.

## Пример на Python

```python
from scipy.stats import randint
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV, RandomizedSearchCV, train_test_split

X, y = make_classification(n_samples=1000, n_features=20, n_informative=6, random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)
rf = RandomForestClassifier(n_estimators=100, random_state=0)

grid = GridSearchCV(rf, {"max_depth": [3, 6, None], "min_samples_leaf": [1, 5, 20]},
                    cv=5, scoring="roc_auc", n_jobs=-1)
grid.fit(X_train, y_train)
print(grid.best_params_, round(grid.best_score_, 3))
# {'max_depth': None, 'min_samples_leaf': 1} 0.957

rand = RandomizedSearchCV(rf, {"max_depth": randint(2, 20),
                               "min_samples_leaf": randint(1, 30),
                               "max_features": [0.2, 0.5, "sqrt"]},
                          n_iter=9, cv=5, scoring="roc_auc", n_jobs=-1, random_state=0)
rand.fit(X_train, y_train)
print(rand.best_params_, round(rand.best_score_, 3))
# {'max_depth': 14, 'max_features': 'sqrt', 'min_samples_leaf': 2} 0.958

print("Тест:", round(rand.score(X_test, y_test), 3))   # 0.955 — трогаем один раз
```

При одинаковом бюджете (9 комбинаций) случайный поиск перебрал три параметра вместо двух и нашёл не хуже. Оценка на тесте (0.955) чуть ниже лучшей CV-оценки (0.958) — так и должно быть: лучший результат из многих проб всегда немного оптимистичен.

Все результаты лежат в `grid.cv_results_` — его удобно превратить в `pd.DataFrame` и посмотреть, как метрика зависит от каждого параметра и насколько велик разброс между фолдами (`std_test_score`).

## Подводные камни

- **Утечка при предобработке.** Если масштабирование или отбор признаков сделаны на всех данных до поиска, CV-оценки завышены. Кладите предобработку в `Pipeline` и ищите по нему: ключи вида `"model__C"`.
- **Подбор по тесту.** Тестовая выборка — для финальной оценки, а не для выбора. Если нужна честная оценка всей процедуры подбора, используют вложенную кросс-валидацию (nested CV).
- **Лучшее значение на краю сетки.** Если лучший `max_depth` — максимальный из перебранных, оптимум, вероятно, дальше. Расширьте диапазон.
- **Шум в оценках.** Разница 0.957 против 0.958 при std между фолдами 0.01 ничего не значит. Не гонитесь за третьим знаком — смотрите на разброс.
- **Время.** `n_jobs=-1` распараллеливает перебор; для дорогих моделей берите `HalvingRandomSearchCV` (отсеивает слабых кандидатов на малом объёме данных) или байесовскую оптимизацию.

## Итоги

- Гиперпараметры задаются до обучения; их подбирают перебором с оценкой через кросс-валидацию.
- Grid Search проверяет все сочетания — честно, но число комбинаций растёт экспоненциально.
- Random Search с тем же бюджетом исследует важные параметры плотнее и обычно эффективнее.
- Параметры «на порядки» перебирайте в логарифмической шкале; предобработку держите внутри Pipeline.
- Тест — один раз в самом конце; лучший CV-результат всегда немного оптимистичен.
