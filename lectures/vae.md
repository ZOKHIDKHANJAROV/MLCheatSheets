# Вариационные автоэнкодеры (VAE)

<!-- время: 18 мин -->

> **О чём лекция.** Как превратить автоэнкодер из «архиватора» в генератор: энкодер начинает выдавать не точку, а распределение, а штраф KL делает латентное пространство гладким и без дыр. Разберём функцию потерь VAE, трюк репараметризации и то, почему картинки VAE получаются размытыми.

## Зачем это нужно

Обычный автоэнкодер хорошо сжимает, но плохо генерирует. Его латентное пространство устроено как попало: коды обучающих картинок разбросаны островками, а между ними пустота. Возьмите случайную точку z — декодер выдаст бессмыслицу, потому что такие точки он никогда не видел.

Хочется другого: чтобы можно было взять z из простого известного распределения, например стандартного нормального N(0, I), пропустить через декодер и получить правдоподобный новый объект. И чтобы соседние точки давали похожие объекты, а путь между двумя точками — плавный переход (интерполяцию). Это и даёт **вариационный автоэнкодер** (Kingma и Welling, 2013). Он генеративная модель: учится не просто сжимать, а описывать распределение данных.

## Интуиция: не точка, а облачко

В обычном автоэнкодере каждая картинка кодируется точкой. В VAE энкодер говорит: «эта картинка где-то вот здесь, примерно в этом облачке» — выдаёт центр μ и разброс σ. Из облачка случайно берётся точка z, и декодер должен восстановить картинку по любой точке облачка.

Что это меняет:

- декодер учится работать не с отдельными точками, а с целыми областями — пространство «заполняется»;
- облачка соседних картинок перекрываются, поэтому между ними нет пустот, а переходы плавные;
- отдельный штраф тянет все облачка к стандартному нормальному распределению, чтобы при генерации было ясно, откуда брать z.

Два желания тянут в разные стороны: точное восстановление хочет маленьких облачков в разных местах, а штраф хочет, чтобы все облачка были похожи на N(0, I). Компромисс между ними и даёт хорошее латентное пространство.

## Как это работает

Архитектура:

```
Encoder:  x → μ, log σ²          (два выхода размером latent_dim)
Sampling: z = μ + σ · ε,  ε ~ N(0, I)
Decoder:  z → x̂
```

Функция потерь — сумма двух частей:

```
L = Reconstruction(x, x̂) + KL( N(μ, σ²) ‖ N(0, I) )
```

- **Reconstruction** — как в обычном автоэнкодере: BCE для пикселей в [0, 1] или MSE.
- **KL-дивергенция** — насколько распределение кода отличается от стандартного нормального. Для нормальных распределений она считается по формуле:

```
KL = −½ · Σ (1 + log σ² − μ² − σ²)
```

KL равна нулю, только когда μ = 0 и σ = 1 по всем координатам. Если энкодер пытается «спрятать» картинку в далёкой точке (большое μ) или сделать облачко слишком узким (σ → 0), KL растёт. Например, при μ = (0.5, −1.0) и log σ² = (0, −0.5) получаем KL ≈ 0.68.

Строго говоря, эта сумма — минус ELBO (evidence lower bound), нижней оценки логарифма правдоподобия данных. Минимизируя L, мы максимизируем оценку того, насколько хорошо модель объясняет данные.

## Трюк репараметризации

Здесь главная техническая проблема. Сеть обучается обратным распространением, а через операцию «взять случайное число из N(μ, σ²)» градиент не проходит: случайная выборка — не дифференцируемая функция от μ и σ.

Решение — вынести случайность наружу:

```
ε ~ N(0, I)          # случайность, от параметров не зависит
z = μ + σ · ε        # детерминированная функция от μ и σ
```

Теперь z — обычное выражение, и производные ∂z/∂μ = 1, ∂z/∂σ = ε считаются без проблем. Распределение z при этом то же самое — N(μ, σ²). Энкодер выдаёт log σ², а не σ: так выход может быть любым числом, а σ = exp(½·log σ²) всегда положительно.

## Генерация и интерполяция

После обучения энкодер для генерации не нужен:

1. Взять z ~ N(0, I).
2. Пропустить через декодер: x̂ = decoder(z).

Интерполяция: закодировать две картинки в μ₁ и μ₂, пройти по отрезку `z = (1 − t)·μ₁ + t·μ₂`, t от 0 до 1, и декодировать каждую точку — получится плавное превращение одной картинки в другую.

## Пример на Python

PyTorch, полный шаг обучения (в среде курса torch не установлен — код по актуальному API):

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class VAE(nn.Module):
    def __init__(self, input_dim=784, hidden_dim=400, latent_dim=20):
        super().__init__()
        self.fc1 = nn.Linear(input_dim, hidden_dim)
        self.fc_mu = nn.Linear(hidden_dim, latent_dim)
        self.fc_logvar = nn.Linear(hidden_dim, latent_dim)
        self.fc3 = nn.Linear(latent_dim, hidden_dim)
        self.fc4 = nn.Linear(hidden_dim, input_dim)

    def encode(self, x):
        h = F.relu(self.fc1(x))
        return self.fc_mu(h), self.fc_logvar(h)

    def reparameterize(self, mu, logvar):
        std = torch.exp(0.5 * logvar)
        return mu + std * torch.randn_like(std)      # z = μ + σ·ε

    def decode(self, z):
        return torch.sigmoid(self.fc4(F.relu(self.fc3(z))))

    def forward(self, x):
        mu, logvar = self.encode(x)
        return self.decode(self.reparameterize(mu, logvar)), mu, logvar

def vae_loss(x_hat, x, mu, logvar, beta=1.0):
    recon = F.binary_cross_entropy(x_hat, x, reduction="sum")
    kl = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp())
    return recon + beta * kl

model = VAE()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
x = torch.rand(64, 784)                              # батч «картинок» в [0, 1]
x_hat, mu, logvar = model(x)
loss = vae_loss(x_hat, x, mu, logvar)
optimizer.zero_grad(); loss.backward(); optimizer.step()

with torch.no_grad():                                # генерация
    samples = model.decode(torch.randn(16, 20))
```

## Подводные камни

- **Размытые картинки.** VAE усредняет по облачку, а MSE/BCE поощряют «средний» ответ. Поэтому образцы VAE мягче, чем у GAN и диффузионных моделей. Это свойство метода, а не ошибка в коде.
- **Posterior collapse.** Если декодер очень мощный (например, авторегрессионный), он может научиться игнорировать z, а KL падает до нуля: все облачка совпадают с N(0, I), код ничего не несёт. Помогают KL-annealing (вес KL плавно растёт от 0 до 1 в начале обучения) и более слабый декодер.
- **Баланс частей потерь.** При `reduction="sum"` реконструкция по 784 пикселям намного больше KL; при `"mean"` — наоборот, KL задавит всё. Следите за масштабом обеих частей.
- **β-VAE.** Вес β > 1 при KL делает латентные оси более «раздельными» (одна ось — наклон, другая — толщина), но ухудшает восстановление. Это ручка, которую подбирают под задачу.
- **Выход декодера.** Сигмоида + BCE — для данных в [0, 1]; для стандартизованных признаков — линейный выход и MSE.

## Итоги

- VAE — генеративный автоэнкодер: энкодер выдаёт параметры распределения (μ, log σ²), а не точку.
- Потери = реконструкция + KL к N(0, I); KL делает латентное пространство гладким и заполненным.
- Трюк репараметризации `z = μ + σ·ε` позволяет обучать сеть обратным распространением сквозь случайность.
- Генерация: z ~ N(0, I) → декодер. Плавная интерполяция между объектами — бесплатный бонус.
- Слабые места — размытые образцы и posterior collapse; сильные — устойчивое обучение и осмысленное латентное пространство.
