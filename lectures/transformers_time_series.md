# Transformers для временных рядов

<!-- время: 16 мин -->

> **О чём лекция.** Что происходит, когда трансформер — архитектуру, покорившую тексты, — применяют к числовым рядам. Почему «один шаг времени = один токен» работает плохо, как это исправляют патчи (PatchTST) и Temporal Fusion Transformer, почему простая линейная модель оказалась серьёзным соперником, и что такое foundation models для рядов.

## Зачем это нужно

Механизм внимания позволяет модели напрямую связать любой момент последовательности с любым другим, без долгой передачи информации через скрытое состояние, как в RNN. Для рядов это звучит заманчиво: прогноз на завтра может «посмотреть» на тот же день год назад. Плюс трансформеры обучаются параллельно и хорошо масштабируются.

На практике история сложнее. Волна моделей 2019–2022 годов (Informer, Autoformer, FEDformer) показывала рекорды на стандартных наборах данных, а в 2022 году выяснилось, что простая линейная модель часто их обыгрывает. Понимание того, почему так вышло и что из этого следует, — главное в теме.

## Интуиция: в чём ряд не похож на текст

В тексте один токен — слово или его часть — несёт много смысла. В ряде одна точка — это одно число, и само по себе оно почти ничего не значит: «23.4» говорит что-то только в контексте соседей. Отсюда трудности:

- **Внимание по отдельным точкам бессмысленно.** Сравнивать одно число с другим через скалярное произведение их векторов — слабый сигнал.
- **Квадратичная стоимость.** Внимание стоит O(L²) по длине L. Окно из 720 часов — уже полмиллиона пар.
- **Порядок важен, а внимание к нему безразлично.** Самовнимание переставочно-инвариантно: порядок модель узнаёт только из позиционного кодирования, а в рядах порядок — это всё.
- **Мало данных.** Тексты — триллионы токенов, а типичный набор данных для прогноза — несколько тысяч точек. Большая модель легко переобучается.

## Как это работает: базовая схема

Простейший трансформер для рядов устроен так:

1. Каждый шаг (или группа шагов) переводится линейным слоем в вектор размерности d_model.
2. Добавляется **позиционное кодирование** (синусоидальное или обучаемое) плюс, часто, календарные признаки: час, день недели, месяц.
3. Несколько слоёв энкодера: многоголовое самовнимание и полносвязная сеть с остаточными связями.
4. Выходной линейный слой выдаёт прогноз на весь горизонт сразу.

Для прогноза обычно используют только энкодер с прямым многовыходным прогнозом — генерировать по одному шагу, как в языковых моделях, медленнее и накапливает ошибки.

## PatchTST: токен — это кусок ряда

Ключевая идея **PatchTST** (2023): нарезать окно истории на **патчи** — отрезки по 16 точек, как картинку в Vision Transformer режут на квадраты. Каждый патч становится одним токеном.

Что это даёт:

- токен несёт **локальную форму** (рост, пик, спад), а не одно число — вниманию есть что сравнивать;
- длина последовательности падает в 16 раз, а стоимость внимания — в сотни раз; можно смотреть дальше в прошлое;
- ещё одна идея PatchTST — **независимость каналов**: каждый ряд многомерного набора обрабатывается отдельно одной и той же моделью; это снижает переобучение.

## Temporal Fusion Transformer

**TFT** (Google, 2019) — архитектура для практических задач, где кроме самого ряда есть разные признаки:

- **статические** — свойства ряда, не меняющиеся во времени (категория товара, регион);
- **известные в будущем** — календарь, запланированные акции;
- **наблюдаемые только в прошлом** — фактические продажи, погода.

TFT сочетает LSTM для локальной обработки, слои отбора признаков и внимание для дальних зависимостей, а на выходе даёт **квантильные прогнозы** — например, 10-й, 50-й и 90-й процентили. Плюс модель интерпретируема: веса отбора показывают, какие признаки важны, а веса внимания — на какие моменты прошлого она смотрит.

## Холодный душ: DLinear

Статья «Are Transformers Effective for Time Series Forecasting?» (Zeng и др., 2022) предложила **DLinear**: разложить окно на тренд (скользящее среднее) и остаток и к каждой части применить **один линейный слой**, который отображает L прошлых точек сразу в H будущих. На стандартных наборах данных эта модель с несколькими тысячами параметров обыграла большинство сложных трансформеров.

Выводы, которые стоит запомнить:

- архитектурная сложность не гарантирует качества; нужны сильные простые бейзлайны;
- важнее всего **длина окна истории** и **прямой многовыходной прогноз**;
- последующие модели (PatchTST, iTransformer) учли эти уроки и снова опередили линейные модели, но с небольшим отрывом.

## Foundation models для рядов

Последнее направление — модели, **предобученные на огромном количестве разных рядов** (продажи, энергетика, трафик, погода), которые дают прогноз для нового ряда без обучения — в режиме zero-shot. Примеры: TimesFM (Google), Chronos (Amazon, ряд переводится в «токены» квантованием значений и обрабатывается языковой моделью T5), Moirai, Lag-Llama.

Их сильная сторона — короткие и новые ряды, где своей модели обучить не на чем, и быстрое получение разумного бейзлайна. Но их всё равно нужно проверять на ваших данных: доменная модель или бустинг на хороших признаках нередко точнее.

## Пример на Python

Посмотрим на две ключевые идеи без нейросетей: нарезку окна на патчи и «линейную модель», которая одним шагом отображает 96 прошлых точек в 24 будущие — это суть DLinear без декомпозиции:

```python
import numpy as np
from sklearn.linear_model import Ridge

rng = np.random.default_rng(0)
t = np.arange(1000)
y = np.sin(2 * np.pi * t / 24) + 0.002 * t + rng.normal(scale=0.2, size=1000)   # суточный цикл + тренд
window, horizon = 96, 24

X = np.array([y[i:i + window] for i in range(len(y) - window - horizon)])
Y = np.array([y[i + window:i + window + horizon] for i in range(len(y) - window - horizon)])
patches = X[0].reshape(-1, 16)                # PatchTST: окно 96 → 6 токенов по 16 точек
print("патчи:", patches.shape)                # (6, 16)

split = 700                                   # первые 700 окон — train, остальные — test
lin = Ridge(alpha=1.0).fit(X[:split], Y[:split])
mae_lin = np.mean(np.abs(lin.predict(X[split:]) - Y[split:]))
mae_season = np.mean(np.abs(X[split:, -24:] - Y[split:]))   # сезонный наивный: «как сутки назад»
print(f"MAE линейная: {mae_lin:.3f}, MAE сезонный наивный: {mae_season:.3f}")   # 0.140 и 0.200
```

Именно такую линейную модель и сезонный наивный прогноз должен обыграть трансформер, чтобы оправдать свою сложность. Готовые реализации PatchTST, TFT и других моделей есть в библиотеках `neuralforecast` и `darts`, а также в Hugging Face Transformers (`PatchTSTForPrediction`).

## Подводные камни

- **Нет простых бейзлайнов.** Сравнивайте с сезонным наивным прогнозом, линейной моделью по окну и бустингом на лагах.
- **Короткое окно.** Трансформер с окном в 48 точек не увидит недельную сезонность часовых данных. Длина окна — один из самых важных гиперпараметров.
- **Утечка нормализации.** Нормализуйте по train или по каждому окну отдельно (RevIN — обратимая нормализация окна — стандартный приём).
- **Переобучение на маленьких данных.** Трансформер с миллионами параметров на ряде из 2000 точек почти наверняка переобучится. Используйте маленькие модели, dropout, раннюю остановку — или предобученную модель.
- **Красивые карты внимания.** Веса внимания не всегда объясняют, почему модель дала такой прогноз; не делайте по ним сильных выводов.

## Итоги

- Трансформеры дают прямые связи между далёкими моментами, но точка ряда — слабый токен, а внимание дорого и безразлично к порядку.
- PatchTST превращает отрезки ряда в токены и обрабатывает каналы независимо; TFT работает со статическими, будущими и прошлыми признаками и выдаёт квантили.
- DLinear показал, что простая линейная модель — обязательный бейзлайн; важны длина окна и прямой прогноз горизонта.
- Foundation models (TimesFM, Chronos) дают прогноз без обучения, но требуют проверки на ваших данных.
