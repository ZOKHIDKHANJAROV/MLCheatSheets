# Multi-head Attention

<!-- время: 13 мин -->

> **О чём лекция.** Почему трансформер использует не одно внимание, а 8, 12 или 96 параллельных «голов»: как вектор делится между головами, как результаты склеиваются обратно и почему это почти не стоит лишних параметров.

## Зачем это нужно

Одна операция self-attention даёт каждому токену один набор весов: одно распределение внимания по остальным токенам. Но связи между словами бывают разной природы. В предложении «Кошка, которую я вчера видел, спала на тёплом окне» слово «спала» связано:

- с «кошка» — синтаксически, это подлежащее;
- с «вчера» — по времени;
- с «окне» — по месту.

Если голова одна, ей приходится усреднять все эти связи в одном распределении весов, и они смешиваются. **Multi-head attention** (многоголовое внимание) запускает несколько независимых вниманий параллельно. Каждая голова может специализироваться на своём типе связей, а потом их результаты объединяются.

## Интуиция: комиссия экспертов

Представьте, что текст читает не один эксперт, а комиссия из восьми. Каждому выдают свои «очки» — свою проекцию данных: один видит грамматику, другой — соседние слова, третий — смысловые связи. Каждый независимо решает, на какие слова смотреть, и пишет короткое заключение. Затем секретарь склеивает заключения и сводит их в общий отчёт.

- **Очки** — свои матрицы `W_Q^i`, `W_K^i`, `W_V^i` у каждой головы.
- **Короткое заключение** — выход головы размера d_k (меньше, чем d_model).
- **Секретарь** — выходная матрица `W_O`, которая смешивает склеенные результаты.

Исследования внутреннего устройства обученных моделей показывают, что головы действительно специализируются: одни следят за предыдущим токеном, другие — за синтаксическими связями, третьи — за повтором слов. Но многие головы оказываются избыточными, и их можно удалить почти без потери качества.

## Как это работает

```
head_i = Attention(Q · W_Q^i, K · W_K^i, V · W_V^i)
MultiHead(Q, K, V) = Concat(head_1, …, head_h) · W_O
```

Размерности подобраны так, чтобы общий объём вычислений остался таким же, как у одной большой головы:

```
d_k = d_model / h
```

Например, в исходном Transformer `d_model = 512`, `h = 8`, значит каждая голова работает в пространстве размерности 64. Восемь голов по 64 после склейки снова дают 512.

На практике не создают отдельные маленькие матрицы для каждой головы. Берут одну большую матрицу `W_Q` размера d_model × d_model, умножают, а результат **разрезают** на h кусков по d_k: `(n, d_model) → (h, n, d_k)`. Затем внимание считается для всех голов одним батчевым умножением, головы склеиваются обратно и проходят через `W_O`.

## Сколько это стоит

Неочевидный факт: **число параметров не зависит от числа голов**. В любом случае есть четыре матрицы d_model × d_model (`W_Q`, `W_K`, `W_V`, `W_O`), то есть `4 · d_model²` весов (плюс смещения). При d_model = 512 это около 1.05 миллиона параметров — и для 1 головы, и для 8.

Головы — это способ *разделить* то же пространство на независимые подпространства, а не добавить новые веса. Вычислительная стоимость тоже почти та же: меняется только форма матриц.

Типичные конфигурации:

| модель | d_model | головы | d_k |
|---|---|---|---|
| Transformer base (2017) | 512 | 8 | 64 |
| BERT-base | 768 | 12 | 64 |
| BERT-large | 1024 | 16 | 64 |
| GPT-2 small | 768 | 12 | 64 |

Заметно, что размер головы часто держат около 64, а число голов растёт вместе с моделью.

## Multi-query и grouped-query attention

При генерации текста модель хранит ключи и значения всех прошлых токенов (**KV-кэш**), чтобы не пересчитывать их. У каждой головы свои K и V, поэтому кэш растёт пропорционально числу голов и для длинных контекстов съедает гигабайты памяти.

- **Multi-query attention (MQA)**: у всех голов свои запросы, но один общий набор K и V. Кэш меньше в h раз, генерация быстрее, качество немного падает.
- **Grouped-query attention (GQA)**: компромисс — головы разбиты на группы, внутри группы K и V общие. Используется во многих современных LLM.

## Пример на Python

Multi-head attention на NumPy: разрезаем проекции на головы, считаем внимание для всех голов разом и склеиваем:

```python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def multi_head_attention(X, W_Q, W_K, W_V, W_O, h):
    n, d_model = X.shape
    d_k = d_model // h
    split = lambda M: M.reshape(n, h, d_k).transpose(1, 0, 2)   # (n, d_model) → (h, n, d_k)
    Q, K, V = split(X @ W_Q), split(X @ W_K), split(X @ W_V)
    A = softmax(Q @ K.transpose(0, 2, 1) / np.sqrt(d_k))         # (h, n, n): у каждой головы свои веса
    heads = A @ V                                                # (h, n, d_k)
    concat = heads.transpose(1, 0, 2).reshape(n, d_model)        # склеиваем головы обратно
    return concat @ W_O, A

rng = np.random.default_rng(0)
n, d_model, h = 5, 16, 4
X = rng.normal(size=(n, d_model))
W_Q, W_K, W_V, W_O = (rng.normal(size=(d_model, d_model)) / np.sqrt(d_model) for _ in range(4))

out, A = multi_head_attention(X, W_Q, W_K, W_V, W_O, h)
print(out.shape, A.shape)        # (5, 16) (4, 5, 5)
print(A[:, 0].round(2))          # как токен 0 распределяет внимание — у каждой головы по-своему
# [[0.16 0.22 0.25 0.19 0.17]
#  [0.18 0.2  0.17 0.4  0.05]
#  [0.2  0.14 0.08 0.08 0.5 ]
#  [0.34 0.12 0.4  0.13 0.  ]]

# Параметры не зависят от числа голов: 4 матрицы d_model × d_model
print(4 * d_model * d_model, 4 * 512 * 512)   # 1024 1048576
```

Один и тот же токен в разных головах смотрит на разные позиции: вторая голова — на токен 3, третья — на токен 4.

В PyTorch есть готовый слой:

```python
import torch
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
x = torch.randn(2, 10, 512)                         # (batch, seq_len, d_model)
out, weights = mha(x, x, x)                         # self-attention: Q = K = V = x
print(out.shape, weights.shape)                     # (2, 10, 512) (2, 10, 10) — веса усреднены по головам
```

## Подводные камни

- **d_model должно делиться на h.** Иначе вектор не разрезать на равные головы; слой упадёт с ошибкой.
- **Перепутанный reshape.** Разрезать нужно последнюю ось (`(n, d_model) → (n, h, d_k)`), а потом переставить оси. Если сразу сделать `reshape(h, n, d_k)`, головы получат перемешанные куски разных токенов — ошибки не будет, но модель будет учиться хуже.
- **Больше голов ≠ лучше.** При фиксированном d_model с ростом h каждая голова становится уже; слишком маленький d_k (8–16) ухудшает качество.
- **`average_attn_weights`.** `nn.MultiheadAttention` по умолчанию возвращает веса, усреднённые по головам; для анализа отдельных голов передайте `average_attn_weights=False`.
- **Маски.** Каузальная и padding-маски применяются ко всем головам одинаково.

## Итоги

- Multi-head attention — несколько независимых вниманий параллельно, каждое в своём подпространстве размерности `d_k = d_model / h`.
- Выход: склейка голов, умноженная на `W_O`.
- Число параметров (`4 · d_model²`) и объём вычислений почти не зависят от числа голов.
- Разные головы учатся разным типам связей: синтаксису, соседству, повторам.
- MQA и GQA делят ключи и значения между головами, чтобы уменьшить KV-кэш при генерации.
