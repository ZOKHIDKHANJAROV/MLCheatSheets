# Автоэнкодеры

<!-- время: 15 мин -->

> **О чём лекция.** Как нейросеть учится сжимать данные без всякой разметки: сеть заставляют восстановить свой же вход через узкое «горлышко», и по пути она находит самые важные закономерности. Разберём устройство, разновидности и где автоэнкодеры полезны на практике — от сжатия признаков до поиска аномалий.

## Зачем это нужно

Большинство данных избыточны. Картинка 28×28 — это 784 числа, но рукописная цифра описывается гораздо меньшим числом «настоящих» факторов: какая цифра, наклон, толщина линии, размер. Если найти такое компактное описание, с ним проще работать: сравнивать объекты, искать похожие, отбрасывать шум, замечать странное.

Метод главных компонент (PCA) делает это линейно. Автоэнкодер — нелинейное обобщение той же идеи, и при этом ему не нужны метки: учителем служат сами данные. Отсюда основные применения:

- **сжатие и снижение размерности** — компактные признаки для других моделей или визуализации;
- **удаление шума** — denoising-автоэнкодер учится восстанавливать чистый сигнал из испорченного;
- **поиск аномалий** — то, что сеть не умеет хорошо восстанавливать, вероятно, не похоже на обучающие данные;
- **предобучение и фундамент для генеративных моделей** — вариационный автоэнкодер (VAE) и латентные диффузионные модели вырастают отсюда.

## Интуиция: пересказ своими словами

Представьте, что вам нужно передать другу длинный текст через узкий канал — разрешено отправить только 30 слов. Вы вынуждены выбросить детали и оставить суть. Друг по этим 30 словам пытается восстановить исходный текст. Если пересказ удачный, восстановление получится близким к оригиналу.

Автоэнкодер — это вы и друг, обученные вместе:

- **энкодер** превращает вход в короткий код (пересказ);
- **узкое горлышко (bottleneck)** — ограничение на длину кода;
- **декодер** восстанавливает вход по коду;
- ошибка восстановления говорит обоим, как улучшить пересказ.

Ключевое слово — *ограничение*. Если код такой же длины, как вход, сеть может научиться тупо копировать, и ничего полезного не выучит.

## Как это работает

Архитектура:

```
x → Encoder → z (латентное представление) → Decoder → x̂
```

- `x` — вход, например вектор из 784 пикселей;
- `z = f_enc(x)` — код в **латентном пространстве**, например 32 числа;
- `x̂ = f_dec(z)` — восстановленный вход.

Обучение — обычный градиентный спуск с функцией потерь «насколько x̂ отличается от x»:

```
L(x, x̂) = ‖x − x̂‖²                       # MSE — для вещественных данных
L(x, x̂) = −Σ [x·log x̂ + (1−x)·log(1−x̂)]  # BCE — для пикселей в [0, 1]
```

Энкодер и декодер обычно симметричны: например, `784 → 128 → 32` и `32 → 128 → 784`. Для картинок вместо полносвязных слоёв берут свёртки в энкодере и транспонированные свёртки (или upsampling) в декодере. На выходе для пикселей в [0, 1] ставят сигмоиду, для стандартизованных признаков — линейную активацию.

Важное наблюдение: автоэнкодер с одним линейным скрытым слоем и MSE находит то же подпространство, что и PCA. Вся сила — в нелинейностях: глубокий автоэнкодер может «развернуть» изогнутую поверхность, на которой лежат данные, а PCA — только плоскость.

## Разновидности

| вид | что меняется | зачем |
|---|---|---|
| Undercomplete (обычный) | код короче входа | сжатие, снижение размерности |
| Denoising | на вход подают зашумлённый x, восстанавливают чистый | устойчивые признаки, удаление шума |
| Sparse | штраф за активность нейронов кода (L1 или KL) | код может быть длинным, но мало «включённых» нейронов |
| Convolutional | свёрточные энкодер и декодер | изображения |
| Contractive | штраф за чувствительность кода к малым изменениям входа | гладкое, устойчивое представление |
| Variational (VAE) | энкодер выдаёт распределение, а не точку | генерация новых объектов |

Denoising-вариант заслуживает отдельного слова: если на входе испорчено 20–50% пикселей, сеть уже не может просто копировать — ей приходится понять структуру данных, чтобы дорисовать пропущенное. Это одна из самых простых и рабочих идей самообучения (self-supervised learning).

## Поиск аномалий

Автоэнкодер, обученный только на «нормальных» данных, хорошо восстанавливает похожие объекты и плохо — непохожие. Отсюда схема:

1. Обучить автоэнкодер на нормальных примерах (транзакции без мошенничества, исправные датчики).
2. Посчитать ошибку восстановления на обучающих данных.
3. Выбрать порог, например 99-й перцентиль этой ошибки.
4. В работе: всё, что восстанавливается хуже порога, — кандидат в аномалии.

Метки аномалий для обучения не нужны, а это ценно: мошенничество и поломки редки, размечать их дорого.

## Пример на Python

Полноценные автоэнкодеры пишут на PyTorch или Keras, но идею можно показать и в scikit-learn: `MLPRegressor`, который учится предсказывать сам вход, с узким слоем посередине.

```python
import numpy as np
from sklearn.neural_network import MLPRegressor
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
z = rng.normal(size=(1000, 2))                           # 2 скрытых фактора
W = rng.normal(size=(2, 10))
X = np.tanh(z @ W) + 0.05 * rng.normal(size=(1000, 10))  # 10 признаков, но свобода — 2
X = StandardScaler().fit_transform(X)

# Горлышко из 2 нейронов: 10 → 16 → 2 → 16 → 10
ae = MLPRegressor(hidden_layer_sizes=(16, 2, 16), activation="tanh",
                  max_iter=3000, random_state=0)
ae.fit(X, X)                                             # цель = сам вход
err = ((X - ae.predict(X)) ** 2).mean(axis=1)
print("средняя MSE:", err.mean().round(3))               # 0.048

X_odd = rng.normal(size=(5, 10)) * 2                     # «чужие» объекты
err_odd = ((X_odd - ae.predict(X_odd)) ** 2).mean(axis=1)
print("MSE на аномалиях:", err_odd.mean().round(3))      # 2.291
print("порог:", np.percentile(err, 99).round(3))         # 0.199
```

Десять признаков сжались в два числа почти без потерь, потому что данные действительно двумерные. А объекты из другого распределения восстанавливаются в десятки раз хуже — их легко отсечь порогом.

На PyTorch то же самое выглядит так (схема, без цикла обучения):

```python
import torch.nn as nn

class Autoencoder(nn.Module):
    def __init__(self, input_dim=784, encoding_dim=32):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(input_dim, 128), nn.ReLU(),
                                     nn.Linear(128, encoding_dim))
        self.decoder = nn.Sequential(nn.Linear(encoding_dim, 128), nn.ReLU(),
                                     nn.Linear(128, input_dim), nn.Sigmoid())

    def forward(self, x):
        return self.decoder(self.encoder(x))

```

## Подводные камни

- **Слишком широкое горлышко или слишком мощная сеть.** Автоэнкодер научится почти тождественному отображению и ничего не обобщит. Признак — идеальное восстановление даже для мусора. Сужайте код, добавляйте шум на вход или регуляризацию.
- **Обычный автоэнкодер — плохой генератор.** Латентное пространство «дырявое»: если взять случайную точку z и прогнать через декодер, обычно выходит каша. Для генерации нужен VAE.
- **Масштаб признаков.** MSE суммирует ошибки по всем признакам, и признак с большим разбросом будет доминировать. Стандартизуйте данные.
- **Аномалии в обучающих данных.** Если «плохие» объекты попали в обучение, сеть научится восстанавливать и их. Чистите выборку или используйте устойчивые пороги.
- **Ошибка восстановления — не вероятность.** Порог приходится подбирать по валидации, и он зависит от данных.

## Итоги

- Автоэнкодер — энкодер, узкое горлышко и декодер; его учат восстанавливать собственный вход, метки не нужны.
- Главное — ограничение: короткий код, шум на входе или разреженность. Без него сеть просто копирует.
- Линейный автоэнкодер эквивалентен PCA; нелинейный находит изогнутые структуры.
- Применения: снижение размерности, удаление шума, поиск аномалий по ошибке восстановления, предобучение.
- Для генерации новых объектов нужен следующий шаг — вариационный автоэнкодер.
