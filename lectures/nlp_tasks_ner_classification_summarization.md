# Задачи NLP: NER, классификация, суммаризация

<!-- время: 15 мин -->

> **О чём лекция.** Три самые частые прикладные задачи обработки текста: отнести текст к классу, найти в нём имена, места и организации, сжать длинный текст до краткого пересказа. Как каждую из них сформулировать для модели, чем решать и — самое коварное — как честно измерить качество.

## Зачем это нужно

Большая часть данных в компаниях — текст: письма, отзывы, договоры, обращения в поддержку, новости. Почти все прикладные задачи над ними сводятся к трём типам:

- **Классификация текста** — один ответ на весь текст: тональность отзыва, тема обращения, спам или нет.
- **Распознавание именованных сущностей (NER, Named Entity Recognition)** — ответ для каждого слова: какие фрагменты текста являются именем человека, организацией, местом, датой, суммой.
- **Суммаризация** — на выходе новый текст: краткое содержание статьи, протокол встречи, выжимка из договора.

Эти задачи отличаются формой ответа, а значит, и архитектурой модели, и метрикой. Если понять эту разницу, большинство NLP-задач на работе раскладывается по полочкам: «маршрутизация писем» — классификация, «вытащить реквизиты из счёта» — NER, «пересказ звонка» — суммаризация.

## Интуиция: какой формы ответ

Удобно думать о задаче по тому, что модель выдаёт:

| задача | вход | выход | пример |
|---|---|---|---|
| классификация | текст | одна метка (или несколько) | «отзыв негативный» |
| NER | текст | метка для каждого токена | «Анна Петрова» → персона |
| суммаризация | текст | другой текст | 3 предложения вместо 3 страниц |

Классификация — самая простая: всё содержимое текста нужно сжать в один вектор и по нему выбрать класс. NER сложнее: решение принимается для каждого слова, но с учётом соседей — «Москва» может быть и городом, и названием гостиницы. Суммаризация — генерация: модель пишет новый текст слово за словом, и правильных ответов много.

## Как это работает: классификация

Классический рецепт, который до сих пор служит сильным бейзлайном: превратить текст в вектор признаков **TF-IDF** (частоты слов, взвешенные по редкости) и обучить логистическую регрессию. Это обучается за секунды и хорошо работает, когда классы различаются словами.

Современный рецепт — **дообучение трансформера** (BERT, RuBERT и подобных): токены проходят через предобученную модель, вектор специального токена `[CLS]` (или усреднение по токенам) подаётся в линейный слой-классификатор. Такая модель понимает контекст и синонимы, поэтому выигрывает там, где важен смысл, а не набор слов.

Если размеченных примеров очень мало, есть ещё два пути:

- **эмбеддинги + простой классификатор**: получить векторы предложений готовой моделью и обучить на них логистическую регрессию — хватает сотен примеров;
- **zero-shot и few-shot через LLM**: описать классы в промпте и дать несколько примеров; это быстро запустить, но дороже в эксплуатации и сложнее контролировать.

## Как это работает: NER как разметка токенов

NER сводят к классификации **каждого токена**. Чтобы сущность из нескольких слов не развалилась на части, используют схему **BIO**:

- `B-ТИП` — первое слово сущности (Begin);
- `I-ТИП` — продолжение той же сущности (Inside);
- `O` — слово вне сущностей (Outside).

```
Анна    Петрова  работает  в  Яндексе  в  Москве
B-PER   I-PER    O         O  B-ORG    O  B-LOC
```

Модели для NER прошли путь от **CRF** (условные случайные поля над вручную придуманными признаками слова) через **BiLSTM-CRF** к **трансформерам с головой для классификации токенов**. CRF-слой полезен тем, что учитывает допустимые переходы: после `O` не может идти `I-PER`.

Тонкость с трансформерами: они режут слова на подтокены («Петрова» → «Пет», «##рова»). Метку обычно ставят только на первый подтокен слова, а остальным присваивают `-100` — так в PyTorch и Hugging Face помечают позиции, которые не участвуют в функции потерь.

## Как это работает: суммаризация

Есть два подхода:

- **Экстрактивная** суммаризация выбирает из текста самые важные предложения и склеивает их. Простейший вариант — оценить предложения по TF-IDF или по похожести на весь текст (алгоритм TextRank). Плюс: модель не может «придумать» факт, ведь все предложения взяты из оригинала. Минус: текст получается рваным.
- **Абстрактивная** суммаризация генерирует новый текст. Для этого используют модели «кодировщик–декодировщик» (T5, BART, mBART) или большие языковые модели. Пересказ получается гладким, но появляется риск **галлюцинаций** — правдоподобных фактов, которых не было в источнике.

Ещё одно практическое ограничение — длина контекста: если документ не помещается в модель, его режут на части, суммаризуют каждую и затем суммаризуют суммаризации.

## Метрики: где чаще всего ошибаются

**Классификация.** Accuracy подходит только при сбалансированных классах. Если спама 2%, модель «никогда не спам» получит 98% accuracy. Смотрите precision, recall, F1 по классам и macro-F1 (среднее F1 по классам, где редкие классы весят столько же, сколько частые).

**NER.** Качество считают **по сущностям, а не по токенам**. Сущность засчитывается, только если совпали и границы, и тип. Причина простая: большинство токенов имеют метку `O`, и точность по токенам почти всегда высокая, даже если модель пропускает половину имён. А «Анна» вместо «Анна Петрова» — это ошибка для пользователя, хотя по токенам она выглядит как маленькая неточность. Стандартная библиотека для такого подсчёта — `seqeval`.

**Суммаризация.** Автоматическая метрика **ROUGE** считает пересечение слов и n-грамм с эталонным пересказом. Она дешёвая, но слепая к смыслу: правильный пересказ другими словами получит низкий балл, а пересказ с перепутанными фактами, но теми же словами — высокий. Поэтому ROUGE дополняют проверкой фактической согласованности (не противоречит ли пересказ источнику), оценкой с помощью LLM и выборочной ручной проверкой.

## Пример на Python

Посчитаем метрики NER по сущностям и сравним их с точностью по токенам:

```python
def spans(tags):
    """BIO-теги → множество сущностей (тип, начало, конец)."""
    result, start, kind = set(), None, None
    for i, tag in enumerate(tags + ["O"]):
        if start is not None and not tag.startswith("I-" + kind):
            result.add((kind, start, i))
            start = None
        if tag.startswith("B-") or (tag.startswith("I-") and start is None):
            start, kind = i, tag[2:]
    return result

tokens = ["Анна", "Петрова", "работает", "в", "Яндексе", "в", "Москве"]
true = ["B-PER", "I-PER", "O", "O", "B-ORG", "O", "B-LOC"]
pred = ["B-PER", "O", "O", "O", "B-ORG", "O", "B-LOC"]   # модель отрезала фамилию

t, p = spans(true), spans(pred)
tp = len(t & p)
precision, recall = tp / len(p), tp / len(t)
f1 = 2 * precision * recall / (precision + recall)
token_acc = sum(a == b for a, b in zip(true, pred)) / len(true)
print(f"точность по токенам: {token_acc:.2f}")       # 0.86
print(f"P={precision:.2f} R={recall:.2f} F1={f1:.2f}")  # P=0.67 R=0.67 F1=0.67
```

Модель ошиблась в одном токене из семи, но одна из трёх сущностей найдена неправильно — и F1 по сущностям это честно показывает.

Бейзлайн для классификации — три строки на scikit-learn:

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

texts = ["доставка быстрая, всё отлично", "отличный товар, рекомендую", "курьер опоздал, товар сломан",
         "ужасное качество, верну", "всё пришло вовремя, спасибо", "сломалось через день, ужас"]
labels = [1, 1, 0, 0, 1, 0]          # 1 — позитивный отзыв

model = make_pipeline(TfidfVectorizer(), LogisticRegression())
model.fit(texts, labels)
print(model.predict(["товар отличный", "курьер сломал коробку"]))   # [1 0]
```

## Подводные камни

- **Нет бейзлайна.** Прежде чем дообучать трансформер, обучите TF-IDF + логистическую регрессию. Иногда разница — пара процентов при стократной разнице в стоимости.
- **Утечка через дубликаты.** Одинаковые или почти одинаковые тексты (шаблонные письма, повторные отзывы) попадают и в train, и в test — качество завышено. Удаляйте дубликаты до разбиения.
- **Метрика NER по токенам.** Выглядит прекрасно и ничего не говорит о деле. Считайте F1 по сущностям.
- **Подтокены.** При дообучении трансформера на NER легко сдвинуть метки относительно токенов. Проверьте выравнивание глазами на нескольких примерах.
- **Галлюцинации в суммаризации.** Высокий ROUGE не гарантирует, что в пересказе нет выдуманных цифр и имён. Проверяйте факты, особенно в юридических и медицинских текстах.
- **Сдвиг домена.** Модель, обученная на новостях, хуже работает на чатах и медицинских записях: другая лексика, опечатки, сокращения.

## Итоги

- Классификация — одна метка на текст, NER — метка на каждый токен (схема BIO), суммаризация — генерация нового текста.
- Сильный бейзлайн для классификации — TF-IDF + логистическая регрессия; лучшее качество обычно даёт дообученный трансформер; при малом числе меток — эмбеддинги или few-shot с LLM.
- NER оценивают по сущностям: совпасть должны границы и тип.
- Экстрактивная суммаризация безопасна, но рвана; абстрактивная гладкая, но может галлюцинировать. ROUGE нужно дополнять проверкой фактов.
