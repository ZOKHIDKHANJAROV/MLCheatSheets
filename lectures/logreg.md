# Логистическая регрессия

<!-- время: 15 мин -->

> **О чём лекция.** Как из линейной модели получить вероятность класса, почему её обучают на log loss, а не на MSE, как читать веса через отношение шансов и почему порог 0.5 — лишь значение по умолчанию.

## Зачем это нужно

Многие практические задачи — это вопросы «да или нет»: уйдёт ли клиент, мошенническая ли транзакция, болен ли пациент, спам ли письмо. Нужна модель, которая для каждого объекта выдаёт **вероятность** положительного класса: с ней можно и принять решение, и оценить риск.

Логистическая регрессия — самый простой и самый популярный ответ. Она быстро обучается, хорошо работает на больших разреженных данных (например, на текстах), её веса легко интерпретировать. На практике это стандартный **baseline**: прежде чем строить бустинг или нейросеть, проверяют, что даёт логистическая регрессия.

Несмотря на слово «регрессия» в названии, это модель **классификации**.

## Интуиция: линейная оценка, сжатая в вероятность

Линейная модель считает взвешенную сумму признаков: `z = w₁x₁ + … + wₙxₙ + b`. Это число может быть любым — от минус до плюс бесконечности, а вероятность должна лежать между 0 и 1. Нужна функция, которая аккуратно «сжимает» любое число в этот отрезок. Это **сигмоида**:

```
σ(z) = 1 / (1 + e⁻ᶻ)

z = −4 → 0.018      z = 0 → 0.5      z = 4 → 0.982
```

Можно думать о z как о «счёте в пользу класса 1»: большой положительный счёт — почти уверенное «да», большой отрицательный — уверенное «нет», около нуля — модель сомневается.

У z есть точный смысл: это **логарифм шансов** (log-odds). Шансы — это `p / (1 − p)`: при p = 0.8 шансы равны 4 к 1. Логистическая регрессия предполагает, что log-шансы линейно зависят от признаков.

## Как это работает

Прогноз модели:

```
P(y = 1 | x) = σ(w·x + b)
```

Граница между классами — это точки, где P = 0.5, то есть `w·x + b = 0`. Это уравнение гиперплоскости: на плоскости — прямая линия. Поэтому логистическая регрессия — **линейный классификатор**: если классы разделяются только кривой, нужны новые признаки (полиномиальные, взаимодействия) или другая модель.

**Функция потерь — log loss** (бинарная кросс-энтропия):

```
L = −(1/n) · Σ [ yᵢ · log(pᵢ) + (1 − yᵢ) · log(1 − pᵢ) ]
```

Если объект класса 1 получил вероятность 0.99, штраф почти нулевой (−log 0.99 ≈ 0.01). Если он получил 0.01, штраф огромный (−log 0.01 ≈ 4.6). Log loss особенно жёстко наказывает **уверенные ошибки**.

Почему не MSE? С сигмоидой внутри MSE становится невыпуклой функцией с плато, и градиент на уверенно неверных объектах почти исчезает. Log loss выпуклый: у него один минимум, и градиентный спуск (или методы вроде L-BFGS, solver `lbfgs` в sklearn) надёжно его находит. Формулы для весов в явном виде нет, поэтому обучение всегда итеративное.

**Регуляризация** в sklearn включена по умолчанию (L2). Её силу задаёт параметр `C` — это величина, **обратная** силе: меньше C — сильнее регуляризация, веса скромнее.

## Как читать веса

Вес wⱼ показывает, на сколько меняется log-шансов при увеличении признака xⱼ на единицу (при прочих равных). Удобнее перейти к **отношению шансов**: `e^wⱼ`.

- `e^w = 2` — рост признака на единицу удваивает шансы класса 1;
- `e^w = 0.5` — уменьшает шансы вдвое;
- `e^w ≈ 1` — признак почти не влияет.

Если признаки стандартизованы, «единица» — это одно стандартное отклонение, и веса разных признаков можно сравнивать между собой.

## Многоклассовый случай

Для K классов есть два подхода. **One-vs-Rest** обучает K отдельных бинарных моделей «этот класс против всех остальных». **Multinomial** (softmax-регрессия) обучает одну модель с K наборами весов и превращает K счётов в распределение вероятностей через softmax. В современных версиях sklearn для многоклассовой задачи по умолчанию используется multinomial.

## Пример на Python

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, roc_auc_score, log_loss
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(n_samples=1000, n_features=5, n_informative=3, n_redundant=0,
                           class_sep=1.5, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=0)

model = make_pipeline(StandardScaler(), LogisticRegression(C=1.0)).fit(X_tr, y_tr)
proba = model.predict_proba(X_te)[:, 1]          # вероятность класса 1

print("accuracy:", round(accuracy_score(y_te, model.predict(X_te)), 3))   # 0.756
print("ROC-AUC: ", round(roc_auc_score(y_te, proba), 3))                  # 0.879
print("log loss:", round(log_loss(y_te, proba), 3))                       # 0.434

w = model[-1].coef_[0]
print("веса:", w.round(2))                       # [ 1.04 -1.06  2.46  0.18  0.07]
print("отношение шансов e^w:", np.exp(w).round(2))   # [ 2.83  0.35 11.69  1.2   1.07]
```

Три признака информативны, два — шум. Это видно по весам: у последних двух они близки к нулю, а отношение шансов — к единице. Третий признак самый сильный: рост на одно стандартное отклонение увеличивает шансы класса 1 почти в 12 раз.

## Подводные камни

- **Масштабирование.** Без него регуляризация действует на признаки неравномерно, а оптимизатор сходится медленно и выдаёт `ConvergenceWarning`. Ставьте `StandardScaler` в пайплайн перед моделью.
- **Порог 0.5 — не закон.** `predict` относит объект к классу 1 при p ≥ 0.5, но если пропуск больного стоит дороже ложной тревоги, порог нужно снижать. Порог выбирают по валидации исходя из цены ошибок, а для этого используют `predict_proba`, а не `predict`.
- **Дисбаланс классов.** При 1% положительных модель может почти всегда выдавать маленькие вероятности. Помогают `class_weight="balanced"`, подбор порога и правильные метрики (PR-AUC, F1), а не accuracy.
- **Нелинейные зависимости** логистическая регрессия сама не уловит. Если связь «U-образная» (риск высок и у очень молодых, и у очень пожилых), добавьте признаки вроде x² или разбейте признак на интервалы.
- **Мультиколлинеарность** делает веса неустойчивыми и их интерпретацию ненадёжной, хотя качество прогноза может не страдать. Регуляризация смягчает проблему.
- **Идеальная разделимость.** Если классы разделяются без ошибок, без регуляризации веса растут бесконечно. L2 по умолчанию этого не допускает.

## Итоги

- Логистическая регрессия — линейная модель классификации: `P(y=1|x) = σ(w·x + b)`, граница между классами — гиперплоскость.
- Обучается минимизацией log loss — выпуклой функции, которая сильно штрафует уверенные ошибки.
- Вес — изменение log-шансов; `e^w` — во сколько раз меняются шансы при росте признака на единицу.
- Масштабируйте признаки, подбирайте `C` и порог под задачу; это сильный и интерпретируемый baseline.
