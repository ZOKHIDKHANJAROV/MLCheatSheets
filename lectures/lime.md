# LIME

<!-- время: 15 мин -->

> **О чём лекция.** Как объяснить одно предсказание любой модели-«чёрного ящика»: насыпать вокруг объекта похожих точек, посмотреть, что на них отвечает модель, и подогнать простую линейную модель, которая ведёт себя так же *в этой окрестности*. Разберём алгоритм, его настройки и почему объяснения LIME бывают нестабильными.

## Зачем это нужно

Сложные модели — бустинги, нейросети, ансамбли — хорошо предсказывают, но их решения трудно объяснить. Глобально модель может быть очень нелинейной. Однако если посмотреть на маленький участок вокруг конкретного объекта, поведение модели часто почти линейно: «здесь рост дохода немного снижает риск, а рост числа просрочек — сильно повышает».

LIME (Local Interpretable Model-agnostic Explanations, Рибейро и соавторы, 2016) использует именно это. Метод:

- **локальный** — объясняет одно предсказание, а не всю модель;
- **model-agnostic** — нужен только доступ к `predict` / `predict_proba`, внутренности модели не важны;
- **интерпретируемый** — результат — несколько весов простой модели, понятных человеку.

Он работает с таблицами, текстами (какие слова повлияли на класс) и изображениями (какие участки картинки).

## Интуиция: Земля плоская — если смотреть под ноги

Земля круглая, но в пределах двора она практически плоская, и для планировки участка хватает плоской карты. Так же и с моделью: сложную поверхность решений можно приблизить плоскостью — но только рядом с интересующей точкой. Чем дальше от неё, тем хуже приближение, поэтому близкие точки при подгонке важнее далёких.

## Как это работает

Алгоритм для объекта x₀:

1. **Сгенерировать возмущения.** Создать много точек z вокруг x₀: для таблиц — добавить шум к признакам (в масштабе их стандартного отклонения), для текста — случайно выкинуть слова, для картинок — закрасить часть суперпикселей.
2. **Спросить чёрный ящик.** Получить предсказания модели f(z) для каждой точки.
3. **Взвесить по близости.** Точкам ближе к x₀ — больший вес. Обычно экспоненциальное ядро:

```
π(z) = exp(−d(x₀, z)² / σ²)
```

   В библиотеке lime ширина ядра по умолчанию `σ = 0.75 · √(число признаков)` для стандартизованных расстояний.
4. **Обучить простую модель.** Взвешенная линейная регрессия (обычно Ridge) g предсказывает f(z) по z, с весами π(z). Часто ограничивают число признаков K, чтобы объяснение было коротким.
5. **Интерпретировать.** Коэффициенты g — локальные вклады признаков: «вокруг x₀ рост признака j на одно стандартное отклонение меняет вероятность класса на wⱼ».

Формально LIME ищет g, которая одновременно близка к f в окрестности и проста:

```
ξ(x₀) = argmin_g  L(f, g, π_x₀) + Ω(g)
```

`L` — взвешенная ошибка приближения, `Ω` — сложность g (например, число ненулевых весов).

Качество приближения тоже стоит проверять: lime сообщает `score` — R² локальной модели на возмущениях. Низкий R² значит, что даже локально модель нелинейна, и объяснению доверять нельзя.

## Пример на Python

Реализуем LIME вручную, чтобы увидеть каждый шаг. Чёрный ящик — градиентный бустинг с нелинейной границей `x0² + x1 > 1`; признак x2 — шум.

```python
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.linear_model import Ridge

rng = np.random.default_rng(0)
X = rng.normal(size=(2000, 3))
y = ((X[:, 0] ** 2 + X[:, 1]) > 1).astype(int)
model = GradientBoostingClassifier(random_state=0).fit(X, y)

x0 = np.array([1.5, 0.0, 0.0])
print(model.predict_proba(x0[None])[0, 1].round(3))     # 0.996

std = X.std(axis=0)
Z = x0 + rng.normal(size=(5000, 3)) * std               # 1) возмущения
p = model.predict_proba(Z)[:, 1]                        # 2) ответы чёрного ящика
dist = np.sqrt((((Z - x0) / std) ** 2).sum(axis=1))
w = np.exp(-dist ** 2 / (0.75 * np.sqrt(3)) ** 2)       # 3) веса по близости
surrogate = Ridge(alpha=1.0).fit((Z - x0) / std, p, sample_weight=w)   # 4) простая модель
print(surrogate.coef_.round(3))                         # [0.407 0.202 0.001]
```

В точке x0 = 1.5 оба значимых признака повышают вероятность класса 1: x0 — сильнее (рядом с x0 = 1.5 производная x0² равна 3), x1 — слабее, а шумовой x2 получил почти ноль. Это и есть локальное объяснение. В точке x0 = −1.5 вес x0 сменил бы знак — глобальная модель это допускает, а локальное объяснение честно это отражает.

С библиотекой lime то же делается в несколько строк (в среде курса не установлена, код по её API):

```python
from lime.lime_tabular import LimeTabularExplainer

explainer = LimeTabularExplainer(X_train, feature_names=feature_names,
                                 class_names=["нет", "да"], mode="classification")
exp = explainer.explain_instance(X_test[0], model.predict_proba, num_features=5)
print(exp.as_list())          # [('income > 0.67', -0.21), ('debts <= 2', -0.12), ...]
print(exp.score)              # R² локальной модели
```

Обратите внимание: по умолчанию `LimeTabularExplainer` **дискретизирует** непрерывные признаки по квартилям, поэтому объяснения выглядят как условия «income > 0.67». Это удобно читать, но веса относятся к попаданию в интервал, а не к изменению на единицу.

## LIME и SHAP

| | LIME | SHAP |
|---|---|---|
| идея | локальная линейная аппроксимация | значения Шепли из теории игр |
| гарантии | нет: зависит от ядра и возмущений | аддитивность, симметрия, единственность |
| стабильность | объяснения меняются от запуска к запуску | детерминированы (для TreeExplainer) |
| скорость | быстро для одного объекта | быстро для деревьев, медленно в общем случае |
| тексты и картинки | естественно (слова, суперпиксели) | возможно, но сложнее |

На таблицах с бустингами сегодня чаще используют SHAP; LIME остаётся простым и наглядным инструментом, особенно для текстов и изображений.

## Подводные камни

- **Нестабильность.** Возмущения случайны: два запуска могут дать разные веса и даже разный порядок признаков. Фиксируйте `random_state`, увеличивайте число возмущений (`num_samples`) и проверяйте устойчивость.
- **Ширина ядра.** Слишком узкое ядро — объяснение по паре точек, шумное; слишком широкое — уже не локальное, а глобальное приближение. Результат заметно зависит от этой настройки.
- **Нереалистичные возмущения.** Шум независимо по признакам создаёт объекты, которых не бывает (коррелированные признаки разъезжаются). Модель на них может вести себя как угодно.
- **Линейность может не подходить.** При резких скачках решения рядом с x₀ (например, у порога дерева) линейная модель плохо приближает — смотрите на `score`.
- **Объяснение модели, а не причинность.** Как и SHAP, LIME говорит, на что реагирует модель, а не что вызывает результат в реальности.

## Итоги

- LIME объясняет одно предсказание любой модели, приближая её простой линейной моделью в окрестности объекта.
- Шаги: возмущения → ответы чёрного ящика → веса по близости → взвешенная линейная регрессия → интерпретация весов.
- Метод model-agnostic и работает с таблицами, текстами и картинками.
- Слабые места — нестабильность, зависимость от ширины ядра и нереалистичные возмущения; проверяйте R² локальной модели.
- По сравнению с SHAP у LIME нет теоретических гарантий, зато он прост и нагляден.
