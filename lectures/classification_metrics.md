# Метрики классификации

<!-- время: 15 мин -->

> **О чём лекция.** Как понять, хорошо ли работает классификатор: почему accuracy обманывает при дисбалансе, что измеряют precision и recall, зачем нужен F1 и как выбрать метрику под цену ошибок в задаче.

## Зачем это нужно

Модель обучена, и она что-то предсказывает. Вопрос «хорошая ли она?» на самом деле состоит из нескольких вопросов. Сколько всего ошибок? Каких именно — ложных тревог или пропусков? Как часто модели можно верить, когда она говорит «да»? И какой доли настоящих «да» она не замечает?

Одно число на всё не отвечает. Неудачно выбранная метрика может выдать «97% качества» модели, которая бесполезна. А от метрики зависит всё дальнейшее: какую модель выбрать, какой порог поставить, как подбирать гиперпараметры. Поэтому выбор метрики — одно из первых решений в любом проекте.

## Интуиция: четыре исхода

У бинарного классификатора есть всего четыре варианта исхода для каждого объекта:

- **TP** (true positive) — объект положительный, модель сказала «да». Попадание.
- **TN** (true negative) — объект отрицательный, модель сказала «нет». Тоже верно.
- **FP** (false positive) — модель сказала «да», а на самом деле «нет». Ложная тревога, ошибка I рода.
- **FN** (false negative) — модель сказала «нет», а на самом деле «да». Пропуск, ошибка II рода.

Все метрики классификации — это разные способы скомбинировать эти четыре числа. Их удобно сводить в таблицу — матрицу ошибок (ей посвящена отдельная лекция).

Ключевая мысль: **FP и FN почти всегда стоят по-разному**. Пропустить мошенническую операцию дорого — потеряны деньги. Ложно заблокировать карту честного клиента — неприятно, но дешевле. В медицине пропуск болезни может стоить жизни, а лишняя проверка — только времени. Метрика должна отражать именно эту асимметрию.

## Как это работает

**Accuracy** — доля верных ответов:

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

Понятна, но опасна при дисбалансе. Если мошеннических транзакций 1%, модель «всегда отвечай нет» получит accuracy 99% и не найдёт ни одного мошенника.

**Precision** (точность) — какая доля объявленных «да» действительно «да»:

```
Precision = TP / (TP + FP)
```

Отвечает на вопрос «насколько можно доверять сигналу модели». Важна, когда дороги ложные тревоги: спам-фильтр, который уносит в спам письмо от начальника, хуже, чем пропущенная реклама.

**Recall** (полнота, sensitivity, TPR) — какую долю настоящих «да» модель нашла:

```
Recall = TP / (TP + FN)
```

Отвечает на вопрос «сколько мы пропускаем». Важна, когда дороги пропуски: скрининг болезней, поиск мошенничества, обнаружение дефектов.

**F1** — одно число, которое высоко только тогда, когда высоки обе метрики:

```
F1 = 2 · Precision · Recall / (Precision + Recall)
```

Это **гармоническое** среднее. В отличие от обычного, оно тянется к меньшему значению: при precision = 1.0 и recall = 0.1 обычное среднее дало бы 0.55, а F1 = 0.18. Так модель не может «выехать» на одной метрике. Если recall важнее precision (или наоборот), используют F-beta: при β = 2 recall весит больше.

**Specificity** (TNR) — доля верно распознанных отрицательных: `TN / (TN + FP)`. Встречается в медицине в паре с sensitivity.

## Precision и recall тянут в разные стороны

Большинство моделей выдают вероятность, а класс получается сравнением с порогом. Понижая порог, мы чаще говорим «да»: находим больше положительных (recall растёт), но и ошибаемся чаще (precision падает). Повышая порог — наоборот. Поэтому precision и recall нельзя улучшать бесконечно одновременно: нужно выбрать рабочую точку.

Порог выбирают на валидационной выборке под требование бизнеса, например «recall не ниже 0.9» или «не больше 5% ложных тревог». Для сравнения моделей без привязки к порогу используют ROC-AUC и PR-AUC (они разобраны в лекции про ROC и AUC).

## Много классов

Для K классов precision, recall и F1 считаются для каждого класса отдельно («этот класс против остальных»), а затем усредняются:

| усреднение | как считается | когда использовать |
|---|---|---|
| macro | простое среднее по классам | все классы одинаково важны, в том числе редкие |
| weighted | среднее с весами по числу объектов класса | важнее частые классы |
| micro | TP, FP, FN суммируются по всем классам | итог по всем объектам; для однометочной задачи совпадает с accuracy |

Macro честно показывает, что модель плохо работает на редком классе, а weighted и micro могут это скрыть. `classification_report` в sklearn печатает всё сразу.

## Пример на Python

Задача с 5% положительных объектов. Сравним «глупую» модель и логистическую регрессию, а потом посмотрим, как меняются метрики с порогом.

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=2000, weights=[0.95], flip_y=0, random_state=1)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, stratify=y, random_state=1)

print("всегда 0 — accuracy:", accuracy_score(y_te, np.zeros_like(y_te)))   # 0.95

m = LogisticRegression(max_iter=1000).fit(X_tr, y_tr)
proba = m.predict_proba(X_te)[:, 1]
for t in [0.5, 0.3, 0.1]:
    pred = (proba >= t).astype(int)
    print(f"порог {t}: precision {precision_score(y_te, pred):.3f} "
          f"recall {recall_score(y_te, pred):.3f} f1 {f1_score(y_te, pred):.3f}")

# порог 0.5: precision 0.952 recall 0.800 f1 0.870
# порог 0.3: precision 0.840 recall 0.840 f1 0.840
# порог 0.1: precision 0.568 recall 0.840 f1 0.677
```

Модель «всегда 0» имеет accuracy 95% и нулевой recall. Логистическая регрессия при пороге 0.5 точна, но пропускает каждый пятый положительный объект. Снижение порога до 0.3 выравнивает precision и recall; дальнейшее снижение уже только добавляет ложных тревог.

## Подводные камни

- **Accuracy при дисбалансе** почти ничего не говорит. Всегда сравнивайте модель с константным прогнозом (`DummyClassifier`).
- **Метрику выбирают до моделирования**, исходя из цены ошибок, а не ту, на которой модель выглядит лучше.
- **Положительный класс.** `precision_score` и `recall_score` по умолчанию считают класс 1 положительным. Если метки строковые или «интересный» класс — 0, укажите `pos_label`.
- **Неопределённость при нуле предсказаний.** Если модель ни разу не сказала «да», precision не определена (0/0); sklearn выдаёт предупреждение и подставляет 0. Это знак, что порог или модель неудачны.
- **Маленькая тестовая выборка.** При 20 положительных объектах один лишний пропуск меняет recall на 5 процентных пунктов. Смотрите на разброс по кросс-валидации, а не на одно число.
- **Порог, подобранный на тесте,** завышает оценку качества. Подбирайте его на валидации.

## Итоги

- Все метрики строятся из TP, TN, FP, FN; ошибки FP и FN обычно стоят по-разному.
- Accuracy обманывает при дисбалансе; precision отвечает «можно ли верить сигналу», recall — «сколько пропускаем».
- F1 — гармоническое среднее precision и recall, низкое, если низка хотя бы одна из них.
- Precision и recall зависят от порога и меняются в противоположные стороны; порог выбирают под задачу на валидации.
- Для многоклассовых задач различайте macro, weighted и micro усреднение.
