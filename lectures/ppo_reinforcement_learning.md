# PPO (Proximal Policy Optimization)

<!-- время: 17 мин -->

> **О чём лекция.** Почему обычный градиент политики так легко «ломает» агента одним неудачным шагом, как TRPO ограничил шаг через KL-дивергенцию и как PPO добился почти того же одной обрезкой в целевой функции. Разберём отношение вероятностей, clipped-цель, GAE и то, почему PPO стал алгоритмом по умолчанию — от роботов до RLHF для языковых моделей.

## Зачем это нужно

В policy gradient методах есть болезненная проблема: **размер шага**. В обучении с учителем слишком большой шаг градиента портит веса, но данные остаются прежними, и сеть может восстановиться. В RL данные собирает сама политика. Если неудачный шаг сделал политику плохой, она начнёт собирать плохие траектории, учиться на них — и может не восстановиться никогда.

Кроме того, собирать траектории дорого. Хочется сделать по одним и тем же данным несколько шагов обновления, а обычный policy gradient — on-policy: после первого шага данные уже собраны «чужой» (старой) политикой.

**PPO** (Schulman и др., OpenAI, 2017) решает обе проблемы: позволяет сделать несколько эпох обновлений на одном батче и не даёт политике уйти слишком далеко от той, что собирала данные. Он простой, устойчивый и почти не требует тонкой настройки — поэтому стал стандартом: робототехника, OpenAI Five в Dota 2 и RLHF при обучении ChatGPT.

## Интуиция: улучшать, но осторожно

Представьте, что вы оптимизируете маршрут доставки по вчерашним данным. Небольшие изменения маршрута можно оценить по вчерашним поездкам надёжно. Но если перекроить маршрут целиком, вчерашние данные о нём почти ничего не говорят — это экстраполяция.

PPO формализует это правило: «улучшай политику, пока она остаётся похожей на старую, для которой у нас есть данные». Область, где оценка надёжна, называется **областью доверия** (trust region).

## Как это работает: отношение вероятностей

Данные собраны старой политикой π_old, а мы обновляем новую π_θ. Чтобы корректно использовать старые данные, вводят **отношение вероятностей** (importance sampling ratio):

```
r(θ) = π_θ(a | s) / π_old(a | s) = exp(log π_θ(a | s) − log π_old(a | s))
```

r = 1 — новая политика выбирает это действие так же часто, как старая; r = 1.5 — на 50% чаще. Тогда «суррогатная» цель — ожидаемое преимущество при новой политике, оценённое по старым данным:

```
L(θ) = E[ r(θ) · A ]
```

Если её просто максимизировать, r может улететь далеко от 1, и оценка станет ненадёжной.

## TRPO и PPO

**TRPO** (2015) максимизировал L(θ) при ограничении на KL-дивергенцию между старой и новой политикой: KL(π_old ‖ π_θ) ≤ δ. Теоретически красиво, но требует методов второго порядка (сопряжённые градиенты, линейный поиск) и сложно в реализации.

**PPO** заменяет жёсткое ограничение **обрезкой** (clipping) прямо в целевой функции:

```
L_CLIP(θ) = E[ min( r · A,  clip(r, 1 − ε, 1 + ε) · A ) ]
```

с ε около 0.1–0.2. Как это работает:

- **A > 0** (действие лучше среднего): выгодно увеличивать r, но как только r > 1 + ε, выигрыш перестаёт расти — градиент нулевой, тянуть дальше незачем;
- **A < 0** (действие хуже среднего): выгодно уменьшать r, но не ниже 1 − ε;
- **min** делает оценку пессимистичной: обрезается только *выгода* от изменений, а ухудшения учитываются полностью. Если политика по ошибке ушла в плохую сторону, градиент вернёт её.

Это алгоритм первого порядка: обычный Adam, обычные мини-батчи.

## GAE: оценка преимущества

Качество PPO сильно зависит от оценки преимущества A. Стандарт — **GAE** (Generalized Advantage Estimation). Сначала для каждого шага считают TD-ошибку критика:

```
δ(t) = r(t) + γ · V(s(t+1)) − V(s(t))
```

а затем преимущество как экспоненциально взвешенную сумму будущих TD-ошибок:

```
A(t) = δ(t) + (γλ) · δ(t+1) + (γλ)² · δ(t+2) + …
```

Параметр λ регулирует компромисс: λ = 0 — только одна TD-ошибка (низкая дисперсия, но смещение из-за неточного критика), λ = 1 — полный Монте-Карло возврат минус V (без смещения, но шумно). Обычно λ = 0.95, γ = 0.99.

## Алгоритм целиком

1. Собрать N шагов опыта текущей политикой (часто в нескольких параллельных средах); сохранить log π_old(a | s), V(s), награды.
2. Посчитать преимущества GAE и возвраты для критика; нормализовать преимущества в батче.
3. K эпох (обычно 3–10) по случайным мини-батчам минимизировать общую функцию потерь:

```
loss = −L_CLIP + c₁ · (V(s) − возврат)² − c₂ · энтропия(π)
```

4. Выбросить данные и повторить с новой политикой.

Член критика учит функцию ценности, бонус за энтропию поддерживает исследование.

## PPO в RLHF

При дообучении языковых моделей по человеческим предпочтениям (RLHF) «агент» — языковая модель, «действие» — очередной токен, а награда приходит от **модели награды**, обученной на сравнениях ответов людьми. Чтобы модель не «взломала» модель награды бессмысленными, но высоко оцениваемыми текстами, к награде добавляют штраф за KL-дивергенцию от исходной модели. PPO с его осторожными шагами хорошо подходит для этого.

## Пример на Python

Clipped-цель и GAE на NumPy — без них не обходится ни одна реализация PPO:

```python
import numpy as np

def clipped_objective(ratio, adv, eps=0.2):
    return np.minimum(ratio * adv, np.clip(ratio, 1 - eps, 1 + eps) * adv)

for r in (0.5, 0.9, 1.0, 1.1, 1.5):
    print(f"r={r}: A=+1 → {clipped_objective(r, 1.0):.2f}, A=−1 → {clipped_objective(r, -1.0):.2f}")
# r=0.5: A=+1 → 0.50, A=−1 → -0.80   (A<0: выгода от уменьшения r обрезана на 1−ε)
# r=1.5: A=+1 → 1.20, A=−1 → -1.50   (A>0: выгода обрезана на 1+ε; ухудшение — нет)

def gae(rewards, values, dones, gamma=0.99, lam=0.95):
    """values длиннее rewards на 1: последняя — оценка состояния после последнего шага."""
    adv, last = np.zeros(len(rewards)), 0.0
    for t in reversed(range(len(rewards))):
        nonterminal = 1.0 - dones[t]
        delta = rewards[t] + gamma * values[t + 1] * nonterminal - values[t]   # TD-ошибка
        last = delta + gamma * lam * nonterminal * last
        adv[t] = last
    return adv

print(np.round(gae(np.array([1.0, 1.0, 1.0]), np.array([0.5, 0.5, 0.5, 0.0]), np.array([0, 0, 1])), 3))
# [2.373 1.465 0.5  ]
```

Обратите внимание на r = 1.5 и A = −1: результат −1.50, а не −1.20. Это и есть пессимизм min: если политика уже ушла в плохую сторону, штраф не обрезается.

В реальных проектах PPO обычно берут готовым: `stable-baselines3` (`PPO("MlpPolicy", env).learn(1_000_000)`) или `CleanRL` (одна понятная реализация в одном файле), для RLHF — библиотеку `trl`.

## Подводные камни

- **Нет нормализации преимуществ и наблюдений.** Без неё PPO заметно хуже; в популярных реализациях она включена по умолчанию.
- **Слишком много эпох на одном батче.** Политика всё равно уходит далеко, несмотря на клиппинг. Следите за приближённой KL-дивергенцией и долей обрезанных примеров (clip fraction); при большой KL останавливайте эпохи досрочно.
- **Неверная обработка конца эпизода** в GAE: на границе эпизода нельзя бутстрапить ценность следующего состояния, а на обрезке по лимиту времени — нужно.
- **Детали реализации важны.** Исследования показали, что многие «мелочи» (инициализация весов, обрезка градиентов, расписание learning rate, нормализации) влияют на результат не меньше самой clipped-цели.
- **Эффективность по данным.** PPO остаётся on-policy и требует много взаимодействий. Если шаг среды дорогой, рассмотрите off-policy методы вроде SAC.

## Итоги

- PPO — on-policy actor-critic алгоритм, который улучшает политику, не давая ей уйти далеко от той, что собирала данные.
- Отношение вероятностей r = π_θ / π_old позволяет использовать старые данные; clipped-цель с min обрезает выгоду от слишком больших изменений.
- В отличие от TRPO, PPO — метод первого порядка: обычный Adam и мини-батчи, несколько эпох на одном батче.
- Преимущества оценивают через GAE с параметром λ; в функцию потерь добавляют потери критика и бонус за энтропию.
- PPO — стандарт в робототехнике, играх и RLHF.
