# GRU (Gated Recurrent Units)

<!-- время: 12 мин -->

> **О чём лекция.** GRU — облегчённая версия LSTM: два вентиля вместо трёх, одно состояние вместо двух и почти то же качество. Разберём, как устроены update и reset gate и как выбирать между GRU и LSTM.

## Зачем это нужно

LSTM решила главную проблему простой RNN — затухание градиента на длинных последовательностях. Но она довольно громоздкая: три вентиля, кандидат в память, два состояния (`h` и `C`), вчетверо больше параметров, чем у RNN.

В 2014 году Cho и соавторы предложили **GRU** (Gated Recurrent Unit) — рекуррентный блок с той же идеей вентилей, но проще. Многочисленные сравнения показали: на большинстве задач GRU и LSTM работают примерно одинаково, а GRU быстрее обучается и требует меньше памяти. Поэтому GRU — частый выбор, когда данных немного или важна скорость.

## Интуиция: ползунок между старым и новым

У GRU нет отдельной «ленты памяти». Есть одно скрытое состояние `h_t`, и на каждом шаге сеть решает, **насколько его обновить**.

Представьте ползунок для каждого элемента памяти:

- в положении 0 — оставить старое значение как есть;
- в положении 1 — полностью заменить новым кандидатом;
- посередине — смешать.

Этот ползунок — **update gate** `z_t`. Он одновременно играет роль forget gate и input gate из LSTM: сколько взяли нового, столько же забыли старого.

Второй вентиль — **reset gate** `r_t` — решает, насколько учитывать прошлое состояние при *составлении* нового кандидата. Если `r_t ≈ 0`, кандидат строится почти только по текущему входу, как будто с чистого листа: полезно, когда начался новый смысловой блок (новое предложение, смена режима ряда).

## Как это работает

На шаге t:

```
z_t = σ(W_z · [h_{t−1}, x_t])            update gate
r_t = σ(W_r · [h_{t−1}, x_t])            reset gate
h̃_t = tanh(W_h · [r_t ⊙ h_{t−1}, x_t])   кандидат
h_t = (1 − z_t) ⊙ h_{t−1} + z_t ⊙ h̃_t     новое состояние
```

(смещения опущены для краткости; `σ` — сигмоида, `⊙` — поэлементное умножение).

Последняя строка — то же сложение вместо перемножения, что и в LSTM. Если update gate для какого-то элемента близок к 0, значение `h_{t−1}` проходит на следующий шаг почти без изменений, и градиент по нему тоже течёт назад почти без потерь. Так GRU удерживает информацию на десятки и сотни шагов.

Обратите внимание: в документации PyTorch формула записана зеркально — `h_t = (1 − z_t) ⊙ n_t + z_t ⊙ h_{t−1}`, то есть там `z_t ≈ 1` означает «сохранить». Это одна и та же модель, просто вентиль обозначает долю старого, а не нового. Сеть выучит любой вариант.

## GRU против LSTM

| | LSTM | GRU |
|---|---|---|
| вентили | 3 (forget, input, output) + кандидат | 2 (update, reset) + кандидат |
| состояния | два: `h_t` и `C_t` | одно: `h_t` |
| параметры | ≈ 4 × RNN | ≈ 3 × RNN |
| скорость | медленнее | быстрее: меньше вычислений на шаг |
| качество | чуть лучше на очень длинных зависимостях и больших данных | обычно сопоставимо, на малых данных иногда лучше |

Практический совет: начните с GRU — быстрее итерации. Если качество упирается в потолок и данных много, попробуйте LSTM. Разница обычно меньше, чем эффект от правильной подготовки данных и подбора размера скрытого слоя.

## Двунаправленная GRU

`bidirectional=True` запускает две GRU: одна читает последовательность слева направо, другая справа налево, их состояния склеиваются (размер выхода удваивается). Это полезно, когда для понимания элемента важен и правый контекст: в NER слово «Москва» в «Москва-река» и «Москва — столица» размечается по-разному.

Нельзя использовать двунаправленную модель, когда будущее неизвестно: прогноз временного ряда, генерация текста, обработка потока в реальном времени. Иначе модель на обучении «подсматривает» в будущее, а в работе этого будущего нет.

## Пример на Python

Шаг GRU на NumPy и иллюстрация того, как закрытый update gate сохраняет память:

```python
import numpy as np

sigmoid = lambda z: 1 / (1 + np.exp(-z))
rng = np.random.default_rng(0)
n_in, n_h = 3, 4
Wz, Wr, Wh = (rng.normal(scale=0.3, size=(n_h, n_h + n_in)) for _ in range(3))

def gru_step(x_t, h_prev):
    hx = np.concatenate([h_prev, x_t])
    z = sigmoid(Wz @ hx)                                   # update gate: сколько обновить
    r = sigmoid(Wr @ hx)                                   # reset gate: сколько прошлого учесть в кандидате
    h_tilde = np.tanh(Wh @ np.concatenate([r * h_prev, x_t]))
    return (1 - z) * h_prev + z * h_tilde                  # смесь старого и нового состояния

h = np.zeros(n_h)
for x_t in rng.normal(size=(6, n_in)):
    h = gru_step(x_t, h)
print(h.round(3))

# Если update gate почти закрыт (z ≈ 0), состояние переносится почти без изменений
h_keep = np.array([0.5, -0.2, 0.8, 0.1])
z = np.full(n_h, 0.02)
print(((1 - z) * h_keep + z * np.ones(n_h)).round(3))   # [ 0.51  -0.176  0.804  0.118]

params = lambda gates: gates * (n_h * (n_h + n_in) + n_h)
print(params(1), params(3), params(4))   # RNN 32, GRU 96, LSTM 128
```

Классификатор текста на GRU в PyTorch:

```python
import torch
import torch.nn as nn

class GRUClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim=128, hidden_dim=256, num_classes=2):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.gru = nn.GRU(embed_dim, hidden_dim, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(2 * hidden_dim, num_classes)   # ×2 из-за двух направлений

    def forward(self, ids):                 # ids: (batch, seq_len)
        x = self.embedding(ids)
        _, h_n = self.gru(x)                # h_n: (2, batch, hidden_dim)
        h = torch.cat([h_n[0], h_n[1]], dim=1)   # последние состояния обоих направлений
        return self.fc(h)
```

## Подводные камни

- **Размер выхода у bidirectional.** Выход удваивается: следующий линейный слой должен принимать `2 * hidden_dim`.
- **`out[:, -1]` у двунаправленной сети.** Для обратного направления последний шаг — это начало его чтения, там оно почти ничего не видело. Берите `h_n` обоих направлений, как в примере.
- **Двунаправленность в прогнозе.** Утечка будущего: на валидации всё отлично, в проде — плохо.
- **Взрыв градиента** возможен и у GRU — используйте gradient clipping.
- **Паддинг.** Нули в конце коротких последовательностей портят последнее состояние; используйте `pack_padded_sequence`.

## Итоги

- GRU — упрощённая LSTM: два вентиля (update и reset) и одно состояние.
- Update gate смешивает старое состояние и новый кандидат; при `z ≈ 0` память сохраняется, и градиент не затухает.
- Reset gate решает, сколько прошлого использовать при составлении кандидата.
- Параметров примерно на четверть меньше, чем у LSTM, обучение быстрее, качество обычно сопоставимо.
- Двунаправленная GRU — для задач с полным контекстом, но не для прогноза будущего.
