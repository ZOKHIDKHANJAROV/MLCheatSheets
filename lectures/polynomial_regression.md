# Полиномиальная регрессия

<!-- время: 12 мин -->

> **О чём лекция.** Как линейная модель может описывать кривые, почему полиномиальная регрессия всё ещё линейна, как выбрать степень полинома и почему высокая степень почти гарантирует переобучение.

## Зачем это нужно

Реальные зависимости часто нелинейны: урожай растёт с удобрениями, но после некоторого предела падает; цена автомобиля быстро снижается в первые годы и медленнее потом. Прямая линия такие формы не опишет — модель будет недообучена.

Полиномиальная регрессия — самый простой способ дать линейной модели гибкость: мы добавляем в данные степени признаков и их произведения и обучаем обычную линейную регрессию. Это также отличный «учебный полигон» для понимания переобучения и выбора сложности модели.

## Интуиция: новые признаки вместо новой модели

Пусть есть один признак `x`. Добавим к нему `x²` и `x³` как будто это отдельные, новые признаки. Для модели это просто три столбца, и она подбирает три веса — ровно так же, как для любой линейной регрессии. Но на графике против исходного `x` получится кривая.

Отсюда главный парадокс: зависимость от `x` нелинейна, а модель **линейна по параметрам** — веса входят в формулу линейно. Поэтому работают все инструменты линейной регрессии: МНК, регуляризация, интерпретация.

## Как это работает

### Формула

Для одного признака и степени `d`:

```
ŷ = β₀ + β₁x + β₂x² + … + β_d·xᵈ
```

Для нескольких признаков добавляются ещё **взаимодействия** — произведения признаков. Для двух признаков и степени 2:

```
ŷ = β₀ + β₁x₁ + β₂x₂ + β₃x₁² + β₄x₁x₂ + β₅x₂²
```

Взаимодействие `x₁x₂` позволяет эффекту одного признака зависеть от другого: например, влияние площади на цену сильнее в центре города.

### Сколько получается признаков

`PolynomialFeatures(degree=2)` для 3 исходных признаков даёт 10 столбцов: константу, 3 исходных, 3 квадрата и 3 попарных произведения. В общем случае при `n` признаках и степени `d` их число равно C(n + d, d) и растёт очень быстро: для 20 признаков и степени 3 — уже 1771. Поэтому высокие степени на многих признаках почти не используют.

### Выбор степени

Степень — гиперпараметр, управляющий сложностью:

- `d = 1` — прямая, высокое смещение;
- небольшая `d` (2–4) — обычно хватает для плавных кривых;
- большая `d` — кривая проходит почти через каждую точку, огромная дисперсия, дикие колебания на краях.

Степень выбирают по ошибке на **кросс-валидации**, а не на обучающей выборке: на train ошибка с ростом степени почти всегда падает. Вместо подбора степени можно взять заведомо достаточную и обуздать её регуляризацией (Ridge).

### Масштабирование

Если `x` меняется от 0 до 1000, то `x³` — до миллиарда. Столбцы с такими разными масштабами делают задачу численно неустойчивой, а регуляризация штрафует их несправедливо. Кроме того, `x`, `x²`, `x³` сильно коррелируют между собой. Поэтому после `PolynomialFeatures` (или до него, приводя `x` к небольшому диапазону) применяют `StandardScaler`.

## Пример на Python

Данные с кубической зависимостью; выбираем степень по кросс-валидации.

```python
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(0)
X = rng.uniform(-3, 3, size=(60, 1))
y = 0.5 * X.ravel() ** 3 - X.ravel() ** 2 + 2 + rng.normal(0, 2, 60)

for degree in [1, 2, 3, 5, 10]:
    model = make_pipeline(PolynomialFeatures(degree, include_bias=False),
                          StandardScaler(), LinearRegression())
    mse = -cross_val_score(model, X, y, cv=5, scoring="neg_mean_squared_error").mean()
    print(f"степень {degree:2d}: CV MSE = {mse:.2f}")

# степень  1: CV MSE = 21.71
# степень  2: CV MSE = 9.70
# степень  3: CV MSE = 5.77   ← истинная степень — лучший результат
# степень  5: CV MSE = 7.31
# степень 10: CV MSE = 66.26  ← переобучение

print(PolynomialFeatures(2).fit(np.zeros((1, 3))).get_feature_names_out().tolist())
# ['1', 'x0', 'x1', 'x2', 'x0^2', 'x0 x1', 'x0 x2', 'x1^2', 'x1 x2', 'x2^2']
```

Ошибка на кросс-валидации имеет форму буквы U: минимум у истинной степени 3, а степень 10 ошибается в десять с лишним раз сильнее. Последняя строка показывает, из каких 10 столбцов состоят признаки степени 2 для трёх исходных.

## Подводные камни

- **Взрыв числа признаков** при многих исходных признаках. Используйте `interaction_only=True`, отбор признаков или другие модели (деревья, бустинг).
- **Поведение на краях и экстраполяция.** Полиномы высокой степени сильно колеблются у границ данных и уходят в бесконечность за их пределами. Не используйте их для прогноза за диапазоном обучения.
- **Без масштабирования** — численные проблемы и несправедливая регуляризация.
- **Выбор степени по train** всегда приведёт к максимальной степени.
- **Интерпретация весов** при `x`, `x²`, `x³` затруднена: они сильно коррелируют, и смысл имеет только вся кривая целиком.
- **Альтернативы.** Для гладких нелинейных зависимостей часто лучше сплайны (`SplineTransformer`): они гибкие, но не колеблются на краях.

## Итоги

- Полиномиальная регрессия = полиномиальные признаки + обычная линейная регрессия.
- Модель нелинейна по `x`, но линейна по параметрам, поэтому работают МНК и регуляризация.
- Степень — гиперпараметр сложности: выбирайте по кросс-валидации, высокая степень переобучается.
- Число признаков растёт комбинаторно; масштабирование обязательно.
- Не экстраполируйте полиномы и рассмотрите сплайны и Ridge как альтернативы.
