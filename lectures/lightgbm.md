# LightGBM

<!-- время: 15 мин -->

> **О чём лекция.** Почему LightGBM обучается в разы быстрее классического бустинга на больших данных: гистограммы, рост деревьев по листьям, GOSS и EFB. Разберём, почему его главный параметр сложности — `num_leaves`, как он работает с категориями и что делать, если он переобучается.

## Зачем это нужно

LightGBM — библиотека градиентного бустинга от Microsoft (2017). Идея та же, что у XGBoost: деревья строятся по очереди, каждое исправляет ошибки предыдущих. Но LightGBM спроектирован для **больших** табличных данных — миллионов строк и сотен признаков, — и на них обучается заметно быстрее и экономнее по памяти.

Поэтому он популярен в промышленных задачах (реклама, рекомендации, ранжирование, антифрод) и на соревнованиях, где за ограниченное время нужно перебрать много вариантов признаков и параметров. Быстрое обучение — это не только экономия времени, но и больше экспериментов, а значит, лучшая модель.

## Интуиция: рост туда, где больше всего ошибок

Классический бустинг (и XGBoost по умолчанию) растит дерево **по уровням**: сначала делит корень, потом оба потомка, потом все четыре внука — как будто равномерно заполняет этаж за этажом. Часть этих разбиений почти ничего не даёт, но строится просто потому, что «этот этаж нужно заполнить».

LightGBM растит дерево **по листьям** (leaf-wise): на каждом шаге он находит лист, разбиение которого сильнее всего уменьшит ошибку, и делит только его. Дерево получается несимметричным: глубоким там, где данные сложные, и мелким там, где всё и так понятно. При том же числе листьев такое дерево уменьшает потери сильнее.

Обратная сторона — на маленьких данных такие деревья легко «закапываются» в шум: одна ветка может вырасти очень глубокой ради нескольких объектов.

## Как это работает

LightGBM ускоряет бустинг четырьмя основными приёмами.

**1. Гистограммы.** Перед обучением значения каждого признака раскладываются по корзинам (`max_bin`, по умолчанию 255). Чтобы найти лучший порог, не нужно сортировать миллионы значений — достаточно пройти по 255 корзинам с суммами градиентов. Дополнительный трюк: гистограмму одного из потомков можно получить вычитанием гистограммы другого потомка из гистограммы родителя — это ещё вдвое сокращает работу.

**2. Рост по листьям** — описан выше. Сложность дерева задаётся числом листьев `num_leaves`.

**3. GOSS (Gradient-based One-Side Sampling).** Объекты с большим градиентом — это те, на которых модель сильно ошибается; они важнее для следующего дерева. GOSS оставляет все объекты с большими градиентами и лишь случайную часть объектов с маленькими, увеличивая веса последних, чтобы не исказить распределение. Дерево учится на меньшем объёме данных почти без потери качества. В новых версиях включается через `data_sample_strategy="goss"`.

**4. EFB (Exclusive Feature Bundling).** В разреженных данных (например, после one-hot) многие признаки почти никогда не бывают ненулевыми одновременно. EFB объединяет такие «взаимоисключающие» признаки в один, сокращая число признаков, которые нужно перебирать.

## Почему главный параметр — num_leaves

При росте по уровням сложность дерева определяется глубиной: дерево глубины d имеет до 2ᵈ листьев. При росте по листьям глубина сама по себе мало что ограничивает: дерево с 31 листом может быть и глубиной 5, и глубиной 20. Поэтому главная «ручка» сложности в LightGBM — **`num_leaves`** (по умолчанию 31).

Правило: держать `num_leaves` заметно меньше, чем `2^max_depth`. Если вы привыкли к XGBoost с глубиной 6 (до 64 листьев), начните с `num_leaves` около 31–63. `max_depth` в LightGBM по умолчанию не ограничен (−1), но его полезно задать как страховку от слишком глубоких веток.

## Категориальные признаки

LightGBM умеет работать с категориями напрямую — без one-hot. Для категориального признака он сортирует категории по статистике градиентов и ищет лучшее разбиение категорий на две группы. Это быстрее и обычно лучше, чем one-hot для признаков с большим числом значений.

Как включить: перевести столбец pandas в тип `category` (LightGBM подхватит его автоматически) или указать `categorical_feature`. Значения должны быть закодированы последовательно на обучении и на тесте — при типе `category` pandas это делает сам, если категории совпадают. Для очень редких категорий есть параметры `min_data_per_group` и `cat_smooth`.

## Борьба с переобучением

| параметр | что делает | направление при переобучении |
|---|---|---|
| `num_leaves` | число листьев | уменьшить |
| `min_child_samples` (`min_data_in_leaf`) | минимум объектов в листе | увеличить (20 → 50–200) |
| `max_depth` | ограничение глубины | задать, например 6–10 |
| `subsample` + `subsample_freq` | доля объектов на итерацию | 0.7–0.9 и частота 1 |
| `colsample_bytree` (`feature_fraction`) | доля признаков на дерево | 0.6–0.9 |
| `reg_alpha`, `reg_lambda` | L1/L2-регуляризация листьев | увеличить |
| `learning_rate` | вклад дерева | уменьшить, добавив деревьев |

И, как в любом бустинге, главное средство — **ранняя остановка** по валидации.

## Пример на Python

```python
import lightgbm as lgb
from sklearn.datasets import make_classification
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=20000, n_features=30, n_informative=10, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)
X_fit, X_val, y_fit, y_val = train_test_split(X_tr, y_tr, test_size=0.2, random_state=0)

model = lgb.LGBMClassifier(
    n_estimators=5000,            # с запасом — остановит early stopping
    learning_rate=0.05,
    num_leaves=31,
    min_child_samples=50,
    subsample=0.8, subsample_freq=1,
    colsample_bytree=0.8,
    random_state=0,
    verbose=-1,
)
model.fit(
    X_fit, y_fit,
    eval_set=[(X_val, y_val)],
    eval_metric="auc",
    callbacks=[lgb.early_stopping(stopping_rounds=100), lgb.log_evaluation(0)],
)

print("лучшая итерация:", model.best_iteration_)
print("ROC-AUC на тесте:", roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]))
```

В современных версиях ранняя остановка задаётся через `callbacks`, а не параметром `early_stopping_rounds` в `fit`. Если LightGBM не установлен, ту же идею (гистограммы, рост по листьям, нативные категории) реализует `HistGradientBoostingClassifier` из scikit-learn: у него параметр `max_leaf_nodes` играет роль `num_leaves`.

## Подводные камни

- **Маленькие данные.** На нескольких тысячах строк рост по листьям легко переобучается. Уменьшайте `num_leaves`, увеличивайте `min_child_samples`, ограничивайте `max_depth`.
- **Нативные категории с огромным числом значений** могут переобучаться: модель подбирает группировку категорий под шум. Помогают `min_data_per_group`, `cat_smooth`, `max_cat_threshold` или target-кодирование с кросс-валидацией.
- **Разные категории на обучении и тесте.** Если коды категорий не совпадают, модель молча применит не те разбиения. Используйте один и тот же `CategoricalDtype`.
- **Устаревшие примеры**: параметры `early_stopping_rounds` и `verbose` в `fit`, `boosting="goss"` — API менялся; сверяйтесь с документацией своей версии.
- **Синонимы параметров.** У LightGBM много алиасов (`feature_fraction` = `colsample_bytree`, `min_data_in_leaf` = `min_child_samples`). Если задать оба, один молча перекроет другой.
- **Подсказка «No further splits with positive gain»** обычно означает, что данные слишком малы или ограничения слишком жёсткие.

## Итоги

- LightGBM — градиентный бустинг, оптимизированный для больших данных: гистограммы, рост по листьям, GOSS и EFB.
- Рост по листьям даёт более точные деревья при том же числе листьев, но сильнее переобучается на маленьких данных.
- Главный параметр сложности — `num_leaves`, его держат меньше `2^max_depth`; важен и `min_child_samples`.
- Категории можно передавать напрямую — через тип `category` в pandas.
- Против переобучения: ранняя остановка, меньше листьев, больше объектов в листе, подвыборки и регуляризация.
