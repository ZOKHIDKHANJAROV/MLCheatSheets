# XGBoost

<!-- время: 15 мин -->

> **О чём лекция.** Что именно XGBoost добавил к классическому градиентному бустингу: вторые производные, регуляризацию прямо в критерии разбиения, обработку пропусков и быструю реализацию. И как его настраивать на практике — какие параметры трогать первыми и как пользоваться ранней остановкой.

## Зачем это нужно

XGBoost (eXtreme Gradient Boosting) появился в 2014 году и быстро стал стандартом для табличных данных: на несколько лет он сделался самым частым компонентом решений-победителей на Kaggle. Он работает в рекламе, кредитном скоринге, антифроде, ранжировании поиска.

Идея у него та же, что у любого градиентного бустинга: деревья строятся по очереди, и каждое исправляет ошибки предыдущих. Но XGBoost сделал бустинг точнее, устойчивее к переобучению и намного быстрее, а ещё дал удобный API, совместимый с scikit-learn. Сегодня у него есть сильные конкуренты — LightGBM и CatBoost, — но понимать XGBoost полезно: многие их идеи пришли отсюда.

## Интуиция: не просто направление, а и кривизна

Обычный градиентный бустинг учит каждое дерево на градиенте — направлении, куда сдвинуть прогнозы. Это как спускаться с горы, зная только наклон под ногами: непонятно, насколько далеко шагать.

XGBoost использует ещё и **вторую производную** — кривизну функции потерь. Если склон резко выполаживается, шаг надо делать короче, если он ровный и длинный — можно шагать смелее. Это аналог метода Ньютона: зная наклон и кривизну, можно сразу оценить, где находится минимум. В результате каждое дерево делает более точную поправку.

## Как это работает

На шаге m для каждого объекта i считаются:

```
gᵢ = ∂L/∂F(xᵢ)       — градиент потерь по текущему прогнозу
hᵢ = ∂²L/∂F(xᵢ)²     — вторая производная (гессиан)
```

Пусть в лист попали объекты с суммами `G = Σgᵢ` и `H = Σhᵢ`. Оптимальное значение листа и вклад листа в улучшение целевой функции записываются явно:

```
w* = −G / (H + λ)
```

Качество разбиения узла на левую и правую части:

```
Gain = ½ · [ G_L²/(H_L + λ) + G_R²/(H_R + λ) − (G_L + G_R)²/(H_L + H_R + λ) ] − γ
```

Здесь видны два встроенных регуляризатора:

- `λ` (`reg_lambda`) — L2-штраф на значения листьев: делает поправки скромнее, особенно в листьях с малым числом объектов;
- `γ` (`gamma`, `min_split_loss`) — «цена» нового листа: разбиение делается, только если прирост больше γ. Это встроенная обрезка дерева.

Есть и `alpha` (`reg_alpha`) — L1-штраф на значения листьев.

Классический бустинг ограничивает сложность только внешними параметрами (глубиной, числом листьев). У XGBoost регуляризация — часть самой целевой функции, которую оптимизирует каждое дерево.

## Пропуски и категории

**Пропуски.** XGBoost не требует заполнять NaN. При каждом разбиении он пробует отправить все объекты с пропуском и влево, и вправо, и запоминает направление, которое даёт больший прирост (**default direction**). На новых данных объекты с пропуском идут в это направление.

**Категориальные признаки.** В новых версиях есть нативная поддержка: столбцы pandas типа `category` и параметр `enable_categorical=True`. Классический путь — one-hot или target-кодирование заранее.

## Скорость

- **Гистограммный алгоритм** (`tree_method="hist"`, по умолчанию в версиях 2.x): значения признаков заранее раскладываются по корзинам (до `max_bin`, по умолчанию 256), и пороги ищутся среди границ корзин, а не среди всех уникальных значений.
- **Параллелизм**: деревья строятся последовательно, но поиск лучшего разбиения внутри дерева распараллеливается по признакам.
- **GPU**: `device="cuda"`.
- Деревья растут **по уровням** (level-wise, `grow_policy="depthwise"`): глубина задаётся `max_depth`.

## Настройка параметров

| параметр | что делает | с чего начать |
|---|---|---|
| `n_estimators` | максимум деревьев | 1000–5000 вместе с ранней остановкой |
| `learning_rate` (eta) | вклад каждого дерева | 0.05–0.1 |
| `max_depth` | глубина деревьев | 4–8 (по умолчанию 6) |
| `min_child_weight` | минимум суммы гессианов в листе (≈ минимум объектов) | 1–10; больше — консервативнее |
| `subsample` | доля объектов на дерево | 0.7–0.9 |
| `colsample_bytree` | доля признаков на дерево | 0.6–0.9 |
| `reg_lambda`, `reg_alpha`, `gamma` | регуляризация | подбирать, если модель переобучается |
| `scale_pos_weight` | вес положительного класса | ≈ число отрицательных / число положительных при дисбалансе |

Практичный порядок: зафиксировать learning rate 0.1 и раннюю остановку, подобрать `max_depth` и `min_child_weight`, затем `subsample` и `colsample_bytree`, затем регуляризацию, и в конце уменьшить learning rate в несколько раз, увеличив число деревьев. Для перебора удобны Optuna и другие байесовские оптимизаторы.

## Пример на Python

```python
import xgboost as xgb
from sklearn.datasets import make_classification
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=5000, n_features=20, n_informative=8, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)
X_fit, X_val, y_fit, y_val = train_test_split(X_tr, y_tr, test_size=0.2, random_state=0)

model = xgb.XGBClassifier(
    n_estimators=2000,            # с запасом — остановит early stopping
    learning_rate=0.05,
    max_depth=5,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_lambda=1.0,
    eval_metric="logloss",
    early_stopping_rounds=50,     # стоп, если 50 итераций без улучшения на валидации
    tree_method="hist",
    random_state=0,
)
model.fit(X_fit, y_fit, eval_set=[(X_val, y_val)], verbose=False)

print("лучшая итерация:", model.best_iteration)
print("ROC-AUC на тесте:", roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]))

importance = model.get_booster().get_score(importance_type="gain")   # важность по приросту
```

Обратите внимание: валидация для ранней остановки (`X_val`) отделена от теста (`X_te`). В версиях XGBoost 2.x параметр `early_stopping_rounds` передаётся в конструктор, а не в `fit`, как было раньше. При предсказании модель автоматически использует деревья до лучшей итерации.

## Подводные камни

- **Ранняя остановка по тесту** завышает итоговую оценку. Нужна отдельная валидационная выборка или кросс-валидация (`xgb.cv`).
- **Устаревшие примеры из интернета**: `early_stopping_rounds` в `fit`, `gpu_hist`, `nthread` — API менялся. Проверяйте документацию своей версии.
- **Глубокие деревья** (max_depth 10+) быстро переобучаются и сильно замедляют обучение.
- **Важность признаков** зависит от типа: `weight` (сколько раз признак использован), `gain` (средний прирост), `cover`. Они могут сильно расходиться; для объяснения модели лучше SHAP — XGBoost умеет считать его быстро (`pred_contribs=True`).
- **Дисбаланс**: `scale_pos_weight` улучшает recall, но смещает вероятности. Если нужны калиброванные вероятности, лучше подбирать порог.
- **Воспроизводимость**: фиксируйте `random_state`; при многопоточности и на GPU результаты могут слегка отличаться между запусками и версиями.

## Итоги

- XGBoost — градиентный бустинг над деревьями с использованием градиента и гессиана (шаг в духе метода Ньютона).
- Регуляризация встроена в критерий разбиения: λ и α штрафуют значения листьев, γ — появление новых листьев.
- Пропуски обрабатываются автоматически через направление по умолчанию; есть нативная поддержка категорий.
- Быстродействие обеспечивают гистограммы, параллельный поиск разбиений и GPU.
- Настройка: learning rate + ранняя остановка, затем глубина и `min_child_weight`, затем subsample/colsample и регуляризация.
