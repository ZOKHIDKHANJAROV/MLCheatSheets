# Transfer learning для CNN

<!-- время: 16 мин -->

> **О чём лекция.** Как взять сеть, обученную на миллионе картинок ImageNet, и за полчаса адаптировать её к своей задаче с парой тысяч изображений: feature extraction и fine-tuning, выбор стратегии, подготовка входа и типичные ошибки.

## Зачем это нужно

Обучить хорошую свёрточную сеть с нуля — это миллионы размеченных картинок, дни работы GPU и много опыта. У типичного проекта — сотни или тысячи изображений: брак на конвейере, виды растений, снимки товаров. Сеть с нуля на таких данных переобучится.

Transfer learning (перенос обучения) решает это: берём сеть, уже обученную на большом датасете (обычно ImageNet — 1.28 млн изображений, 1000 классов), и переиспользуем её признаки. Предобученная сеть на нескольких тысячах картинок почти всегда точнее сети с нуля, а обучается в разы быстрее и стабильнее. В компьютерном зрении это подход по умолчанию.

## Интуиция: признаки переиспользуемы

Вспомним, что учат слои CNN:

- **ранние слои** — границы, цвета, простые текстуры; они универсальны почти для любых изображений;
- **средние** — мотивы и части объектов: глаза, колёса, узоры;
- **поздние** — признаки, специфичные для исходной задачи: морды собак конкретных пород;
- **голова** (последний полносвязный слой) — ровно 1000 классов ImageNet; её всегда заменяют.

Человек, научившийся различать птиц, быстрее научится различать бабочек: умение замечать форму крыла, окраску и пропорции уже есть. Так и сеть: чем ближе к входу слой, тем больше его признаки подходят для новой задачи.

## Как это работает: две стратегии

**Feature extraction** (извлечение признаков). Замораживаем всю предобученную часть (backbone) и обучаем только новую голову. Сеть работает как фиксированный «переводчик» картинки в вектор признаков, а поверх учится простой классификатор. Быстро, мало риска переобучиться, признаки можно даже посчитать один раз и закэшировать.

**Fine-tuning** (дообучение). Размораживаем часть или все слои backbone и продолжаем обучение на своих данных с **маленьким** learning rate (`1e-5`…`1e-4`). Признаки подстраиваются под новую задачу — обычно это точнее, но медленнее и с риском переобучения и «забывания» полезных признаков.

Типичный рецепт объединяет обе: сначала заморозить backbone и несколько эпох обучить голову (lr около `1e-3`), затем разморозить и дообучить всю сеть с малым шагом. Если сразу разморозить всё со случайной головой, её огромные градиенты в первые шаги «испортят» предобученные признаки.

## Какую стратегию выбрать

| | данные похожи на ImageNet | данные сильно отличаются |
|---|---|---|
| **мало данных** (сотни–тысячи) | заморозить backbone, обучить голову | признаки средних слоёв + голова, осторожный fine-tuning верхних блоков, сильные аугментации |
| **много данных** (10⁴+) | fine-tuning верхних блоков или всей сети | полный fine-tuning; иногда предобучение на своём домене |

Ориентир: около 100 изображений на класс уже дают разумный результат с замороженным backbone; от тысячи на класс можно смело дообучать всю сеть. При сильном сдвиге домена — рентген, гистология, спутниковые снимки — низкоуровневые признаки ImageNet ещё полезны, а высокоуровневые хуже. Тогда помогают модели, предобученные на похожих данных, или self-supervised дообучение на неразмеченных снимках.

## Почему маленький learning rate

Предобученные веса уже находятся в хорошей точке. Большой шаг (`1e-2`) за несколько итераций унесёт их далеко и разрушит признаки, ради которых мы и брали модель. Хорошо работает **discriminative learning rate**: чем ниже слой, тем меньше шаг — например, `1e-5` для первых блоков, `1e-4` для последнего и `1e-3` для головы. Ранние признаки универсальны, их почти не трогаем. Warmup и косинусное расписание делают дообучение ещё стабильнее.

## Подготовка входа

Изображения должны выглядеть так же, как при предобучении:

- тот же размер (обычно 224×224);
- значения в [0, 1], затем нормализация средними и стандартными отклонениями ImageNet: mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`;
- порядок каналов RGB (OpenCV читает картинки в BGR!);
- чёрно-белые снимки — повторить канал трижды.

Проще всего взять трансформации, поставляемые с весами: `ResNet50_Weights.IMAGENET1K_V2.transforms()` в torchvision, `timm.data.resolve_data_config` в timm, `preprocess_input` в Keras Applications.

## Пример на Python

Двухэтапное дообучение ResNet-50 в PyTorch на 5 классов (код требует torchvision и данные в `train_loader`):

```python
import torch
import torch.nn as nn
from torchvision.models import resnet50, ResNet50_Weights

weights = ResNet50_Weights.IMAGENET1K_V2
model = resnet50(weights=weights)
preprocess = weights.transforms()                 # правильный размер и нормализация

# Этап 1: feature extraction — замораживаем всё и меняем голову
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 5)     # новая голова обучаемая по умолчанию
optimizer = torch.optim.AdamW(model.fc.parameters(), lr=1e-3)
# ... несколько эпох обычного цикла обучения ...

# Этап 2: fine-tuning — размораживаем и учим с маленьким шагом по слоям
for p in model.parameters():
    p.requires_grad = True
optimizer = torch.optim.AdamW([
    {"params": model.layer3.parameters(), "lr": 2e-5},
    {"params": model.layer4.parameters(), "lr": 1e-4},
    {"params": model.fc.parameters(), "lr": 1e-3},
    {"params": [p for n, p in model.named_parameters()
                if not n.startswith(("layer3", "layer4", "fc"))], "lr": 1e-5},
], weight_decay=1e-4)
# ... ещё несколько эпох с ранней остановкой по валидации ...
```

В Keras аналог: `base = keras.applications.EfficientNetB0(include_top=False, weights="imagenet")`, `base.trainable = False`, а при сборке модели вызывать `base(x, training=False)` — тогда BatchNorm останется в режиме инференса и после разморозки.

## Подводные камни

- **Забытая нормализация** или BGR вместо RGB — модель «видит» не те картинки, и точность падает на десятки процентов без всякой ошибки.
- **Незаменённая голова**: 1000 выходов ImageNet вместо ваших классов.
- **«Замороженный» backbone, который всё равно меняется.** Заморозка весов не останавливает BatchNorm: в режиме `train()` его статистики обновляются по вашим батчам. При feature extraction и маленьких батчах держите BN в `eval()`.
- **Слишком большой learning rate** на всей сети разрушает признаки — точность после дообучения оказывается хуже, чем после одного этапа головы.
- **Утечка данных.** Одинаковые объекты или снимки одного пациента в train и validation дают завышенную оценку.
- **Аугментации без учёта домена.** Горизонтальный флип хорош для фотографий, но опасен для текста и некоторых медицинских снимков; поворот превращает 6 в 9.

## Итоги

- Transfer learning переиспользует признаки сети, обученной на большом датасете; голову всегда заменяют.
- Feature extraction — заморозить backbone и учить только голову; fine-tuning — дообучать слои с маленьким шагом.
- Стандартный рецепт: сначала голова, потом вся сеть с discriminative learning rate.
- Стратегию выбирают по объёму данных и близости домена к ImageNet.
- Вход должен совпадать с предобучением: размер, RGB, нормализация; BatchNorm при заморозке держат в `eval()`.
