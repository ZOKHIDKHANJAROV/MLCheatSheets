# Градиентный бустинг для классификации

<!-- время: 18 мин -->

> **О чём лекция.** Главная идея самых сильных моделей для табличных данных: деревья строятся по очереди, и каждое следующее исправляет ошибки предыдущих. Разберём, почему это градиентный спуск в пространстве функций, зачем нужен маленький learning rate, почему деревья в бустинге неглубокие и как не переобучиться.

## Зачем это нужно

Если у вас таблица — клиенты, транзакции, заказы, датчики — то с большой вероятностью лучшая модель для неё окажется градиентным бустингом над деревьями. XGBoost, LightGBM и CatBoost годами выигрывают соревнования Kaggle на табличных данных и работают в продакшене банков, маркетплейсов и рекламных систем. На таких данных они до сих пор часто обыгрывают нейросети.

Все эти библиотеки реализуют одну и ту же идею, отличаясь деталями. Разобравшись в ней, вы будете понимать, что означают их параметры и как их настраивать.

## Интуиция: команда, которая учится на ошибках

Случайный лес похож на совет независимых экспертов, которые голосуют одновременно. Бустинг устроен иначе — как конвейер исправлений. Первый эксперт делает грубый прогноз. Второй смотрит, где первый ошибся, и учится исправлять **именно эти ошибки**. Третий исправляет то, что осталось после первых двух, и так далее. Каждый эксперт по отдельности слабый, но вместе они строят очень точный прогноз.

| | бэггинг (случайный лес) | бустинг |
|---|---|---|
| как строятся деревья | независимо, параллельно | последовательно, каждое зависит от предыдущих |
| какие деревья | глубокие, переобученные | неглубокие, «слабые» |
| что уменьшает | дисперсию | смещение |
| риск переобучения от числа деревьев | нет | есть — нужна ранняя остановка |

## Как это работает

Начнём с регрессии и MSE — там всё видно напрямую.

1. Начальный прогноз F₀ — константа, например среднее значение y.
2. Считаем **остатки**: rᵢ = yᵢ − F(xᵢ) — насколько ошибается текущая модель.
3. Обучаем неглубокое дерево hₘ предсказывать эти остатки.
4. Добавляем его в модель с маленьким коэффициентом: `F ← F + η · hₘ`.
5. Повторяем шаги 2–4 M раз.

```
F(x) = F₀ + η·h₁(x) + η·h₂(x) + … + η·h_M(x)
```

**Почему «градиентный».** Для MSE остаток y − F — это ровно антиградиент функции потерь по прогнозу F (с точностью до множителя). Значит, каждое дерево показывает, в какую сторону сдвинуть прогнозы, чтобы ошибка уменьшилась быстрее всего. Это градиентный спуск, только шаги делаются не по весам, а по самим функциям-прогнозам.

Для любой другой дифференцируемой функции потерь всё так же: деревья обучаются на **псевдоостатках** — антиградиенте этой функции. Поэтому бустинг подходит для классификации, регрессии с MAE или Huber, ранжирования и многого другого.

**Классификация.** Модель F(x) выдаёт не вероятность, а «счёт» — логарифм шансов, как в логистической регрессии. Вероятность получается сигмоидой: `p = σ(F(x))`. Минимизируется log loss, а его антиградиент по счёту равен `y − p`: каждое новое дерево учится исправлять разницу между правильным ответом и текущей вероятностью. Для K классов строится K наборов счётов и softmax.

## Learning rate и число деревьев

`learning_rate` (η, shrinkage) — множитель вклада каждого дерева. Маленький шаг значит, что каждое дерево исправляет лишь часть ошибки, а следующим остаётся работа. Это работает как регуляризация: модель учится медленнее, но обобщает лучше.

Learning rate и число деревьев связаны: уменьшили η в 2 раза — нужно примерно в 2 раза больше деревьев. Типичная стратегия: взять η = 0.05–0.1, поставить большой лимит деревьев и использовать **раннюю остановку** — прекращать обучение, когда качество на валидации перестаёт улучшаться заданное число итераций.

## Почему деревья неглубокие

Каждое дерево должно сделать маленькую поправку, а не решить задачу целиком. Глубина 3–8 (или 15–63 листа) позволяет учитывать взаимодействия нескольких признаков, но не даёт одному дереву выучить шум. Бустинг снижает **смещение** шаг за шагом, складывая простые модели, поэтому слабые деревья ему подходят идеально — в отличие от случайного леса, которому нужны глубокие деревья с низким смещением.

## Борьба с переобучением

В отличие от леса, бустинг **переобучается** при слишком большом числе деревьев: поздние деревья начинают подгонять шум. Инструменты:

- ранняя остановка по валидации — главный;
- меньше learning rate и больше деревьев;
- ограничение сложности деревьев: глубина, число листьев, минимум объектов в листе;
- **стохастический бустинг**: каждое дерево учится на случайной доле объектов (`subsample` 0.7–0.9) и признаков;
- L1/L2-регуляризация весов листьев (есть в XGBoost, LightGBM, CatBoost).

## Пример на Python

Сначала — бустинг для регрессии «вручную», чтобы увидеть идею:

```python
import numpy as np
from sklearn.tree import DecisionTreeRegressor

rng = np.random.default_rng(0)
X = rng.uniform(-3, 3, size=(300, 1))
y = np.sin(X[:, 0]) * 3 + rng.normal(scale=0.3, size=300)

lr, pred = 0.1, np.full_like(y, y.mean())      # старт: константа
for m in range(100):
    residual = y - pred                        # антиградиент MSE — просто остатки
    tree = DecisionTreeRegressor(max_depth=2).fit(X, residual)
    pred += lr * tree.predict(X)               # маленький шаг в сторону исправления
    if m in (0, 9, 99):
        print(f"деревьев: {m + 1:3}, MSE на обучении: {np.mean((y - pred) ** 2):.3f}")

# деревьев:   1, MSE на обучении: 3.681
# деревьев:  10, MSE на обучении: 0.847
# деревьев: 100, MSE на обучении: 0.053
```

В работе используют готовые реализации. В sklearn самая быстрая — `HistGradientBoostingClassifier` (идея та же, что у LightGBM):

```python
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=5000, n_features=20, n_informative=8, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)

model = HistGradientBoostingClassifier(
    learning_rate=0.1, max_iter=1000,          # максимум деревьев
    max_leaf_nodes=31, early_stopping=True, validation_fraction=0.1,
    n_iter_no_change=20, random_state=0,
).fit(X_tr, y_tr)

print("деревьев после ранней остановки:", model.n_iter_)        # 101
print("accuracy:", round(model.score(X_te, y_te), 3))             # 0.959
print("ROC-AUC: ", round(roc_auc_score(y_te, model.predict_proba(X_te)[:, 1]), 3))   # 0.986
```

Из лимита в 1000 деревьев модель построила около сотни: дальше качество на валидационной части перестало расти, и обучение остановилось само. Для сравнения, случайный лес из 300 деревьев на этих данных даёт accuracy 0.941.

## Подводные камни

- **Нет ранней остановки** — главная причина переобучения бустинга. Всегда держите валидационную выборку или используйте встроенную остановку.
- **Валидация для остановки — не тест.** Если по тестовой выборке выбирается число деревьев, оценка на ней становится завышенной.
- **Слишком большой learning rate** (0.3–1) даёт быстрое, но грубое обучение и худшее итоговое качество.
- **Утечка в признаках** бустинг найдёт первым: он отлично использует любой признак, который «подсказывает» ответ. Подозрительно высокое качество — повод проверить признаки.
- **Экстраполяция**, как у всех деревьев, невозможна: прогноз не выходит за пределы того, что было в обучении.
- **Масштабирование не нужно**, а пропуски все современные реализации обрабатывают сами.

## Итоги

- Бустинг строит деревья последовательно: каждое новое учится на ошибках (антиградиенте потерь) текущей модели.
- Итоговая модель — сумма начального прогноза и вкладов деревьев с множителем learning rate.
- Неглубокие деревья + маленький learning rate + много итераций + ранняя остановка — базовый рецепт.
- Бустинг уменьшает смещение и может переобучиться при избытке деревьев, в отличие от случайного леса.
- XGBoost, LightGBM и CatBoost — реализации этой идеи с ускорениями и регуляризацией.
