# Кодирование категориальных признаков

<!-- время: 15 мин -->

> **О чём лекция.** Как превратить категории — города, тарифы, цвета — в числа так, чтобы модель могла их использовать, и какой способ кодирования выбрать для номинальных, порядковых и высококардинальных признаков.

## Зачем это нужно

Модели машинного обучения работают с числами. Признак «город» со значениями «Москва», «Казань», «Самара» нужно как-то превратить в числовой вид. Способ превращения не нейтрален: он определяет, какие зависимости модель сможет увидеть, а какие — ложно «увидит».

Категориальные признаки встречаются в каждой второй табличной задаче, а выбор кодирования может изменить качество модели не на проценты, а в разы.

## Интуиция: какая информация есть в категории

Категориальные признаки бывают разные:

- **номинальные** — без порядка: город, цвет, марка. «Синий» не больше и не меньше «красного»;
- **порядковые** — с естественным порядком: размер S < M < L, образование, уровень риска;
- **бинарные** — два значения: да/нет, пол в анкете.

Ещё важна **кардинальность** — число различных значений. Тариф из 3 вариантов и почтовый индекс из 30 тысяч требуют разных подходов.

Главный принцип: кодирование не должно добавлять информации, которой нет, и терять ту, что есть.

## Как это работает

### Ordinal / Label encoding

Каждой категории присваивается целое число: `blue → 0, green → 1, red → 2`.

- Для **порядковых** признаков — правильный выбор, если порядок задан явно: `OrdinalEncoder(categories=[["S", "M", "L", "XL"]])`. По умолчанию категории сортируются по алфавиту, и порядок может оказаться бессмысленным.
- Для **номинальных** признаков и **линейных моделей** — опасно: модель воспримет числа как величины, решит, что `red = 2` вдвое «больше» `green = 1`, и подберёт один общий наклон для всех городов.
- Для **деревьев** допустимо и для номинальных признаков: дерево может отделить любую категорию несколькими разбиениями.

`LabelEncoder` в scikit-learn предназначен для кодирования **целевой переменной**, а не признаков.

### One-hot encoding

Для каждой категории создаётся отдельный бинарный столбец:

```
город      →  город_Казань  город_Москва  город_Самара
Москва     →       0             1             0
Самара     →       0             0             1
```

Никакого ложного порядка: у каждой категории свой вес. Это стандарт для номинальных признаков с небольшой кардинальностью в линейных моделях, SVM и нейросетях.

Минусы: при тысячах категорий получаются тысячи столбцов (scikit-learn хранит их разреженно, но деревьям и памяти это всё равно тяжело), а редкие категории дают шумные веса. Параметр `min_frequency` объединяет редкие категории в одну, `max_categories` ограничивает их число.

Для линейной регрессии без регуляризации один столбец иногда удаляют (`drop="first"`), чтобы столбцы не были линейно зависимы — «ловушка фиктивных переменных».

### Target encoding

Категория заменяется средним значением цели среди объектов этой категории: «доля оттока в городе», «средний чек по марке». Один столбец вместо тысяч — отлично для высококардинальных признаков.

Опасность — **утечка**: для объекта, чья категория встречается редко, среднее цели почти равно его собственной цели. Модель получает подсказку ответа и переобучается. Защита:

- **сглаживание** — смешивать среднее категории с общим средним, тем сильнее, чем меньше объектов в категории;
- **подсчёт по фолдам** — для каждого объекта среднее считается по другим фолдам.

`TargetEncoder` в scikit-learn делает и то и другое: при `fit_transform` он использует внутреннюю кросс-валидацию. CatBoost использует похожую идею (упорядоченные статистики) встроенно.

### Другие способы

- **Frequency / count encoding** — частота категории; просто и без утечки.
- **Хеширование** (`FeatureHasher`) — фиксированное число столбцов для огромной кардинальности, ценой коллизий.
- **Эмбеддинги** — в нейросетях категория отображается в обучаемый вектор.

| признак | линейная модель / нейросеть | деревья и бустинги |
|---|---|---|
| бинарный | 0/1 | 0/1 |
| порядковый | ordinal с явным порядком | ordinal |
| номинальный, мало категорий | one-hot | one-hot или ordinal, встроенные категории |
| номинальный, тысячи категорий | target / frequency encoding, эмбеддинги | target encoding, встроенная поддержка CatBoost/LightGBM |

## Пример на Python

50 городов, у каждого свой «эффект» на цель. Сравним три кодирования с логистической регрессией.

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, OrdinalEncoder, TargetEncoder

rng = np.random.default_rng(0)
n = 2000
city = rng.choice([f"c{i}" for i in range(50)], n)          # 50 городов
effect = {c: rng.normal() for c in np.unique(city)}
y = (np.array([effect[c] for c in city]) + rng.normal(0, 1, n) > 0).astype(int)
X = pd.DataFrame({"city": city})

for name, enc in [("ordinal", OrdinalEncoder()),
                  ("one-hot", OneHotEncoder(handle_unknown="ignore")),
                  ("target", TargetEncoder())]:
    auc = cross_val_score(make_pipeline(enc, LogisticRegression()), X, y, cv=5, scoring="roc_auc").mean()
    print(f"{name:8s} ROC-AUC = {auc:.3f}")

# ordinal  ROC-AUC = 0.513   ← почти случайное угадывание
# one-hot  ROC-AUC = 0.790
# target   ROC-AUC = 0.790   ← то же качество одним столбцом вместо 50
```

С ordinal-кодированием линейная модель вынуждена искать одну прямую по номерам городов, а номера никак не связаны с эффектом — качество на уровне монетки. One-hot и target encoding извлекают всю информацию; при тысячах категорий target encoding выигрывает за счёт компактности.

## Подводные камни

- **Новые категории в продакшене.** Город, которого не было в обучении, не должен ронять сервис: `OneHotEncoder(handle_unknown="ignore")`, у `OrdinalEncoder` — `handle_unknown="use_encoded_value"`.
- **`pd.get_dummies` отдельно на train и test** даёт разные наборы столбцов. Используйте кодировщик scikit-learn, обученный на train.
- **Target encoding на всём датасете до разбиения** — классическая утечка; только внутри пайплайна и по фолдам.
- **Алфавитный порядок** в `OrdinalEncoder` для порядковых признаков: задавайте `categories` явно.
- **Редкие категории** дают шумные оценки и в one-hot, и в target encoding — объединяйте их или используйте сглаживание.

## Итоги

- Номинальные признаки — one-hot (для линейных моделей и нейросетей), порядковые — ordinal с явным порядком.
- Label/ordinal encoding номинальных признаков создаёт ложный порядок и вредит линейным моделям; деревьям это почти не мешает.
- Высококардинальные признаки — target encoding со сглаживанием и фолдами, frequency encoding, хеширование или эмбеддинги.
- Кодировщик обучается на train, живёт в пайплайне и умеет обрабатывать новые категории.
