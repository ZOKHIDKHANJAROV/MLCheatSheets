# Векторные представления слов (Word2Vec, GloVe, FastText)

<!-- время: 16 мин -->

> **О чём лекция.** Как превратить слово в вектор чисел так, чтобы похожие по смыслу слова оказались рядом: идея «слово определяется соседями», Word2Vec, GloVe и FastText, а также чем статические эмбеддинги отличаются от контекстных.

## Зачем это нужно

Нейросети работают с числами, а текст состоит из слов. Самый простой способ закодировать слово — **one-hot**: вектор длиной в размер словаря (скажем, 50 000), где одна единица стоит на позиции слова, а остальное — нули.

У one-hot две беды:

- **огромная размерность**: 50 000 чисел на слово, почти все нули;
- **нет смысла**: векторы «кошка» и «котёнок» так же далеки друг от друга, как «кошка» и «бетономешалка». Скалярное произведение любых двух разных слов равно нулю.

**Эмбеддинг** (векторное представление) — плотный вектор небольшой размерности (обычно 50–300 чисел), в котором похожие по смыслу слова расположены близко. Модель, получившая на вход эмбеддинги, сразу «знает», что «кошка» и «котёнок» похожи, и обобщает с одного на другое. Эмбеддинги — первый слой почти любой модели для текста, от классификатора отзывов до GPT.

## Интуиция: скажи мне, кто твой сосед

В основе лежит **дистрибутивная гипотеза**: слова, которые встречаются в похожих контекстах, имеют похожий смысл. Если вы видите «я налил в кружку горячий **___**», вы почти уверены, что там чай, кофе или какао — и эти слова действительно близки по смыслу.

Значит, чтобы получить вектор слова, не нужен словарь значений — достаточно большого корпуса текстов. Мы учим векторы так, чтобы по вектору слова можно было предсказать его соседей. Слова с одинаковыми соседями неизбежно получат похожие векторы.

Удивительное следствие — **линейные аналогии**. В хорошо обученных векторах разность «король − мужчина» близка к разности «королева − женщина»: она кодирует что-то вроде «королевскости». Поэтому `v(король) − v(мужчина) + v(женщина)` оказывается рядом с `v(королева)`. Это работает не всегда, но показывает, что направления в пространстве эмбеддингов несут смысл.

## Как это работает: Word2Vec

**Word2Vec** (Mikolov и соавторы, Google, 2013) — неглубокая сеть с двумя вариантами задачи:

- **Skip-gram**: по центральному слову предсказать слова в окне вокруг него. «кошка» → «пьёт», «молоко».
- **CBOW** (continuous bag of words): по соседям предсказать центральное слово.

У каждого слова два вектора: `v_c` — когда оно центральное, `u_o` — когда оно контекст. Вероятность того, что слово o — сосед слова c:

```
p(o | c) = exp(u_o · v_c) / Σ_w exp(u_w · v_c)
```

Знаменатель — сумма по всему словарю, это слишком дорого на каждом шаге. Поэтому используют **negative sampling**: вместо выбора из всего словаря модель решает бинарную задачу «настоящая пара (слово, сосед) или случайная пара». На каждую настоящую пару берут k случайных «шумовых» слов (k = 5–20 для малых корпусов, 2–5 для больших). Ещё один трюк — **subsampling**: очень частые слова («и», «в», «на») случайно выбрасывают, они почти не несут смысла.

Skip-gram лучше работает для редких слов, CBOW быстрее обучается.

## GloVe: глобальная статистика

**GloVe** (Stanford, 2014) идёт от другой стороны. Сначала по всему корпусу считается матрица совместной встречаемости `X_ij` — сколько раз слово j попадало в окно слова i. Затем векторы подбираются так, чтобы их скалярное произведение приближало логарифм этих счётчиков:

```
w_i · w̃_j + b_i + b̃_j ≈ log X_ij
```

Весовая функция `f(X_ij)` уменьшает вклад редких пар (шум) и ограничивает вклад слишком частых. Итоговое качество близко к Word2Vec; GloVe удобен тем, что есть готовые векторы, обученные на огромных корпусах.

## FastText: слово из кусочков

У Word2Vec и GloVe есть проблема **незнакомых слов** (OOV, out of vocabulary): если слова не было в обучении, вектора для него нет. Особенно больно для языков с богатой морфологией: у русского слова «кошка» десяток форм — «кошки», «кошкой», «кошкам»…

**FastText** (Facebook, 2017) представляет слово как сумму векторов его символьных n-грамм (обычно n = 3–6) плюс вектор самого слова:

```
v(«кошка») = z(«<ко») + z(«кош») + z(«ошк») + … + z(«ка>») + z(«<кошка>»)
```

Знаки `<` и `>` отмечают начало и конец слова. Теперь вектор можно построить даже для слова, которого не было в обучении, — из знакомых кусочков. Формы одного слова делят много n-грамм и получают близкие векторы.

## Как измеряют близость

Близость векторов меряют **косинусным сходством**:

```
cos(a, b) = a · b / (‖a‖ · ‖b‖)      от −1 до 1
```

Используют именно косинус, а не евклидово расстояние, потому что длина вектора связана с частотой слова, а смысл — с направлением.

## Статические и контекстные эмбеддинги

Word2Vec, GloVe и FastText дают **статические** эмбеддинги: у слова один вектор на все случаи. Но «ключ» от двери и «ключ» как родник — разные смыслы, а вектор один, усреднённый.

**Контекстные** эмбеддинги (ELMo, BERT и другие трансформеры) вычисляют вектор слова заново в каждом предложении с учётом соседей. Для большинства задач NLP сегодня используют их. Статические эмбеддинги остаются полезными, когда нужна скорость и простота: поиск похожих слов, признаки для лёгких моделей, инициализация слоя `nn.Embedding`.

## Пример на Python

Игрушечная демонстрация дистрибутивной гипотезы: опишем каждое слово тем, с какими словами оно встречается, и найдём ближайших соседей по косинусу.

```python
import numpy as np

corpus = [
    "кошка пьёт молоко", "кошка ловит мышь", "собака грызёт кость",
    "собака ловит мяч", "кошка спит дома", "собака спит дома",
    "король правит страной", "королева правит страной", "король носит корону",
    "королева носит корону",
]
sentences = [s.split() for s in corpus]
vocab = sorted({w for s in sentences for w in s})
idx = {w: i for i, w in enumerate(vocab)}

# Матрица совместной встречаемости: слова, стоящие в одном предложении
C = np.zeros((len(vocab), len(vocab)))
for s in sentences:
    for a in s:
        for b in s:
            if a != b:
                C[idx[a], idx[b]] += 1

# Вектор слова — строка матрицы: с какими словами оно встречается
emb = C

def cos(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

def nearest(word, k=2):
    v = emb[idx[word]]
    sims = [(cos(v, emb[i]), w) for w, i in idx.items() if w != word]
    return [w for _, w in sorted(sims, reverse=True)[:k]]

print(nearest("кошка"))      # ['собака', 'спит']
print(nearest("король"))     # ['королева', 'страной']
print(round(cos(emb[idx["кошка"]], emb[idx["собака"]]), 2),    # 0.5
      round(cos(emb[idx["кошка"]], emb[idx["корону"]]), 2))    # 0.0
```

«Король» и «королева» ни разу не встретились вместе, но их векторы оказались ближе всего — у них одинаковые соседи. Настоящие методы делают то же самое на миллиардах слов и сжимают векторы до 100–300 чисел.

Обучение Word2Vec на своём корпусе с библиотекой gensim:

```python
from gensim.models import Word2Vec

w2v = Word2Vec(sentences, vector_size=100, window=5, min_count=1,
               sg=1,              # 1 = skip-gram, 0 = CBOW
               negative=5, epochs=20)
print(w2v.wv.most_similar("кошка", topn=3))
```

## Подводные камни

- **Мало данных.** Word2Vec на нескольких тысячах предложений даёт шумные векторы. Для маленьких корпусов берите предобученные векторы (для русского есть готовые векторы FastText).
- **Лемматизация и регистр.** Без приведения к нижнему регистру «Кошка» и «кошка» — разные слова. Для Word2Vec на русском часто помогает лемматизация; FastText меньше в ней нуждается.
- **Аналогии — не тест качества.** Красивые «король − мужчина + женщина» встречаются, но многие аналогии не работают. Оценивайте эмбеддинги на своей задаче.
- **Предвзятость.** Векторы впитывают стереотипы корпуса (профессии и пол и т.п.). Это важно, если эмбеддинги используются в решениях о людях.
- **Многозначность.** У статического эмбеддинга один вектор на все смыслы слова; если это критично — нужны контекстные модели.
- **Косинус, а не расстояние.** Сравнивайте нормированные векторы.

## Итоги

- Эмбеддинг — плотный вектор слова, где похожие слова расположены рядом; one-hot такого не умеет.
- Идея: слово определяется контекстами, в которых встречается (дистрибутивная гипотеза).
- Word2Vec учит векторы, предсказывая соседей (skip-gram, CBOW) с negative sampling; GloVe приближает логарифм счётчиков совместной встречаемости.
- FastText собирает слово из символьных n-грамм и строит векторы даже для незнакомых слов.
- Статические эмбеддинги дают один вектор на слово, контекстные (BERT) — свой вектор в каждом предложении.
