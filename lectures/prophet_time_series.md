# Prophet и современные методы временных рядов

<!-- время: 15 мин -->

> **О чём лекция.** Как устроен Prophet — прогноз как сумма тренда, сезонностей и праздников, — почему он стал популярен в бизнесе, где он работает плохо, и какие современные подходы используют, когда рядов тысячи: бустинг на лагах и глобальные нейросетевые модели.

## Зачем это нужно

Аналитику нужно спрогнозировать число заказов на квартал. Данные дневные, есть недельный цикл (в выходные заказов больше), годовой цикл (пик перед Новым годом), праздники и пара изменений тренда (запуск рекламы, выход на новый рынок). ARIMA требует стационарности и подбора порядков, а аналитик не статистик.

Prophet создали в Facebook (2017) именно для такой ситуации: прогнозирование «в масштабе» силами аналитиков, которые разбираются в бизнесе, но не в теории временных рядов. Он устойчив к пропускам и выбросам, его компоненты легко объяснить, а параметры имеют понятный смысл.

## Интуиция: прогноз как сумма понятных частей

Prophet не пытается моделировать зависимость сегодняшнего значения от вчерашнего, как ARIMA. Вместо этого он смотрит на ряд как на **функцию времени**, сложенную из частей:

```
y(t) = g(t) + s(t) + h(t) + ε(t)
```

- `g(t)` — тренд: долгосрочное направление;
- `s(t)` — сезонности: недельная, годовая, при необходимости — свои;
- `h(t)` — эффекты праздников и событий;
- `ε(t)` — шум.

По сути, это регрессия по времени с хитро устроенными признаками. Поэтому Prophet спокойно переносит пропуски и неравномерный шаг: ему не нужен «предыдущий день», ему нужна только дата.

## Как это работает: тренд и точки излома

Тренд в Prophet — **кусочно-линейная** функция: прямая, которая в некоторых точках (changepoints, точках изменения тренда) может менять наклон.

```
линейный тренд:       g(t) = k·t + m
логистический тренд:  g(t) = C / (1 + exp(−k·(t − m)))
```

Prophet по умолчанию расставляет 25 кандидатов в точки излома в первых 80% истории и сам решает, в каких из них наклон действительно меняется. Гибкость регулирует параметр `changepoint_prior_scale` (по умолчанию 0.05): больше — тренд гибче и ловит изменения, но рискует переобучиться на шуме; меньше — тренд жёстче.

**Логистический тренд** нужен, когда у роста есть естественный потолок: число пользователей не превысит население региона. Потолок задают столбцом `cap`.

## Как это работает: сезонность через ряды Фурье

Сезонность моделируется **рядом Фурье** — суммой синусов и косинусов с периодом сезона P:

```
s(t) = Σ (aₖ·cos(2πkt/P) + bₖ·sin(2πkt/P)),  k = 1..N
```

Число гармоник N (`fourier_order`) управляет формой: при малом N сезонная кривая гладкая, при большом — может повторять резкие детали (например, всплеск в пятницу). По умолчанию для годовой сезонности N = 10, для недельной — N = 3. Свою сезонность (например, месячную) добавляют через `add_seasonality`.

Сезонность может быть **аддитивной** (по умолчанию) или **мультипликативной** (`seasonality_mode="multiplicative"`), если размах колебаний растёт вместе с рядом.

## Праздники и внешние регрессоры

Для каждого праздника Prophet оценивает отдельный эффект. Праздники передают таблицей с датами; окна `lower_window` и `upper_window` позволяют учесть дни до и после события (покупки перед Новым годом). Встроенные календари стран добавляются через `add_country_holidays`.

Внешние факторы — цену, рекламный бюджет, погоду — добавляют через `add_regressor`. Важно: значения регрессоров должны быть известны и на период прогноза.

## Где Prophet работает плохо

Prophet — удобный инструмент, но не универсальный. Он слаб, когда:

- **история короткая** — меньше пары сезонов, оценить годовую сезонность нельзя;
- **ряд определяется краткосрочной динамикой** (финансовые котировки, нагрузка серверов минута к минуте) — Prophet не использует последние значения ряда напрямую;
- **нет выраженной сезонности** и тренд нерегулярен;
- **нужна максимальная точность**: в независимых сравнениях Prophet нередко проигрывает хорошо настроенным ETS, ARIMA и даже сезонному наивному прогнозу.

Вывод: Prophet хорош как быстрый, объяснимый бейзлайн для бизнес-рядов с сильной сезонностью и праздниками, но его обязательно нужно сравнивать с простыми методами.

## Современные подходы: много рядов сразу

Классические модели (ARIMA, ETS, Prophet) строятся **отдельно для каждого ряда**. Когда рядов тысячи (товары × магазины), выгоднее **глобальные модели** — одна модель на все ряды, которая учится на общих закономерностях:

- **градиентный бустинг на признаках**: лаги (значение неделю назад), скользящие средние, календарные признаки, идентификатор товара. LightGBM в таком режиме выиграл соревнование M5 по прогнозированию продаж Walmart;
- **нейросетевые модели**: N-BEATS, DeepAR, Temporal Fusion Transformer, а в последние годы — предобученные «фундаментальные» модели для рядов (TimesFM, Chronos и другие), которые дают прогноз без обучения на ваших данных.

Удобные библиотеки — `statsforecast` (быстрые ARIMA/ETS для тысяч рядов), `neuralforecast`, `darts`, `sktime`.

## Пример на Python

Prophet по сути — регрессия на тренд и признаки Фурье. Соберём такую модель вручную на scikit-learn, чтобы увидеть идею:

```python
import numpy as np
from sklearn.linear_model import LinearRegression

rng = np.random.default_rng(1)
t = np.arange(730)                                  # два года по дням
y = 50 + 0.05 * t + 8 * np.sin(2 * np.pi * t / 7) + rng.normal(scale=2, size=730)

def features(t, period=7, order=3):
    cols = [t]                                      # g(t): линейный тренд
    for k in range(1, order + 1):                   # s(t): ряд Фурье
        cols += [np.sin(2 * np.pi * k * t / period), np.cos(2 * np.pi * k * t / period)]
    return np.column_stack(cols)

model = LinearRegression().fit(features(t[:700]), y[:700])
pred = model.predict(features(t[700:]))
print(f"наклон тренда: {model.coef_[0]:.3f}")                      # 0.050
print(f"MAE на последних 30 днях: {np.mean(np.abs(pred - y[700:])):.2f}")   # 1.98 — на уровне шума
```

С самим Prophet код такой же короткий. Данные — таблица со столбцами `ds` (дата) и `y` (значение):

```python
import pandas as pd
from prophet import Prophet

df = pd.DataFrame({"ds": pd.date_range("2023-01-01", periods=730), "y": y})
model = Prophet(changepoint_prior_scale=0.05, weekly_seasonality=True)
model.add_country_holidays(country_name="RU")
model.fit(df)

future = model.make_future_dataframe(periods=30)
forecast = model.predict(future)        # столбцы yhat, yhat_lower, yhat_upper
model.plot_components(forecast)         # тренд, сезонности и праздники по отдельности
```

## Подводные камни

- **Неправильный формат.** Prophet ждёт столбцы именно `ds` и `y`; дата должна быть датой, а не строкой с неоднозначным форматом.
- **Слишком гибкий тренд.** Большой `changepoint_prior_scale` даёт красивую подгонку на истории и дикий прогноз. Проверяйте на отложенном периоде.
- **Тренд в конце истории.** Если последний участок резко пошёл вверх, Prophet продлит этот наклон — проверьте, разумен ли он.
- **Регрессоры из будущего.** Если признак неизвестен на дату прогноза (фактическая погода, фактические продажи конкурента), модель на проверке будет выглядеть лучше, чем в реальности.
- **Нет сравнения.** Обязательно сравните с сезонным наивным прогнозом и ETS. Для проверки у Prophet есть функция `cross_validation` со скользящим началом прогноза.

## Итоги

- Prophet раскладывает ряд на кусочно-линейный тренд, сезонности (ряды Фурье) и эффекты праздников; по сути это регрессия по времени.
- Гибкость тренда — `changepoint_prior_scale`, форма сезонности — `fourier_order`, режим — аддитивный или мультипликативный.
- Сильные стороны: устойчивость к пропускам, интерпретируемость, учёт праздников. Слабые: короткие ряды, краткосрочная динамика, точность.
- Для тысяч рядов используют глобальные модели: бустинг на лаговых признаках и нейросетевые модели.
