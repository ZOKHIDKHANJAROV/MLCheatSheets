# Сериализация моделей

<!-- время: 12 мин -->

> **О чём лекция.** Как сохранить обученную модель в файл и потом надёжно её загрузить: pickle и joblib, что сохранять вместе с моделью, почему версии библиотек важны, в чём опасность чужих файлов и зачем нужен ONNX.

## Зачем это нужно

Обучение может занимать минуты, часы или недели. Повторять его при каждом запуске сервиса бессмысленно: модель обучают один раз, сохраняют в файл, а потом загружают там, где нужны предсказания — в API, в пакетном скрипте, на телефоне.

**Сериализация** — превращение объекта в памяти (модели со всеми весами и настройками) в последовательность байтов, которую можно записать в файл или передать по сети. **Десериализация** — обратный процесс. Звучит как техническая мелочь, но именно здесь возникает много проблем в продакшене: модель не загружается после обновления библиотек, ведёт себя иначе, потому что потеряли предобработку, или открывает дыру в безопасности.

## Интуиция: консервирование вместе с рецептом

Сохранённая модель похожа на консервы. Само содержимое (веса) хранится долго, но чтобы правильно им воспользоваться, нужно знать, как его готовили: какая предобработка применялась, какие признаки в каком порядке ожидаются, какой версией библиотеки всё это сделано. Поэтому сохраняют не только модель, но и «этикетку» — метаданные.

## Как это работает: основные форматы

| формат | что сохраняет | плюсы | минусы |
|---|---|---|---|
| `pickle` | любой объект Python | встроен в язык, работает со всем | небезопасен, зависит от версий кода |
| `joblib` | объекты Python, особенно с большими массивами NumPy | быстрее на больших массивах, умеет сжимать | те же риски, что у pickle |
| `state_dict` в PyTorch | только тензоры весов | компактно, не зависит от структуры кода | нужен код класса модели для загрузки |
| ONNX | граф вычислений и веса в открытом формате | запуск без Python, на разных платформах и ускорителях | не все операции и модели экспортируются |
| нативные форматы бустингов (`.json`, `.ubj` у XGBoost, `.txt` у LightGBM, `.cbm` у CatBoost) | деревья модели | стабильнее между версиями | только для своей библиотеки |

Для scikit-learn стандартный выбор — `joblib`:

```python
import joblib

joblib.dump(model, "model.joblib")            # сохранить
model = joblib.load("model.joblib")           # загрузить
joblib.dump(model, "model.joblib", compress=3)  # со сжатием, уровень 0–9
```

## Что сохранять вместе с моделью

**Предобработку.** Если модель обучалась на масштабированных признаках, то и предсказывать она должна на масштабированных, причём с теми же средними и дисперсиями, что были на обучении. Самый надёжный способ — сохранять весь `Pipeline` целиком: скейлер, кодировщики категорий и модель одним объектом. Тогда в сервисе просто нет шанса применить предобработку неправильно.

**Метаданные.** Небольшой JSON рядом с моделью:

- версии библиотек (`sklearn.__version__`, `numpy.__version__`, Python);
- список и порядок признаков;
- дата обучения, версия данных, коммит кода;
- метрики на валидации;
- контрольная сумма файла модели (SHA-256).

Контрольная сумма позволяет убедиться, что загружается именно тот файл, который сохраняли, а не повреждённый или подменённый.

## Версии библиотек

pickle и joblib сохраняют не «модель вообще», а внутреннее устройство объекта конкретной версии библиотеки. Если в новой версии scikit-learn класс изменился, старый файл может не загрузиться или загрузиться с предупреждением `InconsistentVersionWarning`, а в худшем случае тихо дать другие предсказания.

Правила:

- фиксируйте версии в `requirements.txt` и собирайте сервис в том же окружении, что и обучение (удобно через Docker);
- при загрузке сверяйте версии из метаданных с текущими;
- после обновления библиотек **переобучайте** модель или хотя бы сравнивайте предсказания старой и новой загрузки на контрольной выборке.

## Безопасность

`pickle.load` и `joblib.load` могут выполнить произвольный код, записанный в файле. Злоумышленнику достаточно подложить «модель», которая при загрузке, например, отправит ваши ключи доступа на чужой сервер. Поэтому:

- никогда не загружайте pickle и joblib из недоверенных источников;
- проверяйте контрольную сумму файлов;
- для обмена моделями с внешним миром используйте форматы без исполняемого кода: ONNX, `safetensors` для весов нейросетей, нативные форматы бустингов.

## PyTorch и ONNX

В PyTorch рекомендуют сохранять не весь объект модели, а только её веса — `state_dict`:

```python
torch.save(model.state_dict(), "weights.pt")

model = MyNet()                                    # нужен код класса
model.load_state_dict(torch.load("weights.pt", weights_only=True))
model.eval()
```

Так файл не зависит от того, где лежал код класса при сохранении, а `weights_only=True` запрещает загрузку произвольных объектов.

**ONNX** — открытый формат, в который можно экспортировать модели из PyTorch, TensorFlow и scikit-learn (через `skl2onnx`). ONNX-модель запускается в ONNX Runtime без исходного фреймворка, в том числе из C++, C#, Java и JavaScript, и часто работает быстрее. Это удобный способ отделить обучение (на Python) от инференса (в любом окружении).

## Пример на Python

Сохраняем пайплайн с метаданными и контрольной суммой, а при загрузке всё проверяем:

```python
import json, hashlib
import joblib, numpy as np, sklearn
from sklearn.datasets import make_classification
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = make_classification(n_samples=500, n_features=4, random_state=0)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X, y)

joblib.dump(model, "model.joblib")
meta = {
    "sklearn_version": sklearn.__version__,
    "features": ["f1", "f2", "f3", "f4"],
    "train_accuracy": round(model.score(X, y), 3),   # 0.836
    "sha256": hashlib.sha256(open("model.joblib", "rb").read()).hexdigest(),
}
json.dump(meta, open("model.json", "w"), indent=2)

# --- в сервисе ---
meta = json.load(open("model.json"))
digest = hashlib.sha256(open("model.joblib", "rb").read()).hexdigest()
assert digest == meta["sha256"], "файл модели изменён"
if meta["sklearn_version"] != sklearn.__version__:
    print("Внимание: модель сохранена в другой версии scikit-learn")
loaded = joblib.load("model.joblib")
print(np.array_equal(loaded.predict_proba(X), model.predict_proba(X)))   # True
```

Скейлер сохранён внутри пайплайна, поэтому загруженная модель даёт точно те же вероятности, что и исходная.

## Подводные камни

- **Сохранили только модель без предобработки.** В сервисе признаки не масштабированы или категории закодированы иначе — предсказания неверны, но ошибок нет.
- **Другая версия библиотеки.** Файл не загружается или работает иначе. Фиксируйте окружение.
- **Загрузка чужого pickle.** Это выполнение чужого кода на вашей машине.
- **Порядок признаков.** Модель на массиве NumPy не знает имён столбцов; если порядок в сервисе другой, предсказания бессмысленны. Храните список признаков в метаданных или передавайте DataFrame.
- **PyTorch без `model.eval()`.** Dropout и BatchNorm остаются в режиме обучения, и предсказания «плавают».

## Итоги

- Сериализация позволяет обучить модель один раз и использовать её где угодно.
- Для scikit-learn — `joblib`, для весов PyTorch — `state_dict`, для переносимого инференса — ONNX.
- Сохраняйте весь пайплайн с предобработкой и метаданные: версии, признаки, метрики, контрольную сумму.
- pickle и joblib зависят от версий библиотек и небезопасны для недоверенных файлов.
