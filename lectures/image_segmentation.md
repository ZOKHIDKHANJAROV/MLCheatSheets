# Сегментация изображений (U-Net, DeepLab, Mask R-CNN)

<!-- время: 16 мин -->

> **О чём лекция.** Как нейросеть размечает изображение попиксельно: виды сегментации, архитектура U-Net и роль skip-связей, атрусная свёртка в DeepLab, instance-сегментация в Mask R-CNN, функции потерь и метрики IoU, Dice и mIoU.

## Зачем это нужно

Классификация отвечает на вопрос «что на картинке?», детекция — «что и где, в виде прямоугольника?». Но иногда прямоугольника мало. Хирургу нужен точный контур опухоли, беспилотнику — какие именно пиксели относятся к дороге, а какие к тротуару, фоторедактору — силуэт человека, чтобы заменить фон.

**Сегментация** — задача присвоить метку **каждому пикселю** изображения. Это самая подробная форма понимания сцены в 2D.

## Три вида сегментации

| вид | что предсказывает | пример |
|---|---|---|
| семантическая (semantic) | класс каждого пикселя | все пиксели людей — класс «человек», без разделения на людей |
| экземплярная (instance) | отдельную маску для каждого объекта | человек 1, человек 2, человек 3 |
| паноптическая (panoptic) | объединение: класс каждого пикселя и номер экземпляра для «вещей» | люди и машины по отдельности, небо и дорога — сплошными областями |

В паноптической сегментации различают **things** — исчисляемые объекты (люди, машины), и **stuff** — аморфные области (небо, трава, дорога), у которых нет экземпляров.

## Интуиция: «что» и «где»

Сеть для классификации постепенно уменьшает изображение: пулинг и свёртки с шагом превращают картинку 224×224 в карту признаков 7×7. По пути сеть хорошо понимает, **что** изображено, но теряет точную информацию о том, **где** именно. Для сегментации нужно и то и другое: на выходе — карта того же размера, что и вход.

Поэтому почти все архитектуры сегментации — это **энкодер**, сжимающий изображение и извлекающий смысл, и **декодер**, восстанавливающий разрешение. Главный вопрос в том, как вернуть потерянные пространственные детали.

## Как это работает: U-Net

**U-Net** (2015, изначально для медицинских снимков) решает эту задачу симметричной архитектурой в форме буквы U.

- **Энкодер**: блоки из двух свёрток 3×3 с ReLU, после каждого блока — max-pooling 2×2. Разрешение уменьшается вдвое, число каналов растёт: 64 → 128 → 256 → 512 → 1024.
- **Декодер**: транспонированные свёртки (`ConvTranspose2d`) увеличивают разрешение вдвое на каждом шаге, число каналов уменьшается.
- **Skip-связи**: карта признаков энкодера того же разрешения **конкатенируется** с картой декодера. Энкодер «передаёт» декодеру мелкие детали — границы и текстуры, — потерянные при сжатии.
- **Выход**: свёртка 1×1 превращает 64 канала в число классов; для каждого пикселя получается вектор логитов.

Без skip-связей декодеру пришлось бы восстанавливать границы объектов из грубой карты 1/16 разрешения, и маски получались бы размытыми. U-Net хорошо обучается даже на сотнях размеченных изображений, особенно с аугментациями, поэтому до сих пор популярна в медицине и промышленности.

## DeepLab: атрусная свёртка

Другой путь сохранить разрешение — не сжимать изображение так сильно, но при этом видеть большой контекст. **Атрусная (расширенная, dilated) свёртка** — это свёртка «с дырками»: ядро 3×3 с dilation = 2 охватывает область 5×5, но по-прежнему имеет 9 весов. Рецептивное поле растёт без потери разрешения и без лишних параметров.

**DeepLab** использует блок **ASPP** (Atrous Spatial Pyramid Pooling): несколько параллельных атрусных свёрток с разной dilation (например, 6, 12, 18) плюс глобальный пулинг. Так сеть одновременно видит объекты разного масштаба. DeepLabv3+ добавляет лёгкий декодер для уточнения границ.

## Mask R-CNN: instance-сегментация

Семантическая сегментация не различает соседних людей — это одна сплошная область «человек». Для **instance**-сегментации нужно сначала найти объекты.

**Mask R-CNN** (2017) — это детектор Faster R-CNN с дополнительной «головой»: для каждого найденного прямоугольника маленькая свёрточная сеть предсказывает бинарную маску 28×28 внутри этого прямоугольника. Важная деталь — **RoIAlign** вместо RoI Pooling: координаты региона не округляются до целых ячеек, а признаки берутся билинейной интерполяцией. Для детекции небольшое смещение не критично, а для пиксельной маски — заметно.

## Функции потерь

Базовая потеря — **попиксельная кросс-энтропия**. Её проблема — дисбаланс классов: если опухоль занимает 1% снимка, модель, которая всё помечает как «фон», уже получает низкую потерю.

Поэтому используют потери, которые смотрят на перекрытие масок:

```
Dice = 2·|P ∩ T| / (|P| + |T|)
Dice loss = 1 − Dice
```

Dice оценивает, насколько предсказанная маска P совпадает с истинной T, независимо от площади фона. Часто комбинируют кросс-энтропию и Dice loss. **Focal loss** снижает вклад лёгких пикселей и тоже помогает при дисбалансе.

## Метрики

**IoU** (Intersection over Union, индекс Жаккара) для одного класса:

```
IoU = |P ∩ T| / |P ∪ T|
```

**mIoU** — среднее IoU по всем классам; это основная метрика семантической сегментации. **Pixel accuracy** (доля правильных пикселей) считается легко, но обманчива: большой фон делает её высокой даже при плохих масках. Для instance-сегментации используют **mask AP** — как в детекции, но с IoU по маскам.

## Пример на Python

IoU, Dice и mIoU на NumPy для маленькой маски 8×8:

```python
import numpy as np

def iou_dice(pred, true):
    inter = np.logical_and(pred, true).sum()
    union = np.logical_or(pred, true).sum()
    return inter / union, 2 * inter / (pred.sum() + true.sum())

def miou(pred, true, n_classes):
    ious = []
    for c in range(n_classes):
        p, t = pred == c, true == c
        if t.sum() == 0 and p.sum() == 0:
            continue                        # класса нет нигде — не учитываем
        ious.append(np.logical_and(p, t).sum() / np.logical_or(p, t).sum())
    return float(np.mean(ious))

true = np.zeros((8, 8), dtype=int); true[2:6, 2:6] = 1   # объект 4×4
pred = np.zeros((8, 8), dtype=int); pred[3:7, 2:6] = 1   # сдвинут на 1 пиксель вниз

iou, dice = iou_dice(pred == 1, true == 1)
print(round(iou, 3), round(dice, 3))    # 0.6 0.75
print(round(miou(pred, true, 2), 3))    # 0.723 — среднее IoU объекта и фона
print((pred == true).mean())            # 0.875 — pixel accuracy выглядит лучше
```

Сдвиг маски всего на один пиксель снижает IoU объекта до 0.6, а pixel accuracy остаётся 87.5% — потому что большая часть изображения — правильно угаданный фон. Dice всегда не меньше IoU для одной и той же пары масок.

## Подводные камни

- **Pixel accuracy как основная метрика.** При большом фоне она почти ничего не говорит о качестве масок.
- **Дисбаланс классов.** Одна кросс-энтропия игнорирует маленькие объекты; добавьте Dice или focal loss, веса классов.
- **Аугментации только изображения.** Повороты и отражения нужно применять одинаково и к картинке, и к маске. Для маски — интерполяция «ближайший сосед», иначе появятся дробные классы.
- **Слишком сильное сжатие.** Маленькие объекты исчезают на карте 1/32; помогают skip-связи, FPN и атрусные свёртки.
- **Неточная разметка границ.** Качество масок ограничено качеством разметки; на границах объектов разметчики часто расходятся.

## Итоги

- Сегментация присваивает метку каждому пикселю: semantic — класс, instance — отдельные объекты, panoptic — оба.
- Архитектура — энкодер (что) и декодер (где); U-Net передаёт детали через skip-связи.
- DeepLab расширяет рецептивное поле атрусными свёртками и ASPP без потери разрешения.
- Mask R-CNN = детектор + голова масок с RoIAlign.
- Потери: кросс-энтропия плюс Dice или focal при дисбалансе. Метрики: IoU и mIoU, а не pixel accuracy.
