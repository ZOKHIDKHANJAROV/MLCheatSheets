# Память агента

<!-- время: 16 мин -->

> **О чём лекция.** Как ИИ-агент «помнит»: что такое кратковременная и долговременная память, как сжимать историю, какие бывают типы воспоминаний, что и когда записывать, как поднимать нужное из хранилища и как осознанно забывать.

## Зачем это нужно

Языковая модель не хранит состояния между вызовами: всё, что она знает о текущем диалоге и задаче, — это текст в её **контекстном окне**. Окно конечно, а каждый токен стоит денег и времени. Если агент работает днями, ведёт длинный диалог или должен помнить предпочтения пользователя, ни «положить всю историю в prompt», ни «ничего не помнить» не подходят.

Поэтому агенту нужна **память** — механизм, который решает, что держать в контексте сейчас, что сохранить на будущее и что можно выбросить.

## Интуиция: рабочий стол и архив

Рабочий стол — это кратковременная память: на нём лежит то, что нужно прямо сейчас, и места мало. Архив в шкафу — долговременная память: вмещает много, но нужную папку надо найти и принести на стол. Хороший сотрудник регулярно решает три вещи:

1. что принести из архива на стол (поиск воспоминаний);
2. что положить в архив из сделанного (запись);
3. что давно не нужно и можно выбросить (забывание).

## Как это работает

### Кратковременная память

Это содержимое контекстного окна: системная инструкция, недавние сообщения, результаты инструментов, найденные воспоминания. Простейшая политика — **скользящее окно**: оставлять последние сообщения в пределах бюджета токенов. Инструкцию и цель задачи из окна не вытесняют, большие ответы инструментов обрезают или хранят вне контекста.

### Суммаризация истории

Когда история перестаёт помещаться, старую её часть заменяют краткой **сводкой**, а последние сообщения оставляют дословно. Сводку обычно делает сама модель. Работает при условии, что в сводку попадают факты, принятые решения, открытые вопросы и имена, а не пересказ реплик. Недостаток: сводка теряет детали, а при многократном сжатии ошибки накапливаются, поэтому важное лучше сохранять в долговременную память до сжатия.

### Типы долговременной памяти

| тип | что хранит | пример |
|---|---|---|
| эпизодическая | события: что, когда и чем закончилось | «12 мая запуск упал из-за нехватки памяти» |
| семантическая | факты и предпочтения без привязки ко времени | «пользователь пишет на Python» |
| процедурная | как действовать: инструкции, навыки, шаблоны | «для отчёта сначала выгрузка, затем проверка пропусков» |

Эпизоды чаще хранят в векторном хранилище и ищут по сходству; факты — в базе «ключ — значение» или тоже в векторном хранилище; процедурную память нередко оформляют как правила в системной инструкции.

### Что и когда записывать

Записывать всё подряд — значит засорять поиск. Практическая политика:

- **Записывают:** явные предпочтения и ограничения, принятые решения, итоги задач, исправленные ошибки, устойчивые факты о пользователе или проекте.
- **Не записывают:** болтовню, повторы, промежуточные рассуждения, секреты и персональные данные, которые пользователь не просил хранить.
- **Когда:** по завершении шага или задачи, перед сжатием контекста, по явной просьбе «запомни».
- Если факт изменился, запись **обновляют** (по ключу), а не дописывают противоречащую копию.

### Поиск воспоминаний

Воспоминание хранят как текст, вектор и метаданные (время, важность, тип). Достают по комбинации сходства, свежести и важности — идея, популяризированная работами про «генеративных агентов»:

```
score = w₁ · sim(q, m) + w₂ · recency(m) + w₃ · importance(m)
recency(m) = 0.5 ^ (Δt / T½)
```

где Δt — время с последнего обращения к воспоминанию, T½ — период полураспада свежести, а importance задаётся при записи (например, самой моделью или правилами).

### Забывание

Память растёт, а поиск зашумляется и дорожает. Стратегии забывания:

- **по давности** (LRU): вытеснять то, к чему давно не обращались;
- **по важности:** низкая важность уходит первой;
- **TTL:** срок жизни для временных фактов;
- **слияние и дедупликация:** похожие записи объединять, цепочки эпизодов сворачивать в обобщение;
- **явное удаление:** по просьбе пользователя и для устаревших фактов.

Простая комбинированная ценность записи: value = a · importance + b · recency; при переполнении удаляют записи с наименьшей ценностью.

## Пример на Python

Мини-память агента на NumPy с «игрушечным» эмбеддингом: скользящее окно, сжатие истории, запись и поиск воспоминаний, забывание. Вызовов LLM нет — сводка заменена заглушкой.

```python
import re
import zlib
import numpy as np


def embed(text, dim=64):
    v = np.zeros(dim)
    for w in re.findall(r"\w+", text.lower()):
        v[zlib.crc32(w.encode()) % dim] += 1.0
    n = np.linalg.norm(v)
    return v / n if n else v


def trim(history, budget=30):
    """Скользящее окно: последние сообщения в пределах бюджета (слова вместо токенов)."""
    kept, used = [], 0
    for msg in reversed(history):
        n = len(msg.split())
        if used + n > budget:
            break
        kept.append(msg)
        used += n
    return kept[::-1]


def compress(history, keep_last=4):
    """Старое заменяем сводкой (здесь — заглушка вместо вызова LLM)."""
    old, recent = history[:-keep_last], history[-keep_last:]
    if not old:
        return history
    return ["[сводка] " + " / ".join(m[:20] for m in old)] + recent


class Memory:
    def __init__(self, half_life=20.0):
        self.items, self.t, self.half_life = [], 0, half_life

    def write(self, text, importance=0.5, kind="semantic"):
        self.t += 1
        self.items.append({"text": text, "vec": embed(text), "imp": importance,
                           "last": self.t, "kind": kind})

    def _recency(self, m):
        return 0.5 ** ((self.t - m["last"]) / self.half_life)

    def recall(self, query, k=2, w=(1.0, 0.5, 0.5)):
        self.t += 1
        q = embed(query)
        score = lambda m: (w[0] * float(m["vec"] @ q) + w[1] * self._recency(m)
                           + w[2] * m["imp"])
        best = sorted(self.items, key=score, reverse=True)[:k]
        for m in best:
            m["last"] = self.t                     # обращение освежает воспоминание
        return [m["text"] for m in best]

    def forget(self, capacity, a=0.6, b=0.4):
        value = lambda m: a * m["imp"] + b * self._recency(m)
        self.items.sort(key=value, reverse=True)
        dropped, self.items = self.items[capacity:], self.items[:capacity]
        return [m["text"] for m in dropped]


history = [f"сообщение номер {i} с несколькими словами" for i in range(10)]
print(len(trim(history)), "сообщений влезло в окно из", len(history))
print(len(compress(history)), "строк после сжатия истории")

mem = Memory()
mem.write("пользователь любит краткие ответы", importance=0.8)
mem.write("в среду обсуждали отчёт по продажам", importance=0.4, kind="episodic")
mem.write("мелкая реплика про погоду", importance=0.1)
print(mem.recall("как отвечать пользователю", k=1))
print("забыто:", mem.forget(capacity=2))
```

Здесь recency пересчитывается при каждом обращении, а важность записана при создании. Измените `half_life` и веса `w` и посмотрите, как меняется выдача `recall`.

## Подводные камни

- **Вся история дословно в контексте.** Окно переполняется, дорожает и «теряет» середину; нужны окно, сводка и поиск.
- **Гипотезы записаны как факты.** Если агент сохраняет собственные догадки, ошибка закрепляется и будет всплывать снова. Отделяйте проверенные факты от предположений и храните источник записи.
- **Противоречивые записи.** Новый факт нужно обновлять по ключу, иначе в поиск попадут и старая, и новая версия.
- **Нет политики забывания.** Шум растёт, качество поиска падает, стоимость растёт.
- **Сжатие без сохранения.** Если важная деталь пропала из сводки и не была записана в долговременную память, вернуть её нельзя.
- **Приватность.** Секреты и персональные данные не должны попадать в память без разрешения; у пользователя должна быть возможность увидеть и удалить свои записи.
- **Отравление памяти.** Текст, пришедший из недоверенного источника (веб-страница, письмо), может попасть в память и повлиять на будущие решения; такие записи нужно помечать и проверять.

## Итоги

- Кратковременная память — контекстное окно; она конечна, поэтому историю обрезают скользящим окном и сжимают в сводку.
- Долговременная память — внешнее хранилище: эпизодическая (события), семантическая (факты), процедурная (как действовать).
- Записывают устойчивое и важное, факт обновляют, а не дублируют; воспоминания достают по сходству, свежести и важности.
- Забывание (по давности, важности, TTL, слиянию, явному удалению) держит память чистой.
- Риски памяти — закрепление ошибок, приватность и отравление; на них отвечают метки источника и контроль записей.
