# Коллаборативная фильтрация (user-based, item-based) — вопросы для самопроверки

### Чем user-based подход отличается от item-based?
**User-based** ищет пользователей с похожими вкусами и рекомендует то, что понравилось им. **Item-based** ищет объекты, похожие на те, что пользователь уже оценил, где сходство объектов считается по оценкам всех пользователей.

### Почему в промышленных системах чаще используют item-based?
Объектов обычно меньше, чем пользователей, а их сходства стабильнее во времени, поэтому матрицу сходства объектов можно предрассчитать офлайн и редко обновлять. Вкусы пользователей меняются быстро, и user-based требует постоянного пересчёта; классический пример — item-to-item у Amazon.

### Зачем при расчёте сходства центрировать оценки (adjusted cosine, корреляция Пирсона)?
Пользователи по-разному используют шкалу: один ставит в основном 4–5, другой 2–3. Вычитание среднего пользователя убирает это смещение, и сходство отражает относительные предпочтения, а не щедрость оценок.

### Почему сходство по двум-трём общим оценкам ненадёжно и как с этим бороться?
Совпадение на малом числе общих объектов может дать сходство ≈ 1 случайно. Используют **shrinkage** — уменьшение сходства пропорционально n / (n + λ), где n — число общих оценок, — и порог минимального числа общих объектов.

### Как предсказать оценку пользователя для объекта в item-based подходе?
Берут k наиболее похожих объектов, которые пользователь уже оценил, и считают взвешенное среднее: r̂ᵤᵢ = ∑ sim(i, j)·rᵤⱼ / ∑ |sim(i, j)|. Ограничение k ближайшими соседями снижает шум от слабо похожих объектов.
