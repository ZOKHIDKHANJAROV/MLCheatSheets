# Память агента — вопросы для самопроверки

### Чем кратковременная память агента отличается от долговременной?
Кратковременная — это содержимое контекстного окна (инструкция, недавние сообщения, результаты инструментов, найденные воспоминания): конечна и существует на время запроса или сессии. Долговременная — внешнее хранилище (векторное, база фактов), которое переживает сессии и из которого нужное поднимают в окно по запросу.

### Как справиться с историей, которая не помещается в контекстное окно?
Скользящее окно оставляет последние сообщения в пределах бюджета токенов, а старую часть заменяют сводкой (её делает LLM). Системную инструкцию и цель задачи не вытесняют. Сводка теряет детали, поэтому важные факты записывают в долговременную память до сжатия.

### Какие бывают типы долговременной памяти? Приведите примеры.
Эпизодическая — события («12 мая запуск упал из-за нехватки памяти»), семантическая — факты и предпочтения («пользователь пишет на Python»), процедурная — как действовать («для отчёта сначала выгрузка, затем проверка пропусков»). Эпизоды ищут по сходству и времени, факты — по ключу или вектору, процедуры часто оформляют правилами в системной инструкции.

### Что и когда стоит записывать в память?
Записывают явные предпочтения и ограничения, принятые решения, итоги задач, исправленные ошибки, устойчивые факты. Не записывают болтовню, повторы, промежуточные рассуждения, секреты и персональные данные без разрешения. Момент записи — конец шага или задачи, перед сжатием контекста, по команде «запомни». Изменившийся факт обновляют по ключу, а не дописывают рядом.

### Как выбирают воспоминания при поиске и чему равна свежесть через 40 единиц времени без обращения при периоде полураспада 20?
Обычно score = w₁·sim + w₂·recency + w₃·importance, где recency = 0.5^(Δt / T½). При Δt = 40 и T½ = 20 recency = 0.5² = 0.25. Обращение к воспоминанию «освежает» его (обнуляет Δt).

### Зачем нужно забывание и какие бывают стратегии?
Без него память растёт, поиск зашумляется и дорожает, а устаревшие факты вредят ответам. Стратегии: вытеснение по давности (LRU) или по важности, TTL для временных фактов, слияние и дедупликация похожих записей, обобщение эпизодов, явное удаление по просьбе пользователя. Простая оценка: value = a·importance + b·recency, при переполнении удаляют минимальные.
