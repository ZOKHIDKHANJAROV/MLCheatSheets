# CI/CD для ML — вопросы для самопроверки

### Чем CI/CD для ML отличается от CI/CD обычного приложения?
Помимо кода, проверяются данные и модели: валидация схемы и распределений данных, проверка качества модели на эталонных метриках, сравнение с текущей продакшен-моделью. Добавляется непрерывное обучение (CT) — автоматическое переобучение.

### Какие тесты имеет смысл запускать в CI для ML-проекта?
Юнит-тесты кода признаков и предобработки, проверки схемы данных, быстрое обучение на маленькой выборке (smoke test), тесты инвариантности и направленности прогнозов, проверку, что метрики не хуже порога.

### Что такое «quality gate» для модели?
Автоматическое условие перед развёртыванием: новая модель должна превзойти текущую (или порог) по ключевым метрикам на фиксированном тесте и пройти проверки на задержку, размер и справедливость. Иначе релиз блокируется.

### Почему в CI не стоит полностью обучать большую модель на каждый коммит?
Это долго и дорого. В CI запускают быстрые проверки на малых данных, а полное обучение — отдельным пайплайном: по расписанию, при изменении данных или по ручному запуску.

### Как обеспечить воспроизводимость сборки модели?
Фиксировать версии зависимостей (lock-файл, Docker-образ), версии данных (DVC или снимки), random seed, конфигурацию эксперимента; логировать всё в трекинге экспериментов.
