# Feature stores — вопросы для самопроверки

### Что такое feature store и какие задачи он решает?
Централизованное хранилище признаков с их определениями. Устраняет дублирование расчётов между командами, обеспечивает одинаковые признаки при обучении и в продакшене, хранит историю значений и метаданные.

### Чем офлайн-хранилище отличается от онлайн-хранилища?
Офлайн (хранилище данных, озеро) — полная история признаков для обучения и пакетных прогнозов. Онлайн (key-value: Redis, DynamoDB) — последние значения признаков для быстрой выдачи при онлайн-инференсе с низкой задержкой.

### Что такое point-in-time correct join и зачем он нужен?
При сборке обучающей выборки для каждого события берутся значения признаков ровно на момент события, а не более поздние. Иначе в обучение попадёт информация из будущего — утечка данных, и модель будет выглядеть лучше, чем есть.

### Как feature store помогает против training-serving skew?
Признак описывается один раз, и одно определение используется и для подготовки обучающих данных, и для выдачи в продакшене. Расчёты не расходятся из-за разного кода.

### Когда feature store не нужен?
Для небольшого проекта с одной моделью и пакетными прогнозами это лишняя инфраструктура. Он окупается, когда моделей и команд много, признаки переиспользуются и нужен онлайн-инференс.
