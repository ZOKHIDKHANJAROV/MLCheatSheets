# Model Context Protocol (MCP) — вопросы для самопроверки

### Какую проблему решает MCP?
Проблему N×M: если N приложений хотят работать с M внешними системами, без стандарта нужно писать N·M отдельных коннекторов. MCP задаёт общий протокол: каждое приложение реализует клиент, каждая система — сервер, и вместе получается N + M реализаций, а любой совместимый клиент работает с любым совместимым сервером.

### Кто такие host, клиент и сервер в MCP?
Host — приложение с моделью (чат, IDE, агент). Клиент — компонент внутри host, который держит соединение ровно с одним сервером. Сервер — программа, открывающая возможности: файлы, базы данных, внешние API. Host может одновременно держать несколько клиентов и подключаться ко многим серверам; решения о вызовах принимает host, а не сам сервер.

### Какие три типа возможностей предоставляет сервер MCP?
Tools — функции, которые что-то делают (поиск, запись, запрос), их вызывает модель. Resources — данные для контекста (файлы, записи, документы), ими управляет приложение. Prompts — готовые шаблоны запросов, обычно с параметрами, которые выбирает пользователь. Различие — в том, кто решает, что использовать.

### Какие транспорты есть у MCP и чем они отличаются?
stdio: host запускает сервер как дочерний процесс, сообщения идут через стандартные ввод и вывод — просто и локально. HTTP: сервер доступен по сети, запросы клиента идут по HTTP, а ответы и уведомления могут приходить потоком — подходит для удалённых серверов, но требует аутентификации. Формат сообщений (JSON-RPC) одинаков для обоих.

### Чем запрос, ответ и уведомление отличаются в JSON-RPC?
Запрос содержит method и id; ответ — тот же id и либо result, либо error (с кодом и сообщением); уведомление содержит method, но не содержит id и ответа не ждёт. Ответ связывается с запросом по id, причём номера выдаёт каждая сторона независимо, поэтому ключ сопоставления — пара «кто спрашивал + id».

### Какие меры безопасности нужны при подключении серверов MCP?
Относиться к серверу как к стороннему коду и подключать только доверенные. Давать минимальные права: нужные папки и данные. Опасные действия (запись, удаление, отправка) подтверждает пользователь. Результаты инструментов — это данные, а не команды: в них может быть prompt injection. Проверять аргументы, ограничивать размер ответов, ставить таймауты и вести журнал вызовов. Сам протокол безопасность не гарантирует.
