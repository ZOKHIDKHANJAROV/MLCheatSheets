# Feature Engineering (подробно) — вопросы для самопроверки

### Почему для признаков с сильной правой асимметрией (доход, цены) применяют log1p?
Логарифм сжимает длинный хвост, уменьшает влияние выбросов и делает зависимость ближе к линейной. **log1p(x) = log(1 + x)** корректно работает при x = 0.

### Чем опасны агрегатные признаки по группам (например, среднее значение по клиенту)?
Если агрегат считается по всем данным, включая текущий объект или будущие записи, возникает утечка. Агрегаты нужно считать только по прошлым данным или по фолдам (out-of-fold).

### Как обработать пропуски, если сам факт пропуска несёт информацию?
Добавить бинарный признак-индикатор `is_missing`, а значение импутировать (медианой, константой). В sklearn это делает `SimpleImputer(add_indicator=True)`. Бустинги вроде LightGBM и XGBoost умеют обрабатывать NaN сами.

### Когда стоит удалять признаки, а не добавлять новые?
Когда признаки константны или почти константны, дублируют друг друга (сильная корреляция), являются идентификаторами или несут утечку. Лишние шумные признаки увеличивают дисперсию модели и время обучения.

### Как проверить, что новый признак действительно полезен?
Сравнить метрику на **кросс-валидации** с признаком и без него при прочих равных, а также посмотреть permutation importance на валидации. Важность по встроенным оценкам дерева может быть завышена для признаков с большим числом уникальных значений.
