# Cross-modal retrieval — вопросы для самопроверки

### В чём суть задачи cross-modal retrieval?
Найти объекты одной модальности по запросу из другой: изображения по тексту, тексты по изображению, видео по описанию, музыку по описанию. Обычно обе модальности отображают в **общее пространство эмбеддингов**, где близость соответствует смысловому совпадению.

### Чем отличаются dual-encoder и cross-encoder для поиска?
**Dual-encoder** (CLIP) кодирует запрос и документы независимо, поэтому эмбеддинги базы считаются заранее и поиск выполняется быстрым ANN-индексом. **Cross-encoder** обрабатывает пару совместно через attention — точнее, но требует прогона модели для каждой пары. На практике dual-encoder отбирает кандидатов, cross-encoder их **переранжирует**.

### Как считается метрика Recall@K в retrieval и чему она равна в примере?
Доля запросов, для которых правильный ответ попал в top-K выдачи. Если из 200 текстовых запросов для 150 нужное изображение оказалось в первых 5 результатах, то Recall@5 = 150 / 200 = **0.75**.

### Зачем нужны hard negatives при обучении поиска?
Случайные негативы слишком легко отличить, и модель быстро перестаёт получать полезный сигнал. **Трудные негативы** (похожие, но неправильные пары) заставляют учить тонкие различия; но слишком «трудные» могут оказаться ложными негативами — фактически правильными ответами без разметки.

### Что такое проблема hubness в пространстве эмбеддингов?
В высокой размерности некоторые точки («хабы») оказываются ближайшими соседями для непропорционально многих запросов и попадают в выдачу почти всегда. Это портит поиск; помогают нормализация, центрирование эмбеддингов и методы переоценки сходства, например CSLS или inverted softmax.
