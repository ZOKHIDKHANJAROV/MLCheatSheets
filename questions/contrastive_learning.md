# Contrastive Learning (SimCLR, MoCo, BYOL) — вопросы для самопроверки

### Как устроен loss InfoNCE (NT-Xent) в SimCLR?
Для каждого вида объекта позитив — второй вид того же объекта, негативы — все остальные 2(N − 1) видов в батче. Loss — кросс-энтропия softmax по косинусным сходствам, делённым на **температуру** τ: −log(exp(sim(zᵢ, zⱼ)/τ) / ∑ₖ exp(sim(zᵢ, zₖ)/τ)).

### Почему для SimCLR критичны аугментации?
Аугментации определяют, к чему представление станет **инвариантным**. Авторы показали, что особенно важна комбинация random crop и цветовых искажений: без color jitter сеть «читерит», сравнивая цветовые гистограммы двух кропов, вместо изучения смысла.

### Какую проблему решает MoCo и как?
SimCLR нужен огромный батч ради большого числа негативов. MoCo хранит **очередь** эмбеддингов прошлых батчей как негативы, а ключи для неё считает **momentum-энкодер** — экспоненциальное скользящее среднее основного; так негативы остаются согласованными, и можно иметь десятки тысяч негативов при обычном батче.

### Как BYOL обходится без негативных примеров и не коллапсирует?
Online-сеть с дополнительным **predictor** предсказывает представление target-сети, которая является EMA online-сети, а градиент через target не идёт. Эта асимметрия (predictor + stop-gradient + EMA) на практике предотвращает тривиальное решение, хотя строгое объяснение до сих пор обсуждается.

### Зачем в SimCLR проекционная голова и почему её отбрасывают после обучения?
Contrastive loss применяется к выходу небольшой MLP-головы g(h), а не к самому представлению h. Голова «впитывает» инвариантности, нужные только для loss, и теряет полезную информацию (например, о цвете), поэтому для downstream-задач берут **h — представление до головы**, оно заметно лучше.
