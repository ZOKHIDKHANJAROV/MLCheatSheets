# Детекция ключевых точек и оценка позы — вопросы для самопроверки

### Почему ключевые точки чаще предсказывают через тепловые карты, а не прямой регрессией координат?
Heatmap сохраняет пространственную структуру: сеть остаётся полностью свёрточной и для каждой точки выдаёт «гауссиану» вероятности. Это обучается стабильнее и точнее, чем регрессия двух чисел из глобального вектора; координату затем берут как argmax или soft-argmax карты.

### Чем отличаются подходы top-down и bottom-up к оценке позы нескольких людей?
**Top-down**: сначала детектор находит людей, затем для каждого бокса отдельно ищутся точки — точно, но время растёт с числом людей. **Bottom-up** (OpenPose): находятся все точки на кадре сразу, а затем группируются по людям (например, через Part Affinity Fields) — время почти не зависит от числа людей.

### Что такое метрика OKS и зачем она нужна?
Object Keypoint Similarity — аналог IoU для ключевых точек: усреднённое exp(−dᵢ² / (2s²kᵢ²)) по видимым точкам, где d — ошибка, s — масштаб объекта, kᵢ — константа точки. Она нормирует ошибку на размер человека и «сложность» точки, и по порогам OKS считают AP в COCO.

### Какая ловушка возникает при горизонтальном отражении изображения как аугментации?
После флипа нужно не только отразить координаты, но и **поменять местами** парные метки: левое запястье становится правым и наоборот. Иначе модель получит противоречивую разметку и будет путать стороны тела.

### Как обрабатывать невидимые (закрытые) ключевые точки при обучении?
В разметке у точек есть флаг видимости; для неразмеченных точек loss обычно **маскируют**, чтобы не штрафовать модель за случайное положение. Для размеченных, но закрытых точек можно обучать предсказание — это помогает модели выучить структуру тела.
