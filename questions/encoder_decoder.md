# Архитектура Encoder-Decoder — вопросы для самопроверки

### Зачем нужна архитектура encoder-decoder?
Для задач, где вход и выход — последовательности разной длины (перевод, суммаризация, распознавание речи). Энкодер строит представление входа, декодер генерирует выход по нему шаг за шагом.

### В чём проблема «бутылочного горлышка» классического seq2seq?
Вся входная последовательность сжимается в один вектор фиксированного размера, и для длинных входов информация теряется — качество падает с длиной. Решение — механизм внимания, который даёт декодеру доступ ко всем состояниям энкодера.

### Что такое teacher forcing и какую проблему он создаёт?
При обучении декодер получает на вход истинный предыдущий токен, а не свой прогноз, что ускоряет и стабилизирует обучение. Но на инференсе он видит свои ошибки, которых не видел при обучении (**exposure bias**); помогает scheduled sampling.

### Чем beam search лучше жадного декодирования?
Жадное декодирование берёт на каждом шаге самый вероятный токен и может пропустить последовательность с большей общей вероятностью. Beam search держит k лучших гипотез, находя более вероятные выходы ценой k-кратных вычислений.

### Как encoder-decoder реализован в трансформерах?
Энкодер — стек слоёв self-attention, декодер — masked self-attention плюс **cross-attention**, где запросы из декодера, а ключи и значения из выхода энкодера. Примеры — оригинальный Transformer, T5, BART.
