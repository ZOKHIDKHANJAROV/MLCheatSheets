# TorchServe — вопросы для самопроверки

### Что такое .mar-архив в TorchServe и что в него входит?
Model Archive, создаваемый `torch-model-archiver`: веса или TorchScript-модель, handler (код пред- и постобработки), дополнительные файлы (словари, конфиги) и метаданные. Сервер загружает модель именно из такого архива.

### Зачем в TorchServe нужен handler и какие этапы он реализует?
Handler задаёт логику обработки запроса: `initialize` (загрузка модели), `preprocess` (разбор входа в тензоры), `inference` и `postprocess` (преобразование выхода в ответ). Есть встроенные handlers для типовых задач, например классификации изображений.

### Для чего нужен Management API в дополнение к Inference API?
Inference API (по умолчанию порт 8080) обслуживает предсказания, а Management API (8081) позволяет регистрировать и удалять модели, менять число воркеров и версии без перезапуска сервера. Метрики отдаются отдельно (8082).

### Как настройки batch_size и max_batch_delay влияют на работу сервиса?
TorchServe ждёт до `max_batch_delay` миллисекунд, чтобы собрать до `batch_size` запросов в один батч. Большие значения повышают пропускную способность, но увеличивают задержку отдельного запроса.

### Какая типичная ошибка возникает при переходе от обучения к TorchServe?
Расхождение предобработки в handler и при обучении (другая нормализация, ресайз, токенизация) или забытый `model.eval()`, из-за чего dropout и BatchNorm работают в режиме обучения. Результат — тихое падение качества без ошибок в логах.
