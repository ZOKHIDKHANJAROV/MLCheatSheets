# Гибридные системы — вопросы для самопроверки

### Зачем объединять коллаборативный и контентный подходы?
Они компенсируют слабости друг друга: коллаборативный ловит неочевидные вкусовые связи, но страдает от холодного старта, контентный работает для новых объектов, но склонен к «пузырю» однотипных рекомендаций. Гибрид даёт лучшее качество и покрытие.

### Чем взвешенная гибридизация отличается от переключающей (switching)?
**Взвешенная** смешивает оценки нескольких моделей: score = w₁·s_CF + w₂·s_CB. **Переключающая** выбирает одну модель в зависимости от ситуации — например, контентную для пользователей с менее чем 5 взаимодействиями и коллаборативную для остальных.

### Как устроена типичная двухэтапная схема «кандидаты + ранжирование»?
Несколько быстрых генераторов (ALS, item-to-item, популярное, контентный поиск по эмбеддингам) отбирают сотни кандидатов из миллионов объектов. Затем модель ранжирования (часто градиентный бустинг) с богатыми признаками, включая скоры генераторов, упорядочивает этот короткий список.

### Какая ошибка часто возникает при обучении ранжирующей модели поверх генераторов кандидатов?
Обучение на скорах генераторов, которые сами обучены на тех же данных: скоры получаются переобученными, и ранжировщик слишком им доверяет. Генераторы нужно обучать на более раннем периоде, а ранжировщик — на следующем, по аналогии со стекингом.

### Как гибридные модели вроде LightFM решают холодный старт?
Эмбеддинг пользователя или объекта строится как сумма эмбеддингов его признаков (включая индикатор ID). Для нового объекта без взаимодействий вектор получается из его контентных признаков, а для известных объектов дополнительно уточняется по ID.
