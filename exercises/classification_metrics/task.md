# Упражнение: Метрики классификации

## Задание

Дан файл `input.csv` с результатами бинарного классификатора (40 объектов):

- `y_true` — истинный класс (0 или 1)
- `y_pred` — предсказанный класс (порог 0.5)
- `y_score` — предсказанная вероятность класса 1

Вычислите:

1. **accuracy** — доля верных ответов
2. **precision** — точность для класса 1
3. **recall** — полнота для класса 1
4. **f1** — F1-мера
5. **roc_auc** — площадь под ROC-кривой (по `y_score`, а не по `y_pred`!)

## Подсказки

- Сначала постройте матрицу ошибок (TP, FP, FN, TN) и посчитайте метрики по формулам.
- precision = TP / (TP + FP), recall = TP / (TP + FN), F1 = 2·P·R / (P + R).
- Для ROC-AUC нужны вероятности, а не метки классов.

## Ожидаемый формат выходного файла

CSV с одной строкой и колонками: `accuracy, precision, recall, f1, roc_auc` (округлить до 4 знаков).

## Разбор

> Читайте после своей попытки — в портале разбор открывается, когда упражнение решено.

**Идея.** Почти все метрики — дроби из матрицы ошибок: precision = TP/(TP+FP) — «сколько найденного верно», recall = TP/(TP+FN) — «сколько верного найдено». ROC-AUC отличается: он оценивает ранжирование по вероятностям, а не метки.

**Типичные ошибки:**
- Перепутать precision и recall — значения меняются местами.
- ROC-AUC по `y_pred` вместо `y_score` — получится AUC «ступеньки» с одним порогом, заметно ниже.
- F1 как среднее арифметическое precision и recall вместо гармонического.

**Что вынести:** accuracy обманчива при дисбалансе классов; выбирайте метрику по цене ошибок (FP или FN). ROC-AUC не зависит от порога — это вероятность, что случайный положительный объект получит оценку выше случайного отрицательного. → шпаргалка «Метрики классификации».
