🛠️ Вызов инструментов (Function Calling)

📅 Ноябрь 2026 · код — с «фейковой LLM», без реальных вызовов API

🔷 1. Идея

Function calling — механизм, при котором модель не выполняет код сама, а возвращает структурированный запрос: имя функции и аргументы в JSON. Выполняет функцию ваш код, результат возвращается модели.

Модель решает, что вызвать. Вызывает и отвечает за безопасность — приложение.

🖼 Вызов инструмента шаг за шагом

🔷 2. JSON-схема инструмента

{
  "name": "get_weather",
  "description": "Температура в городе",
  "parameters": {
    "type": "object",
    "properties": {
      "city":  {"type": "string"},
      "units": {"type": "string",
                "enum": ["c", "f"]}
    },
    "required": ["city"]
  }
}

Модель опирается на name и description, поэтому описание пишут как инструкцию: что делает и когда использовать.

🔷 3. Цикл вызова

  1. Отправляем модели сообщения + список схем инструментов
  2. Модель отвечает либо текстом, либо tool_call (имя, аргументы, id)
  3. Приложение валидирует аргументы и выполняет функцию
  4. Результат добавляется в историю как tool_result с тем же id
  5. Снова вызываем модель — до финального текста или лимита шагов
for _ in range(max_steps):
    reply = llm(messages, tools)
    if not reply.tool_calls:
        return reply.text
    for call in reply.tool_calls:
        messages.append(execute(call))
return "лимит шагов"

🔷 4. Полный пример (заглушка вместо LLM)

SCHEMA = {
    "name": "get_weather",
    "description": "Температура воздуха в городе",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {"type": "string"},
            "units": {"type": "string", "enum": ["c", "f"]},
        },
        "required": ["city"],
    },
}
TYPES = {"string": str, "integer": int, "number": (int, float)}

def validate(args, schema):
    """Возвращает список ошибок (пустой — аргументы корректны)."""
    params = schema["parameters"]
    errors = [f"нет поля {k}" for k in params.get("required", []) if k not in args]
    for key, value in args.items():
        spec = params["properties"].get(key)
        if spec is None:
            errors.append(f"лишнее поле {key}")
        elif not isinstance(value, TYPES[spec["type"]]):
            errors.append(f"{key}: ожидался {spec['type']}")
        elif "enum" in spec and value not in spec["enum"]:
            errors.append(f"{key}: допустимо {spec['enum']}")
    return errors

WEATHER = {"Москва": 5, "Казань": 3}            # условные данные

def get_weather(city, units="c"):
    t = WEATHER[city]
    return t if units == "c" else round(t * 9 / 5 + 32, 1)

REGISTRY = {"get_weather": (SCHEMA, get_weather)}

def execute(call):
    """Выполняет вызов и всегда возвращает tool_result (даже при ошибке)."""
    result = {"role": "tool", "tool_call_id": call["id"], "is_error": False}
    schema, fn = REGISTRY.get(call["name"], (None, None))
    if fn is None:
        return {**result, "is_error": True, "content": "неизвестный инструмент"}
    errors = validate(call["arguments"], schema)
    if errors:
        return {**result, "is_error": True, "content": "; ".join(errors)}
    try:
        return {**result, "content": fn(**call["arguments"])}
    except Exception as exc:                      # ошибка инструмента — тоже наблюдение
        return {**result, "is_error": True, "content": f"сбой: {exc!r}"}

def fake_llm(messages):
    """Заглушка модели: сначала два параллельных вызова (один с ошибкой)."""
    tools = [m for m in messages if m["role"] == "tool"]
    if not tools:
        return {"tool_calls": [
            {"id": "c1", "name": "get_weather", "arguments": {"city": "Москва"}},
            {"id": "c2", "name": "get_weather", "arguments": {"city": "Казань", "units": "k"}},
        ]}
    if any(m["is_error"] for m in tools) and len(tools) == 2:
        return {"tool_calls": [
            {"id": "c3", "name": "get_weather", "arguments": {"city": "Казань", "units": "f"}},
        ]}
    return {"content": "Москва: 5 °C, Казань: 37.4 °F"}

def run(user_text, max_steps=4):
    messages = [{"role": "user", "content": user_text}]
    for _ in range(max_steps):
        reply = fake_llm(messages)
        if "tool_calls" not in reply:
            return reply["content"]
        messages.append({"role": "assistant", "tool_calls": reply["tool_calls"]})
        for call in reply["tool_calls"]:          # независимые вызовы можно запускать параллельно
            messages.append(execute(call))
    return "превышен лимит шагов"

print(run("Какая погода в Москве и Казани?"))   # Москва: 5 °C, Казань: 37.4 °F

🔷 5. Параллельные вызовы

Модель может вернуть несколько tool_call за один ход — если вызовы независимы (погода в двух городах).

  • каждый результат возвращается со своим tool_call_id
  • независимые вызовы можно запускать одновременно (потоки, asyncio)
  • зависимые вызовы (результат первого нужен второму) идут последовательно, в разных ходах

🔷 6. Валидация и ошибки

  • Проверяйте аргументы по схеме до выполнения: обязательные поля, типы, enum, диапазоны
  • Модель может выдумать функцию или аргумент — проверяйте имя по реестру
  • Ошибку возвращайте модели как tool_result с понятным текстом: она сможет исправить вызов
  • Исключения инструмента не должны ронять весь цикл

🔷 8. Плюсы и минусы

Плюсы

  • структурированный вывод вместо разбора свободного текста
  • модель получает свежие данные и может действовать
  • инструменты легко добавлять и тестировать отдельно

Минусы

  • модель может ошибиться в аргументах или выбрать не тот инструмент
  • описания схем занимают контекст
  • риск инъекций через содержимое результатов

🔷 9. Когда использовать

  • нужны актуальные данные (поиск, БД, погода, курсы)
  • нужны точные вычисления (калькулятор, код)
  • нужно совершить действие (создать задачу, отправить письмо)
  • нужен надёжный структурированный ответ

Если ответ целиком известен модели и не требует внешних данных — инструмент не нужен.

🔷 10. Типичные ошибки

  • ❌ Расплывчатое описание инструмента — модель выбирает его невпопад
  • ❌ Нет валидации: аргументы идут в код «как есть»
  • ❌ Ошибка инструмента скрыта — модель не знает, что вызов не удался
  • ❌ Не сопоставлен tool_call_id с результатом
  • ❌ Нет max_steps — модель бесконечно повторяет вызов
  • ❌ Результат огромен и забивает контекст — его нужно обрезать или суммировать
  • ❌ Опасная функция без прав и подтверждений
«Результаты инструментов — недоверенные данные: текст внутри них не должен становиться командой.»
