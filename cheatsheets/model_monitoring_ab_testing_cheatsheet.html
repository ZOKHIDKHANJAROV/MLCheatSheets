📈 Model Monitoring и A/B Testing

📅 Январь 2026

🔷 1. Жизненный цикл: мониторинг + эксперимент

Мониторинг отвечает на вопрос «не сломалась ли текущая модель?», A/B-тест — «лучше ли новая модель старой для бизнеса?». Они замыкают цикл: мониторинг находит деградацию → переобучаем → новую модель выкатываем через shadow/canary → A/B-тест → победитель становится новым бейзлайном мониторинга.

  • Offline-метрики (AUC, RMSE на отложенной выборке) не гарантируют рост онлайн-метрик: другая аудитория, feedback loop, задержка, UX.
  • Online-метрики (CTR, конверсия, выручка, retention) измеряются только на живом трафике.

Подробно про инструменты и дашборды мониторинга — в шпаргалке Model Monitoring; про дрейф — Concept Drift.

🔷 3. Детекция дрейфа: PSI, KS, χ²

  • PSI (Population Stability Index): бьём признак на бины (обычно 10 квантилей по референсу), PSI = Σ (aᵢ − eᵢ) · ln(aᵢ / eᵢ), где eᵢ, aᵢ — доли в референсе и текущем окне. Правило: < 0.1 — стабильно, 0.1–0.25 — умеренный сдвиг, > 0.25 — значимый.
  • KS-тест (непрерывные): D = max|F₁(x) − F₂(x)|. На больших выборках p-value почти всегда < 0.05 — смотрите на величину D, а не только на p.
  • χ²-тест (категориальные): сравнивает частоты категорий в таблице сопряжённости.
  • Wasserstein / JS-дивергенция — «расстояния», удобные как непрерывный индикатор.

При сотнях признаков делайте поправку на множественные проверки (Bonferroni/BH) или алертьте только по важным признакам.

🔷 4. Код: PSI, KS, χ²

import numpy as np
from scipy import stats

def psi(ref, cur, bins=10, eps=1e-6):
    edges = np.quantile(ref, np.linspace(0, 1, bins + 1))
    edges[0], edges[-1] = -np.inf, np.inf
    e = np.histogram(ref, edges)[0] / len(ref) + eps
    a = np.histogram(cur, edges)[0] / len(cur) + eps
    return float(np.sum((a - e) * np.log(a / e)))

rng = np.random.default_rng(0)
ref = rng.normal(0, 1, 10_000)       # обучающее окно
cur = rng.normal(0.3, 1.1, 10_000)   # прод за неделю

print("PSI:", round(psi(ref, cur), 3))
ks = stats.ks_2samp(ref, cur)
print("KS D=%.3f p=%.2e" % (ks.statistic, ks.pvalue))

# категориальный признак: частоты по категориям
ref_counts = np.array([500, 300, 200])
cur_counts = np.array([420, 330, 250])
chi2, p, dof, _ = stats.chi2_contingency([ref_counts, cur_counts])
print("chi2=%.1f p=%.3f" % (chi2, p))

🔷 5. Задержанные метки и алертинг

Метки часто приходят через дни/месяцы (дефолт по кредиту, отток). Пока их нет:

  • Proxy-сигналы: дрейф признаков и распределения скоров, средняя уверенность, доля «пограничных» прогнозов.
  • Ранние метки: короткий горизонт (просрочка 30 дней вместо дефолта за год).
  • Ручная разметка небольшой случайной выборки.
  • Backfill: когда метки пришли — пересчитать метрики по когортам на дату прогноза.

Алертинг: пороги (статические или по истории ± kσ), уровни severity, минимальный объём окна, подавление дублей. Алерт должен иметь runbook: кто реагирует и что делать (откат, переобучение, фича-фикс). Слишком чувствительные алерты → alert fatigue.

🔷 7. Дизайн A/B-теста модели

  1. Гипотеза: «новая модель увеличит конверсию».
  2. Метрики: одна целевая (OEC), guardrail-метрики (latency, жалобы, выручка не падает), диагностические.
  3. Единица рандомизации: пользователь (не запрос!), иначе один человек видит обе модели. Хэш hash(user_id + salt) % 100.
  4. MDE (minimum detectable effect), α (обычно 0.05), мощность 1−β (0.8) → размер выборки.
  5. Длительность: ≥ 1–2 полных недели (сезонность по дням), не меньше расчётной выборки.
  6. Проверки: A/A-тест, SRM (sample ratio mismatch: χ² на размеры групп), отсутствие утечки между группами.
  7. Анализ строго по плану, затем решение и документирование.

🔷 8. Размер выборки и мощность

Для двух долей (конверсии p₁, p₂) на группу: n ≈ (z₁₋α/₂ + z₁₋β)² · [p₁(1−p₁) + p₂(1−p₂)] / (p₂ − p₁)². Для средних: n ≈ 2(z₁₋α/₂ + z₁₋β)² σ² / Δ².

  • Уменьшили MDE вдвое → выборка ×4.
  • Снижение дисперсии: CUPED (ковариата — та же метрика до эксперимента), стратификация, обрезка выбросов.
from statsmodels.stats.power import NormalIndPower, TTestIndPower
from statsmodels.stats.proportion import proportion_effectsize

# конверсия 5% -> хотим заметить 5.5%
es = proportion_effectsize(0.055, 0.05)          # Cohen's h
n = NormalIndPower().solve_power(effect_size=es, alpha=0.05,
                                 power=0.8, ratio=1.0)
print(f"на группу: {n:,.0f}")                    # ≈ 31 000

# непрерывная метрика: Cohen's d = Δ / σ
n_t = TTestIndPower().solve_power(effect_size=0.05, alpha=0.05, power=0.8)
print(f"t-test на группу: {n_t:,.0f}")

🔷 9. Статистические тесты и анализ

МетрикаТест
Доля (CTR, конверсия)z-тест для долей, χ²
Среднее (чек, время)t-тест Уэлча; при тяжёлых хвостах — bootstrap / Манна–Уитни
Ratio-метрика (клики/сессии)delta-метод или bootstrap по пользователям
import numpy as np
from scipy import stats
from statsmodels.stats.proportion import proportions_ztest, confint_proportions_2indep

conv = np.array([1650, 1540]); n = np.array([30000, 30000])  # B, A
z, p = proportions_ztest(conv, n)
lo, hi = confint_proportions_2indep(conv[0], n[0], conv[1], n[1])
print(f"p={p:.4f}, uplift CI=[{lo:.4f}, {hi:.4f}]")

rev_a = np.random.default_rng(1).exponential(100, 5000)
rev_b = np.random.default_rng(2).exponential(104, 5000)
print(stats.ttest_ind(rev_b, rev_a, equal_var=False))

# SRM-проверка: ожидали 50/50
print(stats.chisquare([30000, 30410]).pvalue)   # p < 0.001 → тест сломан

Смотрите на доверительный интервал эффекта, а не только на p-value; при многих метриках/сегментах — поправка на множественность.

🔷 10. Peeking и последовательное тестирование

Peeking — ежедневно смотреть p-value и остановиться при p < 0.05. При 10–20 «подглядываниях» реальная вероятность ложного срабатывания вырастает с 5% до 20–30%.

  • Фиксированный горизонт: анализ только в конце расчётного срока.
  • Group sequential (O'Brien–Fleming, Pocock): заранее заданные промежуточные анализы с более строгими порогами (alpha spending).
  • Always-valid p-values / mSPRT: можно смотреть в любой момент.
  • Байесовский A/B: P(B > A) и ожидаемые потери — понятнее бизнесу, но тоже не защищён от произвольной остановки без правил.

Другие ловушки: novelty/primacy effect (эффект новизны затухает), сетевые эффекты (нарушение независимости групп), изменение модели во время теста.

# Thompson sampling для конверсий (Beta-Bernoulli)
import numpy as np
rng = np.random.default_rng(0)
true_p = [0.050, 0.055, 0.045]
alpha = np.ones(3); beta = np.ones(3)
for _ in range(50_000):
    arm = np.argmax(rng.beta(alpha, beta))
    r = rng.random() < true_p[arm]
    alpha[arm] += r; beta[arm] += 1 - r
print("показы по рукам:", (alpha + beta - 2).astype(int))

🔷 12. Типичные ошибки и чек-лист

Ошибки

  • Рандомизация по запросам вместо пользователей
  • Остановка теста при первом p < 0.05
  • Нет расчёта мощности → «незначимо» при маленькой выборке трактуют как «нет эффекта»
  • Мониторинг только accuracy, без данных и latency
  • Алерты по p-value KS на миллионах строк — шум
  • Не логируется версия модели в каждом прогнозе

Чек-лист

  • Логи прогнозов + версия модели + фичи
  • Дашборд: система, данные, дрейф, скоры, качество
  • Shadow → canary → A/B с guardrail-метриками
  • MDE, α, мощность и длительность зафиксированы до старта
  • A/A и SRM-проверка
  • План отката (rollback) одной кнопкой
