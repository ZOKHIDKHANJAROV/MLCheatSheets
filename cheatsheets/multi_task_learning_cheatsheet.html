🧩 Multi-task Learning

📅 Январь 2026

🔷 1. Суть MTL

Multi-task learning — одна модель обучается сразу на нескольких задачах T₁…T_K с общим представлением. Общий лосс: L = Σₖ wₖ · Lₖ(θ_shared, θₖ).

  • Индуктивный bias / регуляризация: представление должно подходить всем задачам → меньше переобучения под шум одной задачи.
  • Неявная аугментация: связанные задачи дают дополнительный сигнал, особенно задаче с малой разметкой.
  • Attention focusing: другие задачи подсказывают, какие признаки важны.
  • Эффективность: один backbone на инференсе вместо K моделей.

Риск — negative transfer: совместное обучение ухудшает одну из задач. Глубже — MTL Deep Dive; связь с Transfer Learning.

Cross-stitch unit: выходы слоёв двух сетей смешиваются обучаемой матрицей α: [x̃_A, x̃_B] = [[α_AA, α_AB],[α_BA, α_BB]] · [x_A, x_B]. Штрафной вариант soft sharing: λ·‖θ_A − θ_B‖².

🔷 3. Код: hard sharing на PyTorch

import torch, torch.nn as nn, torch.nn.functional as F

class SharedBottom(nn.Module):
    def __init__(self, d_in, d_h=128, n_classes=5):
        super().__init__()
        self.shared = nn.Sequential(
            nn.Linear(d_in, d_h), nn.ReLU(),
            nn.Linear(d_h, d_h), nn.ReLU())
        self.head_cls = nn.Linear(d_h, n_classes)   # задача 1: классификация
        self.head_reg = nn.Linear(d_h, 1)           # задача 2: регрессия

    def forward(self, x):
        h = self.shared(x)
        return self.head_cls(h), self.head_reg(h).squeeze(-1)

model = SharedBottom(d_in=32)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
x = torch.randn(64, 32)
y_cls = torch.randint(0, 5, (64,)); y_reg = torch.randn(64)

logits, pred = model(x)
loss = F.cross_entropy(logits, y_cls) + 0.5 * F.mse_loss(pred, y_reg)
opt.zero_grad(); loss.backward(); opt.step()

Если у объекта нет метки задачи k — маскируйте её лосс (mask * loss_k), а не подставляйте 0.

🔷 4. Взвешивание лоссов

Простая сумма плохо работает: лоссы разного масштаба (CE ~1, MSE ~1000) и разной скорости убывания → одна задача доминирует в градиентах общего слоя.

МетодИдея
Ручные весаGrid search по wₖ; дорого при K > 3
Uncertainty weighting (Kendall, 2018)L = Σ 1/(2σₖ²)·Lₖ + log σₖ, σₖ обучается — шумные задачи получают меньший вес
GradNorm (Chen, 2018)Подбирает wₖ так, чтобы нормы градиентов ‖∇_W wₖLₖ‖ на общем слое были сопоставимы с учётом скорости обучения задачи (параметр α)
DWAВес ∝ softmax от отношения Lₖ(t−1)/Lₖ(t−2): медленно учащаяся задача получает больше
НормировкаДелить Lₖ на начальное значение Lₖ(0)

🔷 5. Код: uncertainty weighting

class UncertaintyWeighting(nn.Module):
    """Kendall et al.: обучаемые log σ² для каждой задачи."""
    def __init__(self, n_tasks):
        super().__init__()
        self.log_vars = nn.Parameter(torch.zeros(n_tasks))

    def forward(self, losses):            # losses: list of scalar tensors
        total = 0.0
        for i, L in enumerate(losses):
            precision = torch.exp(-self.log_vars[i])
            total = total + 0.5 * precision * L + 0.5 * self.log_vars[i]
        return total

uw = UncertaintyWeighting(2)
opt = torch.optim.Adam(list(model.parameters()) + list(uw.parameters()), lr=1e-3)

logits, pred = model(x)
loss = uw([F.cross_entropy(logits, y_cls), F.mse_loss(pred, y_reg)])
opt.zero_grad(); loss.backward(); opt.step()
print(torch.exp(uw.log_vars))  # σ² задач

Член log σ не даёт весу уйти в 0 (иначе тривиально σ → ∞).

🔷 6. Конфликтующие градиенты: PCGrad

Градиенты задач gᵢ, gⱼ по общим параметрам конфликтуют, если cos(gᵢ, gⱼ) < 0: шаг в пользу одной задачи вредит другой. Плюс разная величина норм и высокая кривизна — «трагическая триада» (Yu et al., 2020).

PCGrad: для каждой задачи i в случайном порядке перебираем j; если gᵢ·gⱼ < 0 — проецируем: gᵢ ← gᵢ − (gᵢ·gⱼ / ‖gⱼ‖²) gⱼ. Итоговый шаг — сумма исправленных gᵢ.

import random

def pcgrad_step(model, losses, opt):
    shared = [p for p in model.shared.parameters()]
    grads = []
    for L in losses:
        g = torch.autograd.grad(L, shared, retain_graph=True)
        grads.append(torch.cat([t.flatten() for t in g]))
    projected = []
    for i, gi in enumerate(grads):
        gi = gi.clone()
        others = [g for j, g in enumerate(grads) if j != i]
        random.shuffle(others)
        for gj in others:
            dot = gi @ gj
            if dot < 0:
                gi -= dot / (gj.norm() ** 2 + 1e-12) * gj
        projected.append(gi)
    g_final = torch.stack(projected).sum(0)
    opt.zero_grad()
    sum(losses).backward()               # градиенты голов — как обычно
    offset = 0
    for p in shared:                     # подменяем градиент общих слоёв
        n = p.numel()
        p.grad = g_final[offset:offset + n].view_as(p).clone()
        offset += n
    opt.step()

Альтернативы: MGDA (Парето-оптимальный шаг), CAGrad, GradVac, Nash-MTL.

🔷 7. Negative transfer

  • Признак: MTL-модель хуже single-task бейзлайна на задаче k. Всегда сравнивайте с отдельными моделями!
  • Причины: слабо связанные задачи, конфликт градиентов, дисбаланс данных/лоссов, слишком узкий общий слой.
  • Лечение: больше task-specific слоёв (раньше «развилка»), гейтинг экспертов (MMoE/PLE), балансировка лоссов, PCGrad, группировка задач (task grouping: обучать вместе только «дружащие» задачи, TAG оценивает affinity по влиянию шага одной задачи на лосс другой).
  • Seesaw-эффект (рекомендации): улучшение одной задачи ведёт к ухудшению другой — мотивация для PLE.

🔷 9. Код: MMoE

class MMoE(nn.Module):
    def __init__(self, d_in, n_experts=4, d_exp=64, n_tasks=2):
        super().__init__()
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(d_in, d_exp), nn.ReLU())
            for _ in range(n_experts)])
        self.gates = nn.ModuleList([nn.Linear(d_in, n_experts)
                                    for _ in range(n_tasks)])
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(d_exp, 32), nn.ReLU(), nn.Linear(32, 1))
            for _ in range(n_tasks)])

    def forward(self, x):
        E = torch.stack([e(x) for e in self.experts], dim=1)  # B×N×D
        outs = []
        for gate, tower in zip(self.gates, self.towers):
            w = torch.softmax(gate(x), dim=-1).unsqueeze(-1)   # B×N×1
            outs.append(tower((w * E).sum(1)).squeeze(-1))      # logit
        return outs

m = MMoE(d_in=32)
ctr_logit, cvr_logit = m(torch.randn(16, 32))
y_click = torch.randint(0, 2, (16,)).float()
y_conv = torch.randint(0, 2, (16,)).float()
loss = (F.binary_cross_entropy_with_logits(ctr_logit, y_click)
        + F.binary_cross_entropy_with_logits(cvr_logit, y_conv))

🔷 10. Auxiliary tasks и применения

Вспомогательная задача нужна не сама по себе, а для улучшения главной; её вес обычно меньше, на инференсе голову выбрасывают.

  • CV / автопилот: детекция + сегментация + глубина из одного backbone (HydraNet Tesla, UberNet); экономия вычислений на борту.
  • NLP: T5/инструктивные модели — многие задачи в одном формате; BERT: MLM + NSP.
  • RL: auxiliary losses (UNREAL: предсказание награды, pixel control) — см. Multitask RL.
  • Табличные/медицина: предсказать несколько исходов сразу; редкий исход выигрывает от частых.
  • Подсказки (hints): предсказывать признак, который трудно выучить напрямую; adversarial-задача для удаления информации (domain adaptation через gradient reversal).

🔷 11. Практика и типичные ошибки

Делать

  • Сначала single-task бейзлайны для каждой задачи
  • Нормировать масштабы лоссов, логировать каждый Lₖ отдельно
  • Ранняя остановка / выбор чекпойнта по метрике каждой задачи
  • Маскировать лоссы при отсутствующих метках
  • Сэмплирование задач пропорционально √(размер) при сильном дисбалансе данных

Ошибки

  • Складывать лоссы без весов разного масштаба
  • Судить по суммарному лоссу, а не по метрикам задач
  • Объединять заведомо несвязанные задачи
  • Слишком маленький общий слой → «бутылочное горлышко»
  • Один learning rate для голов с очень разной сложностью без проверки

Когда применять: задачи связаны (общие входы и сходная семантика), у части задач мало меток, нужна экономия на инференсе.
