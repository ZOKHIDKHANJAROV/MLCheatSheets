🤖 PPO (Proximal Policy Optimization)

📅 Январь 2026

🔷 1. Суть

PPO (Schulman et al., OpenAI, 2017) — on-policy actor-critic алгоритм, который улучшает политику, но не даёт ей уйти слишком далеко от старой за одно обновление. Простой, устойчивый, «алгоритм по умолчанию» в RL.

  • Работает с дискретными и непрерывными действиями
  • Несколько эпох мини-батчей на одних данных → лучше sample efficiency, чем у REINFORCE
  • Почти без тюнинга даёт разумный результат
  • Стандарт в робототехнике (сим-ту-реал), играх (OpenAI Five) и RLHF для LLM

🔷 2. От policy gradient к TRPO и PPO

МетодЦельПроблема / решение
REINFORCE / A2CE[log π_θ(a|s)·A]1 шаг на батч; большой шаг может «сломать» политику
TRPO (2015)max E[r·A] при KL(π_old‖π_θ) ≤ δгарантии монотонности, но 2-й порядок: сопряжённые градиенты, line search — сложно
PPO (2017)clip(r) в целевой функции1-й порядок, SGD/Adam, почти та же устойчивость

Ключ: после первого шага данные собраны старой политикой, поэтому используем importance sampling — отношение вероятностей r(θ). Основы — в Policy Gradient и Actor-Critic.

🔷 3. Ratio и clipped objective

r_t(θ) = π_θ(a_t|s_t) / π_θold(a_t|s_t)
       = exp(log π_θ − log π_old)

L_CLIP(θ) = E_t[ min( r_t·A_t,
                      clip(r_t, 1−ε, 1+ε)·A_t ) ]
  • A > 0 (действие лучше среднего): увеличиваем r, но выгода «обрезается» при r > 1+ε
  • A < 0: уменьшаем r, но не ниже 1−ε
  • min — пессимистичная (нижняя) оценка: штраф за плохие изменения не обрезается
  • За пределами клипа градиент = 0 → нет стимула уходить дальше
  • ε = 0.2 типично (0.1–0.3)

🔷 4. GAE — оценка преимущества

δ_t   = r_t + γ·V(s_{t+1})·(1−done) − V(s_t)        # TD-ошибка
A_t   = Σ_l (γλ)^l · δ_{t+l}                          # GAE(γ, λ)
      = δ_t + γλ·(1−done)·A_{t+1}                     # рекурсия с конца
R_t   = A_t + V(s_t)                                  # цель для критика
  • λ = 0: A = δ_t — малая дисперсия, большое смещение (как TD(0))
  • λ = 1: A = G_t − V(s_t) — Монте-Карло, без смещения, большая дисперсия
  • λ = 0.95 — стандартный компромисс
  • Нормализация A по мини-батчу: (A − mean) / (std + 1e-8)

🔷 5. Полный loss

L = −L_CLIP + c₁·L_VF − c₂·H[π_θ](s)
L_VF = (V_θ(s_t) − R_t)²
  • Value loss (c₁ = 0.5): обучение критика; часто общий «торс» с актором
  • Value clipping (опц.): V_clip = V_old + clip(V − V_old, −ε, ε), берут max двух лоссов
  • Entropy bonus (c₂ = 0.0–0.01): поддерживает исследование, не даёт политике рано стать детерминированной
  • Grad clipping: ‖g‖ ≤ 0.5

🔷 6. Алгоритм

  1. Запустить N параллельных сред на T шагов политикой π_old → батч N·T переходов (s, a, r, done, log π_old, V)
  2. Посчитать GAE-преимущества A и цели R
  3. K эпох: перемешать батч, разбить на мини-батчи
  4. Для каждого мини-батча: r = exp(log π_θ − log π_old), L = −L_CLIP + c₁L_VF − c₂H, шаг Adam
  5. (опц.) ранняя остановка эпох, если approx KL > target_kl
  6. π_old ← π_θ, повторить

On-policy: после обновления старый батч выбрасывается (никакого replay buffer).

🔷 8. PPO-Clip vs PPO-Penalty

Цельmin(r·A, clip(r)·A)E[r·A] − β·KL(π_old‖π_θ)

🔷 10. Ядро на PyTorch

import torch
import torch.nn.functional as F

def compute_gae(rewards, values, dones, last_value, gamma=0.99, lam=0.95):
    # тензоры формы (T, n_envs); dones[t] = эпизод закончился на шаге t
    T = rewards.size(0)
    adv = torch.zeros_like(rewards)
    gae = torch.zeros_like(last_value)
    for t in reversed(range(T)):
        next_v = last_value if t == T - 1 else values[t + 1]
        nonterm = 1.0 - dones[t]
        delta = rewards[t] + gamma * next_v * nonterm - values[t]
        gae = delta + gamma * lam * nonterm * gae
        adv[t] = gae
    return adv, adv + values               # преимущества, returns

def ppo_loss(policy, value_fn, obs, actions, old_logp, adv, returns,
             clip_eps=0.2, c1=0.5, c2=0.01):
    dist = policy(obs)                     # torch.distributions.*
    logp = dist.log_prob(actions)
    if logp.dim() > 1:                     # непрерывные действия
        logp = logp.sum(-1)
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)
    ratio = torch.exp(logp - old_logp)
    surr1 = ratio * adv
    surr2 = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * adv
    policy_loss = -torch.min(surr1, surr2).mean()
    value_loss = F.mse_loss(value_fn(obs).squeeze(-1), returns)
    entropy = dist.entropy().mean()
    with torch.no_grad():
        approx_kl = ((ratio - 1) - torch.log(ratio)).mean()
        clipfrac = ((ratio - 1).abs() > clip_eps).float().mean()
    loss = policy_loss + c1 * value_loss - c2 * entropy
    return loss, approx_kl, clipfrac

old_logp, adv, returns считаются при сборе данных под torch.no_grad().

🔷 11. PPO в RLHF

  • Политика: языковая модель (SFT-чекпоинт); действие = токен, эпизод = ответ
  • Награда: reward model, обученная на попарных предпочтениях людей, выдаётся в конце ответа
  • KL-штраф к референсной (SFT) модели: r = RM(x, y) − β·log(π_θ(y|x)/π_ref(y|x)) — не даёт «взломать» RM и потерять язык
  • Критик: value-голова на той же или отдельной LM
  • 4 модели в памяти (policy, ref, reward, value) → дорого
  • Альтернативы: DPO (без RL и RM), GRPO (без критика: преимущество по группе ответов), RLOO
  • Библиотеки: TRL (trl), OpenRLHF, veRL

🔷 12. Типичные ошибки и диагностика

Плохо

  • Пересчитывать old_logp после обновления (ratio всегда 1, клип не работает)
  • Не учитывать done в GAE — «перетекание» ценности между эпизодами
  • Путать truncation (лимит времени) с terminal: при truncation нужен бутстрап V(s)
  • Не нормализовать наблюдения/награды в непрерывных задачах
  • Слишком много эпох / большой lr → KL растёт, clipfrac > 0.3
  • Сумма log_prob по измерениям действия забыта (Gaussian-политика)

Что мониторить

  • approx_kl ~ 0.01–0.02; clipfrac ~ 0.1–0.2
  • Энтропия падает плавно, не обрушивается
  • explained_variance критика → ближе к 1
  • Средняя награда эпизода по нескольким seed'ам
