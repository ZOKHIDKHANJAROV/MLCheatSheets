🔁 Transfer Learning для CNN

📅 Январь 2026

🔷 1. Идея

Берём CNN, обученную на большом датасете (обычно ImageNet: 1.28 млн изображений, 1000 классов), и переиспользуем её признаки для своей задачи с небольшим числом картинок.

  • Ранние слои: края, цвета, текстуры — универсальны почти для любых изображений
  • Средние: мотивы, части объектов
  • Поздние: специфичны исходной задаче (морды собак, колёса)
  • Голова (fc-классификатор): полностью под 1000 классов ImageNet — всегда заменяется
Предобученная сеть на 1–5 тыс. картинок почти всегда лучше сети с нуля, обучается в разы быстрее и стабильнее.

Общая теория — в Transfer Learning; архитектуры — в CNN Architectures.

Типичный рецепт: сначала заморозить и обучить голову несколько эпох, потом разморозить и дообучить всё с малым LR (иначе случайная голова «пинает» бэкбон большими градиентами).

🔷 4. Выбор стратегии: данные × домен

Похож на ImageNetСильно отличается
Мало данных (сотни–тыс.)заморозить, обучить головупризнаки из средних слоёв + голова; осторожный FT верхних блоков; сильные аугментации
Много данных (10⁴+)fine-tuning верхних блоков или всей сетиполный fine-tuning; иногда domain-specific предобучение
  • Ориентир: ~100 изображений на класс уже дают разумный результат с замороженным бэкбоном; от ~1000 на класс — смело полный FT
  • Домен-шифт: медицина (рентген, гистология), спутники, микроскопия, ИК — низкоуровневые признаки ещё полезны, высокоуровневые хуже
  • При сильном сдвиге: предобучение на своём домене (RadImageNet), self-supervised дообучение на неразмеченных данных (SimCLR, DINO, MAE)

🔷 5. Подготовка входа

Вход должен выглядеть так же, как при предобучении:

from torchvision import transforms as T
from torchvision.models import ResNet50_Weights

MEAN, STD = [0.485, 0.456, 0.406], [0.229, 0.224, 0.225]
train_tf = T.Compose([
    T.RandomResizedCrop(224, scale=(0.6, 1.0)),
    T.RandomHorizontalFlip(),
    T.ColorJitter(0.2, 0.2, 0.2),
    T.ToTensor(),                 # [0,1], RGB, C×H×W
    T.Normalize(MEAN, STD),
])
val_tf = T.Compose([T.Resize(256), T.CenterCrop(224),
                    T.ToTensor(), T.Normalize(MEAN, STD)])

# или ровно те трансформации, что у весов:
preprocess = ResNet50_Weights.IMAGENET1K_V2.transforms()
  • RGB, не BGR (OpenCV читает BGR!)
  • Ч/б снимки → повторить канал ×3 (или усреднить веса первого conv)
  • Размер: 224 типичен; больше — точнее, но дороже
  • В timm: timm.data.resolve_data_config({}, model=m) — свои mean/std/размер

🔷 6. Аугментации

  • Базовые: RandomResizedCrop, HorizontalFlip, ColorJitter — почти всегда
  • Сильные: RandAugment, TrivialAugment, Mixup/CutMix, RandomErasing — при малых данных и долгом FT
  • Учитывать домен: вертикальный flip ок для спутников/гистологии, но не для рентгена органов или текста; поворот цифр 6/9 меняет класс
  • Валидация — без случайных аугментаций; TTA (flip + усреднение) — +0.5–1%

Подробно: Data Augmentation.

🔷 7. Код: feature extraction

import torch
import torch.nn as nn
from torchvision.models import resnet50, ResNet50_Weights

model = resnet50(weights=ResNet50_Weights.IMAGENET1K_V2)
for p in model.parameters():
    p.requires_grad = False          # заморозить всё

num_classes = 5
model.fc = nn.Linear(model.fc.in_features, num_classes)  # новая голова (обучаемая)
# EfficientNet / MobileNet: model.classifier[-1] = nn.Linear(...)
# timm: model.reset_classifier(num_classes)

optimizer = torch.optim.AdamW(model.fc.parameters(), lr=1e-3)
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)

model.train()
model.apply(lambda m: m.eval() if isinstance(m, nn.BatchNorm2d) else None)
# ↑ BN замороженного бэкбона держим в eval (не обновлять running stats)

🔷 8. Код: fine-tuning с discriminative LR

for p in model.parameters():
    p.requires_grad = True           # разморозить

param_groups = [
    {"params": list(model.conv1.parameters()) + list(model.bn1.parameters())
               + list(model.layer1.parameters()), "lr": 1e-5},
    {"params": model.layer2.parameters(), "lr": 2e-5},
    {"params": model.layer3.parameters(), "lr": 5e-5},
    {"params": model.layer4.parameters(), "lr": 1e-4},
    {"params": model.fc.parameters(),     "lr": 1e-3},
]
optimizer = torch.optim.AdamW(param_groups, weight_decay=1e-4)
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    optimizer, max_lr=[g["lr"] for g in param_groups],
    total_steps=10 * 100)            # epochs * steps_per_epoch
  • Discriminative LR: чем ниже слой, тем меньше LR (ранние признаки универсальны, их почти не трогаем)
  • Layer-wise LR decay: lrk = lrtop·γdepth−k, γ ≈ 0.7–0.9 (популярно для ViT/ConvNeXt)
  • Warmup + cosine / OneCycle — стандарт

🔷 9. Постепенная разморозка

Gradual unfreezing (ULMFiT, Howard & Ruder): размораживаем блоки сверху вниз, по одному за этап.

stages = [model.fc, model.layer4, model.layer3, model.layer2]
for p in model.parameters():
    p.requires_grad = False
for i, block in enumerate(stages):
    for p in block.parameters():
        p.requires_grad = True
    trainable = [p for p in model.parameters() if p.requires_grad]
    optimizer = torch.optim.AdamW(trainable, lr=1e-3 / (3 ** i))
    # train_epochs(model, optimizer, n=2)
  • Уменьшает катастрофическое забывание на малых данных
  • Проще альтернатива: 2 этапа (голова → всё)
  • Заодно экономит память: замороженным слоям не нужны градиенты

🔷 10. BatchNorm при fine-tuning

  • BN хранит running mean/var ImageNet; в train() они обновляются по вашим батчам
  • Маленький батч (<16): статистики шумные → лучше держать BN в eval() (заморозить статистики) или заменить на GroupNorm
  • Feature extraction: BN бэкбона — в eval, иначе «замороженная» сеть всё равно меняется
  • Большой сдвиг домена + достаточно данных: обновлять статистики BN полезно (иногда достаточно только пересчитать их — AdaBN)
  • Keras: base.trainable = False и вызов base(x, training=False) — держит BN в режиме инференса даже после разморозки

См. Batch Normalization.

🔷 11. Типичные ошибки

Плохо

  • Забыть Normalize с mean/std ImageNet или подать BGR
  • Большой LR (1e-2) на всю сеть — признаки разрушаются
  • Сразу размораживать всё со случайной головой
  • Заморозить, но забыть requires_grad=False или BN в eval — бэкбон всё равно «плывёт»
  • Не заменить голову: 1000 выходов вместо своих классов
  • Утечка: одинаковые объекты/пациенты в train и val

Хорошо

  • Бейзлайн: заморозка + линейная голова, потом FT
  • Discriminative LR, warmup, cosine
  • Ранняя остановка по валидации
  • Сравнить с сильным self-supervised бэкбоном (DINOv2)
  • Mixed precision (torch.autocast) для скорости
