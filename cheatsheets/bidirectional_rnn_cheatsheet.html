↔️ Двунаправленные RNN (BiRNN, BiLSTM, BiGRU)

📅 Январь 2026

🔷 1. Идея

Обычная RNN в момент t видит только прошлое x1..t. Но смысл элемента часто зависит и от правого контекста: в «Лук был натянут до предела» значение слова «лук» (оружие или овощ) раскрывается только справа. Bidirectional RNN (Schuster & Paliwal, 1997) читает последовательность двумя независимыми RNN:

  • Прямая (forward) →: слева направо, h→t = f(xt, h→t−1)
  • Обратная (backward) ←: справа налево, h←t = g(xt, h←t+1)
  • Объединение: ht = [h→t ; h←t] — представление видит весь вход

Ячейка может быть любой: простая RNN, LSTM, GRU. Основы рекуррентных сетей — в RNN Basics.

🔷 2. Схема и формулы

x1     x2     x3     x4
 │      │      │      │
→h1 ──→ h2 ──→ h3 ──→ h4     (forward)
←h1 ←── h2 ←── h3 ←── h4     (backward)
 │      │      │      │
[→;←]  [→;←]  [→;←]  [→;←]  → y_t
  • У направлений свои веса (W→, W←) — параметров ×2
  • Выход: yt = Wy·[h→t; h←t] + b
  • Способы объединения: concat (стандарт, размер 2H), сумма, среднее, поэлементное произведение (в Keras — merge_mode)
  • Время ≈ ×2, но направления независимы → считаются параллельно

🔷 3. Когда можно, а когда нельзя

Можно: вся последовательность известна

  • NER, POS-тегирование, chunking
  • Классификация текста, тональность
  • Офлайн-распознавание речи, разметка аудио
  • Энкодер в seq2seq (декодер — однонаправленный)
  • Классификация/сегментация готовых временных рядов, биопоследовательностей

Нельзя: будущего ещё нет

  • Прогноз ряда на следующий шаг — утечка будущего
  • Языковая модель / генерация слово за словом
  • Потоковое (онлайн) распознавание с малой задержкой
  • Декодер seq2seq

Компромисс для потока: обратный проход по окну ограниченной длины (look-ahead несколько кадров) ценой задержки.

🔷 4. PyTorch: формы выходов

import torch
import torch.nn as nn

B, T, D, H, L = 4, 10, 16, 128, 2
lstm = nn.LSTM(D, H, num_layers=L, batch_first=True,
               bidirectional=True)
x = torch.randn(B, T, D)
output, (h_n, c_n) = lstm(x)

print(output.shape)  # (4, 10, 256)  = (B, T, 2*H)
print(h_n.shape)     # (4, 4, 128)  = (L*2, B, H)

# разделить направления
out = output.view(B, T, 2, H)
fwd, bwd = out[..., 0, :], out[..., 1, :]

h = h_n.view(L, 2, B, H)      # (слой, направление, B, H)
h_fwd_last = h[-1, 0]         # forward последнего слоя: после x_T
h_bwd_last = h[-1, 1]         # backward последнего слоя: после x_1 !
sent = torch.cat([h_fwd_last, h_bwd_last], dim=-1)   # (B, 2H)
  • output[:, t] = [fwdt; bwdt] — по шагам
  • h_n — форма (num_layers·2, B, H), порядок: слой0-fwd, слой0-bwd, слой1-fwd, …
  • h_n не зависит от batch_first — batch всегда второй
  • Следующий слой/Linear должен принимать 2·H

🔷 5. Ловушка: финальное состояние

Для обратного направления «конец» — это первый токен. Поэтому:

  • output[:, -1, :H] — forward после всей последовательности ✅
  • output[:, -1, H:] — backward, видевший только последний токен ❌
  • output[:, 0, H:] — backward после всей последовательности ✅

Правильно для классификации: cat(h_n последнего слоя обоих направлений), или пулинг по времени (mean/max) с учётом маски, или attention-пулинг.

Padding: без pack_padded_sequence обратный проход начинается с PAD-токенов и «портит» состояние. С упаковкой h_n корректен для каждой длины.

🔷 6. Классификатор с упаковкой

from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

class BiLSTMClassifier(nn.Module):
    def __init__(self, vocab, emb=100, H=128, n_cls=2):
        super().__init__()
        self.emb = nn.Embedding(vocab, emb, padding_idx=0)
        self.rnn = nn.LSTM(emb, H, batch_first=True,
                           bidirectional=True, num_layers=2,
                           dropout=0.3)
        self.fc = nn.Linear(2 * H, n_cls)

    def forward(self, ids, lengths):
        e = self.emb(ids)
        packed = pack_padded_sequence(e, lengths.cpu(), batch_first=True,
                                      enforce_sorted=False)
        _, (h_n, _) = self.rnn(packed)
        h = torch.cat([h_n[-2], h_n[-1]], dim=-1)  # fwd и bwd последнего слоя
        return self.fc(h)

model = BiLSTMClassifier(vocab=5000)
ids = torch.randint(1, 5000, (3, 12)); ids[1, 8:] = 0
logits = model(ids, torch.tensor([12, 8, 12]))

🔷 7. Разметка последовательностей и BiLSTM-CRF

Для тегирования (NER: B-PER, I-PER, O…) классификатор применяется к каждому output[:, t]. Но независимые решения дают невалидные цепочки (I-ORG после O).

  • BiLSTM-CRF (Huang et al., 2015; Lample et al., 2016): BiLSTM выдаёт emission-оценки для каждого тега, CRF-слой учит матрицу переходов между тегами
  • Обучение: −log p(y|x) через forward-алгоритм
  • Инференс: Витерби — лучшая цепочка тегов целиком
  • Часто + char-level BiLSTM/CNN для OOV-слов и морфологии
  • До BERT — SOTA в NER; и сейчас — лёгкий сильный бейзлайн

🔷 8. ELMo и контекстные эмбеддинги

  • ELMo (Peters et al., 2018): char-CNN + 2-слойный biLM
  • Два отдельных языковых моделирования: forward LM предсказывает следующее слово, backward LM — предыдущее (каждое направление не видит целевое слово)
  • Эмбеддинг слова = обучаемая взвешенная сумма слоёв: ELMok = γ·Σ sj·hk,j
  • Нижние слои — синтаксис, верхние — семантика
  • Отличие от BiLSTM-энкодера: там направления сразу объединяются для задачи; в ELMo они обучаются как LM раздельно, иначе слово «увидело бы себя»
  • Наследник — BERT: «глубокая» двунаправленность через self-attention и MLM

🔷 9. Keras и глубокие BiRNN

from tensorflow import keras
from tensorflow.keras import layers

model = keras.Sequential([
    layers.Embedding(5000, 100, mask_zero=True),
    layers.Bidirectional(layers.LSTM(128, return_sequences=True)),
    layers.Bidirectional(layers.LSTM(64), merge_mode="concat"),
    layers.Dense(2, activation="softmax"),
])
  • Стек: второй слой получает [fwd; bwd] первого — уже обе стороны контекста
  • 2–3 слоя обычно достаточно; dropout между слоями
  • merge_mode: "concat" | "sum" | "mul" | "ave" | None (вернуть два тензора)

🔷 11. Типичные ошибки

Плохо

  • BiRNN для прогноза будущего — утечка, отличные метрики на валидации и провал в проде
  • Брать output[:, -1] как вектор предложения
  • Linear(H, …) вместо Linear(2H, …) — ошибка форм
  • h_n[-1] вместо h_n[-2:] — потерять forward
  • Паддинг без упаковки/маски — обратный проход начинается с PAD

Хорошо

  • pack_padded_sequence(..., enforce_sorted=False)
  • Разделять направления через view(L, 2, B, H)
  • Для тегирования — CRF сверху
  • Пулинг по времени с маской вместо «последнего шага»
