🔷 1. Постановка

Данные приходят потоком (x₁, y₁), (x₂, y₂), … На шаге t модель получает xₜ, выдаёт прогноз ŷₜ, затем узнаёт yₜ, платит потерю ℓ(ŷₜ, yₜ) и сразу обновляется. Весь датасет не хранится, каждый объект обычно используется один раз.

Когда нужно: клики/реклама, фрод, IoT-сенсоры, рекомендации в реальном времени; данные не помещаются в память; распределение меняется. Родственное — Incremental Learning.

🔷 2. Regret

В онлайн-постановке (даже adversarial) качество измеряют регретом — насколько суммарные потери алгоритма хуже лучшей фиксированной модели задним числом:

Regret_T = Σₜ ℓₜ(wₜ) − min_w Σₜ ℓₜ(w)

  • Хороший алгоритм — sublinear regret: Regret_T / T → 0.
  • Online gradient descent на выпуклых ℓ с шагом ηₜ ∝ 1/√t: Regret = O(√T); на сильно выпуклых с ηₜ ∝ 1/t: O(log T).
  • Экспертные алгоритмы (Hedge / Weighted Majority): O(√(T log N)) для N экспертов.
  • Бандиты — частичная обратная связь (видим потерю только выбранного действия), см. Multi-Armed Bandits.

🔷 3. SGD по одному объекту и персептрон

Online SGD: w ← w − ηₜ ∇ℓ(w; xₜ, yₜ). Для логистической регрессии: w ← w − η (σ(wᵀx) − y) x.

Персептрон (y ∈ {−1, +1}): обновление только при ошибке: если y·wᵀx ≤ 0, то w ← w + y·x.

  • Теорема Новикова: если данные разделимы с отступом γ и ‖x‖ ≤ R, число ошибок ≤ (R/γ)².
  • На неразделимых данных персептрон не сходится — веса «скачут». Лечат усреднённым персептроном (возвращают среднее wₜ), ограничением эпох, или переходом к hinge/log-loss SGD с регуляризацией.

Learning rate: убывающий шаг (1/t, 1/√t) нужен для сходимости на стационарных данных, но при дрейфе модель «застывает». В нестационарном потоке — постоянный шаг или сброс после детекции дрейфа. Подробнее — Perceptron, Gradient Descent.

🔷 4. Код: персептрон и online-SGD на numpy

import numpy as np

def perceptron_stream(stream, d):
    w = np.zeros(d); w_sum = np.zeros(d); mistakes = 0
    for t, (x, y) in enumerate(stream, 1):     # y in {-1, +1}
        if y * (w @ x) <= 0:
            w += y * x; mistakes += 1
        w_sum += w
    return w, w_sum / t, mistakes              # обычный и усреднённый

def online_logreg(stream, d, eta=0.05, l2=1e-4):
    w = np.zeros(d)
    for x, y in stream:                        # y in {0, 1}
        p = 1 / (1 + np.exp(-(w @ x)))
        w -= eta * ((p - y) * x + l2 * w)      # постоянный шаг → адаптивность
        yield p                                # прогноз ДО обучения

rng = np.random.default_rng(0)
X = rng.normal(size=(5000, 3)); y = (X @ [1., -2., .5] > 0).astype(int)
probs = np.fromiter(online_logreg(zip(X, y), 3), float)
print("prequential acc:", ((probs > .5) == y).mean())

🔷 6. Код: sklearn на потоке чанков

import numpy as np
from sklearn.linear_model import SGDClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import MiniBatchKMeans
from sklearn.datasets import make_classification

X, y = make_classification(n_samples=20_000, n_features=20, random_state=0)
clf = SGDClassifier(loss="log_loss", learning_rate="constant", eta0=0.01)
scaler = StandardScaler(); km = MiniBatchKMeans(n_clusters=5, random_state=0)
classes = np.unique(y); accs = []

for start in range(0, len(X), 500):            # чанки по 500
    Xb, yb = X[start:start+500], y[start:start+500]
    scaler.partial_fit(Xb); Xb = scaler.transform(Xb)
    if start > 0:                               # test-then-train
        accs.append(clf.score(Xb, yb))
    clf.partial_fit(Xb, yb, classes=classes)
    km.partial_fit(Xb)

print("prequential acc по чанкам:", np.mean(accs).round(3))

# Passive-Aggressive через SGDClassifier (sklearn >= 1.8)
pa = SGDClassifier(loss="hinge", penalty=None, learning_rate="pa1", eta0=1.0)

🔷 7. FTRL-Proximal

Follow-The-Regularized-Leader (McMahan et al., Google, 2013) — стандарт для CTR-моделей с миллиардами разреженных признаков. Даёт точность online-SGD и настоящую разреженность весов (благодаря L1), экономя память.

Для каждой координаты i хранятся zᵢ и nᵢ (сумма квадратов градиентов):

import numpy as np

class FTRLProximal:                      # логистическая регрессия
    def __init__(self, d, alpha=0.1, beta=1.0, l1=1.0, l2=1.0):
        self.a, self.b, self.l1, self.l2 = alpha, beta, l1, l2
        self.z = np.zeros(d); self.n = np.zeros(d)

    def weights(self):
        w = -(self.z - np.sign(self.z) * self.l1) / (
            (self.b + np.sqrt(self.n)) / self.a + self.l2)
        return np.where(np.abs(self.z) <= self.l1, 0.0, w)  # точные нули

    def predict_proba(self, x):
        return 1 / (1 + np.exp(-(self.weights() @ x)))

    def learn(self, x, y):
        w = self.weights()
        g = (1 / (1 + np.exp(-(w @ x))) - y) * x          # градиент log-loss
        sigma = (np.sqrt(self.n + g**2) - np.sqrt(self.n)) / self.a
        self.z += g - sigma * w
        self.n += g**2
  • Per-coordinate learning rate α/(β + √nᵢ), как AdaGrad: редкие признаки учатся быстрее.
  • Гиперпараметры: α (шаг), β (≈1), λ₁ (разреженность), λ₂.
  • Есть в river: optim.FTRLProximal; в Vowpal Wabbit — --ftrl.

🔷 8. Concept drift, окна и забывание

  • Виды: virtual drift — меняется P(x); real concept drift — меняется P(y|x). По форме: внезапный, постепенный, инкрементальный, повторяющийся (сезонность).
  • Скользящее окно: обучение только на последних N объектах; N — компромисс стабильность/адаптивность. ADWIN подбирает окно сам.
  • Экспоненциальное забывание: вес объекта ∝ λ^(t−s), 0 < λ < 1; для SGD — просто постоянный шаг.
  • Детекторы: DDM (рост ошибки над минимумом p + s на 2σ — warning, 3σ — drift), EDDM, ADWIN (сравнивает подокна), Page-Hinkley (кумулятивное отклонение от среднего).
  • Реакция: сброс/переобучение, фоновая модель с warning-уровня, ансамбли с заменой слабых членов (ARF, Leveraging Bagging).

Подробно — Concept Drift, потоковые ансамбли.

🔷 9. Библиотека river и prequential-оценка

Prequential (test-then-train): каждый объект сначала предсказываем, обновляем метрику, затем учимся на нём. Все данные идут и в оценку, и в обучение, утечки нет. Часто добавляют затухание или скользящее окно метрики, чтобы видеть текущее качество. Порядок потока важен: отсортированный поток (сначала один класс) сильно смещает модель — нельзя перемешивать временной ряд, но нельзя и подавать искусственно упорядоченный поток.

# pip install river
from river import compose, preprocessing, linear_model, optim
from river import metrics, datasets, evaluate, drift, tree

model = compose.Pipeline(
    preprocessing.StandardScaler(),
    linear_model.LogisticRegression(optimizer=optim.SGD(0.05)))

# вручную: test-then-train
metric = metrics.ROCAUC()
for x, y in datasets.Phishing():
    p = model.predict_proba_one(x).get(True, 0.0)
    metric.update(y, p)
    model.learn_one(x, y)
print(metric)

# то же одной строкой; Hoeffding Adaptive Tree сам реагирует на дрейф
hat = preprocessing.StandardScaler() | tree.HoeffdingAdaptiveTreeClassifier()
print(evaluate.progressive_val_score(datasets.Phishing(), hat,
                                     metrics.Accuracy(), print_every=500))

# детектор дрейфа на потоке ошибок
adwin = drift.ADWIN()
for i, err in enumerate([0] * 1000 + [1] * 300):
    adwin.update(err)
    if adwin.drift_detected:
        print("drift at", i); break

🔷 11. Типичные ошибки и чек-лист

Ошибки

  • Оценка на случайном split вместо prequential → утечка будущего
  • Learning rate 1/t в нестационарном потоке — модель перестаёт учиться
  • Забыли classes= в первом partial_fit
  • Нормализация по статистикам всего датасета (утечка) вместо бегущих
  • Метки приходят с задержкой, а обучаемся «как будто сразу»

Чек-лист

  • Бегущая нормализация, hashing trick для категорий
  • Prequential-метрика со скользящим окном на дашборде
  • Детектор дрейфа + план реакции (сброс / фоновая модель)
  • Сравнение с периодически переобучаемой batch-моделью
  • Снапшоты модели для отката при «отравлении» потока
