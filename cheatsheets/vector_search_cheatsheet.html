🔷 1. Суть векторного поиска

Векторный поиск — поиск ближайших соседей: объекты (тексты, картинки, товары) представлены векторами-эмбеддингами, а запрос — тоже вектором; нужно найти k ближайших к нему.

Задача: для базы X из N векторов размерности d и запроса q найти top-k по сходству.

  • точный перебор: N·d операций на запрос — просто и точно, но медленно на миллионах
  • приближённый поиск (ANN): строит структуру, чтобы смотреть лишь часть базы, и платит за скорость небольшой потерей recall

Применения: RAG, рекомендации, поиск дубликатов, память агентов.

🔷 2. Меры близости

  • Скалярное произведение: a·b = Σ aᵢbᵢ — учитывает и угол, и длины
  • Косинус: cos(a, b) = a·b / (‖a‖·‖b‖) — только угол, длины не важны
  • L2-расстояние: ‖a − b‖² = ‖a‖² + ‖b‖² − 2·a·b

Нормализация: если ‖a‖ = ‖b‖ = 1, то ‖a − b‖² = 2 − 2·cos(a, b), а cos = a·b. Тогда все три меры дают одинаковый порядок соседей.

Метрику выбирайте ту, на которой обучалась модель эмбеддингов (обычно косинус).

import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(1000, 32))
q = rng.normal(size=32)

dot = X @ q
cos = dot / (np.linalg.norm(X, axis=1) * np.linalg.norm(q))
l2 = np.linalg.norm(X - q, axis=1)

Xn = X / np.linalg.norm(X, axis=1, keepdims=True)
qn = q / np.linalg.norm(q)
by_cos = np.argsort(-(Xn @ qn))[:10]
by_l2 = np.argsort(np.linalg.norm(Xn - qn, axis=1))[:10]
assert np.array_equal(by_cos, by_l2)   # порядок совпал

🔷 3. Точный перебор (flat)

Считаем сходство запроса со всеми векторами и берём k лучших. Это эталон, с которым сравнивают приближённые индексы.

  • одна матрица на вектор запроса: X @ q — быстро на CPU/GPU даже для сотен тысяч векторов
  • argpartition выбирает top-k за O(N), полная сортировка — O(N log N)
  • память: N·d·4 байт для float32 (1 млн × 768 ≈ 3 ГБ)
def top_k(scores, k):
    idx = np.argpartition(-scores, k)[:k]     # k лучших, без порядка
    return idx[np.argsort(-scores[idx])]      # упорядочили только их

exact = top_k(Xn @ qn, 10)

🔷 4. ANN: IVF

IVF (inverted file): база делится k-means на nlist ячеек; у каждой ячейки есть центроид и список векторов. На запросе берём nprobe ближайших центроидов и перебираем только их ячейки.

  • ≈ nlist + nprobe·N/nlist сравнений вместо N
  • nprobe ↑ → recall ↑, скорость ↓; nprobe = nlist даёт точный перебор
  • слабое место: сосед запроса может лежать в соседней, не просмотренной ячейке
def kmeans(X, k, iters=10, seed=0):
    r = np.random.default_rng(seed)
    C = X[r.choice(len(X), k, replace=False)].copy()
    for _ in range(iters):
        a = np.argmax(X @ C.T - 0.5 * (C ** 2).sum(1), axis=1)  # ближайший по L2
        for j in range(k):
            if (a == j).any():
                C[j] = X[a == j].mean(0)
    return C

def assign(X, C):
    return np.argmax(X @ C.T - 0.5 * (C ** 2).sum(1), axis=1)

def ivf_search(q, X, C, cell, nprobe, k):
    near = np.argsort(-(C @ q - 0.5 * (C ** 2).sum(1)))[:nprobe]
    cand = np.flatnonzero(np.isin(cell, near))      # только выбранные ячейки
    return cand[np.argsort(-(X[cand] @ q))[:k]]

centers = rng.normal(size=(20, 32)) * 3
Xc = centers[rng.integers(0, 20, 5000)] + rng.normal(size=(5000, 32))
Xc /= np.linalg.norm(Xc, axis=1, keepdims=True)
C = kmeans(Xc, 20)
cell = assign(Xc, C)

🔷 5. ANN: HNSW и PQ

HNSW — многоуровневый граф «малого мира»: сверху разреженные «магистрали», внизу все точки. Поиск жадно спускается к ближайшим соседям по рёбрам.

  • M — число рёбер у вершины; efSearch — ширина просмотра на запросе (↑ → recall ↑, медленнее)
  • время поиска ≈ O(log N), recall обычно высокий, но граф занимает много памяти

PQ (product quantization) сжимает векторы: вектор делится на m подвекторов, каждый заменяется номером ближайшего из k центроидов (чаще k = 256 → 1 байт). Вектор из d float32 (4d байт) превращается в m байт.

  • экономия памяти в десятки раз ценой погрешности расстояний
  • часто IVF + PQ: ячейки сужают поиск, PQ сжимает содержимое
def pq_train(X, m=4, k=16):
    d = X.shape[1] // m
    books = [kmeans(X[:, j * d:(j + 1) * d], k, seed=j) for j in range(m)]
    codes = np.stack([assign(X[:, j * d:(j + 1) * d], books[j]) for j in range(m)], axis=1)
    return books, codes.astype(np.uint8)

def pq_decode(books, codes):
    return np.hstack([b[codes[:, j]] for j, b in enumerate(books)])

books, codes = pq_train(Xc)
approx = pq_decode(books, codes)       # 4 байта вместо 128 (float32, d=32)

🔷 6. Recall vs скорость

recall@k приближённого поиска = |ANN-top-k ∩ точный top-k| / k. Это главная метрика качества индекса.

У каждого ANN-индекса есть «ручка» компромисса: nprobe (IVF), efSearch (HNSW). Строят кривую «recall — время/доля просмотренных векторов» и выбирают точку под требования (например, recall ≥ 0.95).

def recall(approx_ids, exact_ids):
    return len(set(approx_ids) & set(exact_ids)) / len(exact_ids)

queries = Xc[:50] + 0.05 * rng.normal(size=(50, 32))
queries /= np.linalg.norm(queries, axis=1, keepdims=True)
for nprobe in (1, 3, 10):
    r = np.mean([recall(ivf_search(qq, Xc, C, cell, nprobe, 10),
                        top_k(Xc @ qq, 10)) for qq in queries])
    print(nprobe, round(r, 2))

🔷 7. Фильтры по метаданным

Часто нужно «ближайшие среди документов языка ru за 2025 год». Два подхода:

  • Пре-фильтр: сначала отбираем подходящие записи, ищем среди них. Точно, но ANN-структуры плохо дружат с жёсткими фильтрами
  • Пост-фильтр: ищем top-k и выкидываем неподходящее. Просто, но можно остаться с пустым результатом — тогда берут запас (k·10)

Узкие фильтры (под них подходит 0.1% базы) проще и надёжнее выполнить точным перебором по отобранным записям.

lang = rng.choice(["ru", "en"], size=len(Xc))

mask = lang == "ru"                                   # пре-фильтр
scores = np.where(mask, Xc @ queries[0], -np.inf)
pre = top_k(scores, 5)

post = [i for i in top_k(Xc @ queries[0], 50) if mask[i]][:5]   # пост-фильтр

🔷 8. Плюсы и минусы ANN

✅ Плюсы

  • скорость: миллисекунды на миллионах векторов
  • масштабируется по памяти (PQ) и по узлам (шардирование)
  • ищет по смыслу, а не по точным словам

❌ Минусы

  • результат приблизительный: нужно измерять recall
  • добавление и удаление векторов сложнее, чем в обычной БД; иногда нужна пересборка индекса
  • качество ограничено моделью эмбеддингов
  • настройка параметров (nlist, nprobe, M, efSearch) зависит от данных

🔷 9. Как выбрать индекс

Размер базыВыбор
до ~100 тыс. векторовточный перебор (flat): просто и точно
~100 тыс. – десятки млнHNSW (быстрый, больше памяти) или IVF
сотни млн и больше, мало памятиIVF + PQ, шардирование

Границы — ориентиры: решает измерение на ваших данных (recall, задержка, память).

  • начните с flat как эталона
  • строите ANN — сравнивайте recall@k с эталоном на реальных запросах
  • тюньте nprobe / efSearch под целевой recall

🔷 10. Частые ошибки

  • ❌ Не нормализуют векторы, но используют скалярное произведение вместо косинуса
  • ❌ Запрос и документы кодируются разными моделями или с разной обработкой
  • ❌ Не измеряют recall ANN относительно точного поиска
  • ❌ Слишком много ячеек IVF на маленькой базе — пустые и перекошенные ячейки
  • ❌ Эмбеддинги из старой модели остались в индексе после смены модели
  • ❌ Пост-фильтр с малым k возвращает пустой результат

Связанные темы: RAG (rag), память агента (agent_memory), k-means, kNN.

«Точный перебор — эталон. ANN меняет немного recall на много скорости: измерьте обмен, а не верьте на слово».
