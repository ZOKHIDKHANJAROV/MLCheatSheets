🤝 Мультиагентные системы

📅 Ноябрь 2026

🔷 1. Суть

Мультиагентная система — несколько LLM-агентов с разными ролями, инструкциями и инструментами, которые вместе решают задачу и обмениваются сообщениями.

Это не «чем больше агентов, тем лучше»: каждое сообщение стоит токенов и времени, поэтому разделять работу стоит только тогда, когда это даёт выигрыш.

  • Специализация — узкая роль и короткий контекст у каждого агента
  • Параллелизм — независимые подзадачи идут одновременно
  • Независимая проверка — один агент проверяет другого

🔷 4. Supervisor

def supervisor(task, workers, llm):
    subtasks = llm(f"Раздели задачу на подзадачи для {list(workers)}: {task}")
    results = {}
    for name, subtask in subtasks.items():     # можно запускать параллельно
        results[name] = workers[name](subtask)
    return llm(f"Собери итог из результатов: {results}")

# заглушки вместо реальных вызовов модели
workers = {"поиск": lambda t: f"найдено: {t}", "анализ": lambda t: f"выводы: {t}"}
llm = lambda prompt: {"поиск": "источники", "анализ": "цифры"} if "Раздели" in prompt else "итог"
print(supervisor("отчёт", workers, llm))

🔷 5. Handoff (передача управления)

def run_swarm(start, agents, message, max_hops=5):
    current = start
    for _ in range(max_hops):                  # защита от бесконечной передачи
        reply, next_agent = agents[current](message)
        message = reply
        if next_agent is None:                 # агент закончил работу
            return reply
        current = next_agent
    raise RuntimeError("слишком много передач")

agents = {
    "приём": lambda m: (f"тема понятна: {m}", "техподдержка"),
    "техподдержка": lambda m: (f"решение для: {m}", None),
}
print(run_swarm("приём", agents, "не работает вход"))

🔷 6. Debate и критик

def debate(question, debaters, judge, rounds=2):
    answers = [d(question, history=[]) for d in debaters]
    for _ in range(rounds - 1):
        answers = [d(question, history=answers) for d in debaters]
    return judge(question, answers)            # судья выбирает или сводит

Полезно для спорных вопросов и проверки фактов. Агенты на одной модели часто делают общие ошибки — разнообразие ролей и источников помогает больше, чем число раундов.

🔷 7. Контекст: общий или изолированный

Практика: исполнителю — короткое задание и нужные факты, оркестратору — сжатые итоги, а не все промежуточные сообщения.

🔷 8. Стоимость координации

def messages_per_round(n, scheme):
    k = n - 1                                  # исполнителей
    return {
        "supervisor": 2 * k,                   # задача туда и ответ обратно
        "pipeline": n - 1,
        "all_to_all": n * (n - 1),
    }[scheme]

for n in (3, 5, 10):
    print(n, [messages_per_round(n, s) for s in ("supervisor", "pipeline", "all_to_all")])
# при n = 10: 18, 9 и 90 сообщений за раунд
  • Каждое сообщение — токены, которые кто-то читает и оплачивает
  • У supervisor узкое место — оркестратор: его контекст растёт быстрее остальных

🔷 9. Когда один агент лучше многих

  • задача короткая или шаги жёстко последовательны
  • нужен общий контекст целиком (правка одного файла)
  • важны цена и задержка
  • агенты зависят друг от друга на каждом шаге
  • сначала сделайте одного хорошего агента с инструментами, потом разделяйте — и сравните на тестах

🔷 10. Плюсы и минусы

Плюсы

  • параллельная работа над подзадачами
  • узкий контекст и роль у каждого агента
  • независимая проверка результата

Минусы

  • рост токенов, задержки и цены
  • сложнее отлаживать: ошибка может родиться на стыке агентов
  • потери информации при передаче
  • риск зацикливания и споров без конца

🔷 11. Частые ошибки

  • ❌ много агентов там, где хватило бы одного
  • ❌ нет лимита раундов и передач
  • ❌ всем агентам отдают всю историю
  • ❌ размытые роли: агенты дублируют друг друга
  • ❌ нет оценки: непонятно, лучше ли команда одиночки
«Агентов добавляют ради измеримой пользы — качества, скорости или проверки, а не ради схемы.»
