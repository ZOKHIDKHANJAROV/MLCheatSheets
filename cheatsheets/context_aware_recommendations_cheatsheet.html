📚 Context-aware рекомендации

📅 Январь 2026

🔷 1. Суть контекстных рекомендаций

Учет контекста (время, место, устройство, социальный контекст)

  • Контекст: дополнительная информация о ситуации потребления
  • Улучшение релевантности: рекомендации зависят от обстоятельств
  • Три подхода: pre-filtering, post-filtering, contextual modeling
  • Многомерность: User × Item × Context вместо User × Item
  • Динамичность: предпочтения меняются в зависимости от контекста
  • Персонализация++: учет не только кто, но и когда/где/как
💡 Фильм, который нравится вечером дома, может не подойти для просмотра в метро

🔷 2. Типы контекста

Temporal, Spatial, Social, Device, Mood, Weather

  • Temporal (время): время дня, день недели, сезон, праздники
  • Spatial (место): местоположение, дом/работа/в пути
  • Social (социальный): один, с семьей, с друзьями, деловая встреча
  • Device (устройство): смартфон, планшет, ТВ, десктоп
  • Mood (настроение): радость, грусть, стресс, расслабление
  • Environmental (окружение): погода, температура, шум
💡 Контекст может быть явным (GPS) или неявным (извлекаемым из поведения)

🔷 3. Контекстуальное pre-filtering

Фильтрация данных по контексту до построения модели

  • Идея: отбираем данные, соответствующие текущему контексту
  • Построение модели: используем только релевантные рейтинги
  • Преимущество: можно использовать любой CF алгоритм
  • Недостаток: мало данных для редких контекстов (data sparsity)
  • Пример: рекомендуем фильмы, используя только вечерние рейтинги
  • Реализация: простая, быстрая, легко объяснимая
💡 Pre-filtering эффективен когда контекст четко сегментирует предпочтения 
import pandas as pd
from surprise import SVD, Dataset, Reader

# Загрузка рейтингов с контекстом
ratings = pd.read_csv('ratings_with_context.csv')
# Columns: user_id, item_id, rating, time_of_day, location

# Pre-filtering: только вечерние рейтинги для домашнего просмотра
context_filter = (ratings['time_of_day'] == 'evening') & \
                 (ratings['location'] == 'home')
filtered_ratings = ratings[context_filter]

# Построение модели на отфильтрованных данных
reader = Reader(rating_scale=(1, 5))
data = Dataset.load_from_df(
    filtered_ratings[['user_id', 'item_id', 'rating']], 
    reader
)

# SVD на контекстно-специфичных данных
trainset = data.build_full_trainset()
model = SVD(n_factors=50)
model.fit(trainset)

# Предсказание для текущего контекста
prediction = model.predict(user_id=123, item_id=456)
print(f"Predicted rating: {prediction.est:.2f}")

🔷 4. Контекстуальное post-filtering

Фильтрация рекомендаций по контексту после построения

  • Идея: строим общую модель, затем фильтруем результаты по контексту
  • Два этапа: 1) генерация рекомендаций, 2) контекстная фильтрация
  • Преимущество: используем все данные для обучения
  • Недостаток: контекст учитывается только на финальной стадии
  • Heuristic filtering: правила типа "не рекомендуй тяжелую еду утром"
  • Model-based filtering: отдельный классификатор для фильтрации
💡 Post-filtering проще реализовать и не требует переобучения основной модели

🔷 5. Контекстуальное моделирование

Включение контекста в модель (Tensor Factorization, Factorization Machines)

  • Идея: контекст как дополнительное измерение в модели
  • Tensor Factorization: разложение 3D тензора User×Item×Context
  • Factorization Machines: универсальный подход для любых признаков
  • Neural networks: deep learning для комплексных взаимодействий
  • Преимущество: полная интеграция контекста в модель
  • Недостаток: сложнее обучать, требует больше данных
💡 Contextual modeling — наиболее мощный, но и самый сложный подход

🔷 6. Tensor Factorization

Разложение тензора (пользователь × объект × контекст)

  • 3D тензор: User × Item × Context вместо 2D матрицы
  • HOSVD: Higher-Order Singular Value Decomposition
  • CP decomposition: CANDECOMP/PARAFAC для разложения
  • Tucker decomposition: более гибкое разложение тензора
  • Латентные факторы: для каждого измерения (user, item, context)
  • Применение: music/video рекомендации с временным контекстом
💡 Tensor Factorization естественно моделирует многомерные взаимодействия

n_users, n_items, n_contexts = 100, 200, 10

    W = np.random.rand(tensor.shape[2], ranks[2])
    
    for _ in range(n_iter):
        # Update U (фиксируем V, W)
        # Update V (фиксируем U, W)
        # Update W (фиксируем U, V)
        pass  # Полная реализация требует тензорных операций
    
    return U, V, W

# Факторные матрицы
U, V, W = tucker_als(tensor, ranks=[10, 15, 3])

# Предсказание рейтинга для user i, item j, context k
def predict(U, V, W, i, j, k):
    return np.dot(U[i], np.dot(V[j], W[k]))

rating = predict(U, V, W, user_id=5, item_id=10, context_id=2)
print(f"Predicted rating: {rating:.2f}")

🔷 7. Factorization Machines

Универсальная модель для учета признаков и контекста

  • Формула: ŷ = w₀ + Σwᵢxᵢ + ΣΣ⟨vᵢ,vⱼ⟩xᵢxⱼ
  • Идея: моделирование всех парных взаимодействий признаков
  • Латентные векторы: vᵢ для каждого признака (user, item, context)
  • Гибкость: работает с разреженными данными, любым числом признаков
  • Эффективность: линейная сложность O(kn) вместо O(n²)
  • Библиотеки: libFM, xLearn, DeepCTR
💡 FM объединяет преимущества matrix factorization и feature-based моделей

🔷 8. Временной контекст

Time-of-day, день недели, сезон, праздники

  • Time-of-day: утро, день, вечер, ночь — разные предпочтения
  • День недели: будни vs выходные — различные паттерны
  • Сезонность: лето/зима влияют на выбор товаров/контента
  • Праздники: особые события меняют поведение
  • Тренды: популярность меняется со временем
  • Recency: недавние предпочтения важнее старых
💡 Музыка для утренней пробежки отличается от музыки для вечернего релакса

🔷 9. Пространственный контекст

Локация, расстояние, POI

  • Геолокация: GPS координаты для location-based рекомендаций
  • POI (Points of Interest): рестораны, магазины, достопримечательности рядом
  • Расстояние: близость влияет на вероятность посещения
  • Mobility patterns: дом → работа → торговый центр
  • Check-ins: история посещений мест
  • Применение: рекомендации ресторанов, отелей, маршрутов
💡 Отличный ресторан в 100 км бесполезен, если пользователь ищет обед сейчас 
import pandas as pd
from sklearn.neighbors import NearestNeighbors
from sklearn.preprocessing import StandardScaler

# Location-based рекомендации
venues = pd.read_csv('venues.csv')  # venue_id, lat, lon, category, rating

# Текущая позиция пользователя
user_lat, user_lon = 37.7749, -122.4194  # San Francisco

# Вычисление расстояния (haversine formula)
from sklearn.metrics.pairwise import haversine_distances
from math import radians

venues_coords = venues[['lat', 'lon']].values
venues_coords_rad = [[radians(lat), radians(lon)] for lat, lon in venues_coords]
user_coords_rad = [[radians(user_lat), radians(user_lon)]]

distances_km = haversine_distances(user_coords_rad, venues_coords_rad)[0] * 6371

# Фильтрация по расстоянию (например, в радиусе 5 км)
nearby = venues[distances_km < 5].copy()
nearby['distance'] = distances_km[distances_km < 5]

# Ранжирование по рейтингу и близости
nearby['score'] = nearby['rating'] / (1 + nearby['distance'])
recommendations = nearby.sort_values('score', ascending=False).head(10)

print(recommendations[['venue_id', 'category', 'rating', 'distance', 'score']])

🔷 10. Социальный контекст

Один, с семьей, с друзьями, на работе

  • Компания: с кем пользователь — влияет на выбор
  • Социальное событие: свидание, встреча с друзьями, семейный ужин
  • Настроение группы: коллективные предпочтения vs индивидуальные
  • Социальные сети: что смотрят/слушают друзья
  • Group recommendations: агрегация предпочтений группы
  • Применение: рестораны, фильмы, мероприятия для групп
💡 Фильм для романтического вечера отличается от фильма для просмотра с детьми

🔷 11. Практические примеры

Рекомендации ресторанов, музыки, фильмов

  • Рестораны: время (обед/ужин), локация, компания, погода
  • Музыка: время дня, активность (спорт/работа/сон), настроение
  • Фильмы/сериалы: время, устройство, компания, день недели

🔷 12. Сбор контекстных данных

Implicit vs explicit, privacy concerns

  • Explicit (явный): пользователь явно указывает контекст (опросы, формы)
  • Implicit (неявный): автоматический сбор (сенсоры, логи, GPS)
  • GPS/Geolocation: местоположение через смартфон
  • Device sensors: акселерометр, гироскоп, ambient light
  • System logs: время, устройство, сетевые параметры
  • Privacy: GDPR, согласие пользователя, анонимизация
💡 Баланс между персонализацией и приватностью — ключевой вызов контекстных систем 
import pandas as pd
from datetime import datetime

# Сбор контекстной информации
def collect_context(user_id, item_id, rating):
    """Автоматический сбор контекста при взаимодействии"""
    context = {
        'user_id': user_id,
        'item_id': item_id,
        'rating': rating,
        
        # Temporal context
        'timestamp': datetime.now(),
        'hour': datetime.now().hour,
        'day_of_week': datetime.now().weekday(),
        'is_weekend': datetime.now().weekday() >= 5,
        
        # Device context (можно получить из HTTP headers)
        'device_type': 'mobile',  # или 'desktop', 'tablet'
        'os': 'iOS',
        'screen_size': 'small',
        
        # Location context (если доступен GPS)
        'latitude': 37.7749,
        'longitude': -122.4194,
        'location_type': 'home',  # home, work, transit
        
        # Session context
        'session_duration': 1200,  # секунд
        'items_viewed': 5,
    }
    
    return context

# Пример использования
interaction = collect_context(user_id=123, item_id=456, rating=5)
df_interactions = pd.DataFrame([interaction])

print(df_interactions.head())
