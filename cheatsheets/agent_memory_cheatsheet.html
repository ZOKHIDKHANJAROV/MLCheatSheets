🔷 1. Суть: зачем агенту память

LLM сама по себе не помнит прошлые вызовы: всё, что она «знает» о диалоге, — это текст в её контекстном окне. Окно конечно и стоит денег, поэтому агенту нужна память — механизм, который решает, что держать в контексте, что сохранить на потом и что забыть.

  • Кратковременная: текущий диалог и состояние задачи в окне
  • Долговременная: внешнее хранилище (векторное, база фактов), живёт между сессиями

Цикл: прочитать нужное из хранилища → действовать → записать важное → время от времени чистить.

🔷 2. Кратковременная память

Это контекст запроса: системная инструкция, недавние сообщения, результаты инструментов, найденные воспоминания. Ограничен окном модели.

  • Скользящее окно: держим последние сообщения в пределах бюджета токенов
  • системную инструкцию и цель задачи не вытесняем
  • большие результаты инструментов обрезаем или сохраняем вне контекста
def trim(history, budget=30):
    """Оставляем последние сообщения, пока влезаем в бюджет (слова как «токены»)."""
    kept, used = [], 0
    for msg in reversed(history):
        n = len(msg.split())
        if used + n > budget:
            break
        kept.append(msg)
        used += n
    return kept[::-1]

history = [f"сообщение номер {i} с несколькими словами" for i in range(10)]
print(len(trim(history)))   # 5: по 6 слов, бюджет 30

🔷 3. Суммаризация истории

Когда история не помещается, старую часть заменяют краткой сводкой, а последние сообщения оставляют дословно. Сводку делает LLM (здесь — заглушка).

  • запускайте сжатие по порогу (например, при 70–80% окна)
  • сохраняйте в сводке факты, решения, открытые вопросы и имена, а не пересказ реплик
  • сводка теряет детали: важное записывайте в долговременную память до сжатия
  • при многократном сжатии ошибки накапливаются — пересобирайте сводку из исходных фактов
def compress(history, keep_last=4, summarize=None):
    old, recent = history[:-keep_last], history[-keep_last:]
    if not old:
        return history
    if summarize is None:                          # заглушка вместо вызова LLM
        summarize = lambda msgs: " / ".join(m[:20] for m in msgs)
    return ["[сводка] " + summarize(old)] + recent

short = compress(history)
print(len(short))   # 1 сводка + 4 последних = 5

🔷 5. Хранилище и поиск воспоминаний

Воспоминания индексируют как чанки в RAG: текст + вектор + метаданные (время, важность, тип). Достают по комбинации сходства, свежести и важности (идея из работ про generative agents):

score = w₁·sim(q, m) + w₂·recency(m) + w₃·importance(m), где recency = 0.5^(Δt / T½) — экспоненциальное затухание с периодом полураспада T½.

import re, zlib
import numpy as np

def embed(text, dim=64):
    v = np.zeros(dim)
    for w in re.findall(r"\w+", text.lower()):
        v[zlib.crc32(w.encode()) % dim] += 1.0
    n = np.linalg.norm(v)
    return v / n if n else v

class Memory:
    def __init__(self, half_life=20.0):
        self.items, self.t, self.half_life = [], 0, half_life

    def write(self, text, importance=0.5, kind="semantic"):
        self.t += 1
        self.items.append({"text": text, "vec": embed(text), "imp": importance,
                           "last": self.t, "kind": kind})

    def recall(self, query, k=2, w=(1.0, 0.5, 0.5)):
        self.t += 1
        q = embed(query)
        def score(m):
            rec = 0.5 ** ((self.t - m["last"]) / self.half_life)
            return w[0] * float(m["vec"] @ q) + w[1] * rec + w[2] * m["imp"]
        best = sorted(self.items, key=score, reverse=True)[:k]
        for m in best:
            m["last"] = self.t                     # обращение «освежает» воспоминание
        return [m["text"] for m in best]

mem = Memory()
mem.write("пользователь любит краткие ответы", importance=0.8)
mem.write("в среду обсуждали отчёт по продажам", importance=0.4, kind="episodic")
print(mem.recall("как отвечать пользователю", k=1))

🔷 6. Что и когда записывать

Записывать всё подряд — значит засорить поиск. Практическая политика:

  • Записывайте: явные предпочтения и ограничения, принятые решения, итоги задач, исправленные ошибки, устойчивые факты о пользователе или проекте
  • Не записывайте: болтовню, повторы, промежуточные рассуждения, секреты и данные, которые пользователь не просил хранить
  • Когда: по завершении шага или задачи, перед сжатием контекста, по явной команде «запомни»
  • факт, который изменился, обновляют (upsert по ключу), а не дописывают противоречащую копию
facts = {}   # семантическая память «ключ → значение»

def upsert(key, value, t):
    old = facts.get(key)
    facts[key] = {"value": value, "updated": t}
    return old["value"] if old and old["value"] != value else None

upsert("город", "Москва", t=1)
print(upsert("город", "Казань", t=5))   # Москва — старое значение заменено

🔷 7. Политика забывания

Память растёт, а поиск зашумляется и дорожает — нужно забывать осознанно.

  • По давности (LRU): вытесняем то, к чему давно не обращались
  • По важности: низкая важность уходит первой
  • TTL: срок жизни для временных фактов («сегодня занят»)
  • Слияние и дедупликация: похожие записи объединяют в одну, эпизоды сворачивают в обобщение
  • Явное удаление: по просьбе пользователя и для устаревших фактов

Комбинированная ценность записи: value = a·importance + b·recency; при переполнении удаляют записи с минимальной value.

def forget(mem, capacity=2, a=0.6, b=0.4):
    def value(m):
        rec = 0.5 ** ((mem.t - m["last"]) / mem.half_life)
        return a * m["imp"] + b * rec
    mem.items.sort(key=value, reverse=True)
    dropped, mem.items = mem.items[capacity:], mem.items[:capacity]
    return [m["text"] for m in dropped]

mem.write("мелкая реплика про погоду", importance=0.1)
print(forget(mem))   # ['мелкая реплика про погоду']

🔷 8. Плюсы и минусы

✅ Плюсы

  • персонализация и преемственность между сессиями
  • экономия контекста: в окно попадает только нужное
  • агент учится на прошлых ошибках и решениях

❌ Минусы

  • ошибки в памяти закрепляются: неверный факт будет всплывать снова
  • риски приватности: что хранится, кто видит, как удалить
  • «загрязнение»: чужие или вредоносные тексты, записанные в память, влияют на будущие ответы (memory poisoning)
  • дополнительная сложность: поиск, обновление, чистка

🔷 9. Когда что использовать

  • Одна короткая сессия: достаточно окна, память не нужна
  • Длинный диалог: скользящее окно + суммаризация
  • Агент между сессиями: факты о пользователе в базе фактов, эпизоды в векторном хранилище
  • Повторяющиеся задачи: процедурная память — шаблоны и инструкции
  • Большая база знаний: это уже RAG; граница условна — меняется источник (документы vs опыт агента)

🔷 10. Частые ошибки

  • ❌ Хранить всю историю дословно и отдавать её в контекст целиком
  • ❌ Не отличать факты от гипотез модели — записывать собственные догадки как истину
  • ❌ Дописывать противоречащие факты вместо обновления
  • ❌ Не иметь политики забывания — шум растёт, качество поиска падает
  • ❌ Сжимать историю, не сохранив важное в долговременную память
  • ❌ Записывать секреты и персональные данные без разрешения
