🤖 Основы ИИ-агентов

📅 Ноябрь 2026 · код — с «фейковой LLM», без реальных вызовов API

🔷 1. Что такое ИИ-агент

ИИ-агент — система, где языковая модель (LLM) в цикле сама выбирает следующее действие, вызывает инструменты и учитывает их результаты, пока не достигнет цели или не упрётся в лимит.

Ключевое отличие от обычного вызова модели: число шагов и их порядок заранее неизвестны — их определяет сама модель по ходу работы.

Агент = LLM + инструменты + память + цикл с условием остановки.

🖼 Цикл ИИ-агента

🔷 2. Цикл агента

Восприятие → рассуждение → действие → наблюдение:

  1. Восприятие: цель пользователя, история, состояние среды
  2. Рассуждение: LLM решает, что делать дальше
  3. Действие: вызов инструмента (поиск, код, API)
  4. Наблюдение: результат попадает обратно в контекст

Цикл повторяется, пока модель не выдаст финальный ответ или не сработает лимит шагов / бюджета.

🔷 5. Пример: мини-агент на Python

# Мини-агент без реальной LLM: «модель» — функция с правилами
PRICES = {"Москва": 100, "Казань": 80}          # условная база цен

def search_price(city):
    return PRICES.get(city, "нет данных")

TOOLS = {"search_price": search_price}

def fake_llm(goal, history):
    """Решает по правилам, что делать, глядя на цель и историю."""
    done = {h["arg"] for h in history}
    for city in ("Москва", "Казань"):
        if city in goal and city not in done:
            return {"action": "search_price", "arg": city}
    prices = [h["observation"] for h in history
              if isinstance(h["observation"], int)]
    return {"action": "finish", "arg": f"Сумма: {sum(prices)}"}

def run_agent(goal, max_steps=5):
    history = []
    for _ in range(max_steps):
        decision = fake_llm(goal, history)                   # рассуждение
        if decision["action"] == "finish":                   # остановка
            return decision["arg"], history
        tool = TOOLS[decision["action"]]
        observation = tool(decision["arg"])                  # действие
        history.append({**decision, "observation": observation})  # наблюдение
    return "лимит шагов", history

answer, trace = run_agent("Сколько стоят билеты: Москва и Казань?")
print(answer)       # Сумма: 180
print(len(trace))   # 2

«Модель» здесь — обычная функция с правилами: так цикл можно запускать и тестировать без API.

🔷 6. Автономность — это шкала

  • Рекомендации: агент только предлагает, решает человек
  • Подтверждение: действия с побочными эффектами требуют «ок»
  • Автономно в песочнице: свободно действует в безопасной среде
  • Полная автономность: оправдана редко и требует мониторинга

Чем выше автономность и необратимее действия, тем строже ограничения.

🔷 7. Когда агент нужен, а когда хватит цепочки

Достаточно цепочки (workflow), если шаги известны заранее: «извлечь → классифицировать → ответить».

Нужен агент, если:

  • путь к цели зависит от промежуточных результатов
  • число шагов заранее не известно
  • нужно выбирать из многих инструментов
  • допустима более высокая цена и задержка

Правило: начинайте с самого простого решения и усложняйте только при доказанной необходимости.

🔷 8. Плюсы и минусы

Плюсы

  • решает задачи с неизвестным заранее путём
  • использует внешние данные и действия
  • гибко реагирует на неожиданные результаты

Минусы

  • дороже и медленнее: много обращений к модели
  • ошибки накапливаются от шага к шагу
  • труднее тестировать и воспроизводить
  • риск лишних или опасных действий

🔷 9. Типичные ошибки

  • ❌ Нет лимита шагов — зацикливание и счёт за токены
  • ❌ Агент там, где хватило бы цепочки или одного запроса
  • ❌ Слишком много инструментов с похожими описаниями
  • ❌ Нет логирования шагов — невозможно разобрать сбой
  • ❌ Опасные действия без подтверждения человеком
  • ❌ Оценка только по финальному ответу, без анализа траектории
«Агент — это не магия, а цикл с моделью внутри. Контролируйте цикл: лимиты, логи, проверки.»
