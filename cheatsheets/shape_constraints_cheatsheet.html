📐 Shape Constraints (ограничения формы)

📅 Январь 2026

🔷 1. Что это и зачем

Shape constraints — априорные требования к форме зависимости f(x) от признаков: «растёт», «выпуклая», «с одним пиком», «эти признаки не взаимодействуют». Модель обучается только внутри допустимого класса функций.

  • Интерпретируемость: поведение модели совпадает со здравым смыслом и знаниями эксперта
  • Регуляторика: кредитный скоринг, страхование, медицина — требуют объяснимых и «логичных» зависимостей (больше просрочек → не меньше риск)
  • Экстраполяция и устойчивость: вне области данных модель ведёт себя предсказуемо
  • Регуляризация: сужение пространства гипотез снижает дисперсию, особенно на малых и шумных данных
  • Справедливость и доверие: нет абсурдных эффектов вроде «выше доход → хуже скоринг»
Ограничение уменьшает дисперсию; смещение растёт, только если оно противоречит истинной зависимости.

🔷 3. Монотонность (кратко)

  • Самое частое ограничение: f не убывает (не возрастает) по признаку при фиксированных остальных
  • Поддерживается почти везде: бустинги, sklearn HistGradientBoosting, GAM, lattice, специальные нейросети
  • Детально — в шпаргалке Monotonic Constraints
Монотонность гарантируется «при прочих равных», а не для маргинальной зависимости: частичный график (PDP) должен быть монотонным, scatter y от x — не обязательно.

🔷 4. Изотоническая регрессия

Непараметрическая монотонная регрессия: min Σ wᵢ(yᵢ − ŷᵢ)² при ŷ₁ ≤ ŷ₂ ≤ … ≤ ŷₙ (точки упорядочены по x). Решение — кусочно-постоянная функция, алгоритм PAVA (Pool Adjacent Violators) за O(n).

import numpy as np
from sklearn.isotonic import IsotonicRegression

x = np.sort(np.random.rand(200)) * 10
y = np.log1p(x) + np.random.normal(0, 0.3, 200)

iso = IsotonicRegression(increasing=True, out_of_bounds="clip")
y_fit = iso.fit_transform(x, y)
iso.predict([0.5, 5.0, 12.0])        # 12.0 обрезается к границе
  • increasing="auto" — направление по знаку корреляции Спирмена
  • Калибровка вероятностей: CalibratedClassifierCV(method="isotonic"), см. калибровку
  • Минусы: одномерная, ступенчатая, переобучается при малых n

🔷 5. GAM со shape constraints (pygam)

GAM: g(E[y]) = β₀ + Σ fⱼ(xⱼ), fⱼ — сплайны. Форма задаётся ограничениями на коэффициенты сплайна; каждая fⱼ видна на графике.

from pygam import LinearGAM, LogisticGAM, s, f, te

# x0 — рекламный бюджет (вогнутая), x1 — цена (убывающая),
# x2 — час суток (периодичная), x3 — категория
gam = LinearGAM(
    s(0, constraints="concave")
    + s(1, constraints="monotonic_dec")
    + s(2, basis="cp")                 # циклический сплайн
    + f(3)
).gridsearch(X, y)                     # подбор сглаживания lam

gam.summary()
XX = gam.generate_X_grid(term=0)
pdep = gam.partial_dependence(term=0, X=XX)   # форма f₀
  • Доступные constraints: "monotonic_inc", "monotonic_dec", "convex", "concave", "none"
  • Взаимодействия — только явно заданные тензорные члены te(i, j): остальные пары не взаимодействуют по построению
  • Альтернативы: scam (R), InterpretML EBM (без жёстких форм, но аддитивная)

🔷 6. Бустинги: monotone + interaction constraints

import lightgbm as lgb, xgboost as xgb
from sklearn.ensemble import HistGradientBoostingRegressor

# признаки: 0 — доход(+), 1 — просрочки(−), 2 — возраст, 3 — регион
mono = [1, -1, 0, 0]
groups = [[0, 1], [2, 3]]     # взаимодействия только внутри групп

lgbm = lgb.LGBMClassifier(
    monotone_constraints=mono,
    monotone_constraints_method="advanced",   # basic / intermediate / advanced
    interaction_constraints=groups)

xgbm = xgb.XGBClassifier(
    tree_method="hist",
    monotone_constraints=tuple(mono),
    interaction_constraints=groups)

hgb = HistGradientBoostingRegressor(
    monotonic_cst=mono, interaction_cst=groups)
  • Monotone: при сплите проверяется порядок значений в листьях; дерево не нарушает направление
  • Interaction constraints: на одном пути от корня к листу могут встречаться только признаки одной группы → f раскладывается в сумму функций от групп
  • Группа из одного признака = чисто аддитивный эффект (как в GAM)
  • Выпуклость/унимодальность в бустингах напрямую не поддерживаются — для них GAM или lattice
  • CatBoost: параметр monotone_constraints

🔷 7. Lattice models (TensorFlow Lattice)

Решётка (lattice) — интерполированная таблица значений на сетке; ограничения формы — линейные неравенства на параметры решётки, выполняются везде, а не только на обучающих точках.

import tensorflow as tf
import tensorflow_lattice as tfl
import numpy as np

inp = tf.keras.Input(shape=(2,))
x0, x1 = tf.split(inp, 2, axis=1)
c0 = tfl.layers.PWLCalibration(          # кусочно-линейная калибровка
    input_keypoints=np.linspace(0, 100, 10),
    monotonicity="increasing", convexity="concave",
    output_min=0.0, output_max=1.0)(x0)
c1 = tfl.layers.PWLCalibration(
    input_keypoints=np.linspace(0, 1, 10),
    monotonicity="decreasing", output_min=0.0, output_max=1.0)(x1)
out = tfl.layers.Lattice(
    lattice_sizes=[2, 2],
    monotonicities=["increasing", "increasing"])(
        tf.concat([c0, c1], axis=1))
model = tf.keras.Model(inp, out)
  • Поддерживает монотонность, выпуклость/вогнутость (в калибраторах), унимодальность, edgeworth/trapezoid trust, доминирование
  • Ансамбли решёток (RTL, Crystals) для многих признаков
  • ⚠️ Библиотека привязана к Keras 2 / определённым версиям TF — проверяйте совместимость

🔷 8. Нейросети: hard vs soft

ПодходКакГарантия
ICNN (input convex NN)неотрицательные веса между скрытыми слоями + выпуклые неубывающие активации (ReLU)выпуклость по входу везде
Монотонные сетинеотрицательные веса по монотонным входам (|W|, softplus), min-max сети, Deep Lattice Networksвезде
Штраф (soft)loss += λ·Σ ReLU(−∂f/∂xⱼ) на точкахприблизительно, только там, где считали
Проверка после обучениясертификация (MILP, SMT), сканирование сеткидиагностика
import torch

def monotonic_penalty(model, x, idx, lam=1.0):
    x = x.clone().requires_grad_(True)
    y = model(x).sum()
    g = torch.autograd.grad(y, x, create_graph=True)[0][:, idx]
    return lam * torch.relu(-g).mean()       # штраф за ∂f/∂x_idx < 0

loss = mse(model(xb), yb) + monotonic_penalty(model, xb, idx=0)
  • Soft: легко добавить к любой модели, но нарушения возможны вне обучающих точек
  • Hard: гарантия для регулятора, но меньший класс функций

🔷 10. Проверка и типичные ошибки

  • Проверка: PDP/ICE-кривые (PartialDependenceDisplay), сканирование сетки значений признака для многих объектов, SHAP dependence plots (SHAP)
  • ❌ Ограничение, противоречащее данным, → рост ошибки; сравнивайте метрику с/без ограничений на CV
  • ❌ Монотонность по признаку, сильно коррелированному с другим без ограничения: эффект «перетекает» в соседний признак
  • ❌ Перепутан знак (−1/+1) или порядок признаков в векторе ограничений
  • ❌ Монотонность на закодированной категории (label encoding) — бессмысленна
  • ❌ Ожидание выпуклости от бустинга — он поддерживает только монотонность и взаимодействия
  • ❌ Soft-ограничение в регуляторной модели без последующей проверки

🔷 11. Когда применять: чек-лист

  • ☐ Есть знание предметной области о форме зависимости (экономика, физика, политика компании)
  • ☐ Модель проверяют регулятор/эксперты (скоринг: credit scoring, тарифы, медицина)
  • ☐ Мало данных или ожидается экстраполяция
  • ☐ Выбрать инструмент: бустинг (монотонность + взаимодействия) → GAM (выпуклость, наглядность) → lattice/ICNN (сложные формы)
  • ☐ Сравнить качество с/без ограничений, проверить PDP/ICE
  • ☐ Задокументировать ограничения и их обоснование
