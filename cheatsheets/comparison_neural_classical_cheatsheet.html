⚖️ Нейросети vs классические методы

📅 Январь 2026

🔷 1. Главная идея

Универсального победителя нет: выбор определяется типом данных, объёмом, требованиями к интерпретации и стоимостью обучения и поддержки.

  • Классические методы: линейные модели, kNN, SVM, деревья, случайный лес, градиентный бустинг (XGBoost, LightGBM, CatBoost)
  • Нейросети: MLP, CNN, RNN, трансформеры — учат представления (representation learning) end-to-end
  • Эмпирическое правило: таблицы → бустинг; изображения, текст, звук → нейросети
Начинайте с сильного простого бейзлайна. Сложная модель должна доказать выигрыш на честной валидации.

🔷 2. Табличные данные: почему бустинг сильнее

  • Разнородные признаки: разные шкалы, категории, пропуски — деревьям всё равно, сетям нужна предобработка
  • Неинформативные признаки: деревья их игнорируют, MLP страдает сильнее
  • Нерегулярные зависимости: ступеньки и пороги — естественны для деревьев; сети смещены к гладким функциям
  • Нет инвариантности к поворотам: смысл у каждого столбца свой, а MLP «перемешивает» признаки линейным слоем
  • Размер данных: типичная таблица — тысячи–сотни тысяч строк; сетям этого часто мало
  • Тюнинг: бустинг хорош почти «из коробки», сети чувствительны к архитектуре, lr, регуляризации

Нейросети на таблицах выигрывают или полезны при: очень больших данных, мультимодальности (таблица + текст/картинки), необходимости дообучения/онлайн-обучения, эмбеддингах высококардинальных категорий, последовательностях событий. См. MLP для таблиц.

🔷 5. Объём данных и интерпретируемость

  • Кривая обучения: у классических методов качество выходит на плато раньше, нейросети продолжают улучшаться с ростом данных и размера модели (scaling laws)
  • Мало данных + неструктурированные: не учить с нуля, а брать предобученную сеть (fine-tuning или эмбеддинги + логрег)
  • Мало табличных данных: регуляризованная линейная модель, бустинг с сильной регуляризацией; TabPFN — нейросетевой вариант для малых таблиц
  • Регуляторика (кредиты, медицина): линейные модели/скоринговые карты, GAM, бустинг с монотонными ограничениями + SHAP
  • Объяснения нейросетей (Grad-CAM, Integrated Gradients) — локальные и менее устойчивые

🔷 6. Стоимость и подбор гиперпараметров

  • Обучение: бустинг на CPU за минуты; сети — GPU, эксперименты с архитектурой, больше времени инженера
  • Инференс: дерево/линейка — латентность микросекунды и маленький артефакт; большая сеть требует батчинга, квантизации, GPU
  • Поддержка: версии фреймворков, CUDA, воспроизводимость, мониторинг дрейфа
  • Тюнинг бустинга: learning_rate, n_estimators + early stopping, num_leaves/max_depth, min_child_samples, subsample, регуляризация
  • Тюнинг сетей: lr и его расписание, ширина/глубина, dropout, weight decay, batch size, нормализация входов, эпохи
  • Для обоих — одинаковый бюджет поиска (например, Optuna на N trials), см. тюнинг гиперпараметров

🔷 8. Бенчмарки (качественно)

  • Grinsztajn et al., 2022 («Why do tree-based models still outperform deep learning on tabular data?»): на средних таблицах деревья в целом впереди; причины — нерегулярные функции, неинформативные признаки, неинвариантность к поворотам
  • Shwartz-Ziv & Armon, 2022 («Tabular data: deep learning is not all you need»): XGBoost в среднем сильнее предложенных табличных сетей, ансамбль сети + XGBoost — лучше всех
  • Gorishniy et al., 2021 (FT-Transformer): хорошо настроенные ResNet/MLP — сильный бейзлайн; явного победителя нет, многое зависит от датасета
  • McElfresh et al., 2023: разница между лучшими сетями и бустингом часто меньше, чем выигрыш от тюнинга; характеристики датасета важнее семейства модели
  • TabPFN (Hollmann et al.): предобученный трансформер, конкурентен на малых таблицах
Выводы бенчмарков зависят от выбора датасетов и бюджета тюнинга — проверяйте на своих данных.

🔷 9. Гибриды

  • Эмбеддинги + бустинг: текст/изображения → эмбеддинги предобученной сети (BERT, CLIP, ResNet) → признаки для LightGBM вместе с табличными
  • Entity embeddings: сеть учит эмбеддинги высококардинальных категорий, затем они идут в бустинг
  • TabNet: последовательное внимание к признакам, встроенный отбор признаков и интерпретация
  • FT-Transformer: каждый признак → токен, далее трансформер; сильный нейросетевой бейзлайн для таблиц
  • NODE, GrowNet: дифференцируемые деревья / бустинг из сетей
  • Ансамбль / стекинг: усреднение бустинга и сети часто лучше каждой модели — ошибки разные (стекинг)

🔷 10. Код: честное сравнение на sklearn

import time
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.neural_network import MLPClassifier

X, y = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)  # одни фолды

models = {
    "logreg": make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=1000)),
    "rf": RandomForestClassifier(n_estimators=300, random_state=42),
    "hgb": HistGradientBoostingClassifier(learning_rate=0.05, max_iter=300,
                                          early_stopping=True, random_state=42),
    "mlp": make_pipeline(StandardScaler(),             # сетям нужен скейлинг
                         MLPClassifier(hidden_layer_sizes=(128, 64), alpha=1e-3,
                                       early_stopping=True, max_iter=500,
                                       random_state=42)),
}
for name, m in models.items():
    t = time.perf_counter()
    r = cross_validate(m, X, y, cv=cv, scoring=["roc_auc", "accuracy"])
    print(f"{name:7s} AUC={r['test_roc_auc'].mean():.4f}±{r['test_roc_auc'].std():.4f} "
          f"acc={r['test_accuracy'].mean():.4f} time={time.perf_counter() - t:.1f}s")
  • Одинаковые фолды и метрики, предобработка внутри Pipeline (нет утечки)
  • Сравнивайте разброс по фолдам, а не только среднее; для значимости — повторный CV

🔷 11. Типичные ошибки сравнения

  • ❌ Одну модель тюнят часами, другую запускают с параметрами по умолчанию
  • ❌ Подбор гиперпараметров на тесте; разные разбиения для разных моделей
  • ❌ MLP без масштабирования признаков и без early stopping
  • ❌ Вывод по одному датасету / одному seed
  • ❌ Игнорирование стоимости: +0.1% AUC ценой GPU-инференса и сложной поддержки
  • ❌ Нейросеть с нуля на 500 картинках вместо transfer learning

🔷 12. Чек-лист выбора

  • ☐ Тип данных и объём; есть ли предобученные модели
  • ☐ Требования к интерпретации, регуляторике, латентности, железу
  • ☐ Бейзлайны: линейная модель + бустинг (+ предобученная сеть для неструктурированных)
  • ☐ Равный бюджет тюнинга, одни фолды, несколько seed
  • ☐ Учесть стоимость обучения, инференса и поддержки
  • ☐ Попробовать гибрид или ансамбль, если модели ошибаются по-разному
