🧭 Планирование агентов

📅 Ноябрь 2026

🔷 1. Суть

Планирование агента — разбиение цели на шаги, их выполнение, проверка результата и исправление плана. Без плана агент действует «по одному шагу» (ReAct) и легко теряет цель на длинной задаче.

Plan-and-execute: сначала планировщик строит весь план, затем исполнитель выполняет его шаги, а при сбое план пересматривается.

  • ReAct — гибко, но каждый шаг заново «думает» с нуля
  • Plan-and-execute — дешевле на длинных задачах, шаги можно проверять
  • Рефлексия — агент оценивает собственный результат и правит его

🔷 3. Plan-and-execute

def plan_and_execute(goal, planner, executor, max_replans=2):
    plan = planner(goal)              # список шагов
    done, replans = [], 0
    while plan:
        step = plan[0]
        result = executor(step, done)
        if result.ok:
            done.append((step, result))
            plan = plan[1:]
        elif replans < max_replans:
            replans += 1              # учтём ошибку и пересоберём остаток
            plan = planner(goal, done=done, error=result.error)
        else:
            return {"status": "failed", "done": done}
    return {"status": "ok", "done": done}

🔷 4. Декомпозиция: DAG подзадач

Подзадачи с зависимостями образуют граф без циклов. Стандартная библиотека умеет упорядочивать его:

from graphlib import TopologicalSorter

deps = {                       # подзадача: от чего зависит
    "найти источники": set(),
    "прочитать A": {"найти источники"},
    "прочитать B": {"найти источники"},
    "сверить цифры": {"прочитать A", "прочитать B"},
    "написать отчёт": {"сверить цифры"},
}
order = list(TopologicalSorter(deps).static_order())
print(order)   # источники → A, B → сверка → отчёт

Независимые подзадачи (A и B) можно выполнять параллельно. Цикл в зависимостях — ошибка плана: TopologicalSorter бросит CycleError.

🔷 5. Reflexion и self-critique

def solve_with_reflection(task, llm, check, max_tries=3):
    reflections = []                           # «память» об ошибках
    for attempt in range(max_tries):
        answer = llm(task, hints=reflections)
        ok, feedback = check(answer)           # тесты, правила или модель-критик
        if ok:
            return answer
        reflections.append(llm(f"Почему не получилось: {feedback}. Что изменить?"))
    return None
  • Обратная связь лучше всего работает, когда она внешняя (тесты, результат инструмента)
  • Критик той же модели без внешнего сигнала может уверенно подтверждать неверный ответ

🔷 6. Tree of Thoughts (идея)

Вместо одной цепочки рассуждений агент разворачивает дерево: на каждом шаге несколько кандидатов-«мыслей», оценка каждого и поиск (в ширину, в глубину или beam) с возвратом из тупиков.

def tree_search(root, expand, score, beam=3, depth=3):
    frontier = [root]
    for _ in range(depth):
        candidates = [c for node in frontier for c in expand(node)]
        candidates.sort(key=score, reverse=True)
        frontier = candidates[:beam]           # оставляем лучших
    return max(frontier, key=score)

Цена — число вызовов модели: beam × ветвление × глубина. Применяйте там, где важен перебор вариантов (головоломки, планирование), а не для каждого запроса.

Выполненные шаги не отменяйте без нужды — пересобирайте только остаток плана.

🔷 8. Бюджет шагов и токенов

class Budget:
    def __init__(self, max_steps=20, max_tokens=50_000):
        self.steps_left, self.tokens_left = max_steps, max_tokens

    def spend(self, tokens):
        self.steps_left -= 1
        self.tokens_left -= tokens
        return self.steps_left >= 0 and self.tokens_left >= 0

budget = Budget(max_steps=3, max_tokens=1000)
for step_cost in (400, 400, 400):
    if not budget.spend(step_cost):
        print("бюджет исчерпан — остановка")
        break
  • Лимит нужен всегда: агент без него способен зациклиться
  • Следите и за повторами: одинаковый вызов подряд — признак цикла

🔷 9. Плюсы и минусы

Плюсы

  • явная цель и прогресс — легко отлаживать
  • можно проверять шаги и параллелить независимые
  • дешевле ReAct на длинных задачах

Минусы

  • план устаревает при неожиданных результатах
  • лишние вызовы на планирование и рефлексию
  • модель может строить правдоподобный, но невыполнимый план

🔷 10. Когда использовать

  • задача длинная и разбивается на понятные шаги
  • шаги зависят друг от друга (есть порядок)
  • результат можно проверить (тесты, правила)
  • для коротких задач хватит одного вызова или ReAct

🔷 11. Частые ошибки

  • ❌ нет лимита шагов и токенов
  • ❌ план без проверки зависимостей (циклы, лишние шаги)
  • ❌ рефлексия без внешнего сигнала
  • ❌ перепланирование с нуля вместо правки остатка
  • ❌ слишком мелкая декомпозиция — расходы на координацию больше пользы
«План — гипотеза. Агент должен уметь его проверять и менять, а не просто выполнять.»
