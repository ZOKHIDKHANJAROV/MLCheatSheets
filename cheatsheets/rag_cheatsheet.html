🔎 RAG: генерация с поиском

📅 Ноябрь 2026

🔷 1. Суть RAG

RAG (Retrieval-Augmented Generation) — генерация, дополненная поиском: перед ответом система находит в базе знаний нужные фрагменты и кладёт их в prompt вместе с вопросом.

Зачем:

  • знания актуальны без дообучения модели — достаточно обновить индекс
  • ответ можно подкрепить ссылками на источники
  • меньше «выдумок»: модель опирается на найденный текст
  • приватные данные остаются в вашем хранилище

Идея: ответ = LLM(инструкция + найденные чанки + вопрос). Качество ответа ограничено качеством поиска: если нужного фрагмента нет в контексте, модель его не «вспомнит».

🔷 2. Пайплайн

Офлайн (индексация):

  1. Загрузка и очистка документов
  2. Чанкинг — нарезка на фрагменты
  3. Эмбеддинг каждого чанка
  4. Запись в индекс + метаданные (источник, дата, раздел)

Онлайн (запрос):

  1. Эмбеддинг вопроса, поиск top-k кандидатов
  2. (Опц.) гибридный поиск и реранкинг
  3. Сборка контекста в пределах бюджета токенов
  4. Генерация ответа со ссылками на источники
import re
import numpy as np

docs = {

    "guide": "Доставка занимает 3 дня. Самовывоз бесплатный.",
}
# индексация:  chunks = chunk(...) -> E = embed(...)
# запрос:      hits = search(q, k) -> context -> prompt -> llm(prompt)

🔷 3. Чанкинг

Чанк — единица поиска. Слишком крупный чанк «размывает» смысл и тратит контекст; слишком мелкий теряет окружение.

Параметры:

  • size — размер чанка (ориентир: 200–500 токенов, подбирайте под данные)
  • overlap — перекрытие соседних чанков (ориентир: 10–20% размера)
  • границы лучше резать по абзацам и заголовкам, а не посреди предложения

Формулы: шаг = size − overlap; число чанков ≈ ⌈(n − overlap) / (size − overlap)⌉ для текста из n токенов.

def chunk(words, size=40, overlap=10):
    step = size - overlap
    return [" ".join(words[i:i + size])
            for i in range(0, max(len(words) - overlap, 1), step)]

words = ("слово " * 100).split()
parts = chunk(words, size=40, overlap=10)
print(len(parts))   # 3 чанка: (100 - 10) / 30 = 3

🔷 4. Эмбеддинги и плотный поиск

Чанк и вопрос превращаются в векторы; близость по смыслу = косинусное сходство. Плотный поиск находит перефразировки, но может промахнуться на редких терминах, кодах и именах.

Ниже — «игрушечный» эмбеддинг (хэшированный мешок слов): настоящая модель даёт смысловую близость, эта — только пересечение слов, зато без API.

import zlib

def embed(text, dim=64):
    v = np.zeros(dim)
    for w in re.findall(r"\w+", text.lower()):
        v[zlib.crc32(w.encode()) % dim] += 1.0
    n = np.linalg.norm(v)
    return v / n if n else v

chunks = ["Возврат товара возможен в течение 14 дней",
          "Доставка занимает 3 дня",
          "Самовывоз из магазина бесплатный"]
E = np.stack([embed(c) for c in chunks])
q = embed("сколько дней на возврат товара")
top = np.argsort(-(E @ q))[:2]   # единичные векторы: cos = E @ q
print([chunks[i] for i in top])

🔷 5. Гибридный поиск

BM25 — лексический поиск по точным словам; эмбеддинги — по смыслу. Вместе они покрывают слабые стороны друг друга.

BM25: score(q, d) = Σₜ IDF(t) · f·(k₁+1) / (f + k₁·(1 − b + b·|d|/avgdl)), где f — частота терма t в документе d; k₁ ≈ 1.2–2, b ≈ 0.75.

RRF (Reciprocal Rank Fusion) сливает ранжирования без подбора весов: score(d) = Σ 1 / (k + rankᵣ(d)), k ≈ 60.

def bm25(query, docs, k1=1.5, b=0.75):
    toks = [re.findall(r"\w+", d.lower()) for d in docs]
    N, avgdl = len(docs), np.mean([len(t) for t in toks])
    scores = np.zeros(N)
    for term in set(re.findall(r"\w+", query.lower())):
        n = sum(term in t for t in toks)
        idf = np.log(1 + (N - n + 0.5) / (n + 0.5))
        for i, t in enumerate(toks):
            f = t.count(term)
            scores[i] += idf * f * (k1 + 1) / (f + k1 * (1 - b + b * len(t) / avgdl))
    return scores

def rrf(rankings, k=60):
    score = {}
    for ranking in rankings:
        for r, d in enumerate(ranking, 1):
            score[d] = score.get(d, 0.0) + 1 / (k + r)
    return sorted(score, key=score.get, reverse=True)

lex = list(np.argsort(-bm25("возврат товара", chunks)))
dense = list(np.argsort(-(E @ embed("возврат товара"))))
fused = rrf([lex, dense])

🔷 6. Реранкинг

Двухэтапная схема: быстрый поиск достаёт 20–100 кандидатов, затем медленная, но точная модель (cross-encoder, смотрит на пару «вопрос + чанк» целиком) пересортировывает их, и в prompt идёт лишь top-3…5.

  • bi-encoder (эмбеддинги): быстро, чанки кодируются заранее
  • cross-encoder: точнее, но считается заново для каждой пары
  • реранкинг повышает precision верхушки, но не вернёт чанк, которого нет среди кандидатов — следите за recall@k первого этапа
def rerank(query, cands, scorer, top=2):
    return sorted(cands, key=lambda c: scorer(query, c), reverse=True)[:top]

# заглушка вместо cross-encoder: доля слов запроса, найденных в чанке
def overlap(q, c):
    qs = set(re.findall(r"\w+", q.lower()))
    return len(qs & set(re.findall(r"\w+", c.lower()))) / len(qs)

best = rerank("возврат товара за 14 дней", chunks, overlap)

🔷 7. Сборка контекста

Чанки добавляются в prompt по убыванию релевантности, пока хватает бюджета токенов. Модели хуже используют информацию из середины длинного контекста («lost in the middle»), поэтому самые важные чанки ставят в начало и конец.

  • явно отделяйте чанки и подписывайте источник: [1] faq.md
  • просите отвечать только по контексту и говорить «не знаю», если ответа нет
  • просите ссылаться на номера источников
def build_context(chunks, budget=60):
    picked, used = [], 0
    for c in chunks:                      # уже по убыванию релевантности
        n = len(c.split())
        if used + n > budget:
            break
        picked.append(c)
        used += n
    ordered = picked[0::2] + picked[1::2][::-1]   # лучшие — по краям
    return "\n".join(f"[{i + 1}] {c}" for i, c in enumerate(ordered))

context = build_context([chunks[i] for i in top])
prompt = (f"Отвечай только по контексту. Если ответа нет — скажи «не знаю».\n"
          f"Контекст:\n{context}\nВопрос: сколько дней на возврат?")

🔷 8. Метрики retrieval

Поиск оценивают отдельно от генерации — на наборе вопросов с известными релевантными чанками.

  • recall@k = |релевантные ∩ top-k| / |релевантные| — попал ли нужный чанк в контекст
  • precision@k = |релевантные ∩ top-k| / k — сколько мусора в контексте
  • MRR = среднее по запросам от 1 / rank первого релевантного (0, если не найден)
def recall_at_k(ranked, relevant, k):
    return len(set(ranked[:k]) & relevant) / len(relevant)

def mrr(rankings, relevants):
    rr = []
    for ranked, rel in zip(rankings, relevants):
        rank = next((i for i, d in enumerate(ranked, 1) if d in rel), None)
        rr.append(1 / rank if rank else 0.0)
    return float(np.mean(rr))

rankings = [["d3", "d1", "d7"], ["d2", "d9", "d4"]]
relevants = [{"d1"}, {"d4", "d5"}]
print(recall_at_k(rankings[1], relevants[1], 3))   # 0.5
print(round(mrr(rankings, relevants), 3))          # 0.417

🔷 10. Плюсы и минусы

✅ Плюсы

  • свежие и приватные знания без дообучения
  • прозрачность: видно, какие источники использованы
  • дешевле и быстрее обновляется, чем fine-tuning

❌ Минусы

  • качество упирается в поиск и чанкинг
  • дополнительная задержка и стоимость (поиск, реранкер, длинный prompt)
  • плохо отвечает на вопросы, требующие свести весь корпус (нужна агрегация, а не поиск фрагментов)
  • нужно поддерживать индекс в актуальном состоянии

🔷 11. Когда использовать

  • вопросы по документации, базе знаний, регламентам
  • данные меняются чаще, чем вы готовы переобучать модель
  • нужны ссылки на источники и аудит ответов
  • корпус слишком велик, чтобы целиком поместиться в контекст

Не стоит: если весь материал умещается в контекст (проще положить его целиком), или нужно изменить стиль/формат ответа модели — это скорее задача prompt engineering или fine-tuning.

🔷 12. Частые ошибки

  • ❌ Не измеряют retrieval отдельно от генерации
  • ❌ Один размер чанка «на глаз» без проверки recall@k
  • ❌ Эмбеддинги запроса и документов из разных моделей
  • ❌ Нет метаданных и дат — нельзя отфильтровать устаревшее
  • ❌ Слишком большой k: контекст забит шумом
  • ❌ Промпт не запрещает отвечать без опоры на контекст
