🎬 Генерация видео

📅 Январь 2026

🔷 1. Задачи

  • Text-to-video (T2V): промпт → клип (Sora, Veo, CogVideoX, HunyuanVideo, Wan)
  • Image-to-video (I2V): оживление картинки, первый кадр задан (Stable Video Diffusion)
  • Предсказание кадров (video prediction): по прошлым кадрам — будущие; для роботов и world models
  • Интерполяция кадров и повышение FPS; video super-resolution
  • Video-to-video: перенос стиля, редактирование по тексту, управление позой/глубиной (ControlNet-подобные)
  • Безусловная генерация: исследовательская постановка (UCF-101, SkyTimelapse)

Видео — тензор T×H×W×3: 5 секунд 720p при 24 fps — это 120 кадров ≈ 330 млн чисел.

🔷 2. Временная согласованность

Главная трудность: кадр по отдельности — изображение, но вместе они должны сохранять идентичность объектов, форму, освещение и давать правдоподобное движение.

  • Покадровая генерация image-моделью → мерцание (flicker), «плывущие» текстуры, объекты меняются
  • Temporal attention / 3D-свёртки связывают кадры внутри модели
  • Совместная генерация всего клипа (а не кадр за кадром) — шум денойзится сразу для всех кадров
  • Пространственно-временной VAE: латенты сжаты и по времени, декодер сглаживает переходы
  • Длинные видео: генерация окнами с перекрытием, условие на последние кадры, иерархия «ключевые кадры → интерполяция»
Модель учит статистику пикселей, а не законы физики: объекты проходят друг сквозь друга, появляются и исчезают, число пальцев меняется.

🔷 3. Эволюция подходов

ПодходИдеяПримеры
GAN-видеогенератор кадров + дискриминаторы по кадру и по клипу; разделение контента и движенияVGAN, TGAN, MoCoGAN, DVD-GAN, StyleGAN-V
Авторегрессия по токенамVQ-VAE/VQGAN кодирует видео в дискретные токены, трансформер предсказывает следующийVideoGPT, CogVideo, Phenaki, VideoPoet
Пиксельная видео-диффузия3D U-Net с факторизованным вниманием, каскад апсемплеровVDM, Imagen Video, Make-A-Video
Латентная видео-диффузиядиффузия в латентах VAE; часто дообучение T2I-модели временными слоямиVideo LDM, AnimateDiff, Stable Video Diffusion
Диффузионные трансформеры (DiT)видео → пространственно-временные патчи → трансформер; flow matchingSora, CogVideoX, HunyuanVideo, Wan, Open-Sora

GAN — быстро, но нестабильно и мало разнообразия; авторегрессия — долгий инференс и накопление ошибок; диффузия — текущий стандарт качества. См. диффузионные модели, GAN.

🔷 4. Видео-диффузия: архитектура

  • 3D U-Net (VDM): 2D-свёртки 3×3 «раздуваются» в 1×3×3 (пространство), добавляются временные слои; внимание по пространству внутри кадра + по времени для каждой позиции
  • Inflation: веса берутся из T2I-модели, временные слои инициализируются так, чтобы сначала быть тождественными (zero-init выхода)
  • Совместное обучение на картинках (как видео из 1 кадра) и видео — больше разнообразия контента
  • Каскад: базовая модель низкого разрешения/FPS → временной апсемплинг → пространственный SR
  • Условия: текст (T5/CLIP через cross-attention), первый кадр (конкатенация латента), FPS и «сила движения» как скалярные эмбеддинги

Цель как у обычной диффузии: ‖ε − εθ(xt, t, c)‖² (или v-prediction / flow matching), но x — латент всего клипа.

🔷 5. Внимание: полное vs факторизованное

ВариантСложностьСвойства
Полное 3DO((T·H·W)²)лучше моделирует сложное движение; очень дорого
Факторизованное (spatial → temporal)O(T·(HW)² + HW·T²)дёшево, легко дообучить T2I; хуже для сложных пространственно-временных связей
Окно / разреженноемежду нимилокальные окна по пространству-времени

Современные DiT (CogVideoX, HunyuanVideo) используют полное 3D-внимание + 3D RoPE на сильно сжатых латентах, опираясь на FlashAttention и параллелизм по последовательности.

🔷 6. Латенты и патчи: считаем токены

Пример CogVideoX: 49 кадров 480×720. 3D VAE сжимает в 4× по времени и 8× по пространству:

  • латент: (1 + 48/4) × 60 × 90 = 13 × 60 × 90
  • патчи 2×2: 13 × 30 × 45 = 17 550 токенов
  • без VAE было бы ≈ 17 млн пикселей на канал — диффузия напрямую неподъёмна

Приёмы удешевления: сильное сжатие VAE (до 4×16×16), низкое разрешение + апсемплинг, меньше FPS + интерполяция, дистилляция в несколько шагов, tiling при декодировании.

🔷 7. Код: image-to-video (diffusers)

import torch
from diffusers import StableVideoDiffusionPipeline
from diffusers.utils import load_image, export_to_video

pipe = StableVideoDiffusionPipeline.from_pretrained(
    "stabilityai/stable-video-diffusion-img2vid-xt",
    torch_dtype=torch.float16, variant="fp16")
pipe.enable_model_cpu_offload()          # экономия видеопамяти

image = load_image("input.jpg").resize((1024, 576))
generator = torch.manual_seed(42)
frames = pipe(image,
              decode_chunk_size=8,       # меньше = меньше памяти
              motion_bucket_id=127,      # больше = больше движения
              noise_aug_strength=0.02,
              generator=generator).frames[0]
export_to_video(frames, "generated.mp4", fps=7)

🔷 8. Код: text-to-video (diffusers)

import torch
from diffusers import CogVideoXPipeline
from diffusers.utils import export_to_video

pipe = CogVideoXPipeline.from_pretrained(
    "THUDM/CogVideoX-2b", torch_dtype=torch.float16)
pipe.enable_model_cpu_offload()
pipe.vae.enable_tiling()                 # декодирование тайлами

video = pipe(
    prompt="A panda playing guitar in a bamboo forest, cinematic",
    num_frames=49,
    num_inference_steps=50,
    guidance_scale=6.0,
    generator=torch.Generator(device="cuda").manual_seed(42),
).frames[0]
export_to_video(video, "panda.mp4", fps=8)

Реальный бюджет: десятки секунд — минуты на клип на одной GPU; длинные подробные промпты работают лучше коротких.

🔷 9. Метрики

МетрикаЧто измеряет
FVD (Fréchet Video Distance)расстояние Фреше между гауссианами признаков I3D реальных и сгенерированных клипов; меньше — лучше. Чувствительна к качеству кадров сильнее, чем к движению
FID по кадрам / ISкачество отдельных кадров, без учёта времени
CLIPSIM / CLIP scoreсоответствие кадров промпту
VBenchнабор осей: согласованность субъекта и фона, плавность и динамика движения, эстетика, соответствие тексту
PSNR / SSIM / LPIPSдля предсказания кадров и SR, когда есть эталон
Человеческая оценкаside-by-side сравнения; ловит нарушения физики, которые FVD пропускает

FVD зависит от числа клипов, длины и разрешения — сравнивайте только при одинаковом протоколе.

🔷 10. Данные и вычисления

  • Датасеты: WebVid-10M (снят с публичного доступа), Panda-70M, HD-VILA-100M, InternVid, UCF-101, Kinetics
  • Курация важнее объёма: нарезка по сменам сцен, фильтр статичных клипов (optical flow), водяных знаков, текста на экране, низкой эстетики
  • Переописание: подробные подписи от VLM сильно улучшают следование промпту
  • Обучение поэтапно: картинки → короткие низкого разрешения видео → длинные HD
  • Вычисления: тысячи GPU для фронтир-моделей; дообучение (LoRA, AnimateDiff-модули) — на одной-нескольких GPU
  • Этика: дипфейки, согласие людей в кадре, авторские права на обучающие видео, водяные знаки/C2PA

🔷 11. Типичные ошибки

Плохо

  • Генерировать кадры независимо image-моделью
  • Сравнивать FVD из разных статей с разным протоколом
  • Оценивать только по метрикам без просмотра
  • Сразу учить HD и длинные клипы

Хорошо

  • Временные слои, генерация всего клипа в латенте
  • Фиксированный протокол FVD + VBench + люди
  • Отдельно проверять физику, идентичность, мерцание
  • Прогрессивное обучение и курация данных
