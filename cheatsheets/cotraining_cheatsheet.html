🤝 Co-training (со-обучение)

📅 Январь 2026

🔷 1. Суть

Co-training (Blum & Mitchell, 1998) — метод полуконтролируемого обучения: два классификатора, обученные на разных «взглядах» (views) на данные, размечают друг для друга неразмеченные примеры.

  • Полуконтролируемое обучение: мало размеченных (L) и много неразмеченных (U) данных
  • Несколько представлений (views): объект описан двумя разными наборами признаков x = (x¹, x²)
  • Взаимное обучение: уверенные предсказания одной модели становятся метками для другой
  • Ключевая идея: ошибки моделей на разных views слабо коррелированы, поэтому одна может исправлять другую
  • Классический пример: веб-страницы — view 1 = текст страницы, view 2 = текст ссылок, ведущих на неё

🔷 2. Предположения и выбор views

  • Достаточность (sufficiency): каждый view сам по себе позволяет классифицировать
  • Условная независимость: P(x¹, x² | y) = P(x¹ | y)·P(x² | y)
  • Совместимость (compatibility): целевые функции на разных views согласуются — f₁(x¹) = f₂(x²) почти всегда
  • Баланс: views примерно одинаково информативны (слабый view портит сильный)
ЗадачаView 1View 2
Веб-страницыТекст страницыТекст ссылок
ВидеоКадры (spatial)Аудио / динамика (temporal)
EmailТело письмаЗаголовок, метаданные
Статьи с фотоТекстИзображения
Object detectionВнешний вид объектаКонтекст сцены

Нет естественных views? Искусственные: случайное разбиение признаков, разбиение по типам признаков, разные алгоритмы/архитектуры или разный preprocessing на одних признаках. Гарантии слабеют, если views сильно зависимы.

🔷 3. Алгоритм

Вход: L (размеченные), U (неразмеченные), k
Обучить h1 на view 1 из L, h2 на view 2 из L

Повторять:
  1. h1 размечает U → k самых уверенных → L1
  2. h2 размечает U → k самых уверенных → L2
  3. Переобучить h1 на L ∪ L2, h2 на L ∪ L1
     (каждая модель учится на метках ДРУГОЙ)
  4. Удалить L1, L2 из U
Пока U не пусто / нет уверенных примеров / лимит итераций

Предсказание: среднее P(y|x¹) и P(y|x²)
  • k: число добавляемых за итерацию примеров (обычно 1–10 на класс, с сохранением пропорций классов)
  • Малое k (1–5): консервативно, меньше ошибок, но больше итераций
  • Большое k (>10): быстрее использует U, но приносит менее уверенные метки
  • Вместо фиксированного k можно использовать порог уверенности (например, P > 0.95)

🔷 4. Почему работает: теория

  • PAC-гарантии (Blum & Mitchell): при достаточности и условной независимости views задача PAC-обучаема по слабому начальному классификатору и неразмеченным данным
  • Независимость → «случайные» примеры: уверенные примеры, отобранные по view 1, для модели на view 2 выглядят как случайная выборка из своего класса — шум меток не концентрируется
  • Согласие как сигнал: ошибку каждой модели можно ограничить сверху через долю несогласия между views (Dasgupta et al., 2001) — минимизация несогласия на U уменьшает ошибку
  • Против confirmation bias: в self-training модель учится на собственных ошибках; в co-training метка от другой модели — новая информация

Условия успеха: views действительно слабо зависимы, каждый информативен, начальных меток хватает, чтобы модели были лучше случайных.

🔷 5. Стратегии выбора примеров

  • Максимальная уверенность: max P(y|x)
  • Margin: P(y₍₁₎|x) − P(y₍₂₎|x) — разница топ-2 классов
  • Entropy: наименьшая энтропия H = −Σ p·log p
  • Agreement: брать только примеры, где оба view согласны
  • Сбалансированный выбор: равное (или пропорциональное) число из каждого класса
  • Динамический порог: адаптивный порог по итерациям вместо фиксированного k
import numpy as np

def select_by_margin(proba, k):
    """k примеров с наибольшим margin"""
    s = np.sort(proba, axis=1)
    margins = s[:, -1] - s[:, -2]
    return np.argsort(margins)[-k:]

def select_by_entropy(proba, k):
    """k примеров с наименьшей энтропией"""
    entropy = -np.sum(proba * np.log(proba + 1e-10), axis=1)
    return np.argsort(entropy)[:k]

def select_balanced(proba, k_per_class):
    """top-k по уверенности внутри каждого класса"""
    pred, conf = proba.argmax(1), proba.max(1)
    idx = []
    for c in np.unique(pred):
        ic = np.where(pred == c)[0]
        idx.extend(ic[np.argsort(conf[ic])[-k_per_class:]])
    return np.array(idx)

🔷 6. Реализация на Python

import numpy as np

class CoTraining:
    def __init__(self, clf1, clf2, k=5, max_iter=10):
        self.clf1, self.clf2 = clf1, clf2  # модели для view 1 и view 2
        self.k, self.max_iter = k, max_iter

    def fit(self, X1_l, X2_l, y_l, X1_u, X2_u):
        X1_l, X2_l, y_l = X1_l.copy(), X2_l.copy(), y_l.copy()
        X1_u, X2_u = X1_u.copy(), X2_u.copy()
        for _ in range(self.max_iter):
            self.clf1.fit(X1_l, y_l)
            self.clf2.fit(X2_l, y_l)
            p1 = self.clf1.predict_proba(X1_u)
            p2 = self.clf2.predict_proba(X2_u)
            idx1 = np.argsort(p1.max(1))[-self.k:]  # уверенные у h1
            idx2 = np.argsort(p2.max(1))[-self.k:]  # уверенные у h2
            # метки h1 → в выборку, метки h2 → в выборку
            y1 = self.clf1.classes_[p1[idx1].argmax(1)]
            y2 = self.clf2.classes_[p2[idx2].argmax(1)]
            new = np.concatenate([idx1, idx2])
            X1_l = np.vstack([X1_l, X1_u[new]])
            X2_l = np.vstack([X2_l, X2_u[new]])
            y_l = np.concatenate([y_l, y1, y2])
            mask = np.ones(len(X1_u), dtype=bool)
            mask[new] = False
            X1_u, X2_u = X1_u[mask], X2_u[mask]
            if len(X1_u) < 2 * self.k:
                break
        self.clf1.fit(X1_l, y_l)
        self.clf2.fit(X2_l, y_l)
        return self

    def predict_proba(self, X1, X2):
        return (self.clf1.predict_proba(X1) + self.clf2.predict_proba(X2)) / 2

    def predict(self, X1, X2):
        return self.clf1.classes_[self.predict_proba(X1, X2).argmax(1)]

Упрощение: общая выборка L для обеих моделей. В классическом варианте у каждой модели своя выборка, пополняемая только метками другой.

🔷 7. Пример использования

from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB
from sklearn.metrics import accuracy_score

X, y = make_classification(n_samples=2000, n_features=20,
                           n_informative=15, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3,
                                          random_state=42)
V1, V2 = slice(0, 10), slice(10, 20)  # два view
n_lab = 50                            # мало меток

ct = CoTraining(GaussianNB(), GaussianNB(), k=10, max_iter=20)
ct.fit(X_tr[:n_lab, V1], X_tr[:n_lab, V2], y_tr[:n_lab],
       X_tr[n_lab:, V1], X_tr[n_lab:, V2])

baseline = GaussianNB().fit(X_tr[:n_lab], y_tr[:n_lab])
print("baseline:", accuracy_score(y_te, baseline.predict(X_te)))
print("co-training:", accuracy_score(y_te, ct.predict(X_te[:, V1], X_te[:, V2])))

🔷 8. Варианты и Deep Co-training

  • Democratic Co-learning: >2 разных классификаторов голосуют, добавляются примеры с консенсусом
  • Tri-training: три классификатора на одних признаках (разнообразие через bootstrap); если два согласны — учат третьего
  • Co-EM: вероятностные (мягкие) метки вместо жёстких. E-шаг: P(y|x) по каждому view; M-шаг: обновить параметры другой модели, взвешивая примеры по P(y|x)
  • Multi-view learning: обобщение на >2 views
  • Self-training: частный случай с одним view (модель учит сама себя)

Deep Co-training — views задаются нейросетями: разные архитектуры (CNN + RNN), разные модальности (vision + text), adversarial-примеры для поддержания разнообразия views.

import torch
import torch.nn.functional as F

def co_step(net1, net2, x1, x2, opt, thr=0.95):
    """Один шаг на неразмеченном батче: каждая сеть
    учится на уверенных псевдометках другой."""
    with torch.no_grad():
        p1, p2 = F.softmax(net1(x1), 1), F.softmax(net2(x2), 1)
    c1, y1 = p1.max(1)
    c2, y2 = p2.max(1)
    m1, m2 = c1 > thr, c2 > thr          # маски уверенности
    loss = 0.0
    if m2.any():
        loss = loss + F.cross_entropy(net1(x1[m2]), y2[m2])
    if m1.any():
        loss = loss + F.cross_entropy(net2(x2[m1]), y1[m1])
    if torch.is_tensor(loss):
        opt.zero_grad(); loss.backward(); opt.step()
    return loss

🔷 9. Проблемы и решения

ПроблемаРешение
Накопление ошибок (error propagation)Строгий порог уверенности, валидация, периодическое удаление шумных меток
Views слишком похожи / зависимыПроверить корреляцию views, другое разбиение признаков, регуляризация на разнообразие
Слабый view портит сильныйВыше порог и меньше k для слабой модели или один сильный view
Дисбаланс классов в уверенных примерахСбалансированный отбор по классам
Модели расходятся / качество падаетОграничить число итераций, early stopping по валидации
Начальные модели почти случайныБольше меток на старте; иначе модели уверенно обмениваются ошибками

🔷 10. Метрики, мониторинг и остановка

  • Качество на валидации/тесте: каждой модели и их комбинации
  • Agreement: доля совпадающих предсказаний двух views
  • Динамика: качество и распределение confidence по итерациям
  • Объём псевдоразметки: сколько примеров добавлено
  • Остановка: agreement или валидационное качество падают, либо нет уверенных примеров
from sklearn.metrics import accuracy_score

def evaluate_cotraining(ct, X1, X2, y):
    p1, p2 = ct.clf1.predict(X1), ct.clf2.predict(X2)
    return {
        'acc_view1': accuracy_score(y, p1),
        'acc_view2': accuracy_score(y, p2),
        'acc_combined': accuracy_score(y, ct.predict(X1, X2)),
        'agreement': np.mean(p1 == p2),
    }

✅ Хорошо

  • Мало меток, много неразмеченных данных, разметка дорогая
  • Естественные views: текст + метаданные, мультимодальность
  • NLP (NER, классификация текстов), web mining, video

❌ Плохо

  • Достаточно размеченных данных
  • Признаки не делятся на достаточные views
  • Views сильно коррелированы

💡 Объяснение заказчику:

«Co-training — две модели, которые смотрят на данные с разных сторон и обучают друг друга. Как два эксперта: один читает текст письма, другой смотрит на отправителя; в чём один уверен, тому учится другой. Так нужно меньше вручную размеченных примеров».
