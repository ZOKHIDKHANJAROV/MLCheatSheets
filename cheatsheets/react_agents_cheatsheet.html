🔷 1. Что такое ReAct

ReAct (Reasoning + Acting, Yao и др., 2022) — подход, где модель чередует рассуждение и действие: мысль объясняет, зачем нужен шаг, действие обращается к внешнему миру, наблюдение возвращает результат.

Рассуждение помогает выбрать действие, а наблюдение — скорректировать рассуждение.

🔷 2. Формат Thought / Action / Observation

Question: Сколько жителей
          в столице Франции?
Thought: нужно узнать столицу
Action: search[столица Франции]
Observation: Париж
Thought: теперь население Парижа
Action: search[население Парижа]
Observation: 2.1 млн
Thought: данных достаточно
Final Answer: 2.1 млн
  • Thought — пишет модель
  • Action — пишет модель, исполняет программа
  • Observation — пишет только среда

🔷 3. Цикл (псевдокод)

transcript = question
for step in range(max_steps):
    out = llm(transcript, stop=["Observation:"])
    transcript += out
    if "Final Answer:" in out:
        return answer(out)
    action = parse(out)
    if action in already_seen:
        return stop("зацикливание")
    obs = run_tool(action)
    transcript += "Observation: " + obs
return stop("лимит шагов")

Стоп-последовательность Observation: не даёт модели дописать результат самой.

🔷 4. Пример на Python (фейковая LLM)

import re

KB = {"столица Франции": "Париж", "население Парижа": "2.1 млн"}   # условная база знаний

def search(query):
    return KB.get(query, "ничего не найдено")

def fake_llm(transcript):
    """Заглушка модели: решает по числу уже полученных наблюдений."""
    n = transcript.count("Observation:")
    if n == 0:
        return "Thought: нужно узнать столицу Франции\nAction: search[столица Франции]"
    if n == 1:
        return "Thought: теперь нужно население города Париж\nAction: search[население Парижа]"
    return "Thought: данных достаточно\nFinal Answer: 2.1 млн"

def looping_llm(transcript):
    """«Сломанная» модель: повторяет одно и то же действие."""
    return "Thought: попробую ещё раз\nAction: search[курс неизвестной валюты]"

ACTION = re.compile(r"Action: (\w+)\[(.*)\]")

def react(question, llm, max_steps=6):
    transcript = f"Question: {question}\n"
    seen = set()
    for _ in range(max_steps):
        out = llm(transcript)                      # генерация останавливается перед Observation
        transcript += out + "\n"
        if "Final Answer:" in out:
            return out.split("Final Answer:")[1].strip(), transcript
        match = ACTION.search(out)
        if match is None:
            obs = "ошибка формата: нужен Action: имя[аргумент]"
        else:
            name, arg = match.groups()
            if (name, arg) in seen:                # защита от зацикливания
                return "зацикливание", transcript
            seen.add((name, arg))
            obs = search(arg) if name == "search" else "неизвестное действие"
        transcript += f"Observation: {obs}\n"      # наблюдение пишет среда, а не модель
    return "лимит шагов", transcript

answer, log = react("Сколько жителей в столице Франции?", fake_llm)
print(answer)                                      # 2.1 млн
print(react("курс?", looping_llm)[0])              # зацикливание

🔷 6. Остановка

  • Финальный ответ: модель выдала Final Answer
  • Лимит шагов: max_steps
  • Бюджет: токены, время, деньги
  • Защита от повторов: то же действие с теми же аргументами
  • Ошибка формата: несколько неудачных разборов подряд

🔷 7. Типичные сбои

  • 🔁 Зацикливание: модель повторяет одно действие, не получив нужного
  • 👻 Галлюцинация наблюдений: модель сама дописывает «Observation» — лечится стоп-последовательностью
  • 🧩 Ошибка формата: нет строки Action или скобки — парсер ломается
  • 🌫️ Потеря цели: в длинной истории теряется исходный вопрос
  • 🪤 Слишком ранний ответ: «Final Answer» без проверки фактов

🔷 8. Плюсы и минусы

Плюсы

  • читаемая траектория: видно, почему принято решение
  • снижает выдумки за счёт реальных наблюдений
  • гибко работает, когда путь заранее неизвестен

Минусы

  • много обращений к модели — дорого и медленно
  • история быстро растёт и забивает контекст
  • чувствителен к формату и качеству инструментов

🔷 9. Когда использовать

  • многошаговые вопросы, где нужны факты из внешних источников
  • исследовательские и поисковые задачи с неизвестным путём
  • нужна объяснимая траектория для отладки

Для простых задач хватит CoT, для известных шагов — обычной цепочки.

🔷 10. Типичные ошибки

  • ❌ Нет max_steps и проверки повторов
  • ❌ Не задана стоп-последовательность — модель «выдумывает» наблюдения
  • ❌ Хрупкий парсер без обработки неверного формата
  • ❌ Результаты инструментов не обрезаются, контекст раздувается
  • ❌ Не логируется траектория — сбой не воспроизвести
  • ❌ ReAct применяют к задачам, где хватило бы одного запроса
«ReAct: думай → действуй → смотри на результат → думай снова».
