# Кросс-валидация — мини-тест

## Перед 5-fold кросс-валидацией вы стандартизовали признаки на всём датасете. Почему оценка получится завышенной?
- [x] Скейлер видел проверочные фолды: информация о них просочилась в обучение
- [ ] Стандартизация делает признаки зависимыми друг от друга и нарушает независимость фолдов выборки
- [ ] Стандартизация уменьшает число объектов в обучающих фолдах из-за удаления выбросов
- [ ] Стандартизацию нельзя использовать вместе с кросс-валидацией, так как она меняет порядок объектов

**Почему.** Статистики предобработки, обученные на всех данных, «подсматривают» значения проверочных фолдов. Правильно поместить скейлер в `Pipeline` и передать пайплайн в `cross_val_score`: тогда предобработка заново обучается на каждом фолде. Сама стандартизация совместима с кросс-валидацией и число объектов не меняет.

## В данных по несколько снимков каждого пациента, а модель должна работать на новых пациентах. Какую схему разбиения выбрать?
- [ ] `KFold(shuffle=True)`, так как снимки независимы
- [ ] `StratifiedKFold` по метке диагноза
- [ ] `TimeSeriesSplit`, так как снимки делались в разное время
- [x] `GroupKFold` с идентификатором пациента в качестве группы

**Почему.** При обычном `KFold` снимки одного пациента попадают и в обучение, и в проверку, модель «узнаёт» пациента, и оценка завышается. `GroupKFold` помещает все объекты группы в один фолд, как и будет в продакшене с новыми пациентами. Стратификация сохраняет доли классов, но группы не учитывает.

## Почему для прогноза продаж по дням нельзя использовать `KFold(shuffle=True)`?
- [ ] Потому что число фолдов не может превышать число месяцев в данных за весь период
- [x] Модель обучится на днях после проверочных, то есть заглянет в будущее
- [ ] Потому что перемешивание уменьшает объём обучающей выборки в каждом фолде
- [ ] Потому что классы окажутся распределены неравномерно между фолдами выборки

**Почему.** При перемешивании в обучение попадают более поздние дни, чем в проверке, и оценка не соответствует реальному прогнозу. `TimeSeriesSplit` строит расширяющиеся окна: обучение всегда раньше проверки. Объём обучающей выборки перемешивание не меняет.

## В выборке 1000 объектов, из них 30 положительных. Применяется `StratifiedKFold(n_splits=5, shuffle=True)`. Сколько положительных объектов будет в каждом проверочном фолде?
- [ ] От 0 до 30, как получится при перемешивании
- [x] 6
- [ ] 3
- [ ] 30

**Почему.** Стратификация сохраняет долю классов в каждом фолде: 200 объектов в фолде, доля положительных 3%, то есть 30 / 5 = 6. Без стратификации в одном из фолдов могло бы оказаться слишком мало положительных или вообще ни одного.

## Вы подбирали гиперпараметры по 5-fold CV и сообщаете лучший CV-score как итоговое качество. Чем это плохо и что делать?
- [x] Оценка оптимистична: выбрано лучшее из многих; нужна вложенная CV
- [ ] Это занижает оценку; нужно просто увеличить число фолдов до 10 или 20
- [ ] Это допустимо, ведь каждый объект был в проверочной части ровно один раз
- [ ] Это приводит к утечке из test в train, поэтому нужно удалить дубликаты объектов

**Почему.** Значение, по которому выбирали лучший вариант, уже участвовало в отборе, поэтому оно смещено в оптимистичную сторону. Во вложенной CV внутренний цикл (`GridSearchCV`) подбирает гиперпараметры, а внешний оценивает всю процедуру (или берут отложенный тест). Увеличение числа фолдов смещение не устраняет.
