# CatBoost — мини-тест

## Почему простое target-кодирование (замена категории средним значением целевой переменной) приводит к переобучению?
- [ ] Признак получается слишком высокой размерности, как при one-hot для редких категорий
- [ ] Категории превращаются в числа с произвольным порядком, и дерево путается
- [x] В среднее для объекта входит его собственный ответ, и признак подсказывает его
- [ ] Среднее нельзя вычислить для категорий, встречающихся в обучении лишь один раз

**Почему.** Для редкой категории среднее практически равно ответу самого объекта (клиент из Томска один и купил — «Томск» = 1.0), поэтому на обучении модель выглядит идеальной, а на новых данных проваливается — это утечка целевой переменной. CatBoost при кодировании объекта использует только «прошлые» объекты в случайной перестановке.

## Ordered target statistics: TS = (сумма y предыдущих объектов категории + a·prior) / (число таких объектов + a). Для текущего объекта в категории уже встречались три объекта с y = 1, 0, 1; prior = 0.5, a = 1. Чему равно TS?
- [x] 0.625
- [ ] 0.667
- [ ] 0.833
- [ ] 0.5

**Почему.** TS = (2 + 1·0.5)/(3 + 1) = 2.5/4 = 0.625. Значение 0.667 — простое среднее предыдущих (без сглаживания), 0.833 получится, если в знаменателе забыть a, а 0.5 — это prior, то есть случай, когда у категории нет предыдущих объектов.

## Сколько листьев и сколько различных условий разбиения у симметричного (oblivious) дерева CatBoost глубины 6?
- [ ] 64 листа и 63 различных условия, как у обычного полного бинарного дерева глубины 6
- [x] 64 листа и 6 условий: на каждом уровне одно общее разбиение
- [ ] 6 листьев и 6 условий, по одному листу и одному условию на каждый уровень
- [ ] 32 листа и 5 условий, поскольку корень дерева в подсчёт не входит

**Почему.** На каждом уровне симметричного дерева применяется одно и то же условие вида xⱼ ≤ t, поэтому ответы на 6 вопросов образуют двоичный код номера листа из 2⁶ = 64. У обычного полного дерева каждый внутренний узел имеет своё условие, то есть 63. Симметричность работает как регуляризация и ускоряет применение.

## Столбец `city` закодирован целыми числами 0…N (label encoding) и передан в CatBoost, но `cat_features` не указан. Что произойдёт?
- [ ] CatBoost сам определит, что столбец категориальный, по числу его различных значений
- [ ] Обучение завершится с ошибкой, так как целочисленные столбцы не поддерживаются
- [ ] Столбец будет автоматически закодирован методом one-hot вместо числовых значений
- [x] Станет числовым признаком с бессмысленным порядком, без target statistics

**Почему.** Без `cat_features` числа остаются обычным числовым признаком, и дерево будет искать пороги вида «city ≤ 7», хотя порядка между городами нет. Поэтому для категориальных столбцов всегда нужно явно указывать `cat_features`.

## Какие утверждения верны? (выберите все верные)
- [x] Ordered boosting считает остаток объекта моделью, обученной только на предыдущих объектах, и уменьшает сдвиг прогноза
- [ ] Категории с числом значений больше `one_hot_max_size` кодируются one-hot
- [x] Пропуски в числовых признаках CatBoost обрабатывает сам
- [ ] Ранняя остановка по тестовой выборке допустима: CatBoost защищён от утечки по построению

**Почему.** Ordered boosting решает проблему, что остатки считаются моделью, уже видевшей эти же объекты. Но one-hot применяют как раз к категориям с небольшим числом значений (не больше `one_hot_max_size`), а защита от утечки в кодировании не отменяет необходимости отдельной валидации: выбор итерации по тесту завышает оценку.
