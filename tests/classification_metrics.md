# Метрики классификации — мини-тест

## В выборке 1% мошеннических транзакций. Модель всегда отвечает «не мошенничество». Что можно сказать о её метриках?
- [ ] Accuracy около 1%, а recall около 99%, потому что модель почти всегда ошибается
- [ ] Accuracy и recall около 99%, так как модель почти не ошибается на всей выборке
- [x] Accuracy около 99%, при этом recall равен 0: мошенников не найдено
- [ ] Accuracy около 50%, а precision равна 1, потому что ложных тревог нет

**Почему.** Верно угаданы все 99% нормальных операций, поэтому accuracy ≈ 99%. Но TP = 0, значит recall = TP / (TP + FN) = 0. Именно поэтому при дисбалансе accuracy обманывает и модель нужно сравнивать с константным прогнозом.

## Модель нашла 40 из 50 мошенников и подняла 60 ложных тревог. Чему равны precision и recall?
- [ ] Precision 0.80, recall 0.40
- [ ] Precision 0.67, recall 0.80
- [ ] Precision 0.40, recall 0.40
- [x] Precision 0.40, recall 0.80

**Почему.** TP = 40, FN = 50 − 40 = 10, FP = 60. Precision = TP / (TP + FP) = 40 / 100 = 0.40, recall = TP / (TP + FN) = 40 / 50 = 0.80. Если перепутать формулы, получится зеркальный ответ 0.80 и 0.40.

## Что произойдёт с precision и recall бинарного классификатора, если понизить порог вероятности с 0.5 до 0.2?
- [x] Recall, как правило, вырастет, а precision — снизится
- [ ] Precision, как правило, вырастет, а recall, как правило, снизится
- [ ] Обе метрики вырастут, так как модель выдаёт больше предсказаний
- [ ] Обе метрики не изменятся, так как порог влияет только на ROC-AUC

**Почему.** При меньшем пороге модель чаще говорит «да»: находит больше настоящих положительных (recall растёт, он не может упасть), но и добавляет ложные тревоги (precision обычно падает). Поэтому рабочую точку выбирают под цену ошибок, на валидации, а не на тесте.

## При precision = 1.0 и recall = 0.1 чему равен F1 и почему он так отличается от среднего арифметического (0.55)?
- [ ] F1 = 0.55, потому что F1 — это и есть арифметическое среднее двух метрик
- [ ] F1 = 1.0, так как F1 берёт максимум из двух метрик (precision и recall)
- [ ] F1 = 0.10, так как F1 равен меньшему из двух значений метрик
- [x] F1 ≈ 0.18: гармоническое среднее тянется к меньшему значению

**Почему.** F1 = 2·P·R / (P + R) = 2·1.0·0.1 / 1.1 ≈ 0.18. Гармоническое среднее высоко только тогда, когда высоки обе метрики, поэтому модель не может «выехать» на одной из них. Но F1 не равен минимуму: он немного выше меньшего значения.

## Какие утверждения о многоклассовых метриках верны? (выберите все верные)
- [ ] Weighted-усреднение берёт простое среднее по классам, не учитывая их размер
- [x] Macro-усреднение даёт всем классам одинаковый вес, поэтому плохое качество на редком классе заметно
- [ ] Specificity определяется как TP / (TP + FN)
- [x] Для однометочной многоклассовой задачи micro-усреднённая полнота совпадает с accuracy

**Почему.** Macro — простое среднее по классам, поэтому редкий класс влияет так же, как частый. В micro суммируются TP, FP, FN по всем классам, и для однометочной задачи это совпадает с accuracy. Weighted использует веса по числу объектов класса, а выражение TP / (TP + FN) — это recall, specificity равна TN / (TN + FP).
