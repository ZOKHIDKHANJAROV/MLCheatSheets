# Сегментация изображений (U-Net, DeepLab, Mask R-CNN) — мини-тест

## На снимке две машины стоят вплотную. Нужно получить отдельную маску для каждой из них. Какая сегментация подходит?
- [ ] Семантическая: она присваивает пикселям класс «машина», и соседние машины разделяются границей
- [ ] Паноптическая нужна только для «stuff» вроде неба и дороги, а для машин не подходит
- [x] Экземплярная (instance): она даёт отдельную маску каждому объекту, например через Mask R-CNN
- [ ] Классификация: она отвечает, есть ли на снимке машина, и этого достаточно для масок

**Почему.** Семантическая сегментация предсказывает лишь класс каждого пикселя, поэтому соседние машины сливаются в одну область. Различать экземпляры умеет instance-сегментация, а паноптическая объединяет оба подхода: «вещи» (things) получают номер экземпляра, а «stuff» — нет.

## Предсказанная маска объекта содержит 8 пикселей, истинная — 10 пикселей, их пересечение — 6 пикселей. Чему равен IoU?
- [ ] 0.60
- [ ] 0.75
- [x] 0.50
- [ ] 0.667

**Почему.** Объединение |P ∪ T| = 8 + 10 − 6 = 12, поэтому IoU = 6 / 12 = 0.5. Значение 0.667 — это коэффициент Dice: 2·6 / (8 + 10) = 0.667, а Dice для одной и той же пары масок не меньше IoU.

## Какую проблему решают skip-связи в U-Net?
- [ ] Они уменьшают число параметров, заменяя свёртки в декодере прямым копированием карт признаков из энкодера
- [x] Они возвращают декодеру детали (границы, текстуры), потерянные при пулинге в энкодере, чтобы граница маски была чёткой
- [ ] Они заменяют функцию потерь на реконструкционную и позволяют обучаться совсем без разметки пикселей
- [ ] Они делают так, что вход и выход сети могут иметь разные размеры, а маска не зависит от разрешения снимка

**Почему.** Карта признаков энкодера того же разрешения конкатенируется с картой декодера, и тот восстанавливает точные границы, а не размытую маску из грубой карты 1/16 разрешения. Параметры при этом не убираются, а разметка по пикселям по-прежнему нужна.

## Объект занимает 1% пикселей снимка. Модель помечает все пиксели как «фон». Чему примерно равны pixel accuracy и mIoU по двум классам (фон, объект)?
- [ ] pixel accuracy 0.99 и mIoU 0.99
- [x] pixel accuracy 0.99 и mIoU 0.495
- [ ] pixel accuracy 0.495 и mIoU 0.495
- [ ] pixel accuracy 0.01 и mIoU 0

**Почему.** Верно угаданы 99% пикселей, поэтому pixel accuracy = 0.99. IoU фона = 99 / 100 = 0.99, IoU объекта = 0, а mIoU — их среднее: 0.495. Поэтому pixel accuracy при большом фоне обманчива, а mIoU и Dice показывают провал.

## Какие утверждения верны? (выберите все верные)
- [x] RoIAlign в Mask R-CNN берёт признаки билинейной интерполяцией и не округляет координаты региона
- [ ] Dice для одной и той же пары масок всегда меньше IoU
- [x] Ядро 3×3 с dilation = 2 охватывает область 5×5, не увеличивая число весов
- [ ] Mask R-CNN предсказывает маски без детектора, сразу для всего изображения

**Почему.** Округление координат у RoI Pooling искажает маску на пиксельном уровне, поэтому в Mask R-CNN применяют RoIAlign. Расширенная (atrous) свёртка расширяет рецептивное поле при тех же 9 весах. Dice = 2·I / (|P| + |T|) не меньше IoU, а Mask R-CNN — это Faster R-CNN с головой масок, и без найденных прямоугольников он не работает.
