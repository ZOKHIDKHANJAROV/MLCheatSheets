# Grid Search / Random Search — мини-тест

## Какие из этих величин являются гиперпараметрами, то есть задаются до обучения, а не находятся им? (выберите все верные)
- [x] Максимальная глубина дерева `max_depth`
- [ ] Веса линейной регрессии
- [x] Скорость обучения (learning rate)
- [ ] Пороги разбиений в узлах дерева

**Почему.** Гиперпараметры (глубину дерева, learning rate, силу регуляризации `C`, число деревьев) задаёт человек, и они определяют, переобучится модель или недообучится. Веса и пороги в узлах дерева — это параметры, их модель находит сама в процессе обучения.

## `GridSearchCV` перебирает сетку: `max_depth` — 4 значения, `min_samples_leaf` — 3 значения, `n_estimators` — 5 значений, `cv=5`. Сколько обучений модели понадобится (без учёта итогового переобучения на всей выборке)?
- [ ] 60
- [ ] 12
- [ ] 1 500
- [x] 300

**Почему.** Число комбинаций — произведение размеров списков: 4·3·5 = 60. Каждую оценивают на 5 фолдах, получается 60·5 = 300 обучений. Значение 60 — число комбинаций без учёта фолдов, а 1 500 получилось бы при ошибочном умножении на число фолдов дважды. Именно поэтому сетка быстро становится слишком дорогой при росте числа гиперпараметров.

## Почему при одинаковом бюджете (например, 9 проб) случайный поиск часто находит настройки не хуже сетки, а нередко лучше?
- [ ] Потому что он гарантированно проверяет все возможные сочетания значений параметров, включая крайние
- [x] Потому что сильно влияют обычно один-два гиперпараметра, а он пробует 9 разных значений каждого вместо 3
- [ ] Потому что случайный поиск не использует кросс-валидацию, не тратит бюджет на повторные обучения и поэтому честнее
- [ ] Потому что он сам выбирает метрику качества, которая лучше всего подходит для данной задачи и данных

**Почему.** Сетка 3×3 перебирает лишь 3 разных значения важного параметра, а 9 случайных проб — 9 разных, поэтому важные измерения исследуются плотнее (Бергстра и Бенжио, 2012). Кросс-валидация и метрика нужны в обоих методах, и ни один из них не выбирает метрику сам.

## Learning rate ищут, выбирая значения равномерно на отрезке [0.0001, 0.1]. Какая примерно доля проб попадёт в интервал [0.01, 0.1]?
- [x] около 90%
- [ ] около 33,3%
- [ ] около 50%
- [ ] около 10%

**Почему.** Длина всего отрезка ≈ 0.0999, а интервал [0.01, 0.1] занимает 0.09, то есть около 90%. Поэтому для параметров, которые меняются на порядки (learning rate, `C`), берут логарифмическую шкалу `loguniform`: тогда каждый порядок получает примерно равную долю проб (около 33% на каждый из трёх).

## Признаки масштабировали `StandardScaler` на всей обучающей выборке и затем запустили `GridSearchCV` с кросс-валидацией. В чём проблема и как её исправить?
- [ ] Проблемы нет: масштабирование не использует метки целевой переменной, поэтому утечки быть не может при любом разбиении
- [ ] Масштабирование нужно делать только после выбора лучших гиперпараметров на тесте, иначе кросс-валидация исказит масштаб
- [x] Параметры скейлера считаются и по валидационным фолдам, оценки завышены; нужен `Pipeline`, обучающий скейлер заново на каждом фолде
- [ ] Кросс-валидацию нельзя применять к масштабированным данным, так как фолды перестают быть независимыми

**Почему.** Среднее и стандартное отклонение, посчитанные на всех данных, включают информацию из валидационных фолдов, и CV-оценки получаются слишком оптимистичными. Предобработку кладут в `Pipeline`, тогда она обучается заново на каждом фолде (ключи вида `"model__C"`), а тест остаётся для финальной оценки.
