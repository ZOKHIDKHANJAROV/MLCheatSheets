# ROC и AUC — мини-тест

## Что означает ROC-AUC = 0.85, если объяснять через пары объектов?
- [x] В 85% пар «положительный — отрицательный» положительный получает оценку выше
- [ ] Модель правильно классифицирует 85% всех объектов при пороге классификации 0.5
- [ ] При пороге 0.5 доля найденных положительных объектов (recall) равна 0.85
- [ ] 85% объектов, предсказанных положительными, действительно положительны

**Почему.** AUC — вероятность того, что случайный положительный объект получит оценку выше случайного отрицательного, то есть мера качества ранжирования. Accuracy, recall и precision зависят от выбранного порога, а AUC от порога не зависит.

## На тесте получена матрица ошибок: TP = 40, FN = 10, FP = 30, TN = 920. Какая точка (FPR; TPR) соответствует этому порогу на ROC-кривой?
- [ ] (0.429; 0.800)
- [ ] (0.033; 0.571)
- [ ] (0.800; 0.032)
- [x] (0.032; 0.800)

**Почему.** TPR = TP/(TP + FN) = 40/50 = 0.80, FPR = FP/(FP + TN) = 30/950 ≈ 0.032. Значение 0.43 — это FP/(FP + TP), то есть 1 − precision, 0.57 — precision, а точка (0.800; 0.032) перепутала оси.

## Модель показала ROC-AUC = 0.3 на тесте. Что это значит?
- [ ] Модель случайная: значение AUC ниже 0.5 — это просто статистический шум
- [ ] Значение невозможно: AUC не бывает меньше 0.5, так что в расчёте ошибка
- [x] Оценки инвертированы: при замене на 1 − p AUC станет 0.7; проверьте метки и знак
- [ ] Модель правильно классифицирует 30% объектов, а остальные 70% классифицирует с ошибкой

**Почему.** Случайному угадыванию соответствует AUC = 0.5, а значение ниже означает, что положительные объекты в основном получают оценки ниже отрицательных. Перевернув оценки, получаем 1 − 0.3 = 0.7. Обычно это признак перепутанных меток или знака.

## В данных 1% положительных объектов. Чему примерно равен average precision (PR-AUC) случайной модели?
- [ ] 0.500
- [x] 0.01
- [ ] 0.990
- [ ] 0.100

**Почему.** Базовый уровень PR-кривой — доля положительного класса, а не 0.5, как у ROC-AUC. Поэтому при сильном дисбалансе PR-AUC честнее показывает, сколько «мусора» приходится на найденные положительные объекты.

## Какие утверждения верны? (выберите все верные)
- [x] ROC-AUC не зависит от выбранного порога классификации
- [ ] Если вместо вероятностей передать в `roc_auc_score` метки из `predict`, AUC не изменится
- [x] Высокий AUC не гарантирует, что вероятности модели откалиброваны
- [ ] AUC = 0.5 означает, что модель правильно классифицирует ровно половину объектов

**Почему.** AUC оценивает ранжирование по всем порогам сразу: модель, выдающая 0.51 и 0.52 в правильном порядке, может иметь высокий AUC, но верить её вероятностям нельзя. Метки 0/1 дают «кривую» из одной точки и занижают AUC. Значение 0.5 означает случайное ранжирование, а не долю верных ответов.
