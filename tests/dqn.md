# Deep Q-Networks (DQN) — мини-тест

## Зачем DQN нужен буфер воспроизведения (experience replay) и почему он совместим с Q-learning?
- [ ] Он хранит веса прошлых версий сети, чтобы усреднять их по времени и тем самым снижать переоценку Q-значений
- [ ] Он ускоряет шаг обучения, потому что в нём уже лежат готовые Q-значения следующих состояний, поэтому сеть не нужно вызывать для вычисления цели
- [x] Случайные мини-батчи разрушают корреляцию соседних кадров, а старый опыт годится, так как Q-learning — off-policy
- [ ] Он нужен, чтобы цель r + γ·max Q(s′, ·) оставалась неподвижной между обновлениями

**Почему.** Подряд идущие кадры почти одинаковы, и случайная выборка из буфера делает данные ближе к независимым и позволяет использовать каждый переход много раз. Неподвижную цель обеспечивает целевая сеть, а не буфер, а усреднение весов и снижение переоценки — это другие механизмы.

## Для перехода: r = 1, γ = 0.9, done = 0. Целевая сеть выдаёт для s′ значения Q = [2, 5, 3] по трём действиям. Чему равна цель y в обычном DQN?
- [x] 5.5
- [ ] 6.0
- [ ] 4.0
- [ ] 3.33

**Почему.** y = r + γ·(1 − done)·max Q(s′, ·; θ⁻) = 1 + 0.9·5 = 5.5. Значение 6.0 получится, если забыть дисконтирование, 4.0 — если взять среднее Q по действиям вместо максимума, а 3.33 — если ещё и не учесть r и γ.

## В Double DQN для s′ основная сеть выдаёт Q = [4, 6, 5], а целевая — Q = [5, 3, 7]. При r = 1 и γ = 0.5 (done = 0) чему равна цель y?
- [ ] 4.5
- [ ] 4.0
- [ ] 3.25
- [x] 2.5

**Почему.** Действие выбирает основная сеть: argmax = второе действие (6). Его оценка берётся из целевой сети — это 3, поэтому y = 1 + 0.5·3 = 2.5. Обычный DQN взял бы max целевой сети (7) и получил бы 4.5; именно такое завышение лечит Double DQN.

## Эпизод в CartPole оборвали по лимиту в 500 шагов (truncated), хотя шест всё ещё стоял. Какое значение done нужно записать для последнего перехода в буфер?
- [ ] done = 1, потому что эпизод закончился по лимиту шагов и новых наград в буфер уже не поступит
- [x] done = 0: терминального состояния не было, поэтому будущую ценность нужно бутстрапить, а не обнулять
- [ ] Такой переход нужно выбросить из буфера, потому что обрезанный эпизод не содержит терминального состояния
- [ ] done = 1 только в случае, если за последний шаг агент получил положительную награду, иначе 0

**Почему.** Флаг done должен означать настоящее завершение (terminated), после которого будущих наград нет. При обрезке по времени будущее существует, и цель нужно считать с бутстрапом; done = 1 занижает ценность таких состояний.

## Что неверно в этом шаге обучения DQN?
```python
q = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)
y = r + gamma * (1 - done) * q_net(s2).max(dim=1).values
loss = F.smooth_l1_loss(q, y)
```
- [ ] Функцию потерь Хьюбера (smooth L1) нельзя применять в обучении с подкреплением, нужна только MSE
- [ ] Вместо `max` по действиям нужно брать среднее по действиям, иначе цель завышается и обучение расходится
- [x] Цель считается той же обучаемой сетью и с градиентом: нет целевой сети и `torch.no_grad()` при расчёте y
- [ ] Метод `gather` здесь выбирает Q-значения всех действий сразу, а для функции потерь нужно только выбранное

**Почему.** Цель y должна считаться замороженной целевой сетью θ⁻ и без градиента, иначе каждый шаг двигает и предсказание, и цель, а обучение колеблется. Потеря Хьюбера как раз стандартна для DQN, `max` нужен для оптимальной цели, а `gather` как раз выбирает Q(s, a) для совершённого действия.
