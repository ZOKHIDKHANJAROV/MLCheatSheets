# PyTorch полный гайд — мини-тест

## Что выведет код?

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
for _ in range(2):
    loss = (w * 2 - 4) ** 2
    loss.backward()
print(w.grad)
```
- [ ] `tensor(8.)`
- [ ] `tensor(8., requires_grad=True)`
- [ ] `tensor(0.)`
- [x] `tensor(16.)`

**Почему.** Градиент ∂loss/∂w = 2·(2w − 4)·2 = 8 при w = 3. Градиенты накапливаются: каждый `backward()` прибавляет к `.grad`, а не перезаписывает, поэтому после двух вызовов получится 16. Чтобы получить 8, нужно обнулять градиент перед каждым шагом (`optimizer.zero_grad()`).

## Чем `model.eval()` отличается от `torch.no_grad()` при оценке модели на валидации?
- [ ] `model.eval()` отключает построение графа вычислений, а `torch.no_grad()` выключает dropout и BatchNorm
- [x] `model.eval()` переключает слои (dropout, BatchNorm), а `torch.no_grad()` отключает построение графа
- [ ] Это два названия одного режима, поэтому достаточно вызвать любой из них, результат одинаков
- [ ] `model.eval()` замораживает веса модели, а `torch.no_grad()` включает их обновление по градиентам

**Почему.** В режиме `eval()` dropout не обнуляет нейроны, а BatchNorm использует накопленную статистику вместо статистики батча. `torch.no_grad()` лишь отключает запись операций для градиентов. Для корректной и быстрой оценки нужны оба, а веса ни один из них не замораживает.

## Что нужно подавать в `nn.CrossEntropyLoss` в задаче классификации на 10 классов при батче из 32 объектов?
- [ ] Вероятности формы [32, 10] после softmax и one-hot метки формы [32, 10]
- [ ] Логиты формы [32, 10] и вещественные one-hot метки
- [x] Логиты формы [32, 10] и метки формы [32] типа `int64` с номерами классов
- [ ] Вероятности после softmax формы [32, 10] и метки формы [32] с номерами классов

**Почему.** `CrossEntropyLoss` сам применяет log-softmax, поэтому на вход идут необработанные логиты; softmax перед ним даёт неверную функцию потерь. Метки — индексы классов типа `long`, а не one-hot векторы.

## Что не так в этом фрагменте цикла обучения с точки зрения расхода памяти?

```python
history = []
for xb, yb in train_loader:
    loss = criterion(model(xb), yb)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    history.append(loss)
```
- [ ] Ничего: тензоры в списке занимают не больше памяти, чем обычные числа
- [ ] Нужно вызывать `loss.backward()` после `append`, иначе граф не освободится
- [ ] Нужно положить `history` на GPU, иначе он переполнит оперативную память
- [x] Хранятся тензоры потерь вместе с графом; в логи кладут `loss.item()`

**Почему.** Тензор `loss` ссылается на граф операций, поэтому накопление таких тензоров в списке держит в памяти графы всех батчей. Число `loss.item()` не несёт графа, и именно его кладут в историю.

## Что выведет код, если установлен NumPy и PyTorch?

```python
import numpy as np
import torch

a = np.arange(3.0)
t = torch.from_numpy(a)
a[0] = 100.0
print(t[0].item())
```
- [ ] 0.0, так как `torch.from_numpy` копирует данные в новую память
- [ ] 3.0, так как первое значение пересчитывается как сумма элементов
- [ ] Будет ошибка, потому что массив NumPy нельзя менять после создания тензора
- [x] 100.0, так как тензор и массив используют общую память

**Почему.** `torch.from_numpy` не копирует данные: тензор и массив разделяют одну область памяти, и изменение одного видно в другом. Если нужна независимая копия, используют `torch.tensor(a)` или `.clone()`.
