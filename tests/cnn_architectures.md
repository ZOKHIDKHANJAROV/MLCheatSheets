# Архитектуры CNN — мини-тест

## Почему в VGG используют стопку свёрток 3×3 вместо одной свёртки с большим ядром, например 5×5?
- [ ] Две свёртки 3×3 имеют рецептивное поле 3×3 и поэтому быстрее считаются, чем одна 5×5
- [x] Две свёртки 3×3 видят поле 5×5, но весов меньше и нелинейностей больше
- [ ] Свёртки 3×3 не требуют padding, поэтому размер карты признаков не меняется по слоям
- [ ] Свёртка 5×5 нужна только для первого слоя, а дальше работают только свёртки 3×3

**Почему.** Две подряд идущие свёртки 3×3 видят область 5×5, но для 256 каналов это около 1.18 млн весов против около 1.64 млн у одного слоя 5×5, и между ними стоит ещё одна активация. Поле двух слоёв 3×3 растёт до 5×5, а не остаётся 3×3. Сохранять размер как раз помогает padding = 1.

## Сколько параметров (веса и смещения) в свёрточном слое с ядром 3×3, 64 входными и 128 выходными каналами?
- [ ] 9·64 + 128 = 704
- [ ] 9·64·128 + 64 = 73 792
- [x] 9·64·128 + 128 = 73 856
- [ ] 9·(64 + 128) + 128 = 1 856

**Почему.** Для каждого из 128 фильтров нужно 9·64 = 576 весов (ядро 3×3 по всем входным каналам) плюс одно смещение. Формула k·k·c_in·c_out + c_out даёт 73 728 + 128 = 73 856. Число смещений равно числу выходных каналов (128), а не входных (64), а веса перемножаются, а не складываются.

## Зачем в Inception-модуле перед свёртками 3×3 и 5×5 ставят свёртки 1×1?
- [ ] Чтобы увеличить рецептивное поле, не меняя число каналов на выходе
- [ ] Чтобы заменить max pooling, который в модуле не используется
- [ ] Чтобы добавить skip-связь между входом и выходом модуля, как в ResNet
- [x] Чтобы сжать число каналов и удешевить большие свёртки

**Почему.** Свёртка 1×1 уменьшает глубину (число каналов) перед дорогими операциями, так что параллельные ветви с 3×3 и 5×5 не раздувают вычисления. Рецептивное поле она не увеличивает, пулинг в модуле остаётся одной из параллельных ветвей, а skip-связи — идея ResNet.

## Где у VGG16 сосредоточена основная часть параметров (около 138 млн)?
- [ ] В первых свёрточных слоях с 64 каналами, где самое большое разрешение карт
- [x] В трёх полносвязных слоях в конце сети
- [ ] В слоях max pooling, потому что их в сети больше всего
- [ ] Равномерно по всем 16 слоям, примерно по 8.6 млн на слой

**Почему.** Первый полносвязный слой принимает 512·7·7 = 25 088 признаков и выдаёт 4096, это более 100 млн весов; все три полносвязных слоя дают около 124 млн параметров. Все 13 свёрточных слоёв дают лишь около 14.7 млн. У слоёв пулинга обучаемых параметров нет.

## Какие утверждения об архитектурах верны? (выберите все верные)
- [ ] AlexNet использовала активацию tanh, а ReLU появилась позже в ResNet
- [x] В ResNet блок вычисляет y = F(x) + x, что позволило обучать сети на 50–152 слоя
- [ ] EfficientNet улучшает качество, увеличивая только ширину сети
- [x] В MobileNet depthwise-свёртка работает с каждым каналом отдельно, а свёртка 1×1 смешивает каналы

**Почему.** Skip-связь y = F(x) + x решила проблему деградации очень глубоких обычных сетей. В depthwise separable свёртке сначала каждая карта признаков обрабатывается своим ядром 3×3, затем pointwise 1×1 смешивает каналы. ReLU пришла уже в AlexNet (2012), а EfficientNet масштабирует глубину, ширину и разрешение согласованно.
