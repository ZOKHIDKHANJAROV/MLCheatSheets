# BERT: fine-tuning — мини-тест

## Почему при fine-tuning BERT берут learning rate порядка 2e-5, а не 1e-3?
- [ ] Меньший шаг нужен, чтобы AdamW вообще мог вычислять градиенты у предобученных весов
- [ ] При большом шаге нельзя использовать warmup, поэтому его заменяют малым шагом
- [ ] Для токена `[CLS]` градиенты по определению меньше, чем для остальных токенов
- [x] Большой шаг стирает знания предобучения (catastrophic forgetting)

**Почему.** Fine-tuning — «мягкий инструктаж»: энкодер лишь слегка подстраивается, а резкое переучивание стирает выученное. Поэтому шаг на два-три порядка меньше, чем при обучении с нуля. Градиенты у предобученных весов считаются обычным образом, а warmup как раз помогает при больших шагах в начале.

## Какой выход BERT и какая голова используются для NER (разметки токенов)?
- [ ] Вектор `[CLS]` и линейный слой на число типов сущностей
- [x] Вектор каждого токена и линейный слой на каждой позиции
- [ ] Среднее по всем токенам и один линейный слой над ним
- [ ] Вектор токена `[SEP]` и линейный слой на число типов сущностей

**Почему.** NER требует метку для каждого токена, поэтому линейный слой применяется к выходному вектору каждой позиции. Вектор `[CLS]` годится для классификации всего текста целиком, а усреднение или один `[SEP]` дали бы единственную метку на весь текст.

## В LoRA поправка к матрице весов 768×768 задаётся как ΔW = B·A, где B размера 768×8, а A размера 8×768 (ранг r = 8). Сколько обучаемых параметров добавляется для этой матрицы?
- [x] 12 288
- [ ] 589 824
- [ ] 6 144
- [ ] 98 304

**Почему.** 768·8 + 8·768 = 12 288 — около 2% от 768·768 = 589 824 параметров самой матрицы. Значение 6 144 учитывает только одну из двух матриц, а 589 824 — это полное дообучение. Исходные веса при LoRA заморожены.

## Документ содержит около 3000 токенов, а модель BERT ограничена 512 токенами. Какой подход корректен?
- [ ] Просто задать `max_length=3000`: BERT сам расширит позиционные эмбеддинги
- [ ] Отключить позиционные эмбеддинги, тогда ограничение на длину последовательности исчезает
- [x] Разбить текст на перекрывающиеся куски и усреднить предсказания по ним
- [ ] Увеличить batch size до 3000, чтобы весь документ поместился в один батч

**Почему.** Позиционные эмбеддинги BERT обучены только для 512 позиций, а стоимость self-attention растёт квадратично, поэтому длину просто так не увеличить. Скользящее окно (с усреднением или максимумом по кускам), иерархия или модели вроде Longformer — рабочие варианты. Позиционные эмбеддинги нужны модели для учёта порядка слов, а batch size длину последовательности не меняет.

## Какие утверждения верны? (выберите все верные)
- [x] RoBERTa отказалась от задачи NSP и использует динамическое маскирование
- [ ] ALBERT уменьшает размер модели за счёт дистилляции в 6 слоёв
- [x] DistilBERT получен дистилляцией и содержит 6 слоёв вместо 12
- [ ] `bert-base-uncased` подходит для русских текстов, потому что токенизатор у него общий для всех языков

**Почему.** DistilBERT и RoBERTa описаны правильно. ALBERT экономит параметры за счёт общих весов между слоями и разложенных эмбеддингов, а не дистилляции. `bert-base-uncased` обучена на английском и почти не знает русского: нужны многоязычная модель или русская (например, RuBERT).
