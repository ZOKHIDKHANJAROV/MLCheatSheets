# Обратное распространение ошибки — мини-тест

## Зачем прямой проход сохраняет промежуточные значения (входы слоёв, активации)?
- [ ] Чтобы при предсказании на новых данных не пересчитывать их заново
- [ ] Чтобы обновлять веса модели вообще без вычисления градиентов
- [x] Они нужны в формулах обратного прохода: f′(z) и hᵀ·δ
- [ ] Чтобы нормировать градиенты перед шагом оптимизатора

**Почему.** Например, производная tanh равна 1 − tanh²(z), а градиент по весам линейного слоя — входᵀ·градиент_выхода; без сохранённых значений обратный проход не посчитать. Поэтому обучение расходует намного больше памяти, чем предсказание.

## Нейрон с ReLU: z = w·x + b, a = max(0, z), потеря L = (a − y)². Заданы x = 2, w = 3, b = −1, y = 1. Чему равна ∂L/∂w?
- [ ] 8
- [x] 16
- [ ] 24
- [ ] −16

**Почему.** z = 3·2 − 1 = 5 > 0, поэтому a = 5. По цепному правилу ∂L/∂w = 2(a − y)·1·x = 2·4·2 = 16. Значение 8 получится, если забыть множитель ∂z/∂w = x, а 24 — это градиент по входу ∂L/∂x = 8·w, а не по весу.

## Что неверно в этом цикле обучения на PyTorch?
```python
for x, y in loader:
    loss = loss_fn(model(x), y)
    loss.backward()
    optimizer.step()
```
- [x] Нет `optimizer.zero_grad()`: градиенты копятся в `.grad`
- [ ] `loss.backward()` нужно вызывать после `optimizer.step()`
- [ ] Перед `backward()` необходимо обернуть модель в `torch.no_grad()`
- [ ] `backward()` обнуляет градиенты, поэтому `step()` делает нулевые шаги

**Почему.** PyTorch складывает новые градиенты с теми, что уже лежат в `.grad`, поэтому без обнуления шаги получаются неверными. Порядок «обнулить → backward → step» стандартный. `no_grad()` отключает построение графа и на обучении как раз не нужен.

## В середине обучения потеря становится `nan`, перед этим она резко росла. Что наиболее разумно сделать в первую очередь?
- [ ] Увеличить скорость обучения, чтобы быстрее выйти из плохой области
- [ ] Заменить ReLU в скрытых слоях на сигмоиду
- [ ] Добавить в сеть ещё слоёв, чтобы градиенты распределились
- [x] Уменьшить скорость обучения и включить gradient clipping

**Почему.** Рост потерь, а затем `nan` — типичный признак взрыва градиентов; помогают меньший шаг, обрезка нормы градиента, а также проверка `log(0)` и деления на ноль. Сигмоида в скрытых слоях лишь добавит затухание градиентов, а больше слоёв — ещё больше множителей в произведении.

## Какие утверждения верны? (выберите все верные)
- [x] Для линейного слоя z = h·W + b градиент по весам равен hᵀ·δ, где δ = ∂L/∂z
- [ ] Для sigmoid и бинарной кросс-энтропии градиент по логиту равен p·(1 − p)
- [x] Обратный проход стоит примерно как несколько прямых, а не как по одному прямому проходу на каждый вес
- [ ] Численный градиент (L(w+ε) − L(w−ε))/2ε быстрее backpropagation на больших сетях

**Почему.** Backpropagation переиспользует общие части цепочек, поэтому цена не растёт с числом весов как у численного метода (отдельный проход на каждый вес); численный градиент пригоден лишь для проверки. Для sigmoid с BCE градиент на логите — это p − y, а не p·(1 − p).
