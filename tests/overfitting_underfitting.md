# Переобучение и недообучение — мини-тест

## Train accuracy 99%, validation accuracy 72%. Что происходит и что разумно сделать первым?
- [ ] Недообучение; усложнить модель и обучать дольше
- [ ] Нормальная ситуация: разрыв такого размера ожидаем, менять ничего не нужно
- [ ] Модель слишком чувствительна к масштабу; стандартизировать признаки
- [x] Переобучение; добавить данные, усилить регуляризацию или упростить модель

**Почему.** Ключевой признак переобучения — большой разрыв между ошибками: на train модель почти идеальна, на validation заметно хуже, то есть запомнила обучающие данные вместе с шумом. Усложнение модели и более долгое обучение — лечение недообучения и здесь только усугубят разрыв.

## Кривые обучения по размеру выборки: обе кривые быстро сходятся на плохом уровне. Что это означает?
- [x] Недообучение (высокое смещение): модели не хватает сложности
- [ ] Переобучение (высокая дисперсия): нужна регуляризация и больше данных
- [ ] Хорошая модель: кривые сошлись, значит качество оптимально
- [ ] Утечка данных: у честной модели кривые не должны сходиться

**Почему.** При недообучении модель плоха уже на train, и кривые train и validation быстро сходятся на низком качестве. При переобучении кривые, наоборот, разделены большим зазором, который сокращается с ростом данных. Лечат недообучение сложностью модели и новыми признаками.

## По какому сигналу ранняя остановка прекращает обучение?
- [ ] Ошибка на train перестала уменьшаться в течение нескольких эпох
- [ ] Ошибка на тестовой выборке начала расти в течение нескольких эпох
- [x] Ошибка на validation перестала улучшаться
- [ ] Ошибка на train стала равна нулю на всей обучающей выборке

**Почему.** Потери на train падают всё время, поэтому по ним останавливаться бессмысленно. Момент, когда потери на validation перестали падать (и начали расти), — начало переобучения. Тест для этого использовать нельзя: он нужен только для финальной оценки.

## Какая схема подбора гиперпараметров и оценки корректна?
- [ ] Подбирать гиперпараметры по test, чтобы итоговый результат на нём был как можно лучше
- [x] Подбирать по validation или кросс-валидации, test использовать один раз в конце
- [ ] Подбирать гиперпараметры по ошибке на train, а на test смотреть после каждой эпохи
- [ ] Оценивать на validation, а test использовать многократно, пока метрика не устроит

**Почему.** Если настраивать модель по тесту, мы фактически обучаемся на нём, и итоговая оценка становится оптимистичной. Поэтому train нужен для обучения, validation (или CV) — для выбора модели, а test — для однократной финальной оценки.

## Модель хорошо работала на отложенном тесте, а через полгода в продакшене стала заметно хуже. Что вероятнее всего произошло?
- [ ] Переобучение: со временем модель запоминает train всё сильнее
- [ ] Недообучение: модель со временем стала слишком простой
- [x] Дрейф данных: распределение входных данных изменилось
- [ ] Утечка из test в train, проявившаяся со временем

**Почему.** Переобучение видно по разрыву между train и тестовой ошибкой на момент обучения, а веса обученной модели со временем не меняются. Если на тесте всё было хорошо, ухудшение через полгода — это скорее изменение данных (дрейф), а не переобучение.
