# Optuna / Hyperopt — мини-тест

## Как алгоритм TPE выбирает следующую пробу?
- [ ] Строит гауссовский процесс по всем пробам и берёт точку с наибольшим разбросом
- [x] Сравнивает плотности хороших и плохих проб, берёт точку с максимумом l(x)/g(x)
- [ ] Перебирает сетку значений по порядку, пропуская уже проверенные ячейки сетки
- [ ] Берёт лучшую пробу и сдвигает каждый параметр на небольшой случайный шаг с отжигом

**Почему.** После нескольких проб TPE делит их на «хорошие» (лучшие 10–25%) и остальные, строит плотность l(x) для хороших и g(x) для плохих и выбирает x, где хорошие точки плотные, а плохие редкие. Гауссовский процесс в TPE не используется — поэтому он легко работает с целыми, категориальными и условными параметрами.

## Параметр `learning_rate` ищется в диапазоне от 1e-5 до 1e-1. Зачем указывать `log=True` в `suggest_float`?
- [ ] Чтобы предлагаемые значения были целыми числами, а не вещественными
- [ ] Чтобы значение параметра вычислялось из другого параметра пробы
- [x] Чтобы пробы равномерно покрывали порядки величины, а не большие значения
- [ ] Чтобы алгоритм TPE заменился случайным поиском по диапазону

**Почему.** При равномерном распределении по [1e-5, 0.1] около 90% проб попадает в значения больше 0.01, и малые порядки почти не проверяются. С `log=True` каждый порядок величины получает одинаковую долю проб, что и нужно для learning rate.

## Что делает `MedianPruner`, если objective сообщает промежуточные значения через `trial.report` и проверяет `trial.should_prune()`?
- [ ] Останавливает весь study, когда медиана значений превысила заданный порог
- [ ] Заменяет пропущенные значения гиперпараметров медианой по прошлым пробам
- [ ] Усредняет результаты кросс-валидации по медиане фолдов, а не по среднему
- [x] Прерывает пробу, если на том же шаге она хуже медианы предыдущих проб

**Почему.** Прунер сравнивает промежуточное значение текущей пробы с медианой значений прошлых проб на этом же шаге и досрочно останавливает отстающие. За счёт этого плохие настройки отсеиваются за долю времени, и при том же бюджете проверяется больше вариантов.

## Hyperopt минимизирует целевую функцию. Как с его помощью максимизировать AUC?
- [ ] Вернуть `{"loss": auc, "status": STATUS_OK}`: `fmin` сама определит направление
- [x] Вернуть `{"loss": -auc, "status": STATUS_OK}`
- [ ] Передать в `fmin` параметр `direction="maximize"`
- [ ] Вернуть `auc` и взять худшую пробу из `Trials`

**Почему.** `fmin` всегда минимизирует поле `loss`, поэтому для максимизации AUC минимизируют −AUC. В Optuna направление задаётся иначе — аргументом `direction` в `create_study`.

## Какие утверждения верны? (выберите все верные)
- [x] Лучшее значение за сотни проб на одних и тех же фолдах кросс-валидации оптимистично, поэтому финальную оценку делают на отложенном тесте
- [ ] При бюджете 15–20 проб TPE заметно превосходит случайный поиск, ведь с самого начала выбирает точки умно
- [x] Условный параметр в Optuna задают обычным `if` внутри `objective`
- [ ] Для pruning безопасно сообщать через `trial.report` метрику на обучающей выборке

**Почему.** Первые ~10 проб TPE делает случайно, поэтому на малом бюджете он почти не отличается от случайного поиска. Метрику для прунера нужно сообщать на валидации: иначе он будет отсекать не те пробы. Define-by-run позволяет описывать пространство кодом с `if` и циклами.
