# Пайплайны ML — мини-тест

## Пайплайн `Pipeline([("scale", StandardScaler()), ("model", LogisticRegression())])`. Что происходит при вызовах `fit` и `predict`?
- [ ] `fit` вызывает `fit` у скейлера и модели на всех данных, `predict` снова обучает скейлер на новых данных и применяет его
- [ ] `fit` обучает только модель, а скейлер обучается при первом вызове `predict` на пришедших данных и запоминает их статистики
- [ ] Оба метода вызывают `fit_transform` скейлера, чтобы масштабировать данные каждый раз по-новому
- [x] `fit` — это `fit_transform` скейлера и `fit` модели, `predict` — `transform` скейлера и `predict` модели

**Почему.** Трансформеры учатся только при `fit` и запоминают статистики обучающей выборки (среднее, стандартное отклонение). При `predict` применяется только `transform` с запомненными параметрами. Если переобучать скейлер на новых данных, результаты стали бы несогласованными.

## Скейлер обучили на всей выборке, затем разделили данные на train/test и обучили модель. Почему это ошибка и как её избежать?
- [ ] Это не ошибка, потому что скейлер не использует целевую переменную, а значит информации о тестовых метках он не получает
- [ ] Это ошибка, потому что масштабирование нужно делать после обучения модели, иначе веса модели окажутся в другом масштабе
- [x] Статистики теста попали в обучение, и оценка завышена; скейлер нужно включить в `Pipeline` и учить только на train
- [ ] Это ошибка только для деревьев и бустингов, а для линейных моделей и нейросетей порядок шагов не важен

**Почему.** Среднее и стандартное отклонение, посчитанные по всей выборке, содержат информацию о тестовых объектах — это утечка данных. Внутри `Pipeline` кросс-валидация и `GridSearchCV` заново обучают скейлер на каждом фолде только по его обучающей части.

## Как правильно задать в `GridSearchCV` перебор параметра `strategy` у импьютера, если пайплайн собран так?
```python
num = Pipeline([("impute", SimpleImputer(strategy="median")), ("scale", StandardScaler())])
prep = ColumnTransformer([("num", num, ["age", "income"])])
pipe = Pipeline([("prep", prep), ("model", LogisticRegression())])
```
- [x] `"prep__num__impute__strategy"`
- [ ] `"impute_strategy"`
- [ ] `"prep__num__imputer__strategy"`
- [ ] `"strategy"`

**Почему.** Имя параметра вложенного шага собирается из имён всех уровней через двойное подчёркивание: пайплайн `prep`, ветка `num`, шаг `impute`, параметр `strategy`. Доступные имена показывает `pipe.get_params().keys()`.

## В сервис пришёл клиент из города, которого не было в обучающих данных. Пайплайн использует `OneHotEncoder()` с настройками по умолчанию. Что произойдёт?
- [ ] Для такого города все признаки города получат пропуски и будут заполнены средним
- [ ] Модель молча переобучится на лету, добавив новый столбец для нового города и пересчитав веса
- [ ] Незнакомый город автоматически заменится на самую частую категорию из обучающей выборки и пройдёт дальше
- [x] Будет ошибка при `predict`; нужен `OneHotEncoder(handle_unknown="ignore")` для неизвестных категорий

**Почему.** По умолчанию `OneHotEncoder` падает на неизвестной категории. С `handle_unknown="ignore"` все one-hot столбцы города будут нулевыми, и модель всё равно сделает прогноз. После `fit` пайплайн ничего заново не обучает.

## Какие утверждения о пайплайнах верны? (выберите все верные)
- [x] `FeatureUnion` применяет несколько трансформеров к одним и тем же данным и объединяет их выходы
- [ ] `ColumnTransformer` передаёт данные от одного трансформера к другому по цепочке, как `Pipeline`
- [x] Идемпотентную задачу оркестратора можно просто перезапустить: с теми же входами она даёт тот же результат
- [ ] Airflow — часть scikit-learn и заменяет `Pipeline`, поскольку решает ту же задачу

**Почему.** `ColumnTransformer` применяет разные трансформеры к разным столбцам и склеивает результат, а цепочку шагов задаёт `Pipeline`. Airflow — оркестратор задач по расписанию, а sklearn `Pipeline` — один объект «предобработка + модель», это разные уровни.
