# Механизм внимания — мини-тест

## Какую проблему seq2seq-перевода без внимания решает механизм внимания?
- [x] Вся фраза любой длины сжимается в один вектор фиксированного размера
- [ ] Рекуррентный декодер не умеет генерировать перевод по одному слову за шаг, поэтому нужен параллельный
- [ ] Энкодер вынужден читать слова источника параллельно и теряет информацию об их порядке в предложении
- [ ] Декодер не имеет доступа к словарю целевого языка при генерации и поэтому выдаёт случайные слова

**Почему.** В классическом seq2seq энкодер отдаёт декодеру один вектор («бутылочное горлышко»), и качество падает на длинных предложениях. Внимание сохраняет состояния для каждого слова источника, и декодер на каждом шаге строит новый вектор контекста как взвешенную сумму этих состояний.

## Размерность ключей d_k = 16. Скалярные произведения запроса с двумя ключами равны 8 и 0, значения v₁ = (1, 0), v₂ = (0, 1). Каков результат масштабированного скалярного внимания (округлено)?
- [ ] (0.50, 0.50)
- [ ] (0.62, 0.38)
- [x] (0.88, 0.12)
- [ ] (1.00, 0.00)

**Почему.** Оценки делятся на √d_k = 4: получаем (2, 0). Softmax даёт e²/(e² + 1) ≈ 0.88 и 0.12, итог 0.88·v₁ + 0.12·v₂. Результат (0.62, 0.38) получится при ошибочном делении на d_k, а (1.00, 0.00) — почти без масштабирования (softmax от (8, 0)).

## Как правильно «выключить» позиции паддинга, чтобы они не получали вес внимания?
- [ ] Умножить оценки позиций паддинга на 0 перед применением softmax
- [x] Прибавить к оценкам паддинга −∞ перед применением softmax
- [ ] Заменить оценки позиций паддинга на 1 перед применением softmax
- [ ] Обнулить веса паддинга после softmax, не пересчитывая остальные веса

**Почему.** После экспоненты e^(−∞) = 0, и веса остальных позиций по-прежнему суммируются в 1 (на практике берут очень большое отрицательное число). Оценка 0 или 1 даёт ненулевой вес e⁰ или e¹, а обнуление после softmax нарушает нормировку: сумма весов становится меньше 1.

## Можно ли по картам внимания надёжно объяснять причину решения модели?
- [ ] Да: вес внимания каждого слова напрямую равен его вкладу в итоговое решение модели
- [ ] Да, но только если в слое несколько голов, а веса усреднены по всем головам и слоям
- [ ] Нет: веса внимания не зависят от входа и заданы заранее в процессе обучения модели
- [x] Нет: веса показывают поток информации, но не обязательно причину решения

**Почему.** Исследования показали, что можно получить существенно другие веса внимания практически без изменения предсказаний. Поэтому для объяснений используют специальные методы (градиентные, SHAP). Сами веса при этом вычисляются динамически, по запросам и ключам, а не задаются заранее.

## Какие утверждения верны? (выберите все верные)
- [x] В переводе запросом служит состояние декодера, а ключами и значениями — состояния энкодера
- [ ] Число оценок внимания растёт линейно с длиной последовательности n
- [x] Любые две позиции связаны одной операцией внимания, а не цепочкой шагов, как в RNN
- [ ] Деление на √d_k нужно для того, чтобы веса внимания в сумме давали 1

**Почему.** Короткий путь между позициями и роли Q/K/V — суть внимания. Но оценок для n запросов и n ключей n², то есть стоимость квадратична. Сумму 1 обеспечивает softmax, а масштабирование нужно, чтобы большие оценки не делали softmax почти one-hot.
