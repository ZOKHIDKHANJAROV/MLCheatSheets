# Оценка позы человека — мини-тест

## Почему для оценки позы обычно предсказывают тепловые карты ключевых точек, а не напрямую координаты (x, y)?
- [ ] Потому что тепловые карты позволяют получить точность лучше пикселя без какого-либо уточнения
- [x] Потому что они сохраняют пространственную структуру и показывают неуверенность, например два «пятна»
- [ ] Потому что прямая регрессия координат не может быть обучена градиентным спуском из-за разрывности
- [ ] Потому что тепловые карты не зависят от размера и расположения человека в кадре и не требуют нормализации

**Почему.** Признаки свёрточной сети привязаны к местам на изображении, а свёртка их в несколько чисел эту структуру выбрасывает. На тепловой карте при сомнении видны два пятна, а координату берут по максимуму. Точность ограничена разрешением карты, поэтому её уточняют субпиксельно или через integral regression; регрессия координат обучаема, просто работает хуже.

## Нужно оценивать позы в многолюдной сцене, где время обработки не должно сильно расти с числом людей. Какой подход подходит лучше всего?
- [ ] Top-down: детектор находит каждого человека, и поза оценивается в его рамке
- [x] Bottom-up: сеть находит все точки сразу, а затем группирует их в скелеты
- [ ] Top-down, потому что время его работы не зависит от числа людей
- [ ] Прямое предсказание 3D-тепловых карт для каждого человека по отдельности

**Почему.** В bottom-up сеть запускается один раз на весь кадр, поэтому время почти не растёт с числом людей, хотя группировка в толпе сложнее и точность ниже. В top-down модель позы запускается для каждой рамки, так что время растёт с числом людей, зато точность выше, особенно на мелких людях.

## Угол в колене считают по точкам бедра (0, 0), колена (0, 1) и лодыжки (1, 2) как угол в вершине «колено» между векторами к бедру и к лодыжке. Чему он равен?
- [ ] 45°
- [ ] 90°, как у согнутой под прямым углом ноги
- [ ] 180°
- [x] 135°

**Почему.** Векторы из колена: к бедру (0, −1), к лодыжке (1, 1). Косинус угла = (0·1 + (−1)·1)/(1·√2) = −1/√2, то есть угол 135°. Значение 45° соответствует углу между (0, 1) и (1, 1), то есть смежному углу.

## Модель обучают с аугментацией горизонтальным отражением изображения. Что необходимо сделать с разметкой ключевых точек?
- [ ] Ничего: отражение не меняет смысл меток, поскольку скелет симметричен
- [ ] Отразить только координаты по вертикали и оставить метки прежними как есть
- [x] Отразить x-координаты и поменять местами метки левых и правых точек
- [ ] Удалить из разметки все парные точки: плечи, локти, колени, запястья, бёдра

**Почему.** После отражения левая рука становится правой, поэтому без перестановки меток «левый локоть» и «правый локоть» модель получит противоречивые данные. Нужно и отразить x-координаты, и поменять местами пары левых и правых точек.

## Для чего в OpenPose предсказываются поля сродства частей (PAF)?
- [ ] Для повышения разрешения тепловых карт ключевых точек до уровня пикселей изображения
- [x] Чтобы определить, какие точки (локоть и запястье) относятся к одному человеку
- [ ] Чтобы восстанавливать глубину каждой точки и переводить 2D-позу в 3D-позу
- [ ] Чтобы вычислять метрику OKS без ручной разметки ключевых точек

**Почему.** PAF — векторное поле для каждой «кости» скелета: оно направлено вдоль конечности. Алгоритм проверяет, насколько поле вдоль отрезка между двумя точками согласовано с его направлением, и так группирует точки в скелеты. К разрешению карт, глубине и метрикам PAF отношения не имеют.
