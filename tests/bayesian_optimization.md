# Bayesian Optimization — мини-тест

## Что выдаёт суррогатная модель (гауссовский процесс) в каждой точке x и зачем нужна именно неуверенность?
- [x] Среднее μ(x) и отклонение σ(x); σ указывает, где стоит исследовать новое
- [ ] Только среднее μ(x); неуверенность нужна, чтобы получать градиент настоящей функции
- [ ] Точное значение f(x); неуверенность нужна только для оценки шума в данных
- [ ] Только отклонение σ(x); среднее вычисляется самой функцией выбора

**Почему.** GP возвращает нормальное распределение: μ — прогноз, σ — неуверенность, малая рядом с уже вычисленными точками и большая вдали. Функция выбора использует оба числа, чтобы сбалансировать использование (хороший прогноз) и исследование (большая σ). Градиента настоящей функции у чёрного ящика нет.

## Минимизируем f. Лучшее найденное значение f* = 0.5. В точке x суррогат даёт μ(x) = 0.5 и σ(x) = 1. Чему равен Expected Improvement, если EI = (f* − μ)·Φ(z) + σ·φ(z), z = (f* − μ)/σ, а φ(0) ≈ 0.40?
- [ ] ≈ 0.00
- [ ] ≈ 0.50
- [ ] ≈ 1.00
- [x] ≈ 0.40

**Почему.** Здесь z = 0, первое слагаемое равно 0, и остаётся σ·φ(0) ≈ 1·0.40 = 0.40. Прогноз не лучше текущего рекорда, но высокая неуверенность даёт ненулевое ожидаемое улучшение — это «исследовательская» часть EI. Ответ 0.50 получился бы, если взять Φ(0) вместо φ(0).

## Нужно подобрать 30 гиперпараметров, среди которых есть категориальные и условные (зависящие от выбора других). Какой суррогат обычно разумнее взять?
- [ ] Гауссовский процесс: его стоимость растёт линейно с числом точек, а размерность не мешает
- [x] TPE (как в Optuna или Hyperopt) или случайный лес (как в SMAC)
- [ ] Гауссовский процесс с RBF-ядром: он естественно работает с категориальными переменными
- [ ] Суррогат не нужен: достаточно перебора по сетке

**Почему.** GP хорошо работает с малым числом непрерывных параметров (до 10–20), его стоимость растёт как куб числа точек, а смешанные пространства для него неудобны. TPE и случайный лес справляются с категориальными и условными параметрами. Сетка при 30 измерениях просто невозможна.

## Оптимизация застряла вокруг первого найденного минимума и почти не пробует новых областей. Что поправить в функции выбора LCB = μ(x) − κ·σ(x)?
- [ ] Уменьшить κ, чтобы сильнее доверять прогнозу μ в точках, где он лучше
- [ ] Заменить её на PI, которая по своей природе менее жадная, чем LCB
- [x] Увеличить κ, чтобы поощрять точки с большой неуверенностью
- [ ] Убрать σ из формулы и выбирать следующие точки только по значению μ

**Почему.** Параметр κ задаёт вес неуверенности: чем он больше, тем больше исследования. PI и LCB с малым κ как раз склонны застревать у первого минимума, а выбор только по μ — это чистое использование.

## Какие утверждения верны? (выберите все верные)
- [x] Learning rate и силу регуляризации стоит искать в логарифмической шкале
- [ ] Каждая следующая точка в байесовской оптимизации выбирается независимо от прошлых результатов
- [x] Максимизация функции выбора дёшева, потому что она считается по суррогату, а не по настоящей f
- [ ] Для функции, считающейся секунды, байесовская оптимизация всегда заметно превосходит случайный поиск

**Почему.** Суррогат вычисляется мгновенно, а логарифмическая шкала упрощает его работу для параметров, различающихся на порядки. Независимый выбор точек — это случайный поиск, а при дешёвой функции накладные расходы на суррогат не окупаются, и Random Search с большим бюджетом не хуже.
