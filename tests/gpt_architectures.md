# GPT-архитектуры — мини-тест

## Почему из одного текста длиной 1000 токенов GPT получает сразу около 1000 обучающих примеров и не нуждается в разметке?
- [ ] Потому что текст разбивают на 1000 независимых фрагментов, и каждый заранее размечают вручную как отдельный обучающий пример
- [x] Потому что каузальная маска позволяет за один проход предсказать каждый токен по предыдущим, а ответ — следующий токен текста
- [ ] Потому что модель использует двунаправленное внимание и угадывает случайно скрытые токены, а скрытые позиции берутся из того же текста
- [ ] Потому что отдельный дискриминатор оценивает каждый токен как настоящий или поддельный, и это даёт метку для каждой позиции

**Почему.** Позиция t видит только токены 1…t, поэтому одна последовательность даёт предсказания для всех позиций сразу, а целью служит следующий токен самого текста. Двунаправленное внимание со скрытыми токенами характерно для BERT, а не для GPT.

## Логиты для двух токенов равны [2.0, 0.0]. Чему равна вероятность первого токена при temperature T = 2 (P = softmax(logits / T))?
- [ ] 0.88
- [ ] 0.982
- [x] 0.73
- [ ] 0.50

**Почему.** Делим логиты на T: [1, 0]. Тогда P₁ = e / (e + 1) ≈ 0.73. При T = 1 было бы 0.88, а при T = 0.5 — 0.98 (распределение острее). Рост T делает распределение ровнее, поэтому вероятность лидера падает.

## Вероятности токенов по убыванию: 0.5, 0.3, 0.1, 0.07, 0.03. Сколько токенов останется в наборе для сэмплирования при top-p = 0.85?
- [x] 3 токена
- [ ] 2 токена
- [ ] 4 токена
- [ ] 5 токенов

**Почему.** Берём минимальный набор самых вероятных токенов с суммарной вероятностью не меньше p: 0.5 + 0.3 = 0.8 < 0.85, а 0.5 + 0.3 + 0.1 = 0.9 ≥ 0.85, поэтому остаются 3 токена. Двух недостаточно, чтобы набрать 0.85.

## Почему при генерации можно хранить KV-кэш прошлых токенов и не пересчитывать для них ключи и значения?
- [ ] Потому что модель при генерации перестаёт использовать внимание к прошлым токенам и опирается только на последний сгенерированный
- [ ] Потому что ключи и значения не зависят от входного текста, а определяются только весами модели и номером слоя
- [ ] Потому что кэш заменяет предыдущие слои трансформера целиком, поэтому их веса можно не хранить в памяти
- [x] Потому что при каузальной маске K и V прошлых токенов не меняются от появления новых, поэтому их достаточно сохранить

**Почему.** Прошлые токены смотрят только влево, поэтому добавление нового токена не меняет их представлений, и K и V каждого слоя можно сохранить. Для нового токена считают запрос, ключ и значение, а внимание к кэшу остаётся. Цена — память на длинных контекстах.

## Предобученная GPT на запрос «Как испечь хлеб?» выдаёт список других вопросов в духе форума, а не ответ. Как получить из неё ассистента?
- [ ] Увеличить температуру и top-p, чтобы она стала отвечать на вопросы, а не продолжать форум, как раньше на обучении
- [x] Дообучить на парах «инструкция → ответ» (SFT), затем на предпочтениях людей (RLHF или DPO) для согласования с ними
- [ ] Убрать каузальную маску на этапе инференса, чтобы все токены вопроса видели друг друга и модель понимала его целиком
- [ ] Заменить декодер на энкодер, как у BERT, так как только энкодеры способны понимать вопрос и формировать ответ

**Почему.** Предобученная GPT учится продолжать текст, а не следовать инструкциям, поэтому её дообучают на инструкциях и затем на сравнениях ответов людьми. Температура лишь меняет случайность выбора токена, а без каузальной маски модель потеряла бы способность авторегрессионно генерировать.
