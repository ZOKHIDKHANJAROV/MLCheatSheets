# Функции потерь — мини-тест

## Модель предсказывает одну константу c для целей [1, 2, 3, 4, 100]. Какое значение c минимизирует MAE?
- [x] 3
- [ ] 22
- [ ] 4
- [ ] 2.5

**Почему.** MAE минимизируется медианой (здесь 3), а MSE — средним (здесь 22). Поэтому один огромный выброс сильно тянет решение MSE и почти не влияет на MAE. Для c = 3 сумма абсолютных ошибок 101, для c = 4 — уже 102.

## Для объекта класса 0 модель выдала вероятность класса 1, равную p = 0.9. Чему примерно равна бинарная кросс-энтропия BCE = −[y·ln p + (1 − y)·ln(1 − p)] на этом объекте?
- [ ] 0.1054
- [ ] 0.81
- [ ] 0.9
- [x] 2.303

**Почему.** При y = 0 остаётся слагаемое −ln(1 − p) = −ln 0.1 ≈ 2.303: уверенная ошибка штрафуется сильно. Значение 0.1054 — это −ln 0.9, штраф при верном уверенном ответе для класса 1, а 0.81 — это (y − p)², то есть MSE.

## Что произойдёт при обучении такой модели в PyTorch?
```python
import torch.nn as nn

model = nn.Sequential(nn.Linear(10, 3), nn.Softmax(dim=1))
criterion = nn.CrossEntropyLoss()
```
- [ ] Будет выброшено исключение при подсчёте потерь: `CrossEntropyLoss` не принимает на вход вероятности после softmax
- [x] Ошибки не будет, но softmax применится дважды и обучение ухудшится; `Softmax` нужно убрать из модели
- [ ] Потери окажутся нулевыми, так как вероятности каждого объекта суммируются в единицу и градиент исчезнет
- [ ] Всё корректно: `CrossEntropyLoss` ожидает на входе вероятности классов после softmax, а не логиты

**Почему.** `nn.CrossEntropyLoss` принимает логиты и сама делает log-softmax. Подача вероятностей даёт тихий баг: код работает, но градиенты и качество хуже. Вероятности для вывода считают softmax-ом отдельно, вне обучения.

## Чему равна функция Huber с порогом δ = 2 при ошибке e = 5 (½e² при |e| ≤ δ, иначе δ·(|e| − ½δ))?
- [x] 8
- [ ] 12.5
- [ ] 25
- [ ] 10

**Почему.** Так как |e| = 5 > δ = 2, используется линейная ветка: 2·(5 − 1) = 8. Квадратичная формула ½e² дала бы 12.5, MSE — 25, а формула δ·|e| без поправки ½δ — 10. Huber ведёт себя как MSE у нуля и как MAE на хвостах, поэтому выбросы не доминируют.

## Как можно учесть сильный дисбаланс классов (1 % положительных) на уровне функции потерь? (выберите все верные)
- [x] Задать `pos_weight` в `BCEWithLogitsLoss` или веса классов, чтобы ошибки на редком классе стоили дороже
- [ ] Заменить кросс-энтропию на MSE, потому что она не зависит от частот классов
- [x] Использовать focal loss с множителем (1 − p)^γ, снижающим вклад лёгких примеров
- [ ] Оптимизировать accuracy напрямую градиентным спуском, так как это гладкая функция

**Почему.** Веса классов и focal loss смещают акцент на редкий класс и трудные примеры. Accuracy — метрика, а не функция потерь: она ступенчатая, и градиента у неё нет. Замена на MSE дисбаланс не устраняет, а градиент с сигмоидой только ухудшает.
