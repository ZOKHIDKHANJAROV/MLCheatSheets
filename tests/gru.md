# GRU (Gated Recurrent Units) — мини-тест

## В GRU h_t = (1 − z_t) ⊙ h_{t−1} + z_t ⊙ h̃_t. Для одного элемента состояния h_{t−1} = 0.8, кандидат h̃_t = −0.4, update gate z_t = 0.25. Чему равно h_t?
- [x] 0.5
- [ ] −0.1
- [ ] 0.4
- [ ] 0.6

**Почему.** h_t = 0.75·0.8 + 0.25·(−0.4) = 0.6 − 0.1 = 0.5. Значение −0.1 получится, если перепутать роли весов (0.25 на старое, 0.75 на новое), а 0.6 — если забыть про вклад кандидата.

## Что делает reset gate r_t, если его значения близки к нулю?
- [ ] Обнуляет скрытое состояние h_t на выходе шага, и сеть полностью теряет память о прошлых токенах
- [ ] Заставляет update gate перенести старое состояние на следующий шаг без изменений
- [x] Кандидат h̃_t почти не зависит от прошлого и строится по текущему входу x_t
- [ ] Отключает градиент по входу x_t на этом шаге

**Почему.** Reset gate решает, сколько прошлого состояния учитывать при составлении кандидата: h̃_t = tanh(W·[r_t ⊙ h_{t−1}, x_t]). При r ≈ 0 кандидат почти не зависит от h_{t−1}, а итоговое состояние всё равно смешивается со старым через update gate.

## У LSTM с заданными размерами входа и скрытого слоя примерно 128 тысяч параметров. Сколько примерно параметров у GRU с теми же размерами?
- [ ] 64 тысячи
- [x] 96 тысяч
- [ ] 32 тысячи
- [ ] 128 тысяч

**Почему.** У LSTM четыре блока весов (три вентиля и кандидат в память), а у GRU три (два вентиля и кандидат), то есть примерно в 3/4 раза меньше: 128 · 3/4 = 96 тысяч. Именно поэтому GRU быстрее и требует меньше памяти.

## Для какой задачи двунаправленную GRU применять нельзя?
- [ ] Разметка именованных сущностей в готовом предложении
- [ ] Классификация тональности целого отзыва
- [ ] Разметка частей речи в готовом предложении
- [x] Генерация продолжения текста слово за словом

**Почему.** Двунаправленная сеть читает последовательность и слева направо, и справа налево, поэтому ей нужна вся последовательность целиком. При генерации текста и прогнозе временных рядов будущего ещё нет, и на обучении модель «подсмотрела» бы его, а в работе работала бы хуже.

## Что неверно в этом коде для классификации последовательностей?
```python
gru = nn.GRU(128, 256, batch_first=True, bidirectional=True)
fc = nn.Linear(256, 2)
out, h_n = gru(x)          # x: (batch, seq_len, 128)
logits = fc(out[:, -1])
```
- [ ] Параметр `batch_first=True` нельзя сочетать с `bidirectional=True`
- [ ] GRU возвращает только `h_n`, поэтому `out` не существует
- [x] Выход двунаправленной GRU имеет размер 512, а `fc` ожидает 256
- [ ] Размер скрытого слоя GRU должен совпадать с размером входа

**Почему.** При `bidirectional=True` состояния двух направлений склеиваются, и размер выхода удваивается до 2·256 = 512, поэтому `nn.Linear` должен принимать 512 входов. Кроме того, `out[:, -1]` для обратного направления — это начало чтения, и лучше брать `h_n` обоих направлений.
