# Память агента — мини-тест

## Что относится к кратковременной памяти агента?
- [ ] База фактов о пользователе, которая сохраняется между сессиями и подгружается в начале каждой новой беседы
- [ ] Векторное хранилище прошлых эпизодов, к которому агент обращается по сходству с текущим запросом
- [x] Содержимое контекстного окна: инструкция, недавние сообщения и подобранные воспоминания
- [ ] Набор правил и навыков, сохранённых в отдельном файле и неизменных между запусками агента

**Почему.** Кратковременная память — это то, что в данный момент лежит в контекстном окне модели. База фактов, векторное хранилище эпизодов и файл с правилами живут вне окна и переживают сессии — это разные виды долговременной памяти.

## Инструкция «Для отчёта сначала сделай выгрузку, затем проверь пропуски» — какой тип памяти она иллюстрирует?
- [ ] Эпизодическую, поскольку она описывает конкретное событие, которое уже произошло в одной из прошлых сессий
- [x] Процедурную: это способ действовать (порядок шагов), а не факт и не событие
- [ ] Семантическую, поскольку это общее утверждение о предметной области, не привязанное ко времени и способу действий
- [ ] Кратковременную, так как инструкция всегда хранится только в контекстном окне и пропадает после ответа

**Почему.** Процедурная память хранит «как делать»: порядок шагов, шаблоны, навыки. Эпизодическая — это события с датой, семантическая — факты и предпочтения. Инструкции можно хранить и в системном prompt, и во внешнем хранилище, поэтому они не обязаны исчезать после ответа.

## Какие записи имеет смысл сохранять в долговременную память? (выберите все верные)
- [x] Явное предпочтение пользователя: «отвечай кратко и без эмодзи»
- [ ] Все промежуточные рассуждения модели, чтобы затем можно было полностью восстановить ход каждого её ответа
- [x] Принятое решение по проекту вместе с причиной, чтобы в следующей сессии не обсуждать его заново
- [ ] Пароль, который пользователь однажды вставил в чат, чтобы автоматически подставлять его в будущие запросы

**Почему.** В память идут устойчивые и полезные в будущем сведения: предпочтения, решения, итоги. Промежуточные рассуждения засоряют поиск, а секреты и персональные данные без явного разрешения хранить нельзя.

## Воспоминание не использовалось 40 единиц времени. Период полураспада свежести T½ = 20, recency = 0.5^(Δt / T½). Чему равна свежесть?
- [ ] 0.5, потому что свежесть вдвое падает при первом же превышении периода полураспада и дальше не меняется
- [ ] 0.05, поскольку каждые 20 единиц времени значение уменьшается в десять раз по десятичному закону
- [ ] 0, потому что при Δt больше периода полураспада воспоминание считается полностью устаревшим
- [x] 0.25, потому что Δt равно двум периодам полураспада, а значит 0.5² = 0.25

**Почему.** Δt / T½ = 40 / 20 = 2, поэтому recency = 0.5² = 0.25. Экспоненциальное затухание продолжается и после первого периода, но не обнуляется и убывает вдвое за каждый период, а не втрое или вдесятеро.

## Факт «город пользователя — Москва» изменился: пользователь сообщил, что переехал в Казань. Как правильно обновить память?
- [ ] Дописать новую запись рядом со старой и надеяться, что при поиске модель сама выберет более свежий факт
- [ ] Оставить как есть: старая запись надёжнее, потому что она была сохранена раньше и уже много раз использовалась
- [ ] Удалить из памяти все факты о пользователе и заново собрать их из текущего диалога, чтобы избежать расхождений
- [x] Обновить запись по ключу: новое значение заменяет старое, при необходимости с отметкой времени

**Почему.** Для фактов используют upsert по ключу, чтобы не накапливать противоречия. Если дописывать копии, в контекст попадут обе версии и модель может выбрать устаревшую. Стирать всё лишнее, а старой записи отдавать приоритет нет оснований.
