# Transfer learning для CNN — мини-тест

## Почему при переносе обучения голову предобученной сети заменяют, а ранние слои обычно сохраняют?
- [x] Ранние слои находят границы и текстуры, нужные везде, а голова рассчитана на 1000 классов ImageNet
- [ ] Голова слишком мала по числу параметров, поэтому её нельзя обучать на новых данных, только заменять
- [ ] Ранние слои специфичны для классов ImageNet, а голова содержит самые универсальные признаки
- [ ] Ранние слои технически нельзя менять в PyTorch, а голову можно, поэтому их сохраняют

**Почему.** Чем ближе слой к входу, тем универсальнее его признаки (границы, цвета, простые текстуры). Последний полносвязный слой выдаёт ровно 1000 классов ImageNet, поэтому под свою задачу его всегда заменяют на новый.

## Есть 500 фотографий товаров на 5 классов; снимки похожи на обычные фотографии из ImageNet. Какую стратегию разумно выбрать в первую очередь?
- [ ] Обучить такую же сеть с нуля, чтобы признаки подходили именно под товары
- [ ] Разморозить всю сеть и дообучать с learning rate 1e-2
- [x] Заморозить backbone и обучить только новую голову
- [ ] Заменить голову, но обучать только первые свёрточные слои

**Почему.** При малом объёме данных и похожем домене достаточно feature extraction: признаки уже хороши, а риск переобучения минимален. С нуля на 500 картинках сеть переобучится, а большой learning rate при fine-tuning разрушит предобученные признаки.

## После полной заморозки параметров backbone вы запускаете обучение так. Что произойдёт с BatchNorm-слоями backbone?
```python
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 5)
model.train()
```
- [x] Их скользящие средние и дисперсии продолжат обновляться по батчам новых данных
- [ ] Их обучаемые параметры γ и β будут обновляться оптимизатором вместе с весами новой головы
- [ ] Ничего: у BatchNorm нет накапливаемых статистик, которые могли бы измениться при обучении
- [ ] Они автоматически перейдут в режим `eval()`, потому что веса заморожены и не требуют градиентов

**Почему.** `requires_grad = False` останавливает градиенты, но статистики BatchNorm — это буферы, и в режиме `train()` они пересчитываются по вашим батчам. Чтобы backbone оставался неизменным, его BN переводят в `eval()`.

## Точность дообученной модели оказалась неожиданно низкой, ошибок в коде нет. Какая подготовка входа могла стать причиной?
- [ ] Картинки были приведены к размеру 224×224 интерполяцией до подачи в сеть
- [ ] Значения пикселей были переведены в [0, 1] делением на 255 и затем нормализованы средним и std ImageNet
- [ ] Картинки были прочитаны через PIL в порядке RGB и нормализованы средним и std ImageNet
- [x] Картинки прочитаны через OpenCV (BGR) и не нормализованы средним и std ImageNet

**Почему.** Вход должен выглядеть так же, как при предобучении: тот же размер, RGB и нормализация mean/std ImageNet. OpenCV читает BGR, поэтому без перестановки каналов и нормализации сеть видит «не те» картинки, а ошибки при этом не возникает.

## Почему рекомендуют сначала обучить новую голову при замороженном backbone, а потом размораживать сеть с маленьким learning rate?
- [ ] Потому что замороженный backbone ускоряет обучение, а разморозка потом уменьшает размер модели
- [x] Потому что случайная голова даёт большие градиенты и может испортить признаки backbone
- [ ] Потому что fine-tuning возможен только после полной сходимости головы на тестовой выборке
- [ ] Потому что маленький learning rate нужен только для головы, а backbone учится с обычным

**Почему.** Новая голова инициализирована случайно, и её градиенты вначале велики; если сразу учить всю сеть, они «пинают» backbone. Поэтому сначала учат голову (lr около 1e-3), затем размораживают всё и дообучают с малым шагом (1e-5…1e-4).
