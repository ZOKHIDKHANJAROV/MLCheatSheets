# Балансировка классов (Imbalanced Data) — мини-тест

## Среди 1000 транзакций 10 мошеннических. Модель всегда отвечает «не мошенничество». Чему равны accuracy и recall по классу мошенничества?
- [ ] accuracy 50%, recall 0
- [ ] accuracy 99%, recall 99%
- [x] accuracy 99%, recall 0
- [ ] accuracy 1%, recall 100%

**Почему.** Верно угаданы все 990 нормальных транзакций, поэтому accuracy = 990 / 1000 = 99%, но ни одно мошенничество не найдено, и recall = 0. Поэтому при дисбалансе accuracy не годится как главная метрика, а смотрят на precision, recall, F1, PR-AUC и матрицу ошибок.

## В обучающей выборке 980 объектов класса 0 и 20 объектов класса 1. Во сколько раз ошибка на объекте редкого класса весит больше, чем на объекте частого, при `class_weight="balanced"`?
- [ ] В 98 раз
- [x] В 49 раз
- [ ] В 24,5 раза
- [ ] В 2 раза

**Почему.** Веса назначаются обратно пропорционально частотам классов: n / (k · nₖ) даёт 1000 / (2·980) ≈ 0.51 для частого и 1000 / (2·20) = 25 для редкого, то есть отношение равно 980 / 20 = 49. Числа 25 и 0.51 — это сами веса классов, а не их отношение; 24,5 получится, если поделить 49 на 2.

## SMOTE берёт объект редкого класса x = (2, 4) и его ближайшего соседа того же класса (6, 8). Какую синтетическую точку он создаст при λ = 0.25 (x_new = x + λ·(x_сосед − x))?
- [ ] (1, 1)
- [ ] (4, 6)
- [ ] (2.25, 4.25)
- [x] (3, 5)

**Почему.** x_сосед − x = (4, 4); умножаем на 0.25 и получаем (1, 1); прибавляем к x: (2 + 1, 4 + 1) = (3, 5). Новая точка всегда лежит на отрезке между объектом и соседом: при λ = 0.5 была бы (4, 6), а (1, 1) — только сдвиг без исходной точки, (2.25, 4.25) — результат прибавления λ к каждой координате вместо сдвига к соседу.

## Команда применила SMOTE ко всему набору данных, а затем разбила его на обучающую и тестовую части. Почему оценка на тесте окажется завышенной?
- [x] Синтетические точки, построенные по соседям, попадут и в обучение, и в тест, то есть будет утечка
- [ ] Потому что SMOTE меняет метки тестовых объектов, и модель оценивается уже на других ответах, чем при обучении
- [ ] Потому что SMOTE удаляет часть объектов частого класса, и поэтому в тесте остаётся мало нормальных примеров для оценки
- [ ] Потому что после SMOTE нельзя считать PR-AUC, так как классы в выборке становятся сбалансированными

**Почему.** Пересэмплировать нужно только обучающую часть (при кросс-валидации — внутри каждого фолда, например через `imblearn.pipeline.Pipeline`). Тест должен сохранять реальное распределение классов, а искусственно построенные по тестовым соседям точки в обучении дают утечку.

## После `class_weight="balanced"` recall редкого класса вырос с 0.49 до 0.79, precision упала с 0.91 до 0.14, а PR-AUC почти не изменилась. Что это показывает?
- [ ] Модель стала лучше отличать редкий класс от частого, а precision упала из-за шума в данных
- [ ] Метрика PR-AUC неприменима к моделям, обученным с весами классов, поэтому её значение ничего не показывает
- [x] Ранжирование прежнее: веса по сути сдвинули порог отсечения, как его снижение, и поэтому recall вырос
- [ ] Веса классов исправили калибровку вероятностей, поэтому precision и recall изменились одновременно

**Почему.** PR-AUC оценивает качество ранжирования, а оно почти не изменилось, поэтому веса, как и пересэмплирование, делают модель «смелее» в отношении редкого класса: recall растёт, а precision падает. Вероятности при этом смещаются и перестают отражать реальный риск без калибровки.
