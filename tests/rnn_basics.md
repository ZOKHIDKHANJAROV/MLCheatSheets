# Основы RNN — мини-тест

## Почему число параметров RNN не зависит от длины последовательности?
- [ ] Потому что RNN обрабатывает только первые несколько шагов, а остальные отбрасывает
- [x] Потому что одни и те же матрицы W_xh, W_hh и W_hy применяются на каждом шаге
- [ ] Потому что вся последовательность сжимается в один вектор, который обучается отдельными весами
- [ ] Потому что длинная последовательность автоматически режется на окна фиксированной длины

**Почему.** Развёрнутая во времени RNN — это один и тот же слой, повторённый на каждом шаге, поэтому веса общие. Благодаря этому длина входа может быть любой, а закономерность, выученная в одном месте текста, работает и в другом. Сжатие в один вектор и обрезка — свойства других подходов.

## Слой RNN: input_size = 10, hidden_size = 128, последовательность из 50 шагов. Сколько обучаемых элементов в матрицах W_xh и W_hh вместе (смещения не считаем)?
- [ ] 883 200
- [ ] 16 384
- [x] 17 664
- [ ] 1 280

**Почему.** W_xh имеет размер 128×10 = 1 280 элементов, W_hh — 128×128 = 16 384; вместе 17 664. Длина последовательности на число параметров не влияет, поэтому умножать на 50 (получилось бы 883 200) не нужно. Значения 16 384 и 1 280 учитывают лишь одну из двух матриц.

## При обучении простой RNN на длинных последовательностях потери внезапно стали `nan`. Что вероятнее всего произошло и что делать?
- [x] Взрыв градиента; добавить `clip_grad_norm_`
- [ ] Затухание градиента; увеличить длину последовательностей
- [ ] Ошибка паддинга; брать `out[:, 0, :]` вместо последнего шага
- [ ] Переобучение; увеличить число эпох

**Почему.** При BPTT градиент многократно умножается на W_hh. Если множители больше 1, он растёт экспоненциально, веса «прыгают», а потери становятся `nan`. Лечится обрезкой градиента по норме (порог около 1–5). Затухание проявляется иначе: сеть просто перестаёт учить далёкие связи.

## В какой задаче уместна двунаправленная RNN?
- [ ] Прогноз завтрашнего значения временного ряда по истории
- [ ] Генерация текста слово за словом
- [ ] Распознавание речи в потоковом режиме с выводом по ходу речи
- [x] Разметка именованных сущностей (NER) в уже готовом тексте

**Почему.** Двунаправленная RNN читает последовательность в обе стороны, поэтому ей нужен весь вход сразу — это верно для классификации и NER готового текста. При прогнозе или генерации «правой» части ещё нет, а в потоковом режиме она появляется только позже.

## Какую форму имеет `last` в этом коде?
```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=10, hidden_size=128, batch_first=True)
x = torch.randn(32, 50, 10)
out, h_n = rnn(x)
last = out[:, -1, :]
```
- [ ] (32, 50, 128)
- [x] (32, 128)
- [ ] (50, 128)
- [ ] (1, 32, 128)

**Почему.** При `batch_first=True` вход имеет форму (batch, seq_len, input_size), а `out` — (32, 50, 128). Срез `out[:, -1, :]` берёт последний шаг для каждого объекта батча и убирает ось времени, оставляя (32, 128). Форма (1, 32, 128) принадлежит `h_n`.
