# XGBoost — мини-тест

## Чем XGBoost отличается от классического градиентного бустинга по используемой информации о функции потерь?
- [x] Использует не только градиент, но и гессиан, что даёт шаг в духе метода Ньютона
- [ ] Использует градиент, но обучает все деревья одновременно, а не по очереди, как обычный бустинг
- [ ] Использует только знак градиента, а не его величину, поэтому устойчив к выбросам
- [ ] Не использует градиенты и подбирает значения листьев полным перебором по сетке

**Почему.** Для каждого объекта XGBoost считает градиент g и гессиан h, а значение листа получает как −G/(H + λ). Деревья по-прежнему строятся последовательно, каждое исправляет ошибки предыдущих; параллелится только поиск лучшего разбиения внутри дерева.

## В листе дерева XGBoost сумма градиентов G = −6, сумма гессианов H = 4, параметр reg_lambda λ = 2. Каково оптимальное значение листа w* = −G/(H + λ)?
- [ ] 3.0
- [ ] 1.5
- [ ] −1.0
- [x] 1.0

**Почему.** w* = −(−6)/(4 + 2) = 6/6 = 1.0. Вариант 1.5 получится, если забыть про λ (6/4), а вариант 3.0 — если взять в знаменателе только λ. L2-штраф λ делает значения листьев скромнее.

## Как XGBoost обрабатывает пропущенные значения признака?
- [ ] Автоматически заполняет их медианой по столбцу перед обучением и добавляет признак-индикатор
- [ ] Удаляет все строки с пропусками из обучающей выборки и предупреждает об этом в логе
- [x] На каждом разбиении подбирает направление по умолчанию для NaN (влево или вправо) по приросту
- [ ] Отправляет объекты с пропуском всегда в левую ветку, независимо от прироста на разбиении

**Почему.** При каждом разбиении пробуются оба направления для объектов с NaN, и запоминается то, что даёт больший прирост (default direction). Заполнять пропуски заранее не нужно, а на новых данных объекты с пропуском идут в выученное направление.

## Для ранней остановки в `eval_set` передали тестовую выборку, а затем на ней же измерили итоговое качество. В чём проблема?
- [ ] Ранняя остановка не работает без тестовой выборки
- [ ] Модель не сможет использовать `best_iteration` при предсказании
- [ ] Качество на тесте будет заниженным, так как модель увидит меньше данных
- [x] Число деревьев подобрано по тесту, поэтому итоговая оценка завышена

**Почему.** Ранняя остановка выбирает лучшую итерацию по данным из `eval_set`, то есть тест участвует в подборе модели и перестаёт быть независимым. Нужна отдельная валидационная выборка или кросс-валидация (`xgb.cv`).

## Какие утверждения о параметрах XGBoost верны? (выберите все верные)
- [x] `gamma` задаёт минимальный прирост, при котором разбиение вообще выполняется
- [ ] `scale_pos_weight` при дисбалансе берут примерно равным числу положительных объектов, делённому на число отрицательных
- [x] `reg_lambda` добавляет L2-штраф на значения листьев
- [ ] Увеличение `min_child_weight` делает деревья менее консервативными

**Почему.** `gamma` — «цена» нового листа, `reg_lambda` — L2-регуляризация листьев. `scale_pos_weight` ≈ (число отрицательных) / (число положительных), то есть наоборот, а больший `min_child_weight` запрещает листья с малой суммой гессианов и делает модель консервативнее.
