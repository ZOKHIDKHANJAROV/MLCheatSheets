# Предобработка данных (Preprocessing) — мини-тест

## Почему медиану для заполнения пропусков нужно вычислять только по обучающей выборке?
- [ ] Потому что в тестовой выборке пропусков не бывает, а в обучающей они есть
- [ ] Потому что медиана по всему датасету всегда отличается от медианы по train слишком сильно
- [x] Потому что медиана по всему датасету использует тест, и метрика завышается (утечка данных)
- [ ] Потому что `SimpleImputer` не умеет вычислять медиану по нескольким выборкам одновременно в одном вызове

**Почему.** Параметры предобработки — часть модели: их вычисляют (`fit`) на train, а к валидации, тесту и новым данным только применяют (`transform`). Если посчитать медиану по всем данным до разбиения, в обучение просачивается информация из теста. Пропуски в тесте и в продакшене бывают, и заполняют их как раз медианой из train.

## `StandardScaler` обучили на признаке со значениями [2, 4, 6, 8] в train. Какое значение получит объект теста x = 9 после `transform`? (σ — стандартное отклонение с делением на n)
- [ ] 1.55
- [ ] 4.00 (без деления на σ)
- [x] 1.79
- [ ] 2.00

**Почему.** Среднее в train равно 5, σ = √((9 + 1 + 1 + 9)/4) = √5 ≈ 2.236. Значит, (9 − 5)/2.236 ≈ 1.79. Значение 1.55 получится, если делить на выборочное отклонение с n − 1 (≈ 2.58), но `StandardScaler` делит на n.

## Для какой пары моделей масштабирование признаков наиболее важно?
- [ ] Случайный лес и градиентный бустинг над деревьями
- [ ] Одиночное решающее дерево и случайный лес
- [x] k-NN и SVM
- [ ] Градиентный бустинг и одиночное решающее дерево

**Почему.** k-NN и SVM работают с расстояниями и скалярными произведениями, поэтому признак в больших единицах «перекрикивает» остальные. Деревья и бустинги над ними сравнивают признак с порогом по одному, и монотонное масштабирование порядок значений не меняет.

## Что даёт передача целого `Pipeline` (с `ColumnTransformer` внутри) в `cross_val_score` вместо матрицы, уже обработанной на всех данных?
- [ ] Ускорение кросс-валидации за счёт однократного вычисления параметров предобработки
- [ ] Автоматический подбор стратегии заполнения пропусков и типа кодирования по качеству на фолдах
- [x] На каждом фолде предобработка обучается только на его train-части, утечки нет
- [ ] Возможность не разделять данные на обучение и валидацию вообще, фолды делают это сами

**Почему.** `Pipeline` повторяет все шаги `fit` на обучающей части каждого фолда, а на валидационной только применяет `transform`. Тот же объект целиком выкатывают в продакшен, чтобы не разошлись параметры. Ничего он сам не подбирает и не ускоряет.

## Какие утверждения верны? (выберите все верные)
- [ ] Деревьям решений для корректной работы необходима стандартизация признаков
- [x] Удаление строк с пропусками может выбросить неслучайную часть данных и сместить модель
- [ ] Параметры заполнения пропусков можно считать по всему датасету до разбиения, если тест не участвует в обучении самой модели
- [x] Label encoding номинального признака для линейной модели вводит несуществующий порядок категорий

**Почему.** Если пропуски связаны, например, с тем, что человек не указал доход, удаление строк делает выборку нерепрезентативной. Присвоение городам чисел 0, 1, 2 заставляет линейную модель считать, что A < B < C, поэтому нужен one-hot. Утечка возникает и тогда, когда тест не участвует в обучении самой модели: достаточно, что его статистики вошли в предобработку. Деревьям масштабирование не нужно.
