# Детекция объектов (YOLO, SSD, Faster R-CNN) — мини-тест

## Чем одностадийные детекторы (YOLO, SSD) отличаются от двухстадийных (Faster R-CNN)?
- [ ] Одностадийные детекторы выдают только класс всего изображения без рамок, как классификаторы
- [ ] Двухстадийные детекторы не используют свёрточные сети, а работают только на трансформерах
- [ ] Одностадийные детекторы требуют, чтобы на кадре был ровно один объект, иначе рамка неопределённа
- [x] Одностадийные сразу выдают рамки и классы за один проход, а двухстадийные сначала ищут кандидатов

**Почему.** В Faster R-CNN сеть-генератор кандидатов (RPN) предлагает области, а отдельная голова уточняет их класс и рамку; это точно, но медленнее. YOLO и SSD предсказывают всё за один проход, поэтому подходят для видео в реальном времени, а число объектов на скорость почти не влияет.

## Две рамки — квадраты 10×10, сдвинутые друг относительно друга на 5 пикселей по горизонтали. Чему равен IoU?
- [x] 0.33
- [ ] 0.250
- [ ] 0.500
- [ ] 0.667

**Почему.** Площадь пересечения 5·10 = 50, площадь объединения 100 + 100 − 50 = 150, поэтому IoU = 50/150 ≈ 0.33. Вариант 0.5 получился бы, если поделить пересечение на площадь одной рамки, а не на объединение.

## Для объектов одного класса детектор выдал три рамки: A (уверенность 0.9), B (0.8) и C (0.6). IoU(A, B) = 0.7, IoU(A, C) = 0.2, IoU(B, C) = 0.65. Какие рамки останутся после NMS с порогом IoU 0.5?
- [ ] A, B и C
- [ ] Только A
- [ ] B и C
- [x] A и C

**Почему.** NMS берёт самую уверенную рамку A и удаляет рамки с IoU > 0.5 по отношению к ней, то есть B. Рамка C с A почти не пересекается (0.2), и поскольку B уже удалена, она не может подавить C, поэтому остаются A и C.

## Чем метрика mAP@0.5:0.95 строже, чем mAP@0.5?
- [ ] Она учитывает только объекты крупнее заданного размера и игнорирует мелкие и средние
- [ ] Она вычисляется по порогу уверенности 0.95 вместо 0.5, отбрасывая менее уверенные рамки
- [x] Она усредняет AP по порогам IoU от 0.5 до 0.95, поэтому награждает точные рамки
- [ ] Она считает только true positive и не учитывает ни ложные срабатывания, ни пропуски

**Почему.** mAP@0.5 засчитывает предсказание при IoU ≥ 0.5, а метрика COCO усредняет AP по порогам IoU от 0.5 до 0.95 с шагом 0.05, поэтому неточные рамки получают штраф. Поэтому значения mAP@0.5 обычно заметно выше, и сравнивать нужно одинаковые метрики.

## Файл разметки в формате YOLO содержит строку `0 0.5 0.5 0.2 0.4` для картинки 640×480 пикселей. Что она описывает?
- [x] Объект класса 0 с центром в (320, 240) и размером 128×192 пикселя
- [ ] Объект класса 0 с центром в (320, 240) и размером 256×96 пикселей
- [ ] Объект класса 0 с центром в (0.5, 0.5) пикселя и размером 0.2×0.4 пикселя
- [ ] Объект класса 0 с левым верхним углом (320, 240) и размером 128×192 пикселя

**Почему.** Формат YOLO: `класс x_center y_center width height`, все значения нормированы на размер картинки. Центр: 0.5·640 = 320 и 0.5·480 = 240; ширина 0.2·640 = 128, высота 0.4·480 = 192. Перепутанный формат разметки — частая причина того, что модель ничего не находит.
