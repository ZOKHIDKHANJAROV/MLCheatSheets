# ReAct-агенты — мини-тест

## Из каких частей состоит шаг ReAct и кто пишет Observation?
- [ ] Question / Answer / Feedback; Observation пишет модель после рассуждения, чтобы сохранить связность текста
- [x] Thought / Action / Observation; Observation вставляет среда после реального вызова
- [ ] Plan / Execute / Verify; Observation формирует отдельная модель-критик, а не среда выполнения
- [ ] Thought / Action / Observation; Observation дописывает сама модель сразу после строки Action, не дожидаясь вызова

**Почему.** Thought и Action генерирует модель, а Observation — результат реального вызова, который добавляет среда. Если наблюдение пишет модель, это уже галлюцинация, поэтому генерацию останавливают перед «Observation:».

## Чем ReAct отличается от Chain-of-Thought?
- [ ] ReAct не использует рассуждения и только вызывает инструменты, а CoT — единственный метод с «мыслями»
- [ ] ReAct работает быстрее CoT, потому что делает меньше обращений к модели на один вопрос
- [x] ReAct чередует мысли с действиями и получает реальные наблюдения; CoT рассуждает без них
- [ ] CoT обязательно требует инструментов поиска, а ReAct целиком обходится данными, заложенными в обучение модели

**Почему.** CoT — рассуждение внутри модели без обращений к внешнему миру. ReAct добавляет действия и наблюдения, благодаря чему опирается на свежие данные. Обращений к модели у ReAct, как правило, больше, а не меньше.

## Агент получает от инструмента search ответ «ничего не найдено» и снова и снова вызывает search с тем же запросом. Как называется сбой и что помогает?
- [x] Зацикливание; помогают лимит шагов и проверка повторов одинаковых действий
- [ ] Галлюцинация наблюдений; помогает поднять температуру генерации до максимума
- [ ] Переобучение; помогает дообучить модель на этом запросе
- [ ] Потеря формата; помогает убрать Thought из промпта и оставить только Action

**Почему.** Повтор одного и того же действия без прогресса — зацикливание. Его ловят проверкой повторов и лимитом шагов, а модели подсказывают сменить запрос или инструмент. Остальные меры к этому сбою отношения не имеют, а убирать Thought вредно.

## Какие меры реально защищают ReAct-цикл от типичных сбоев? (выберите все верные)
- [x] Стоп-последовательность «Observation:», чтобы модель не выдумывала результаты инструмента
- [ ] Бесконечный рост истории без обрезки, чтобы модель точно ничего не забыла из прошлых шагов
- [x] Лимит шагов и бюджета, после которого цикл завершается с понятным сообщением
- [ ] Скрытие ошибок инструментов от модели, чтобы она не отвлекалась на неудачные вызовы

**Почему.** Стоп-последовательность предотвращает выдуманные наблюдения, а лимиты — бесконечный цикл и перерасход. Неограниченный контекст раздувает цену и ухудшает качество, а скрытые ошибки лишают модель сигнала, что надо менять действие.

## В каком случае ReAct, скорее всего, избыточен?
- [ ] Когда нужно ответить на вопрос, требующий нескольких поисков в заранее неизвестном порядке
- [ ] Когда для отладки необходима прозрачная траектория с видимыми мыслями и действиями
- [ ] Когда нужно проверить факты во внешнем источнике, которого нет в обучающих данных модели
- [x] Когда хватает одного запроса к модели или простой цепочки с известными шагами

**Почему.** ReAct окупается там, где путь заранее неизвестен и нужны внешние данные. Для простых задач он только добавляет обращения к модели, цену и задержку; здесь проще один запрос или цепочка.
