# Детекция объектов — мини-тест

## Две рамки в формате (x1, y1, x2, y2): A = (0, 0, 4, 4) и B = (2, 2, 6, 6). Чему равен IoU?
- [ ] 0.50
- [ ] 0.25
- [x] 0.14
- [ ] 1/3 ≈ 0.33

**Почему.** Пересечение — квадрат 2×2 площадью 4, объединение — 16 + 16 − 4 = 28, значит IoU = 4/28 = 1/7 ≈ 0.14. Значение 0.25 = 4/16 получается, если поделить пересечение на площадь одной рамки, а не на площадь объединения.

## Что происходит при слишком низком пороге IoU в NMS (например, 0.1)?
- [x] Удаляются рамки соседних реальных объектов, перекрытых с более уверенной рамкой
- [ ] Вокруг одного объекта остаются дубликаты, потому что рамки почти не удаляются порогом
- [ ] NMS перестаёт сортировать рамки по уверенности и берёт их в произвольном порядке
- [ ] Растёт число ложных срабатываний на фоне, потому что порог слабо фильтрует рамки

**Почему.** NMS оставляет самую уверенную рамку и удаляет остальные с IoU выше порога. Чем порог ниже, тем больше рамок удаляется, и в толпе пропадают реальные соседние объекты. Дубликаты остаются как раз при слишком высоком пороге.

## Какую проблему решает focal loss в RetinaNet?
- [ ] Разный масштаб объектов на изображении: мелкие и крупные рамки
- [x] Дисбаланс: тысячи лёгких фоновых якорей заглушают немногие объекты
- [ ] Дубликаты рамок вокруг одного объекта после предсказания сети
- [ ] Неточную локализацию рамок при высоком пороге IoU на оценке

**Почему.** Множитель (1 − p_t)^γ в FL(p_t) = −α·(1 − p_t)^γ·log(p_t) гасит лёгкие примеры: при p_t = 0.9 и γ = 2 он равен 0.01, то есть вклад падает в 100 раз, а трудные примеры сохраняют вес. Масштабы решает FPN, дубликаты убирает NMS.

## Какую роль играет RPN (Region Proposal Network) в Faster R-CNN?
- [ ] Приводит регионы к фиксированному размеру, например 7×7, для полносвязной головы
- [ ] Считает карту признаков всего изображения свёрточным backbone
- [ ] Окончательно классифицирует каждый регион и уточняет рамку
- [x] Предсказывает для якорей «объект или фон» и уточняет координаты

**Почему.** RPN скользит по карте признаков и для 9 якорей в каждой точке (3 размера × 3 пропорции) выдаёт оценку «объект/фон» и поправку к рамке, оставляя несколько сотен лучших предложений. Карту признаков считает backbone, к фиксированному размеру регионы приводит RoI Pooling (RoIAlign), а финальное решение принимает голова.

## Одна статья сообщает mAP@0.5 = 0.60 для детектора A, другая — COCO mAP@[.5:.95] = 0.40 для детектора B. Можно ли утверждать, что A точнее?
- [x] Нет: это разные метрики, и сравнивать их напрямую нельзя
- [ ] Да, потому что 0.60 больше 0.40, значит детектор A точнее
- [ ] Нет: mAP@0.5 строже COCO mAP, поэтому на деле лучше детектор B
- [ ] Да, но только если оба детектора двухстадийные, как Faster R-CNN

**Почему.** mAP@0.5 засчитывает предсказание при IoU ≥ 0.5, а COCO mAP усредняется по порогам от 0.5 до 0.95 с шагом 0.05 и требует точной локализации, то есть строже. Числа получены на разных шкалах, поэтому сравнение имеет смысл только в рамках одного определения метрики.
