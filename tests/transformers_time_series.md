# Transformers для временных рядов — мини-тест

## Почему подавать в трансформер каждую точку ряда как отдельный токен — плохая идея?
- [ ] Потому что внимание не умеет работать с вещественными числами и требует целочисленных индексов
- [x] Потому что одна точка почти ничего не значит, а стоимость внимания квадратична по длине
- [ ] Потому что позиционное кодирование нельзя применять к числовым рядам без дискретных позиций
- [ ] Потому что трансформер принимает только последовательности короче 16 элементов из-за размера батча

**Почему.** В отличие от слова в тексте, отдельная точка ряда почти ничего не значит без соседей, а внимание стоит O(L²): окно в 720 часов уже даёт около полумиллиона пар. Поэтому токеном делают патч — кусок ряда. Позиционное кодирование к рядам применяется (часто вместе с календарными признаками).

## В PatchTST окно истории длиной 512 точек нарезают на непересекающиеся патчи по 16 точек. Сколько получится токенов и во сколько раз уменьшится число пар токенов в матрице внимания?
- [ ] 32 токена, примерно в 16 раз
- [ ] 16 токенов, примерно в 32 раза
- [ ] 512 токенов, число пар не изменится
- [x] 32 токена, в 256 раз

**Почему.** 512 / 16 = 32 токена. Число пар внимания растёт как n²: 512² = 262 144 против 32² = 1 024, то есть в 256 раз меньше. Именно поэтому патчи позволяют смотреть дальше в прошлое при той же стоимости.

## Что показала статья «Are Transformers Effective for Time Series Forecasting?» с моделью DLinear?
- [ ] Линейные модели непригодны для рядов с трендом и сезонностью, их нужно заменять трансформерами
- [ ] Любая нейросеть на стандартных наборах данных хуже классической модели ARIMA или ETS
- [ ] Трансформеры для рядов принципиально не могут работать с длинным окном истории, больше 96 точек
- [x] Простая линейная модель по окну часто обыгрывает сложные трансформеры, поэтому нужны сильные бейзлайны

**Почему.** DLinear раскладывает окно на тренд и остаток и применяет к каждой части один линейный слой, отображающий L прошлых точек сразу в H будущих; на стандартных наборах она обыграла многие трансформеры. Позднейшие PatchTST и iTransformer снова превзошли линейные модели, поэтому сравнивать с ними стоит все новые методы.

## Какой из признаков Temporal Fusion Transformer относит к «известным в будущем»?
- [ ] Категорию товара из справочника номенклатуры магазина
- [x] Календарь запланированных акций на следующие недели
- [ ] Фактические продажи за последние дни, уже попавшие в историю
- [ ] Фактическую температуру, измеренную вчера на метеостанции

**Почему.** Известные в будущем признаки — это календарь и запланированные события, их значения есть и для горизонта прогноза. Категория товара — статический признак, а фактические продажи и измеренная погода наблюдаются только в прошлом.

## Почасовой ряд имеет недельную сезонность. Что плохого в том, чтобы обучить трансформер с окном истории всего в 48 точек?
- [x] Окно в 48 часов короче недельного периода (168 часов), и модель его не увидит
- [ ] Окно короче 100 точек технически несовместимо с внимательными слоями трансформера
- [ ] Модель из-за короткого окна не сможет выдать прогноз сразу на весь горизонт
- [ ] Короткое окно делает внимание вычислительно более дорогим, чем длинное окно

**Почему.** Длина окна — один из важнейших гиперпараметров: чтобы уловить недельную сезонность часовых данных, окно должно покрывать минимум 168 часов. Стоимость внимания при коротком окне, наоборот, меньше.
