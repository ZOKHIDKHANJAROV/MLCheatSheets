# TensorFlow/Keras полный гайд — мини-тест

## В какой ситуации стоит писать модель подклассом `keras.Model`, а не через Sequential или Functional API?
- [x] Когда в прямом проходе нужна произвольная Python-логика в `call`
- [ ] Когда у модели два входа, объединяемых через слой `Concatenate`
- [ ] Когда нужна skip-связь между двумя слоями через слой `Add`
- [ ] Когда модель состоит из одной простой стопки слоёв `Dense`

**Почему.** Подкласс нужен для нестандартной логики прямого прохода (условия, циклы). Skip-связи и несколько входов выражаются графом слоёв в Functional API, а простая стопка слоёв — это Sequential.

## Какую функцию потерь нужно указать в `compile` для такой модели и таких меток?
```python
model.add(layers.Dense(3, activation="softmax"))
y_train = np.array([0, 2, 1, 1, 0])
```
- [ ] `categorical_crossentropy` с `from_logits=True`
- [ ] `binary_crossentropy` с порогом 0.5
- [ ] `mse` после one-hot кодирования меток
- [x] `sparse_categorical_crossentropy`

**Почему.** Метки заданы номерами классов, а выход — softmax по трём классам, поэтому подходит `sparse_categorical_crossentropy`. `categorical_crossentropy` ожидает one-hot метки, а `binary_crossentropy` предназначена для двух классов с одним сигмоидным выходом.

## Почему `validation_split=0.2` в `fit` может дать нерепрезентативную валидацию?
- [ ] Валидационная часть случайно выбирается заново в каждой эпохе, поэтому метрики сильно скачут
- [x] Берутся последние 20% строк без перемешивания, а данные могут быть отсортированы по классу
- [ ] Валидационные объекты также участвуют в вычислении градиента и обновлении весов на каждом шаге
- [ ] Метрики на валидации считаются только для первого батча каждой эпохи, остальные игнорируются

**Почему.** `validation_split` отрезает хвост массива до обучения и не перемешивает его. Если данные отсортированы по классу, в валидацию попадёт один-два класса. Выход: заранее перемешать данные или передать `validation_data`.

## Что делает колбэк `EarlyStopping(monitor="val_loss", patience=5, restore_best_weights=True)`?
- [ ] Через 5 эпох без улучшения уменьшает learning rate вдвое и продолжает обучение с новым шагом
- [ ] Сохраняет лучшую по val_loss модель на диск в файл после каждой эпохи обучения
- [x] Останавливает обучение после 5 эпох без улучшения val_loss и возвращает лучшие веса
- [ ] Останавливает обучение сразу, как только val_loss вырос на одну эпоху подряд

**Почему.** `patience=5` означает, что ждём 5 эпох без улучшения, а `restore_best_weights=True` возвращает веса с лучшей эпохи, а не последней. Уменьшением learning rate занимается `ReduceLROnPlateau`, а сохранением на диск — `ModelCheckpoint`.

## Какие утверждения верны? (выберите все верные)
- [ ] `from_logits=True` в функции потерь нужен, когда последний слой модели уже содержит softmax
- [x] `prefetch` в `tf.data` готовит следующий батч, пока ускоритель считает текущий
- [ ] `ModelCheckpoint` останавливает обучение, когда качество перестало расти
- [x] `GradientTape` записывает операции, чтобы затем посчитать градиенты по обучаемым переменным

**Почему.** `prefetch` перекрывает подготовку данных и вычисления, а `GradientTape` — аналог autograd для собственного цикла обучения. `from_logits=True` указывают, когда выход модели без активации (логиты), а остановкой обучения занимается `EarlyStopping`, не `ModelCheckpoint`.
