# RNN/LSTM для временных рядов — мини-тест

## Ряд состоит из 200 точек. Из него нарезают окна длины 10, по каждому окну предсказывается следующее значение (горизонт 1). Сколько обучающих пар получится?
- [ ] 200 пар
- [ ] 191 пара
- [x] 190 пар
- [ ] 189 пар

**Почему.** Окно начинается с позиций 0, 1, …, пока после него остаётся хотя бы одна точка для цели: число пар = 200 − 10 − 1 + 1 = 190. Это совпадает с формой `X` (190, 10) в примере лекции.

## Что не так в этом коде подготовки данных?
```python
from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
scaled = scaler.fit_transform(series.reshape(-1, 1))
split = int(0.8 * len(scaled))
train, test = scaled[:split], scaled[split:]
```
- [x] Скейлер обучен на всём ряде, включая тест: его минимум и максимум просачиваются в обучение
- [ ] Разбиение должно быть случайным, а не по времени, иначе в тест попадут только поздние значения
- [ ] `MinMaxScaler` неприменим к временным рядам, для них подходит только `StandardScaler` с нулевым средним
- [ ] `reshape(-1, 1)` перемешивает значения и нарушает их порядок во времени

**Почему.** Скейлер нужно обучать только на train и лишь применять к остальным частям, иначе возникает утечка данных и оценка становится оптимистичной. Разбиение по времени как раз правильное, а `reshape` порядок элементов не меняет.

## Чем рекурсивная стратегия многошагового прогноза уступает прямой?
- [ ] Требует обучать отдельную модель на каждый шаг прогнозируемого горизонта
- [x] Подставляет свои прогнозы в окно как факты, поэтому ошибки копятся
- [ ] Не работает с LSTM и подходит только для линейных моделей и деревьев
- [ ] Выдаёт сразу весь горизонт одним вектором, из-за чего значения несогласованны

**Почему.** При рекурсивной стратегии прогноз на шаг подставляется в окно и используется для следующего прогноза, поэтому ошибка копится. Достоинство подхода — одна модель. Отдельные модели на каждый шаг — это прямая стратегия, а сразу весь горизонт даёт многовыходная.

## Что помогает, когда ряд имеет растущий тренд? (выберите все верные)
- [ ] Обучить скейлер на всём ряде, чтобы значения теста не выходили за диапазон
- [x] Предсказывать приращения y(t) − y(t−1) вместо уровня, а затем складывать их обратно
- [x] Вычитать из каждого окна его последнее значение и добавлять его обратно к прогнозу
- [ ] Перемешать окна до разбиения, чтобы в train попали и высокие значения

**Почему.** Сеть плохо экстраполирует уровни за пределы увиденного в train, поэтому ей дают приращения или значения относительно окна. Обучение скейлера на всём ряде и перемешивание окон до разбиения создают утечку и завышают оценку.

## Прогноз LSTM на графике почти совпадает с фактом, но выглядит как тот же ряд, сдвинутый на один шаг. Что это значит и что делать?
- [ ] Это норма: у любой хорошей модели прогноз по определению запаздывает ровно на один шаг
- [ ] Ошибка в `inverse_transform`: нужно заново обучить скейлер на всём ряде
- [ ] Модель переобучилась на шуме обучающей выборки: нужно вдвое увеличить размер сети
- [x] Сеть выучила наивный прогноз «повтори последнее значение»; сравните с ним по MASE

**Почему.** Такая «тень» — типичный признак того, что сеть просто повторяет последнее значение окна. Нужно посчитать наивный прогноз и линейную модель по тому же окну: MASE (ошибка модели, делённая на ошибку наивного прогноза) меньше 1 только если модель лучше наивной.
