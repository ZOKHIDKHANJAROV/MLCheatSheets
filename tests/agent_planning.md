# Планирование и рефлексия агентов — мини-тест

## Что должно происходить с планом в схеме plan-and-execute, когда один из шагов завершился ошибкой?
- [ ] Весь план отбрасывается, и агент строит новый с первого шага, так как результаты прежних шагов считаются недостоверными
- [x] Выполненные шаги сохраняются, а планировщик пересобирает оставшуюся часть плана с учётом ошибки
- [ ] Исполнитель молча пропускает сбойный шаг и идёт дальше, поскольку зависимые шаги всё равно как-нибудь выполнятся
- [ ] Агент навсегда переключается на режим ReAct и больше никогда не возвращается к составленному ранее плану

**Почему.** Выполненная работа по-прежнему верна, поэтому пересматривают только остаток плана. Полная перестройка тратит токены впустую, пропуск шага ломает зависимые подзадачи, а переход на ReAct не нужен: план остаётся полезной опорой.

## План — DAG из четырёх подзадач: A → B, A → C, B → D, C → D. Длительности: A = 1, B = 4, C = 2, D = 3. Сколько шагов займёт план при неограниченном параллелизме?
- [ ] 10: нужно сложить длительности всех четырёх подзадач, так как они относятся к одному плану
- [ ] 6: путь A → C → D, потому что план идёт по самой короткой из ветвей и пропускает остальные
- [ ] 7: самая длинная ветка B плюс подзадача D, поскольку подзадача A выполняется до старта плана
- [x] 8: критический путь A → B → D, ветка C короче и укладывается в ожидание B

**Почему.** Время плана равно длине критического пути — самой длинной цепочки зависимых подзадач: 1 + 4 + 3 = 8. Ветка C (1 + 2 + 3 = 6) выполняется параллельно и имеет запас. Сумма всех длительностей (10) верна только при полностью последовательном выполнении.

## Какие утверждения о Reflexion верны? (выберите все верные)
- [x] Рефлексия — это текстовое описание ошибки, которое хранится в памяти и учитывается в следующей попытке
- [ ] Метод дообучает веса модели градиентным спуском на неудачных траекториях после каждой попытки агента
- [x] Лучше всего метод работает при внешнем сигнале, например при результатах тестов или ошибке инструмента
- [ ] Самокритика той же модели без внешних данных гарантированно находит все ошибки в собственном ответе

**Почему.** Reflexion не меняет веса: опыт накапливается в виде текстовых заметок, которые подмешиваются в промпт. Эффективность держится на внешней обратной связи. Критик без доступа к реальности может уверенно подтвердить неверный ответ, поэтому «гарантированно находит все ошибки» неверно.

## Чем Tree of Thoughts отличается от обычной цепочки рассуждений?
- [ ] Модель обучается прямо во время рассуждения: после каждого шага её веса слегка обновляются
- [ ] Одна и та же цепочка запускается несколько раз, и выбирается самый частый итоговый ответ
- [x] На каждом шаге порождается несколько вариантов мыслей, их оценивают и ведут поиск с возвратом из тупиков
- [ ] Рассуждение целиком заменяется вызовом инструмента, поэтому промежуточные мысли не генерируются вообще

**Почему.** В Tree of Thoughts мысли образуют дерево: кандидаты оцениваются, плохие ветки отбрасываются, а при тупике поиск возвращается назад. Выбор самого частого ответа из нескольких независимых цепочек — это self-consistency, а не дерево. Веса модели при этом не меняются.

## Агент пятый шаг подряд вызывает один и тот же инструмент с теми же аргументами и не продвигается к цели. Что разумно сделать?
- [x] Прервать цикл по лимиту повторов, вернуть частичный результат и пересмотреть план
- [ ] Увеличить бюджет шагов вдвое, чтобы у агента появилось больше шансов случайно найти другой путь
- [ ] Повышать температуру модели, пока ответ не изменится, и продолжать без ограничения числа шагов
- [ ] Стереть из контекста всю историю вызовов, чтобы агент начал рассуждать с чистого листа заново

**Почему.** Повтор одного вызова без прогресса — признак цикла. Нужно остановиться, сохранить достигнутое и пересобрать план или позвать человека. Больший бюджет и случайность лишь тратят ресурсы, а стирание истории возвращает агента к тем же ошибкам.
