# Prompt Engineering для LLM — мини-тест

## Чем few-shot промпт отличается от zero-shot и когда примеры особенно полезны?
- [ ] Few-shot дообучает веса модели на приведённых примерах, а zero-shot — нет, поэтому требует отдельного этапа обучения
- [x] В few-shot к инструкции добавляют пары «вход → выход»; это помогает, когда важны формат или тонкие правила
- [ ] Few-shot отличается тем, что запрос отправляется несколько раз с разной температурой, а ответы затем сравниваются
- [ ] Few-shot полезен только для задач с рассуждением, а для классификации и извлечения полей примеры бесполезны

**Почему.** Zero-shot — это только инструкция; few-shot — инструкция плюс примеры внутри самого промпта, веса модели при этом не меняются. Примеры хорошо задают формат ответа и пограничные случаи, поэтому их берут разнообразными и сбалансированными по классам. Многократный запрос с голосованием — это уже self-consistency.

## Вы попросили модель вернуть ответ строго в JSON, и в примерах она всегда так делала. Что нужно сделать в коде, который читает ответ?
- [ ] Ничего: если формат указан в промпте, модель гарантированно ему следует и проверка не нужна
- [ ] Проверять только наличие фигурных скобок в ответе, остальное можно не проверять
- [ ] Увеличить температуру, чтобы снизить вероятность нарушения формата в ответах
- [x] Разобрать ответ, проверить схему и допустимые значения, при сбое повторить запрос

**Почему.** Модель может нарушить формат (например, ответить текстом вместо JSON) или вернуть недопустимое значение поля. Поэтому ответ проверяют кодом, как в `parse_answer`, а при сбое повторяют запрос; если API умеет принудительно выдавать JSON по схеме, используют это. Температуру для стабильности формата скорее понижают, а не повышают.

## Модель должна отвечать по внутренним документам компании и не выдумывать факты. Какой подход подходит лучше всего?
- [ ] Сильно повысить температуру и top_p, чтобы модель «вспомнила» нужные документы компании
- [ ] Добавить в system-промпт роль «эксперт по документам компании» — этого достаточно, модель сама найдёт факты
- [x] RAG: вставлять найденные фрагменты в промпт и просить отвечать только по ним, иначе говорить «не знаю»
- [ ] Попросить рассуждать по шагам (chain-of-thought), тогда модель найдёт нужные факты внутри себя

**Почему.** Модель не знает внутренних документов, поэтому нужные фрагменты надо предоставить в промпте (Retrieval-Augmented Generation) и разрешить ответ «не знаю», чтобы снизить галлюцинации. Роль и рассуждение по шагам знаний, которых у модели нет, не добавляют.

## Какое утверждение о prompt injection верно?
- [ ] Проблема возникает только при обращении к собственной модели, а при вызове внешнего API её не бывает
- [ ] Её полностью устраняют разделители вокруг пользовательского текста вроде `<<< >>>` и просьба не выполнять инструкции
- [x] Недоверенный текст может содержать инструкции, которым модель последует; разделители риск лишь снижают
- [ ] Она опасна только при нулевой температуре, когда модель следует любому тексту буквально

**Почему.** Письмо, страница или отзыв могут содержать фразы вроде «игнорируй предыдущие указания», и модель способна им подчиниться. Поэтому модели, читающей недоверенные данные, не дают права на опасные действия без проверки и не кладут в промпт секреты. Температура и принадлежность модели тут не причина.

## Как правильно выбрать между двумя вариантами промпта для классификации отзывов?
- [ ] Выбрать вариант, давший более красивый ответ на пару тщательно подобранных примеров, и больше не проверять
- [ ] Выбрать более длинный вариант: чем больше в нём инструкций и примеров, тем надёжнее и стабильнее ответ модели
- [x] Прогнать оба на размеченном наборе со сложными случаями и сравнить accuracy, F1, долю валидного JSON
- [ ] Взять вариант, который лучше сработал в одном запуске при нулевой температуре на всём наборе примеров

**Почему.** Промпт — это код: впечатление от нескольких удачных ответов ничего не доказывает, нужны тестовый набор (хотя бы 30–100 примеров) и метрика. Слишком длинный промпт, наоборот, теряет важные инструкции, а даже при температуре 0 ответы не всегда воспроизводимы, поэтому один запуск ненадёжен.
