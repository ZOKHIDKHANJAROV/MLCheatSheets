# Multi-head Attention — мини-тест

## В модели d_model = 768 и 12 голов внимания. Какова размерность d_k каждой головы?
- [ ] 12
- [ ] 768
- [ ] 9216
- [x] 64

**Почему.** Вектор делится между головами поровну: d_k = d_model / h = 768 / 12 = 64. После склейки 12 голов по 64 снова дают 768. Поэтому d_model должно делиться на число голов без остатка.

## Сколько весов (без смещений) в матрицах W_Q, W_K, W_V и W_O слоя multi-head attention при d_model = 256 и h = 4?
- [ ] 65 536
- [x] 262 144
- [ ] 1 048 576
- [ ] 131 072

**Почему.** Это четыре матрицы 256 × 256, то есть 4·256² = 262 144, причём число голов на это число не влияет: головы лишь делят то же пространство на подпространства. Значение 65 536 — одна матрица, 131 072 — две, а 1 048 576 получилось бы, если бы у каждой из 4 голов были полноразмерные матрицы.

## Что вернёт `weights` в этом коде?
```python
import torch
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
x = torch.randn(2, 10, 512)
out, weights = mha(x, x, x, average_attn_weights=False)
```
- [x] Тензор формы (2, 8, 10, 10): веса каждой головы по отдельности
- [ ] Тензор формы (2, 10, 10): веса внимания, усреднённые по всем головам
- [ ] Тензор формы (8, 2, 10, 10): сначала идут головы, потом батч, как в самописных реализациях
- [ ] Тензор формы (2, 10, 512): веса внимания совпадают по форме с выходом слоя out

**Почему.** По умолчанию `nn.MultiheadAttention` усредняет веса по головам и возвращает (batch, seq, seq). Если передать `average_attn_weights=False`, форма становится (batch, heads, seq, seq) = (2, 8, 10, 10). Выход `out` имеет форму (2, 10, 512).

## Разработчик режет проекцию Q формы (n, d_model) на головы так. В чём проблема?
```python
import numpy as np

n, h, d_k = 5, 4, 4
Q = np.random.randn(n, h * d_k)
heads = Q.reshape(h, n, d_k)
```
- [ ] Код выбросит ошибку ValueError, так как число элементов в массиве Q не совпадает с размером новой формы
- [ ] Проблемы нет: так и получаются головы формы (h, n, d_k), и каждая голова содержит все n токенов целиком
- [ ] Проблема только в том, что при `h > n` код не работает, а при h ≤ n головы получаются корректными
- [x] Ошибки не будет, но в головы попадут куски разных токенов; нужен `reshape(n, h, d_k)` и перестановка осей

**Почему.** `reshape(h, n, d_k)` читает данные подряд и смешивает признаки разных токенов, хотя число элементов сходится. Корректно разрезать последнюю ось: `(n, d_model) → (n, h, d_k)`, а затем `transpose(1, 0, 2)`. Такой баг не вызывает исключений, модель просто хуже учится.

## Какие утверждения верны? (выберите все верные)
- [x] В multi-query attention у всех голов общий набор K и V, что уменьшает KV-кэш при генерации
- [ ] При фиксированном d_model рост числа голов увеличивает размер каждой головы d_k
- [x] Число голов должно делить d_model, чтобы вектор можно было разрезать на равные части
- [ ] Каузальная маска применяется только к первой голове, остальные видят все токены

**Почему.** Размер головы d_k = d_model / h с ростом h уменьшается, а слишком малый d_k (8–16) ухудшает качество. Каузальная и padding-маски применяются ко всем головам одинаково. MQA и GQA делят K и V между головами, чтобы экономить память на длинных контекстах.
