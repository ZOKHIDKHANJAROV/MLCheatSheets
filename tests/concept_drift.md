# Дрейф данных и концептуальный дрейф — мини-тест

## В модели кредитного скоринга распределение доходов клиентов не изменилось, но при том же доходе люди стали чаще не возвращать кредиты. Какой это дрейф и можно ли его заметить по одним входным данным?
- [ ] Data drift (covariate shift): изменилось P(X), заметно по признакам без меток
- [ ] Label drift: изменилось P(Y), заметно по распределению признаков
- [x] Concept drift: изменилось P(Y | X), по признакам не видно, нужны метки
- [ ] Это не дрейф, а обычная ошибка модели, так как P(X) осталось прежним

**Почему.** Связь между признаками и целевой переменной P(Y | X) изменилась, а P(X) нет, поэтому мониторинг только входных данных ничего не покажет. Нужны метки (даже с задержкой) или прокси-метрики. Data drift — это именно сдвиг P(X).

## Доли объектов по двум корзинам: в эталоне e = (0.5; 0.5), в текущем окне a = (0.7; 0.3). Чему примерно равен PSI = Σ (aᵢ − eᵢ)·ln(aᵢ / eᵢ) и как его принято интерпретировать?
- [ ] ≈ 0.07, сдвиг незначителен: данные стабильны
- [x] ≈ 0.17, умеренный сдвиг: стоит посмотреть
- [ ] ≈ 0.34, значительный сдвиг: нужно переобучать модель
- [ ] ≈ 0.00, так как суммы долей в обоих окнах равны 1

**Почему.** (0.7 − 0.5)·ln(1.4) + (0.3 − 0.5)·ln(0.6) = 0.2·0.336 + 0.2·0.511 ≈ 0.17. Это попадает в диапазон 0.1–0.25 (умеренный сдвиг); порог значительного сдвига — 0.25. Равенство сумм долей не делает PSI нулевым: нулевым он бывает только при совпадении долей в каждой корзине.

## На очень большой выборке (сотни тысяч объектов) тест Колмогорова–Смирнова показывает p < 0.001 почти для каждого признака. Как правильно поступить?
- [ ] Считать, что модель деградировала, и сразу переобучать её
- [ ] Увеличить уровень значимости до 0.5, чтобы убрать лишние срабатывания
- [ ] Отказаться от статистических тестов и мониторить только среднее признаков
- [x] Смотреть на величину эффекта (статистика KS, PSI), а не только на p-value

**Почему.** На больших выборках значимыми становятся даже ничтожные различия, которые модели не вредят. Поэтому нужны пороги на величину сдвига. Кроме того, при проверке сотен признаков каждый день что-то «сработает» случайно (множественные сравнения).

## Эталонный период — июль, текущее окно — декабрь, а продажи сильно зависят от сезона. Какая ошибка здесь возможна при мониторинге дрейфа?
- [x] Сезонные различия будут приняты за дрейф, хотя они ожидаемы
- [ ] Сезонность скроет любые изменения признаков, дрейф не обнаружится
- [ ] PSI станет отрицательным из-за разницы в объёме выборок
- [ ] Тест Колмогорова–Смирнова перестанет работать на сезонных данных

**Почему.** Сравнение разных сезонов покажет «дрейф», который просто повторяется каждый год. Эталон лучше брать из того же периода прошлого года или учитывать сезонность. PSI по построению неотрицателен.

## Какие утверждения о мониторинге дрейфа верны? (выберите все верные)
- [x] Распределение прогнозов модели можно отслеживать без меток как дешёвый сигнал
- [ ] Мониторинг распределения входных признаков позволяет заметить concept drift при неизменном P(X)
- [ ] Recall на свежих данных можно считать сразу, как только пришли новые объекты, без меток
- [x] Перед переобучением нужно проверить, что «дрейф» не вызван поломкой данных, например сменой единиц

**Почему.** Распределение выходов реагирует на дрейф важных признаков и не требует меток. Значительная часть «дрейфа» — баги в пайплайне, поэтому их исключают в первую очередь. Метрики качества (например, recall) требуют меток, а concept drift при неизменном P(X) по признакам не виден.
