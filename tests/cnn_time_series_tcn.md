# CNN для временных рядов (TCN) — мини-тест

## Модель на основе одномерной свёртки для прогноза использует `padding="same"`. Что не так?
- [ ] Выход становится короче входа, и последние точки временного ряда теряются при прогнозе
- [x] Фильтр видит и будущие значения: на обучении возникает утечка из будущего
- [ ] Свёртка перестаёт быть дилатированной и не может видеть длинную историю ряда
- [ ] Число параметров слоя удваивается из-за дополнения нулями с двух сторон

**Почему.** Симметричное дополнение означает, что выход в момент t зависит и от t+1, t+2…, то есть от будущего: на обучении модель подсматривает ответ, а на реальных данных будущего нет. Правильный вариант — дополнять нулями только слева на (k − 1)·d позиций. Проверка: изменение последней точки входа не должно менять выходы в более ранние моменты.

## Чему равно рецептивное поле стека каузальных свёрток (по одной на уровень) с ядром 2 и дилатациями 1, 2, 4, 8, 16?
- [ ] 31
- [x] 32
- [ ] 62
- [ ] 64

**Почему.** R = 1 + (k − 1)·(d₁ + … + dₙ) = 1 + 1·(1 + 2 + 4 + 8 + 16) = 32. Значение 31 забывает слагаемое 1, а 64 или 62 получаются при ошибочном умножении на k вместо k − 1.

## Зачем дилатацию в TCN удваивают с каждым слоем (1, 2, 4, 8, …)?
- [x] Чтобы поле зрения росло экспоненциально при линейном росте числа параметров
- [ ] Чтобы число параметров каждого следующего слоя росло вдвое вслед за дилатацией
- [ ] Чтобы выход слоя можно было считать параллельно по всем моментам времени ряда
- [ ] Чтобы заменить остаточные связи при обучении глубоких стеков свёрточных слоёв

**Почему.** Ядро с шагом d смотрит на точки x(t), x(t−d), x(t−2d): чем больше d, тем дальше в прошлое. Размер ядра при этом не меняется, поэтому параметров на слой столько же. Параллельность вычислений — свойство самих свёрток, а остаточные связи решают другую задачу — устойчивость обучения глубоких сетей.

## Дневной ряд имеет годовую сезонность (период 365 шагов), а рецептивное поле вашей TCN равно 127. К чему это приведёт?
- [ ] Модель всё равно выучит сезонность, так как веса ядра общие для всего ряда
- [ ] Модель выучит сезонность, если обучать её достаточно долго и на большом числе эпох
- [x] Модель не увидит значения старше 127 шагов и не уловит годовой цикл
- [ ] Модель станет терять информацию о недавних значениях и ухудшит краткосрочный прогноз

**Почему.** Выход зависит только от точек внутри рецептивного поля, и информации о событиях старше него у модели нет. Это главное ограничение TCN по сравнению с RNN. Поле нужно подбирать заранее: добавить уровней, увеличить ядро или дилатации так, чтобы R ≥ 365.

## Что вернёт этот код для входа формы (1, 8, 100) и какой будет длина выхода?
```python
import torch
import torch.nn as nn

conv = nn.Conv1d(8, 16, kernel_size=3, dilation=2)
y = conv(torch.zeros(1, 8, 100))
print(y.shape[-1])
```

- [ ] 100
- [ ] 94
- [x] 96

**Почему.** Без padding длина выхода равна 100 − (k − 1)·d = 100 − 2·2 = 96. Чтобы сохранить длину и остаться каузальным, перед свёрткой нужно добавить слева ровно (k − 1)·d = 4 нуля, например `F.pad(x, (4, 0))`. Формат (batch, channels, time) для `Conv1d` соблюдён.
